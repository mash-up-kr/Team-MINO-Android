# ADR·실패 기록 파일명은 일련번호 대신 날짜 접두어를 쓴다

- **상태**: Accepted
- **작성일**: 2026-07-27
- **작성자**: Jaesung Lee

## 컨텍스트

ADR과 실패 기록은 일련번호 접두어(`NNNN-`, `NNN-`)를 파일명·본문 헤더·README 인덱스에 사용해 왔다. 그런데 번호는 "다음 번호 = 가장 큰 번호 + 1"이라는 중앙 카운터여서, 병렬 브랜치에서 각자 ADR을 작성하면 develop 병합 시점에 번호가 겹치고, 한쪽이 파일명·본문 제목·인덱스·참조를 전부 재조정해야 했다.

이 문제는 이미 실제로 발생했다. 병렬로 진행되던 두 feature 브랜치가 같은 번호(0006·0007)를 선점해 ADR 본문에 충돌 경고 메모를 남겨야 했고, 번호 재배정을 거치며 코드 주석·문서의 "ADR NNNN" 프로즈 참조가 엉뚱한 문서를 가리키는 부패도 관측됐다.

## 결정

ADR·실패 기록 파일명을 `YYYY-MM-DD-kebab-제목.md`(작성일 접두어)로 한다. 본문 헤더에서도 번호를 제거하고 제목만 쓴다. 다른 문서에서 참조할 때는 "ADR NNNN" 같은 번호 프로즈가 아니라 제목과 파일 경로 링크로 참조한다.

## 근거

- 날짜는 중앙 카운터가 아니므로 병렬 브랜치에서 동시에 작성해도 파일명이 겹치지 않는다.
- `ls` 시간순 정렬성은 일련번호와 동일하게 유지된다.
- 문서 발견은 kebab 슬러그(grep·glob)와 README 인덱스 제목으로 이루어지므로 번호가 검색에 기여하는 바가 없다.
- 파일 경로 링크 참조는 번호 재배정에 영향을 받지 않고, 대상이 사라지면 깨진 링크로 드러난다.

## 결과

- 기존 ADR 7건을 각 문서의 작성일 기준으로 리네임하고, 형식 SSOT(`adr-format.md`·`failure-format.md`)·스킬·참조 문서를 갱신했다.
- README 인덱스에 행을 추가하는 병합 충돌 자체는 남지만, 리네임 없이 두 행을 모두 살리면 되는 자명한 충돌로 축소된다.
- 미머지 브랜치에 구 번호 체계로 작성된 ADR이 있다면 머지 시 날짜 접두어로 리네임한다.

## 고려한 대안

- **일련번호 유지**: 병합 충돌 시 리네임 부담과 프로즈 참조 부패가 반복된다.
- **번호 없이 제목만**: 병합 충돌은 해소되지만 파일 목록의 시간순 정렬성을 잃고, 같은 주제의 결정이 뒤집혀 비슷한 제목의 문서가 다시 생길 때 파일명이 충돌할 여지가 있다.
