# SUITE 폰트의 빈 글리프를 cmap에서 제거해 OS 시스템 폰트 폴백으로 처리한다

- **상태**: Accepted
- **작성일**: 2026-07-30
- **작성자**: full_avocado

## 컨텍스트

`core:design-system`은 본문 폰트로 SUITE(`res/font/suite_{regular,medium,bold}.ttf`)를 사용한다. 일부 드문 한글 음절(예: `볷` U+BCF7)이 화면에서 **빈 공백**으로 렌더링되는 문제가 보고됐다(이슈 #95).

원인을 폰트 내부까지 파고들어 확인했다. 원본 SUITE는 이 코드포인트들을 **cmap에는 포함**하지만 매핑된 글리프의 **외곽선이 0개인 빈 글리프**다. 안드로이드/Compose는 지정한 `FontFamily`의 cmap에 코드포인트가 **있으면** "이 폰트가 해당 글자를 가진다"고 판단해 **시스템 폰트 폴백을 하지 않는다.** 그 결과 빈 글리프가 그대로 그려져 공백이 된다. 원본 SUITE는 전체 11,437개 코드포인트 중 **8,506개가 이런 빈 글리프**였다.

즉 문제는 "폰트에 글자가 없어서"가 아니라 "cmap엔 있는데 그림이 없어서 폴백이 막혀서"다.

## 결정

SUITE에서 **외곽선이 0개인 빈 글리프의 코드포인트를 cmap에서 전부 제거**한 파생 폰트를 만들어 번들한다. cmap에서 빠지면 안드로이드가 해당 코드포인트를 **시스템 폰트(단말의 Noto 계열)로 폴백**해 정상 렌더링한다.

- 파생 폰트를 기존 파일명(`suite_regular/medium/bold.ttf`)으로 **그대로 덮어써** 코드(`AtomicTypographyToken.FontFamilySuite`의 `R.font.suite_*` 참조)는 변경하지 않는다.
- **Noto 글리프를 폰트에 embed하지 않는다.** 폴백은 런타임에 OS 시스템 폰트로 처리되므로, 번들되어 재배포되는 것은 SUITE 파생본뿐이다.

## 근거

- **빈 글리프 제거는 무손실이다.** 제거한 8,506개는 원본에서 이미 외곽선이 없어 어차피 공백이었다. 실제로 그려지던 글리프 손실은 0개이며(검증 완료), 파생 폰트에 남은 빈 글리프도 0개다.
- **앱 용량을 지킨다.** 결손의 대부분은 CJK 한자(20,902자 전 범위 미보유)다. 이를 실제로 채우려면 Noto Sans CJK를 embed해야 하는데 weight당 수 MB~십수 MB로 APK가 크게 불어난다. 단말의 시스템 Noto 폴백을 활용하면 용량 증가 없이 같은 결과를 얻는다.
- **코드 변경이 없다.** 파일명을 유지해 디자인시스템 타이포 토큰 배선을 건드리지 않는다.

## 결과

- `볷` 등 빈 글리프였던 코드포인트가 시스템 폰트로 폴백돼 정상 표시된다.
- **폴백 글자의 자형은 단말 시스템 폰트에 의존**하므로 기기마다 픽셀 단위로 동일하지 않다(SUITE가 실제로 그리는 글자는 모든 기기에서 동일).
- 부수효과: `space`(U+0020)도 외곽선 0짜리라 함께 제거됐다. 공백 역시 시스템 폰트로 폴백돼 정상 렌더된다(실사용 지장 없음).
- 부수효과: 병합 과정에서 `suite_medium.ttf`의 내부 name 테이블이 `Regular`로 남았다. Compose는 코드에서 weight를 지정(`Font(R.font.suite_medium, FontWeight.Medium)`)하므로 렌더링엔 영향이 없다(메타데이터 흠집).
- **OFL 준수**: 파생본을 [`core/design-system/OFL.txt`](../../core/design-system/OFL.txt)로 OFL 고지와 함께 배포한다. 원본 SUITE는 Reserved Font Name을 선언하지 않아(name 테이블 copyright에 RFN 문구 없음) `suite_*` 이름 유지는 OFL 위반이 아니다.
- **재생성 절차**: SUITE 원본을 갱신할 때는 다시 fontTools 등으로 **외곽선 0개 글리프의 코드포인트를 cmap에서 제거**한 뒤 번들한다. 이 전처리를 빠뜨리면 빈 글리프 문제가 재발한다.

## 고려한 대안

- **Noto 글리프를 폰트에 병합(embed)** — SUITE에 없는 글리프를 Noto에서 가져와 단일 TTF로 합친다. 결손의 핵심인 CJK 한자까지 채우려면 Noto Sans CJK가 필요해 APK가 수십 MB 증가한다. 단말 시스템 폴백으로 같은 결과를 얻을 수 있어 배제.
- **원본 SUITE를 그대로 사용** — cmap이 빈 글리프를 가리켜 폴백이 막히므로 `볷`류 공백이 그대로 남는다. 문제 미해결로 배제.
- **런타임 `FontFamily` 폴백 체인에 번들 Noto를 추가** — 결국 Noto를 embed해야 하고, 무엇보다 빈 글리프는 cmap에 존재해 첫 폰트에서 "매칭"되므로 폴백 폰트로 넘어가지 않는다. 근본 원인(빈 글리프 cmap 매핑)을 못 풀어 배제.
