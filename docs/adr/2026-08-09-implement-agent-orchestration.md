# SDD Implement 단계는 오케스트레이터 + 전문가 서브에이전트로 실행하고 `.claude/agents/`를 다시 둔다

- **상태**: Accepted
- **작성일**: 2026-08-09
- **작성자**: Jaesung Lee

> [!NOTE]
> 아래 "전문가 서브에이전트 9종"과 "검증 2종"은 이슈 #147에서 **10종·검증 3종**으로 늘었다. Figma 대조를 담당하는 `design-auditor`가 추가됐고, 이 ADR이 정한 나머지 전제 — 리드 단독 조율, 피어 통신 금지, 게이트의 수정 권한 박탈 — 는 그대로 적용된다. 다만 아래 `[X]` 마킹 근거 조항은 **UI를 만드는 작업에 한해** 좁혀졌다. 빌드·테스트가 디자인 일치를 검사하지 않으므로 `quality-gate-runner`의 통과 보고만으로는 마킹하지 않고, `design-auditor`의 판정을 함께 받는다. 배경은 [디자인 토큰은 값이 일치할 때만 강제한다](2026-08-13-design-token-when-value-matches.md)와 [`conventions/figma-design-fidelity.md`](../conventions/figma-design-fidelity.md).

## 컨텍스트

이슈 #129에서 SDD 마지막 단계인 `mino-implement` 스킬을 추가했다. 초안 본문은 tasks.md의 작업을 메인 단일 컨텍스트가 직렬로 실행하는 것을 전제한다.

구현 단계는 앞 단계들과 성격이 다르다.

- 산출물이 문서 하나가 아니라 여러 모듈에 걸친 코드다. 모듈마다 읽어야 할 규약 문서가 갈린다 — `:core:domain`·`:core:data`는 각 README, 화면은 `feature-module.md`, 토큰은 design-system README, 예외는 `error_handling.md`. 한 컨텍스트가 전부 쌓으면 40KB대 문서가 누적되고 뒤로 갈수록 앞의 제약을 잃는다. 이 비용은 [SDD 파이프라인은 단계별 단일 스킬로 구성한다](2026-08-07-sdd-single-skill-per-stage.md)가 이미 결과 항목으로 기록해 둔 것이다.
- 분할 경계가 이미 문서에 있다. tasks.md는 작업을 **파일 경로 단위**로 쪼개고 `[P]` 마커로 병렬 가능 여부까지 표시한다.
- 검증 주체와 구현 주체가 같으면 자기 산출물을 통과시킨다. 이 저장소는 모듈 경계·규약을 검사하는 자동 장치가 없어(헌법 §기술 표준과 제약) 그 자기검증이 마지막 방어선이 된다.

두 개의 기존 기록이 이 지점을 명시적으로 예약해 두었다.

- [plan-gen 고도화는 에이전트 팀이 아닌 서브에이전트 오케스트레이션으로 한다](2026-07-15-plan-gen-subagent-orchestration.md)(Superseded)는 **피어 협상형 팀**과 **오케스트레이터 + 서브에이전트**를 구분하고, 전자의 재검토를 "plan 실행(실제 구현) 단계의 스킬을 만들 때"로 미뤘다.
- 2026-08-07 ADR은 `.claude/agents/`를 없앴지만 **결정의 범위를 "Spec·Plan 생성 단계"로 못박고**, 위 유보는 그대로 유효하다고 남겼다.

## 결정

Implement 단계를 **리드(메인 세션) + 전문가 서브에이전트 9종** 구조로 실행한다. `.claude/agents/`를 다시 두고 전역에 등록한다.

- **조율은 두 지점에서만 일어난다** — 배정 시점의 브리프 주입, 완료 시점의 보고. 전문가끼리 직접 메시지를 주고받지 않는다. 즉 피어 협상형 "팀"이 아니라 2026-07-15가 채택했던 오케스트레이션 구조다. 작업 중 전제가 깨지면 `blocked`로 리드에 반환하고 리드가 브리프를 갱신해 재배정한다.
- **tasks.md `[X]` 마킹은 리드 단독 권한**이다. 마킹 근거는 리드의 산출물 직접 확인 또는 `quality-gate-runner`의 통과 보고 둘 중 하나이며, 전문가의 자기신고만으로는 체크하지 않는다.
- **소유 범위를 모듈 경계와 일치시킨다.** 전문가는 자기 범위 밖 파일을 고치지 않고 `blocked`로 반환한다.
- **검증 2종(`quality-gate-runner`·`constitution-auditor`)은 `tools` 프론트매터에서 수정 도구를 뺀다.** 지적만 하고 고칠 수 없다.
- **각 에이전트 정의는 규약 본문을 담지 않고 경로만 지목한다**(헌법 원칙 I). 규칙은 전문가가 작업 시점에 그 문서를 직접 읽어 확인한다.
- 2026-08-07의 결정을 뒤집지 않는다. Spec·Plan 생성 단계는 스킬 1개 + 템플릿 1개 구성 그대로다.

## 근거

- **협상거리가 없다.** 2026-07-15가 팀 구조를 기각한 기준은 "런타임 협상이 필요한가"였다. 구현 단계는 인터페이스가 일하면서 드러날 여지가 있어 재검토 대상이었지만, plan을 입력으로 만든 tasks.md가 이미 파일 경로까지 확정해 준다. 리드가 시작 전에 배정을 고정할 수 있으므로 같은 기준에서 같은 결론이 나온다.
- **컨텍스트 비용의 방향이 앞 단계와 반대다.** 생성 단계는 산출물이 하나여서 팬아웃 이득이 적었다. 구현은 모듈별로 읽을 문서가 갈리므로 분리가 곧 절감이며, 리드는 브리프와 보고 줄만 들고 간다.
- **권한 분리가 문서보다 강하다.** "고치지 마라"를 문장으로 적으면 지켜지지 않을 수 있지만, `tools` 화이트리스트는 그것을 실행 불가로 만든다. 자동 검증이 얇은 저장소에서 얻을 수 있는 몇 안 되는 실질적 강제력이다.
- **마킹 권한을 단일화하지 않으면 병렬 실행이 진행 상태를 깬다.** 여러 에이전트가 같은 파일에 체크를 쓰면 충돌하고, 무엇이 실제로 끝났는지가 후속 `/mino-analyze`에서 신뢰할 수 없게 된다.

## 결과

- `.claude/agents/`에 정의 9개(`context-analyst`·`build-setup-engineer`·`test-engineer`·`core-layer-developer`·`ui-developer`·`navigation-integrator`·`design-system-builder`·`quality-gate-runner`·`constitution-auditor`)가 생기고, `mino-implement/SKILL.md`에 §에이전트 팀과 §에이전트 공통 계약이 추가된다. 실행 구조의 단일 출처는 SKILL.md, 각 전문가 정의의 단일 출처는 해당 에이전트 파일이다.
- **2026-08-07이 없앴던 비용이 일부 돌아온다.** 세션마다 에이전트 정의 9개의 이름·설명이 로드되고, 전역 등록이라 SDD와 무관한 세션에서도 목록에 뜬다. 이것이 이 결정의 가장 큰 대가다.
- **자가검수 게이트가 Implement 단계에만 되살아난다.** Spec·Plan에는 여전히 없고 사람 컨펌만 있다.
- 규약 문서가 바뀌어도 에이전트 정의는 고치지 않는다 — 경로만 들고 있기 때문이다. 반대로 문서가 **이동하면** 9개 파일의 링크가 함께 깨진다.
- **실행 실적이 없는 상태의 결정이다.** 이 구조로 돌린 기능이 아직 없다. 첫 적용에서 배정 단위(모듈 소유)나 동시 3종 제한이 실제와 어긋나면 이 기록을 갱신한다.
- 전문가가 소유 범위 밖을 만나면 `blocked`를 반환하므로, 경계 설계가 틀리면 `blocked`가 잦아진다. 그 빈도가 경계 재조정의 신호다.

## 고려한 대안

- **단일 컨텍스트 직렬 실행 유지** — 가장 싸고 스킬 본문도 늘지 않는다. 그러나 모듈별 규약 문서가 한 컨텍스트에 그대로 누적되고, 구현한 주체가 자기 산출물을 검증하는 구조를 벗어날 수 없다. 기각.
- **피어 협상형 에이전트 팀** — 2026-07-15가 구현 단계용으로 유보해 둔 구조. 작업 중 인터페이스 협상이 필요한 개방형 작업에 적합하지만, tasks.md가 plan을 근거로 파일 경로까지 확정하므로 협상할 것이 남지 않는다. 통신 오버헤드와 재현성 저하만 남아 기각.
- **에이전트 정의를 스킬 디렉터리 안에 둔다**(`.claude/skills/mino-implement/agents/`) — 전역 에이전트 목록을 늘리지 않아 위 컨텍스트 비용을 피할 수 있다. 그러나 서브에이전트로 자동 등록되지 않아 리드가 파일 내용을 프롬프트로 복사해 넘겨야 하고, 정의가 파일과 주입된 사본 두 곳에 존재하게 되어 원칙 I이 깨진다. 기각.
