# 익명 세션 확보의 재시도·지연 판정은 호출 화면이 소유하고, 데이터 레이어는 멱등한 1회 확보만 제공한다

- **상태**: Accepted
- **작성일**: 2026-08-22
- **작성자**: Jaesung Lee

## 컨텍스트

비회원 익명 인증 세션(이슈 #176)의 요구사항은 확보 실패를 사용자에게 알리고 **사용자 조작 없이 자동으로 다시 시도**할 것, 확보가 **지연되는 상태를 실패와 구분**해 다룰 것, 세션이 확보되기 전에는 진입 화면 밖으로 사용자를 내보내지 않을 것이었다. 재시도에는 상한을 두지 않는다 — 진입 화면을 벗어나는 경로가 세션 확보뿐이라 재시도를 그만둘 지점이 없기 때문이다.

이 요구들은 자연스럽게 "그러면 재시도 루프와 지연 임계를 어디에 두는가"를 묻게 만든다. 후보는 둘이었다. UseCase가 백오프 재시도를 소유하거나, 데이터 레이어는 한 번만 시도하고 호출자가 루프를 도는 것이다.

제약이 하나 있었다. 안내 문구·정상/지연/실패를 가르는 임계 시간·표시 위치는 명세 단계에서 **진입 화면 스펙 소관**으로 명시적으로 이연된 상태였고, 그 진입 화면은 아직 구현이 없다.

## 결정

**재시도와 지연 판정을 호출자(진입 화면)가 소유한다.** `:core:domain`과 `:core:data`는 **멱등한 1회 확보**만 계약으로 제공한다.

- `AnonymousAuthRepository.ensureSession()`과 `EnsureAnonymousSessionUseCase`는 재시도 루프·백오프·타임아웃 임계를 갖지 않는다. 이 함수는 스스로 상한을 두지 않는다.
- 멱등성은 구현이 보장한다 — 잠금 밖에서 현재 사용자를 먼저 확인해 확보된 경우 즉시 반환하고(네트워크 왕복 0회), 없을 때만 `Mutex`를 잡고 잠금 안에서 한 번 더 확인한 뒤 익명 로그인을 수행한다. 몇 번을 호출해도, 동시에 호출해도 세션은 하나만 만들어진다.
- 확보 **과정**의 상태(정상·지연·연결 실패·그 밖의 실패)는 도메인 모델이 아니다. 진입 화면이 소유한다.
- 호출자가 지켜야 할 조건은 [`contracts/anonymous-auth-repository.md`](../specs/anonymous-auth-session/contracts/anonymous-auth-repository.md) §4가 C-1~C-8로 소유한다.

## 근거

임계 시간·문구·표시 위치가 화면 정책인데 데이터 레이어에 임계를 두면 같은 값을 두 곳이 갖게 된다. 명세가 이미 그 값들의 소유자를 진입 화면 스펙으로 지목했으므로, 데이터 레이어에 상수를 박는 순간 SSOT가 갈린다.

더 결정적인 이유는 재시도의 **종료 조건**이다. 재시도는 "진입 화면을 벗어났는가"로 끝나는데, 데이터 레이어는 그 화면의 수명주기를 알지 못한다. 반대로 UseCase가 루프를 소유하면 화면이 "지연 중" 상태를 표시할 시점을 알 수 없다 — UseCase가 반환하기 전까지 진행 상황이 보이지 않기 때문이다.

재호출이 멱등하고 부작용이 없으므로 호출자가 루프를 도는 것으로 충분하다. 이미 확보된 상태의 재호출은 SDK가 로컬에 유지한 상태를 읽는 동작이라 네트워크 왕복이 없고, 그래서 루프의 비용이 낮다.

잠금 안 재확인(double-checked)이 없으면 동시 호출 두 건이 모두 "세션 없음"을 보고 로그인을 두 번 시도할 수 있다. 같은 문제를 `Mutex.withLock`으로 푼 선례가 이번에 제거되는 `DeviceRepositoryImpl`에 이미 있었다.

## 결과

- 진입 화면 스펙이 임계 시간·안내 문구·표시 위치를 소유한다. 그 화면이 만들어지기 전까지 이 기능에는 프로덕션 호출자가 없고, 확보 계약의 검증은 데이터 레이어 단위 테스트까지다.
- **`withTimeout`으로 지연 임계를 걸면 안 된다.** `TimeoutCancellationException`은 `CancellationException`이라 도메인 예외 경로를 타지 않고 CEH로 샌다. `withTimeoutOrNull`로 받아 화면 상태 전이로 처리한다.
- **재시도 루프를 도메인 예외 수신에만 종속시키지 않는다.** 화이트리스트 밖 예외는 CEH로 가는데, 진입 화면은 넘어갈 곳이 없어 사용자가 안내도 재시도도 없는 화면에 남을 수 있다. CEH의 통상 전제("죽는 것은 코루틴 하나이며 UI·네비게이션은 살아 있다")가 이 화면에서만 다른 의미를 갖는다는 뜻이다. 탈출구 리프로 전부 흡수하는 대신 이 조건을 호출자 계약(C-5)에 두었다 — [도메인 예외 매핑 지점은 원천마다 하나씩 두고, 인증 실패용 `Auth` 리프를 추가한다](2026-08-22-domain-exception-mapping-per-source.md) 참조.
- 데이터 레이어 테스트는 확보 횟수로 계약을 판정한다 — 최초 확보 1회, 재호출 시 증가 없음, 동시 N 호출에도 1회. 계측 테스트가 필요 없다.
- 이 결정은 세션 확보에 한정된 것이 아니라, **"부작용이 있는 확보 동작은 멱등하게 만들고 재시도 정책은 화면이 소유한다"**는 형태로 이후의 유사한 작업(권한 확보, 토큰 발급 등)에 그대로 적용할 수 있다.

## 고려한 대안

**UseCase가 백오프 재시도를 소유한다.** 호출자가 한 줄만 쓰면 된다는 장점이 있으나, 임계와 간격이 화면 정책인데 domain에 상수로 박히고, 화면이 "지연 중"을 표시할 시점을 알 수 없다. UseCase가 반환하기 전까지 진행 상황이 밖에서 보이지 않는다.

**`WorkManager`·`ProcessLifecycle` 기반으로 백그라운드에서 재시도한다.** 진입 화면 체류가 요구사항이라 화면 밖 실행 주체가 필요 없다. 재시도의 종료 조건을 화면 수명주기에서 떼어내면 오히려 끝낼 시점이 사라진다.

**`Mutex` 없이 `lazy`·`Deferred`로 캐시한다.** 실패했을 때 캐시된 실패 `Deferred`가 남아, 이후의 모든 재시도가 영구히 같은 실패를 재생한다. 자동 재시도 요구와 정면으로 충돌한다.

**Firebase SDK의 내부 직렬화에 의존한다.** 이미 익명 사용자가 있으면 `signInAnonymously()`가 기존 사용자를 돌려주는 동작이 있으나, 이는 SDK 구현 세부이고 앱 코드에서 검증할 수 없다. 앱 계약으로 요구되는 성질을 SDK 동작에 위임하지 않는다.

**`Flow<AnonymousSession?>` 상태 스트림으로 노출한다.** 세션은 확보 후 폐기되지 않으므로 관찰할 상태 변화가 없다. 호출자가 다뤄야 할 상태를 늘리기만 한다.
