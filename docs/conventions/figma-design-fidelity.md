# Figma 디자인 정확도 컨벤션

화면·컴포넌트를 Figma 디자인대로 구현하고, 그것이 실제로 일치하는지 확인하는 절차. 사람이 짜든 에이전트가 짜든 같다.

이 문서는 **판정과 대조 절차**만 소유한다. 겹치는 문서와의 경계는 다음과 같다.

| 무엇을 | 어디가 소유하는가 |
|---|---|
| 강제 규칙의 본문 (무엇이 위반인가) | [헌법 §기술 표준과 제약](../constitution.md) |
| 결정의 근거·배제한 대안 | [ADR — 값이 일치할 때만 토큰 강제](../adr/2026-08-13-design-token-when-value-matches.md) · [ADR — 셰이프 foundation 폐기](../adr/2026-08-13-no-shape-token-foundation.md) |
| 토큰 체계·계층·토큰 추가 절차 | [`core:design-system` README §4](../../core/design-system/README.md#4-토큰-시스템) |

## 1. 전제 — Figma 조회 경로

MCP 서버가 둘 등록돼 있다. **둘 다 동작한다** — 고르는 기준은 아래 표 다음에 있다.

| | `figma` (클라우드) | `figma-desktop` |
|---|---|---|
| 문서 지정 | 호출마다 `fileKey`를 넘긴다. **파일을 자유롭게 오간다** | **활성 탭의 문서만** 본다. `nodeId`는 지정해도 문서는 고를 수 없다 |
| 시작 전 준비 | 없음. 데스크톱 앱을 켜지 않아도 된다 | 대상 파일을 **활성 탭으로 열어 둔다** |
| 그 밖에 있는 것 | `download_assets`(에셋 파일 export) · `search_design_system` · `get_libraries` · 쓰기 계열 | 읽기 6종만. 호출 한도가 없다 |

**클라우드를 쓴다. 데스크톱은 클라우드가 막혔을 때만 쓴다.**

데스크톱은 **사람이 지금 무엇을 열어 두었는지에 의존한다.** 에이전트는 탭을 바꿀 수 없고 무엇이 열려 있는지도 모른다. 여러 작업이 동시에 도는 실행에서 서로 다른 파일을 요구하면 활성 탭 하나로는 댈 수 없어 [§1.2](#12-조회가-막혔을-때)의 `No node could be found`로 막힌다 — 실패가 시끄러운 것이지 손실이 없는 것이 아니다. 에셋을 다루는 작업은 데스크톱에 `download_assets`가 아예 없어 선택지도 아니다([§1.3](#13-에셋-export--아이콘-svg이미지)).

- **데스크톱으로 넘어가는 조건은 하나다 — 클라우드 호출 한도에 걸렸을 때.** 그때도 대상 파일이 활성 탭인지 먼저 확인하고, 확인할 수 없으면 추측하지 말고 중단한다(같은 절)
- 예외: **사람이 대화형으로** 작업하며 URL 없이 지금 선택한 노드를 집을 때. 에이전트에는 해당하지 않는다 — 에이전트는 언제나 노드 ID를 갖고 시작한다

### 1.1 클라우드의 제약 — 컴포넌트 정의 노드

인스턴스(`<instance>`)는 정상 조회되지만, **그 인스턴스가 물고 있는 컴포넌트/컴포넌트셋 노드 ID**를 넣으면 `This is an invalid node selection`이 난다. 화면 파일에 보이는 그 ID는 인스턴스의 내부 참조이고, 실제 정의는 **디자인 시스템 라이브러리 파일에 다른 ID로** 있기 때문이다.

- 뚫는 법은 하나다 — **사용자에게 그 컴포넌트셋의 링크(Copy link)를 받는다.** URL의 `fileKey`+`nodeId`면 바로 열린다.
- `search_design_system`은 소속 라이브러리만 알려주고 **노드 ID를 주지 않아** 단독으로는 못 뚫는다.
- 인스턴스 하나로도 variant 이름과 그 상태의 변수 값은 얻을 수 있다. 다만 **화면에 안 그려진 variant는 이 경로로 볼 수 없다.**

### 1.2 조회가 막혔을 때

에러 문구가 원인을 가른다.

| 문구 | 뜻 |
|---|---|
| `invalid node selection` | 노드는 실재하나 정의 노드라 막힌 것 → [1.1](#11-클라우드의-제약--컴포넌트-정의-노드) |
| `not found in the file` | 그 파일에 없는 ID → `fileKey`가 틀렸거나 노드가 지워졌다 |
| `No node could be found for the provided nodeId` (데스크톱) | 대상 파일이 활성 탭이 아니다 |

어느 쪽이든 **추측으로 값을 채우지 않고 중단한다** — 에이전트라면 `blocked`로 반환한다. 확인할 수 없는 축은 통과가 아니라 **미검증**이다([§6](#6-검증)).

### 1.3 에셋 export — 아이콘 SVG·이미지

**클라우드 `download_assets`가 노드를 파일로 내보낸다. 사람 손이 필요하지 않다.**

1. 대상 노드를 `download_assets`에 넘긴다. `rawImages`가 아니라 **`export`**를 쓴다 — `rawImages`는 원본 업로드 이미지라 컴포넌트 렌더 결과가 아니다.
2. 반환된 `export.url`을 `curl -L -o <저장 경로>`로 받는다.
3. 래스터는 `defaultScale` 1·2·3으로 밀도별로 뽑는다. 아이콘 SVG는 스케일이 필요 없다.

아이콘을 `MinoIcons`에 올리는 절차와 변환 스크립트가 받는 SVG 조건은 [README §5.2](../../core/design-system/README.md#52-아이콘-추가하기)가 소유하며, 위 export가 그 1번 단계를 대신한다. 스크립트가 SVG를 거부하면 Figma에서 패스를 병합해야 하므로 **그때만** 사람 손이 필요하다.

데스크톱 서버에는 이 툴이 없다. 데스크톱 `get_screenshot`은 인라인 이미지만 반환해 파일로 저장되지 않는다.

## 2. 판정 — 토큰이냐 실측값이냐

기준은 **"토큰이 존재하는가"가 아니라 "값이 같은가"**다. 존재 기준으로는 규칙을 지키고도 디자인과 어긋난다.

1. 대상 노드를 `get_variable_defs`로 연다. 그 노드가 쓰는 변수의 이름과 값이 나온다.
2. **변수가 있고 값이 같은 토큰이 코드에 있다** → 반드시 토큰으로 접근한다.
3. **변수가 있는데 대응 토큰이 없다** → 토큰을 추가한다([README §4.4](../../core/design-system/README.md#44-토큰-추가하기)). 단 **토큰 신설을 구현의 선행 조건으로 삼지 않는다.** `:core:design-system`이 소유 범위 밖이면 실측값으로 진행하고, [2.2의 마커 주석](#22-토큰-미존재-마커)을 남긴 뒤 토큰화를 별도 작업으로 보고한다.
4. **변수가 안 붙어 있다** → `get_design_context`로 실측값을 읽어 그대로 쓴다. 주석을 남기지 않는다.

**금지**

- **값이 같은 토큰이 있는데 raw를 쓰는 것.** 이 컨벤션의 유일한 위반 판정이다.
- **값의 출처를 코드 주석으로 복사해 두는 것.** 그 주석은 Figma의 사본이라 디자인이 바뀌는 순간 조용히 낡고, 검증한 척하는 근거가 된다. 검증은 주석이 아니라 대조로 한다. **이번에 구현하지 않은 variant·상태의 값을 "참고로" 남기는 것도 같은 금지다.** 예외는 [2.2](#22-토큰-미존재-마커) 하나뿐이다.
- **눈대중.** 스크린샷만 보고 값을 옮기지 않는다.

### 2.1 다크 모드 단서

색만 라이트/다크 2벌(`ColorScheme`)이라, 토큰을 우회하면 **모드 전환이 조용히 깨진다.** raw 색은 모드에 따라 바뀌지 않는다.

- Figma에 변수가 안 붙은 색은 디자이너가 다크 값도 정하지 않은 색이므로, raw 고정이 오히려 디자인에 충실하다.
- 그러나 **모드에 따라 달라져야 하는 색은 raw로 표현할 수 없다.** 이 경우 디자이너에게 변수 바인딩을 요청하고, 받기 전까지 라이트 값으로 고정한 뒤 그 사실을 보고에 남긴다.

### 2.2 토큰 미존재 마커

판정 3번 — **변수는 있는데 대응 토큰만 없는** 경우는 해소되어야 할 임시 상태다. 이때만 raw 값에 주석을 남긴다.

```kotlin
// Figma Radius 변수 대응 — 토큰 미존재
val CoverShape: Shape = RoundedCornerShape(14.dp)
```

- **대응 변수의 이름만 적는다. 값은 적지 않는다** — 값을 적는 순간 그 주석이 사본이 되어 디자인 변경에 낡는다. 값은 코드 리터럴 하나로 족하다.
- 판정 4번(Figma에 변수 자체가 없음)은 임시 상태가 아니므로 **주석을 남기지 않는다.**
- 토큰이 추가되면 주석과 raw 값을 함께 지운다.

## 3. 그리기 — 노드를 먼저 연다

**코드를 쓰기 전에** 노드를 열어 구조부터 확보한다. tasks.md의 설명은 작업의 범위이지 디자인의 사본이 아니다 — 산문을 먼저 코드로 옮기면 값은 나중에 맞출 수 있어도 **구조는 이미 굳는다.**

| 순서 | 도구 | 가져올 것 |
|---|---|---|
| 1 | `get_metadata` | 요소 계층과 순서, 각 요소의 크기·위치. 하위 컴포넌트의 노드 ID도 여기서 얻어 필요하면 그 노드로 내려간다 |
| 2 | `get_design_context` | auto-layout(방향·간격·패딩·정렬), 크기 제약(fill/hug/fixed), 텍스트 스타일, 참조 코드 |
| 3 | `get_screenshot` | 최종 형태. 위 둘로 읽은 구조가 맞는지 확인한다 |

- 화면 프레임만 지목받았어도 1번이 자식 계층을 통째로 주므로, 컴포넌트 단위 작업은 거기서 해당 자식으로 내려간다. **검수자도 같은 경로로 내려오므로 둘이 같은 것을 본다.**
- 2번의 참조 코드는 **그대로 붙여 넣지 않는다.** 이 저장소의 컴포넌트·토큰·레이아웃 관례로 옮겨 적는다.
- 산문 설명과 노드가 어긋나면 **노드를 따르고** 그 사실을 보고에 적는다.

## 4. 대조 — 무엇을 어디까지 보는가

그린 뒤, UI를 만드는 작업 하나당 세 단계를 모두 거친다.

| 단계 | 도구 | 확인할 것 |
|---|---|---|
| 1 | `get_variable_defs` | 노드가 쓰는 **변수 전수**. 코드 값과 1:1로 맞춰 본다 |
| 2 | `get_design_context` | 변수가 붙지 않은 치수·간격·색 |
| 3 | `get_screenshot` | **구조** — 요소 누락·추가, 순서, 중첩 계층, 정렬, 간격 구조, 크기 제약 |

값과 구조 어느 쪽이든 **어긋나면 위반이다. 심각도를 나누지 않는다.** 다만 구조 판정의 기준은 **렌더 결과**이며, 결과가 같은 순수 그룹핑 차이는 위반이 아니다 — §3이 참조 코드를 이 저장소의 관례로 옮겨 적기를 요구하므로, Figma 프레임 트리와 Composable 트리의 1:1을 함께 요구할 수는 없다.

**전수 대조가 기준이다.** "색·타이포처럼 토큰 체계가 있는 축만" 보는 대조는 통과로 보지 않는다 — 치수 오차가 정확히 그 틈으로 지나간다. `RoomCardTokens.CoverShape`가 16dp로 굳어 있던 동안 Figma는 `Radius` 변수 14를 쓰고 있었고, 그것을 잡아낸 것은 코드 검토가 아니라 노드를 열어 변수를 읽은 대조였다([ADR §근거](../adr/2026-08-13-design-token-when-value-matches.md)).

## 5. 노드 참조 표기

- 형식은 `2314-95318`. 각 문서에서 **최초 1회만** 전체 URL을 링크하고 이후는 ID만 쓴다. 한글 파일명이 percent-encoding된 URL은 옮길 때마다 토큰을 크게 낭비한다.
- **UI를 만드는 작업은 대조할 노드를 명시한다.** 노드가 없는 UI 작업은 대조 대상이 없다는 뜻이므로, 값의 출처를 밝히거나 `[TBD]`로 남긴다.
- **코드에는 노드 ID를 적지 않는다.** 2절의 주석 금지와 같은 이유다.

## 6. 검증

빌드·테스트·Lint 게이트는 이 컨벤션을 **전혀 검사하지 않는다.** 게이트 통과를 디자인 일치의 근거로 삼지 않는다.

통과 근거로 제출할 것:

```text
<노드 ID> | 대조: <변수명>=<값> · <변수명>=<값> … | <불일치 또는 미바인딩 항목>
```

- 검증 주체는 **Figma를 조회할 수 있어야 한다.** 코드만 읽어서는 어떤 raw 값이 "토큰이 없어서 raw"인지 "토큰을 안 찾아봐서 raw"인지 구분되지 않는다.
- 조회할 수 없는 주체는 이 축을 **통과로 판정하지 않는다.** 미검증으로 보고한다.
