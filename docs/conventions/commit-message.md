# 커밋 메시지 컨벤션

**Conventional Commits** 스타일을 기반으로 하되, 메시지는 **한국어**로 작성한다. scope는 사용하지 않으며, `Co-Authored-By` 꼬리표는 붙이지 않는다.

## 포맷

```
<type>: <한국어 제목>

<선택: 한국어 본문 — 배경, 구현 세부, 고려 사항>

<선택: 푸터 — BREAKING CHANGE, 이슈 참조 등>
```

- **제목**: 한 줄, 마침표 없음, 명령형보다는 완료형/요약형 권장
- **본문**: 필요할 때만. "왜" 바꿨는지 위주로
- **푸터**: 필요할 때만

## type 목록

| type | 쓰임 |
|---|---|
| `feat` | 신규 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 구조 개선 |
| `docs` | 문서·주석·KDoc 수정 |
| `chore` | 빌드·설정·의존성·CI 등 부수 작업 |
| `test` | 테스트 추가/수정 |
| `style` | 포맷·세미콜론·공백 등 동작 무관 스타일 변경 |
| `perf` | 성능 개선 |

## scope

**사용하지 않는다.** `feat(auth):` 같은 scope 표기 금지. 단순히 `feat: 로그인 API 연동` 형태로 유지.

## 예시

```
feat: 로그인 API 연동
```

```
fix: 홈 화면 진입 시 크래시 해결

탭 전환 시 Fragment 재생성 타이밍과 ViewModel 초기화가
충돌하는 문제였음. onViewCreated에서 상태 복원 순서를 조정함.
```

```
docs: 디자인 시스템 KDoc 작성
```

```
refactor: UseCase 계층 중복 코드 정리
```

```
chore: AGP 9.1.1 업그레이드
```

## 기여자 표기

`Co-Authored-By: Claude` 꼬리표는 **붙이지 않는다.** Claude가 작성을 보조하더라도 판단 최종 결정자이자 커밋 작성자는 개발자이므로 기여자에 별도 표기하지 않는다.

## BREAKING CHANGE

드물지만 하위 호환을 깨는 변경이 포함된 경우 푸터에 명시:

```
feat: 세션 토큰 저장 방식 변경

BREAKING CHANGE: SharedPreferences에 저장하던 토큰을
EncryptedSharedPreferences로 이전. 기존 설치본은 재로그인 필요.
```

## 쪼개기 원칙

한 PR/브랜치에 여러 논리 단위의 변경이 섞여 있다면, **가능한 한 커밋을 분리**한다. 분리 기준 예시:

- 기능 추가 ↔ 리팩토링
- 프로덕션 코드 ↔ 테스트
- 모듈 A 작업 ↔ 모듈 B 작업
- 의존성 업그레이드 ↔ 실제 기능 변경

커밋 하나가 하나의 의도만 담도록 한다. 섞여 있으면 리뷰·리버트·히스토리 추적이 어렵다.
