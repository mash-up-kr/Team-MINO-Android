**개정 입력(1.1.0)**: 사용자 설명: "온보딩 플로우에서 시스템 백 프레스에 대한 정책 변경이 있음" — 더 물러설 곳이 없는 지점의 시스템 뒤로가기를 `무반응`에서 `앱을 백그라운드로`로 바꿨다. 앞 스텝으로 되돌아가지 않는 원칙은 그대로다.

**개정 입력(1.2.0)**: 사용자 설명: "개정된 PRD를 통해 spec 업데이트" — 기준 PRD를 `5.0.0`에서 `9.0.0`으로 올리며 대조했다. PRD `6.0.0`~`9.0.0`의 개정은 [SCR-003] 홈 카드 덱·[SCR-006] 장소 상세·[SYS-004] 지도에 한정되어 **이 문서가 다루는 온보딩 섹션([SCR-001]·[SCR-002]·[SYS-001]·[SYS-006]·[SYS-011])은 변경되지 않았다.** 대신 대조 과정에서 드러난 세 가지 어긋남을 §3 비목표와 §4 가정에 기록했다 — PRD [SYS-006] Flow A에 남은 뒤로가기 서술, 온보딩 진입 판정의 소유권, 튜토리얼 문구의 제스처 방향.

> 위 두 개정은 작성 시점에 버전을 동결했다가 `1.1.0`으로 함께 올렸다. `1.0.0`과 `1.1.0` 사이에서 `FR-007`·`FR-012`의 의미가 바뀌었으므로, 이 spec을 근거로 만든 하위 문서는 `1.1.0` 기준으로 다시 확인해야 한다. `1.2.0`은 요구사항 항목을 하나도 바꾸지 않았고, 늘어난 것은 가정과 비목표의 기술뿐이다.

> 이 문서는 PRD [SCR-002] 앱 온보딩을 다룬다. 온보딩이 거치는 화면 중 **프로필 설정**([SYS-011])과 **공동방 생성 폼**([SYS-001])은 각각 `docs/specs/profile`·`docs/specs/group-room-form`이 정의하므로, 이 문서는 그 화면들의 **진입 조건·이탈 수단·다음 스텝 결정**만 다룬다. 화면 내부의 입력 규칙은 다시 적지 않는다.

## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 온보딩을 처음부터 끝까지 밟는다

앱을 처음 설치한 사용자가 프로필을 만들고, 첫 공동방을 만들고, 친구를 초대하고, 공유 방법을 익힌 뒤 홈에 도착한다. 온보딩은 앞으로만 흐르며, 각 스텝을 끝내는 순간 다음 스텝이 결정된다.

**Figma**: [000-1 튜토리얼_step 1](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-167079&m=dev) · [009-1 친구 초대](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95550&m=dev) · [010-1 프로필 설정_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95662&m=dev) · [001-1-1 공동방_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95301&m=dev)

**진입 조건**: 프로필이 없는 앱 설치에서 스플래시가 익명 세션 확보를 끝내고 온보딩을 띄운 상태. 온보딩의 첫 스텝인 프로필 설정 화면이 열려 있고, 바텀 네비게이션은 보이지 않는다.

1. 사용자가 프로필 설정 스텝에서 프로필을 저장한다 → 시스템이 개인방(`내 장소`) 생성을 촉발한 뒤 공동방 생성 스텝을 연다
2. 사용자가 공동방 생성 스텝에서 방을 만든다 → 시스템이 그 공동방을 만들고 친구 초대 스텝을 연다
3. 사용자가 친구 초대 스텝에서 [초대 링크 복사]를 누른다 → 시스템이 초대 링크를 클립보드에 복사하고 복사 완료 토스트를 띄운다. 화면은 친구 초대 스텝에 머무른다
4. 사용자가 우상단 [X]를 누른다 → 시스템이 공유 방법 튜토리얼 스텝 1을 연다
5. 사용자가 튜토리얼을 스텝 5까지 넘긴다 → 시스템이 스텝마다 안내 문구·예시 이미지·dot 위치를 갱신하고, 스텝 5에서 하단 CTA `꾹 시작하기`를 노출한다
6. 사용자가 `꾹 시작하기`를 누른다 → 시스템이 온보딩을 끝내고 홈 탭을 열며 바텀 네비게이션을 노출한다

**완료 조건**: 이 앱 설치에 프로필과 개인방(`내 장소`)이 존재하고, 공동방이 1개 만들어져 있으며, 온보딩이 완료로 기록되어 홈 탭이 열려 있고 바텀 네비게이션이 보인다.

### 유저 플로우 2 - 공동방 만들기를 건너뛴다

지금 함께 쓸 사람이 없는 사용자가 첫 공동방 만들기를 건너뛰고 바로 공유 방법만 익힌다. 방을 만들지 않았으므로 초대할 방도 없어 친구 초대 스텝은 아예 거치지 않는다.

**Figma**: [001-1-1 공동방_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95301&m=dev) · [000-1 튜토리얼_step 1](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-167079&m=dev)

**진입 조건**: 프로필 저장을 마쳐 개인방(`내 장소`)이 생성됐고, 온보딩의 공동방 생성 스텝이 열려 있다. 상단에 [건너뛰기]가 보이고 뒤로가기는 보이지 않는다.

1. 사용자가 상단 [건너뛰기]를 누른다 → 시스템이 공동방을 만들지 않고 친구 초대 스텝도 거르며 튜토리얼 스텝 1을 연다
2. 사용자가 튜토리얼 상단 [건너뛰기]를 누른다 → 시스템이 온보딩을 끝내고 홈 탭을 열며 바텀 네비게이션을 노출한다

**완료 조건**: 이 앱 설치에 프로필과 개인방(`내 장소`)만 존재하고 공동방은 0개이며, 온보딩이 완료로 기록되어 홈 탭이 열려 있다.

### 유저 플로우 3 - 첫 공동방에 친구를 초대한다

방을 막 만든 사용자에게 초대 링크를 건네는 전체 화면 스텝이다. 아직 방에 아무도 없으므로 참여자 목록은 보여주지 않고, 링크를 넘기는 두 갈래(OS 공유 시트 / 클립보드 복사)만 제공한다.

**Figma**: [009-1 친구 초대](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95550&m=dev) · [009-2 친구 초대_초대링크 복사](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2370-67386&m=dev)

**진입 조건**: 직전 스텝에서 공동방을 1개 만들었고, 친구 초대 스텝이 전체 화면으로 열려 있다. 안내 문구(`친구들을 초대해볼까요?` / `"여기 어때?"는 이제 그만 친구가 들어오면 저장한 장소가 한눈에 모여요. 다음 약속 장소, 여기서 같이 골라요.`)와 두 개의 액션([친구 초대하기]·[초대 링크 복사])이 보이고, 참여자 목록은 없다.

1. 사용자가 [친구 초대하기]를 누른다 → 시스템이 방금 만든 공동방의 초대 링크를 실어 OS 공유 시트를 연다
2. 사용자가 공유 시트에서 카카오톡 등으로 링크를 보내거나 시트를 닫는다 → 시스템이 친구 초대 스텝을 그대로 유지한다. 자동으로 다음 스텝으로 넘기지 않는다
3. 사용자가 [초대 링크 복사]를 누른다 → 시스템이 초대 링크를 클립보드에 복사하고 복사 완료 토스트를 띄운다. 화면은 친구 초대 스텝에 머무르므로 사용자는 링크를 여러 번 복사하거나 [친구 초대하기]를 이어서 쓸 수 있다
4. 사용자가 우상단 [X]를 누른다 → 시스템이 튜토리얼 스텝 1을 연다

**완료 조건**: 방금 만든 공동방의 초대 링크가 사용자에게 전달됐거나(공유 시트 전송·클립보드 복사) 사용자가 이 스텝을 벗어났고, 화면이 튜토리얼 스텝 1로 넘어가 있다.

## 2. 요구사항 (Requirements) *(필수)*

### 2.1 기능적 요구사항 (Functional Requirements)

**스텝 구성과 진행**

- **FR-001**: 시스템은 반드시 온보딩을 `프로필 설정` → `공동방 생성` → `친구 초대` → `공유 방법 튜토리얼` 순서로 진행하며, 앞 스텝이 끝나야 뒤 스텝을 연다. (근거: PRD [SCR-002] Flow A~D)
- **FR-002**: 시스템은 반드시 프로필 설정 스텝에 건너뛰기 수단을 두지 않으며, 프로필 저장이 성공해야만 다음 스텝을 연다. (근거: PRD [SCR-002] Flow A "건너뛰기 불가")
- **FR-003**: 시스템은 반드시 공동방 생성 스텝에 [건너뛰기]를 노출하고, 눌리면 공동방을 만들지 않은 채 공유 방법 튜토리얼 스텝을 연다. (근거: PRD [SYS-001] Flow E, [SCR-002] Flow B)
- **FR-004**: 시스템은 반드시 공동방 생성 스텝에서 공동방을 만든 사용자에게만 친구 초대 스텝을 노출하고, 만들지 않은 사용자에게는 노출하지 않는다. (근거: PRD [SCR-002] Flow C "Flow B에서 공동방을 만든 사용자에게만 노출")
- **FR-005**: 시스템은 반드시 온보딩의 모든 스텝에서 바텀 네비게이션을 노출하지 않고, 온보딩이 끝나 홈 탭에 진입하는 시점부터 노출한다. (근거: PRD [SCR-002] "화면 특성: 바텀 네비게이션 비노출", [SCR-002] Flow D)
- **FR-006**: 시스템은 반드시 온보딩의 모든 스텝에서 앞 스텝으로 되돌아가는 뒤로가기 컨트롤을 노출하지 않는다. 친구 초대 스텝도 예외가 아니다. (근거: PRD [SYS-001] Flow E, [SYS-011] Flow D, §5 확정 "온보딩에서는 뒤로가기를 표출하지 않는다". PRD [SYS-006] Flow A 이탈 경로에 남아 있는 `[뒤로가기]: [SYS-001] 공동방 생성 화면으로 복귀`는 이 재정의 이전의 잔존 서술로 본다 — §4 가정 참조)
- **FR-007**: 시스템은 반드시 시스템 뒤로가기(제스처·물리 키)로 이미 끝낸 앞 스텝으로 되돌아가지 않게 한다. 공유 방법 튜토리얼의 스텝 2~5에서만 한 스텝 앞(스텝 N-1)으로 이동하고, 그 밖의 모든 지점 — 프로필 설정·공동방 생성·친구 초대 스텝과 튜토리얼 스텝 1 — 에서는 **앱을 백그라운드로 보낸다.** 온보딩을 종료하거나 홈 탭으로 내보내지 않는다. (근거: PRD §5 확정 "온보딩은 앞으로만 흐른다", Figma `000-1 튜토리얼` 주석 #1 — dot으로 스텝 간 자유 이동, 2026-08-20 백프레스 정책 변경 — §5 참조)

**친구 초대 스텝**

- **FR-008**: 시스템은 반드시 친구 초대 스텝 진입 시 직전 스텝에서 만든 공동방의 초대 링크를 확보한다. (근거: PRD [SYS-006] Flow A "해당 방의 초대 링크 생성")
- **FR-009**: 시스템은 반드시 친구 초대 스텝에 안내 제목 `친구들을 초대해볼까요?`와 본문 `"여기 어때?"는 이제 그만 친구가 들어오면 저장한 장소가 한눈에 모여요. 다음 약속 장소, 여기서 같이 골라요.`를 노출한다. (근거: Figma `009-1 친구 초대`(노드 `2314-95550`), PRD [SYS-006] Flow A)
- **FR-010**: 시스템은 반드시 친구 초대 스텝에서 참여자 목록을 노출하지 않는다. (근거: PRD [SYS-006] Flow A "아직 방에 아무도 없는 시점이므로 참여자 목록을 노출하지 않는다")
- **FR-011**: 시스템은 반드시 [친구 초대하기]가 눌리면 초대 링크를 실어 OS 공유 시트를 열고, 시트가 닫힌 뒤에도 친구 초대 스텝을 그대로 유지한다. 공유 성공 여부로 스텝을 넘기지 않는다. (근거: PRD [SYS-006] Flow A, Figma `009-1 친구 초대` Action area 주석 #1)
- **FR-012**: 시스템은 반드시 [초대 링크 복사]가 눌리면 초대 링크를 클립보드에 복사하고 복사 완료 토스트를 노출하며, 친구 초대 스텝을 그대로 유지한다. 복사를 계기로 다음 스텝을 열지 않는다. (근거: 2026-08-20 자동 화면 전환 제거 결정 — §5 참조. PRD [SYS-006] Flow A의 "1.5초 뒤 자동 이동" 서술은 이 결정으로 폐기됐다)
- **FR-013**: 시스템은 반드시 친구 초대 스텝 우상단에 [X]를 노출하고, 눌리면 공유 방법 튜토리얼 스텝 1을 연다. 이 스텝의 이탈 수단은 [X] 하나이며 [건너뛰기] 텍스트 버튼은 두지 않는다. (근거: Figma `009-1 친구 초대`(노드 `2314-95550`) 주석 #2 "클릭 시 000[튜토리얼] 화면으로 이동한다")

**공유 방법 튜토리얼 스텝**

- **FR-014**: 시스템은 반드시 튜토리얼을 5스텝으로 구성하고, 각 스텝에 스텝 번호·안내 문구·예시 이미지를 함께 노출한다. 안내 문구는 순서대로 `인스타그램 공유 버튼 찾아서 눌러주기` / `공유 대상 버튼 찾아서 눌러주기` / `앱 목록을 쓸어넘겨 더보기 버튼 눌러주기` / `앱 목록을 쓸어내려 꾹 앱 눌러주기` / `꾹에 공유하기만 하면 지도에 추가 완료` 다. (근거: Figma `000-1`~`000-5 튜토리얼`(노드 `3798-167079`·`3798-167094`·`3798-167109`·`3798-167124`·`3798-167139`))
- **FR-015**: 시스템은 반드시 튜토리얼 하단에 dot 5개를 노출하고 현재 스텝 하나만 선택 상태로 표시한다. (근거: Figma `000-1 튜토리얼` 주석 #1 "총 5개의 화면으로, 모달 내 dot는 5개 표출합니다")
- **FR-016**: 시스템은 반드시 dot을 눌러 해당 스텝으로 곧바로 이동할 수 있게 한다. 앞 스텝으로 되돌아가는 이동도 허용한다. (근거: Figma `000-1 튜토리얼` 주석 #1 "사용자가 현재 페이지와 다른 페이지로 쉽게 이동할 수 있도록 돕습니다", PRD [SCR-002] Flow D)
- **FR-017**: 시스템은 반드시 튜토리얼 스텝 1~4에서 상단에 [건너뛰기]를 노출하고 하단 CTA를 노출하지 않는다. (근거: Figma `000-1`~`000-4 튜토리얼` — Action Area 숨김)
- **FR-018**: 시스템은 반드시 튜토리얼 스텝 5에서 상단 [건너뛰기]를 노출하지 않고 하단 CTA `꾹 시작하기`를 노출한다. (근거: Figma `000-5 튜토리얼_step 5`(노드 `3798-167139`) — Action Area 노출, 상단 [건너뛰기] 없음)
- **FR-019**: 시스템은 반드시 튜토리얼의 [건너뛰기] 또는 `꾹 시작하기`가 눌리면 온보딩을 끝내고 홈 탭을 연다. (근거: PRD [SCR-002] Flow D, Figma `000-1 튜토리얼` 주석 #2 "클릭 시 002[홈]으로 이동합니다")
- **FR-020**: 시스템은 반드시 튜토리얼 안의 예시 이미지를 조작에 반응하지 않는 안내물로만 다루며, 튜토리얼을 거치는 동안 장소를 저장하거나 외부 앱을 열지 않는다. (근거: PRD [SCR-002] Flow D "실제 저장 없이 연습시키는 구간")

**완료와 재진입**

- **FR-021**: 시스템은 반드시 온보딩 완료 표시가 기록된 앱 설치에서 온보딩을 다시 노출하지 않는다. (근거: PRD [SCR-001] Flow A "재실행: 직전 세션의 메인 탭")
- **FR-022**: 시스템은 반드시 이 앱 설치에 기록된 **온보딩 완료 표시**로 완료 여부를 판정한다. 프로필이 있어도 완료 표시가 없으면 온보딩을 끝내지 못한 것으로 보고 온보딩을 연다. 온보딩을 띄울지 메인 탭을 띄울지 결정하는 화면(스플래시)은 이 판정을 그대로 따른다. (근거: PRD [SCR-001] Flow A는 "프로필 없음"만 최초 실행 판정 기준으로 적고 있어, 중단 후 재실행을 판정할 근거가 없다 — §4 가정 참조)
- **FR-023**: 시스템은 반드시 온보딩을 끝내지 못하고 앱이 종료된 뒤 다시 켜졌을 때 **마지막으로 머무른 스텝**을 열어 이어간다. 이미 끝낸 앞 스텝은 다시 노출하지 않으며, 이미 만든 프로필·개인방·공동방을 다시 만들지 않는다. (근거: PRD에 정의 없음 — §5에서 확정)
- **FR-024**: 시스템은 반드시 온보딩 스텝을 옮길 때마다 현재 스텝을 이 앱 설치에 기록하고, 홈 탭으로 나가는 시점에 온보딩 완료 표시를 기록한다. (근거: FR-022·FR-023이 성립하기 위한 기록 요구)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 이미 끝난 스텝의 결과(프로필·개인방·공동방)는 뒤 스텝의 조작이나 앱 재실행으로 취소되거나 다시 만들어지지 않는다. 온보딩을 한 번 거치는 동안 프로필 1개, 개인방 1개, 공동방 최대 1개만 만들어진다. (근거: PRD [SCR-002] Flow A~C)
- **UX-002**: 온보딩의 모든 스텝에는 다음 스텝으로 나아가는 컨트롤이 항상 화면에 있다. 프로필 설정 스텝의 [저장]만 유효한 입력 전까지 비활성이고, 나머지 스텝의 진행 컨트롤은 진입 시점부터 활성이다. (근거: PRD [SCR-002] Flow A~D)
- **UX-003**: 초대 링크 복사 토스트는 스크린 하단에서 40px 띄운 위치에 노출한다. (근거: PRD [SCR-001] Flow E·[SYS-003] 토스트 표출 위치 규칙, Figma `009-2 친구 초대_초대링크 복사`(노드 `2370-67386`))
- **UX-004**: 튜토리얼 스텝을 옮길 때 안내 문구·예시 이미지·dot 선택 위치가 함께 바뀌며, 서로 다른 스텝을 가리키는 상태가 화면에 남지 않는다. (근거: Figma `000-1`~`000-5 튜토리얼`)
- **UX-005**: 스텝을 전환시키는 조작을 연달아 해도 같은 스텝이 두 번 열리지 않는다. 온보딩의 스텝 전환은 모두 사용자의 명시적 조작으로만 일어나며, 시간이 지나 저절로 넘어가는 스텝은 없다. (근거: 2026-08-20 자동 화면 전환 제거 결정 — §5 참조)
- **UX-006**: 온보딩 진행 중 사용자에게 남은 스텝 수나 진행률을 알리는 표시는 두지 않는다. 튜토리얼 안의 dot만이 유일한 진행 표시다. (근거: Figma `010`·`001`·`009` 온보딩 화면 — 진행 인디케이터 없음)

### 2.3 주요 도메인 (Core Domain)

- **온보딩 진행 상태**: 이 앱 설치가 온보딩의 어느 스텝에 머물러 있는지(`마지막 스텝`)와 온보딩을 끝냈는지(`완료 표시`)를 나타낸다. 앱 설치에 하나만 존재하고, 스텝을 옮길 때마다 갱신되며, 완료 표시가 기록되면 다시 되돌아가지 않는다. 앱을 지우면 함께 사라진다.
- **온보딩 결과물**: 온보딩을 거치며 만들어지는 프로필(1개), 개인방 `내 장소`(1개), 첫 공동방(0개 또는 1개). 각 항목의 내용과 규칙은 프로필·방 스펙이 정의하며, 이 문서는 온보딩이 그것들을 만들어 낸다는 사실만 다룬다.
- **초대 링크**: 첫 공동방에 타인을 참여시키는 링크. 친구 초대 스텝이 확보해 OS 공유 시트나 클립보드로 내보낸다. 링크의 형식·유효기간·수신 처리는 이 문서가 정의하지 않는다.

## 3. 범위 (Scope) *(필수)*

### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 온보딩을 최단 경로로 통과하는 데 필요한 스텝 전환 조작이 **3회 이내**다(프로필 [저장] 1회 + [건너뛰기] 2회).
- **SC-002**: 온보딩을 거쳐 홈 탭에 도달한 사용자가 프로필과 개인방(`내 장소`) 없이 홈에 도착하는 경우가 **0건**이다.
- **SC-003**: 온보딩을 한 번 끝낸 앱 설치에서 온보딩이 다시 노출되는 경우가 **0건**이다.
- **SC-004**: 공동방을 만들지 않은 사용자에게 친구 초대 스텝이 노출되는 경우가 **0건**이다.
- **SC-005**: 튜토리얼 어느 스텝에서든 **2회 이내** 조작으로 홈 탭에 도달할 수 있다(dot 이동 후 [건너뛰기], 또는 [건너뛰기] 단독).
- **SC-006**: 튜토리얼을 거치는 동안 장소가 저장되거나 외부 앱이 열리는 경우가 **0건**이다.
- **SC-007**: 온보딩에 진입한 사용자의 **90% 이상**이 이탈 없이 홈 탭 도달까지 완주한다.
- **SC-008**: 한 번의 온보딩에서 프로필·개인방·공동방이 의도한 개수를 넘겨 만들어지는 중복 생성이 **0건**이다. 온보딩을 중단했다 재개한 경우에도 같다.
- **SC-009**: 온보딩을 중단했다 다시 켠 사용자가 이미 끝낸 스텝을 다시 입력하는 경우가 **0건**이다.

### 3.2 비목표 항목 (Out of Scope)

- 프로필 설정 화면의 입력 규칙(닉네임 검증, 아바타 선택, [지우기], 저장 실패 처리)은 `docs/specs/profile`([SYS-011])이 정의한다. 이 문서는 그 화면이 온보딩의 첫 스텝이고 저장이 다음 스텝을 연다는 사실까지만 다룬다.
- 공동방 생성 폼의 입력 규칙(방 이름·설명 길이, 대표 색상 12종, 미리보기, 저장 확인 모달)은 `docs/specs/group-room-form`([SYS-001])이 정의한다. 이 문서는 그 화면이 온보딩의 두 번째 스텝이고 [건너뛰기]가 어디로 보내는지까지만 다룬다.
- 비회원 익명 세션의 확보·유지·실패 처리 정책은 `docs/specs/anonymous-auth-session`이 정의한다. 이 문서는 온보딩 진입 시점에 세션이 이미 확보되어 있다는 전제 위에 선다.
- [SCR-001] 스플래시 **화면**(3초 노출, 로딩 스피너, 네트워크·일시적 오류 토스트, 익명 세션 확보)은 `docs/specs/splash-screen`이 정의한다. 이 문서는 스플래시가 온보딩을 띄운다는 사실까지만 다룬다. 다만 **온보딩을 띄울지 메인 탭을 띄울지 가르는 판정 기준은 이 문서(FR-021·FR-022)가 소유한다** — 스플래시 스펙은 그 판정을 호출해 쓰는 쪽이다.
- 개인방(`내 장소`)의 생성 규칙·표시·삭제 제약은 방 스펙이 정의한다. 이 문서는 프로필 저장이 개인방 생성을 촉발한다는 사실까지만 다룬다.
- 온보딩 직후 열리는 홈 탭의 구성(빈 상태, 카드 덱, 최초 진입 코치마크)은 `docs/specs/home-card-deck`([SCR-003])이 정의한다.
- 방 상세에서 여는 초대 바텀시트([SYS-006] Flow B)와 참여자 목록은 `docs/specs/room-detail`([SCR-005])이 정의한다. 이 문서는 온보딩 전체 화면 변형(Flow A)만 다룬다.
- 초대 링크의 형식·유효기간·수신 처리와 링크로 들어온 사용자의 방 참여 절차는 [SYS-010]이 정의한다.
- 실제 외부 공유 수신(OS 공유 시트로 꾹에 들어온 링크를 장소로 저장하는 경로)은 [SYS-002]가 정의한다. 이 문서의 튜토리얼은 그 동작을 그림으로 안내할 뿐 실행하지 않는다.
- 바텀 네비게이션 자체의 탭 구성과 전환 동작은 [SYS-005]가 정의한다. 이 문서는 온보딩 중 비노출·완료 후 노출이라는 사실만 다룬다.
- 튜토리얼 예시 이미지·캐릭터 일러스트의 에셋과 시각 규격, 온보딩 화면의 색·타이포·간격은 디자인 시스템이 정의한다.
- 온보딩 퍼널을 측정하기 위한 분석 이벤트의 이름과 파라미터는 `core:analytics` 규약과 별도 이슈가 정의한다.
- 온보딩을 다시 보고 싶은 사용자를 위한 재실행 진입점(마이페이지 등)은 MVP 비목표다.

## 4. 가정 (Assumptions)

- 온보딩이 시작되는 시점에 비회원 익명 세션은 이미 확보되어 있다. 스플래시가 세션 없이는 어느 화면으로도 들여보내지 않기 때문이다(PRD [SCR-001] Flow E).
- 온보딩은 앱 설치당 한 번만 거치는 경로이며, 온보딩 진행 상태(마지막 스텝·완료 표시)는 서버가 아니라 이 설치 안에서 판정한다. 앱을 지웠다 다시 설치하면 처음부터 다시 거친다(PRD 「비회원 익명 세션」).
- 온보딩 재개는 스텝 단위로만 한다. 튜토리얼 내부의 스텝 위치(1~5)나 공동방 생성 폼에 입력하던 값은 복원 대상이 아니다.
- 튜토리얼의 소재인 인스타그램 화면은 정적인 예시 이미지이며, 실제 인스타그램 앱 설치 여부나 로그인 상태와 무관하게 같은 내용을 보여준다.
- 튜토리얼 스텝은 dot 탭 외에 좌우 스와이프로도 옮길 수 있다. dot 인디케이터를 둔 5화면 캐러셀의 통상 조작이므로 기본값으로 둔다.
- 온보딩 화면은 세로 방향으로만 사용한다. 가로 방향 대응은 이 문서가 다루지 않는다.
- 초대 링크 확보에는 네트워크가 필요하다. 온보딩 진입 시점에 세션이 확보된 상태이므로 통상 연결이 있다고 본다.
- Figma `001-1-1 공동방_기본` 프레임 상단에 남아 있는 `<` 뒤로가기는 온보딩 이전 버전의 잔재이며, PRD 5.0.0의 재정의(온보딩에서 뒤로가기 비표출)를 따른다.
- PRD [SYS-006] Flow A의 이탈 경로에 남아 있는 `[뒤로가기]: [SYS-001] 공동방 생성 화면으로 복귀`는 **오기로 본다.** 같은 PRD의 [SYS-001] Flow E와 [SYS-011] Flow D가 "온보딩에서는 뒤로가기를 표출하지 않으며 프로필 설정으로 되돌아가는 경로는 없앤다"로 5.0.0에서 재정의됐고, 이 재정의가 온보딩 전체에 걸리기 때문이다. 친구 초대 스텝만 되돌아갈 수 있으면 온보딩이 앞으로만 흐른다는 원칙(FR-006·FR-007)이 그 한 스텝에서만 깨진다. **PRD 9.0.0까지도 이 서술이 남아 있어 개정이 필요하다.**
- 온보딩을 띄울지 메인 탭을 띄울지 가르는 판정은 **이 문서의 FR-021·FR-022가 소유한다.** `docs/specs/splash-screen`은 PRD [SCR-001] Flow A를 그대로 옮겨 "프로필 없음"만으로 최초 실행을 판정하는데, 그 기준만으로는 프로필을 저장한 뒤 온보딩을 중단한 사용자가 메인 탭으로 밀려나 남은 스텝을 영영 보지 못한다. **스플래시 스펙이 완료 표시 기반 판정을 따르도록 개정되어야 한다.**
- 튜토리얼 스텝 3·4의 안내 문구는 Figma 원문(`쓸어넘겨`·`쓸어내려`)을 따른다. PRD [SCR-002] Flow D는 두 스텝 모두 `옆으로 넘겨`로 적고 있어 **스텝 4의 제스처 방향이 실제로 어긋나지만**(Figma는 아래로, PRD는 옆으로), 사용자가 흉내 내야 하는 손동작을 그린 화면 원본을 우선한다. PRD 쪽 표기는 개정 대상으로 본다.
- 복사 완료 토스트 문구는 Figma 원문 `클립 보드에 초대링크가 복사되었어요`를 따른다. PRD의 `클립 보드에 복사되었어요.`와 다르지만 의미가 같아 화면 원본을 우선한다.

  → **A**: (2026-08-20 개정) **제거한다.** 복사는 토스트만 띄우고 친구 초대 스텝을 유지하며, 튜토리얼로 넘어가는 수단은 우상단 [X] 하나다. 이로써 이 스텝의 두 액션([친구 초대하기]·[초대 링크 복사])이 같은 규칙을 따르게 되고, 온보딩 전체에 시간이 지나 저절로 넘어가는 스텝이 사라진다.
  - 대가로 **링크를 복사한 사용자가 [X]를 한 번 더 눌러야** 다음 스텝으로 간다. 대신 링크를 여러 번 복사하거나 복사 후 공유 시트를 이어서 쓰는 것이 가능해진다 — 방 상세 초대 시트([SYS-006] Flow B)의 "자동 이동 없이 시트를 유지" 규칙과 문법이 맞는다.

  → **A**: **마지막으로 머무른 스텝부터 재개한다.** 이를 위해 이 설치에 온보딩 진행 상태(마지막 스텝·완료 표시)를 기록한다.

  → **A**: **이 설치에 기록된 온보딩 완료 표시로 판정한다.** 프로필 존재 여부는 온보딩 진입의 1차 근거로 유지하되, 프로필이 있어도 완료 표시가 없으면 온보딩을 끝내지 못한 것으로 본다. 프로필 존재만으로 판정하면 중단한 사용자를 홈으로 밀어내 남은 스텝을 영영 못 보게 되기 때문이다.
- **Q**: 친구 초대 스텝의 이탈 컨트롤은 Figma의 우상단 [X]인가, PRD [SYS-006] Flow A의 [건너뛰기]인가?
  → **A**: **Figma대로 우상단 [X]를 쓴다.** 이동처는 두 문서가 같으므로(튜토리얼 스텝 1) 화면 원본을 따른다. 공동방 생성·튜토리얼 스텝의 [건너뛰기]와 컨트롤 형태가 달라지는 것은 감수한다. **PRD 9.0.0까지도 [SYS-006] Flow A와 [SCR-002] Flow C가 [건너뛰기]로 적고 있어 함께 개정이 필요하다.**
- **Q**: [친구 초대하기]로 OS 공유 시트를 열었다가 닫힌 뒤 온보딩을 어떻게 이어가는가? PRD는 [초대 링크 복사]에만 자동 이동을 정의했다.
  → **A**: **친구 초대 스텝을 그대로 유지한다.** OS가 공유 성공·취소를 구분해 알려주지 않으므로, 취소하고 돌아온 사용자를 다음 스텝으로 밀어내지 않는다. 다음 스텝으로 가는 것은 사용자가 우상단 [X]로 직접 정한다. *(자동 화면 전환이 제거된 뒤로는 [초대 링크 복사]도 같은 규칙을 따른다.)*
- **Q**: 공유 방법 튜토리얼 안에서 시스템 뒤로가기를 누르면 어떻게 되는가? 온보딩은 앞으로만 흐르지만 튜토리얼 안에서는 dot으로 앞 스텝을 오갈 수 있다.
  → **A**: **스텝 2~5에서는 한 스텝 앞으로 이동한다.** dot 이동과 같은 문법을 따르되, 튜토리얼 밖(친구 초대·공동방 생성 스텝)으로는 나가지 않는다. *(스텝 1의 처리는 위 백프레스 정책 변경으로 `무반응`에서 `앱 백그라운드`로 바뀌었다.)*
