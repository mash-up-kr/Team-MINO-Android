## 검증 기록

### 1차 검증 (2026-09-01) — FAILED · 14/16

두 항목이 실패했고, 둘 다 원인은 같은 `[TBD]` 5건이었다. 모두 이슈 #275가 「논의 항목 (스펙 단계에서 결정)」으로 넘긴 항목이다.

| # | 위치 | 미정이던 것 |
|---|---|---|
| 1 | FR-009 | 푸시 탭의 도착지 — 알림 탭 고정 / [SCR-007] FR-005와 같은 최종 도착지 |
| 2 | FR-011 | foreground 수신 시 시스템 알림을 띄우는가 |
| 3 | FR-008 | 알림 채널 구성 — 단일 / 유형 6종별 / 성격별 묶음 |
| 4 | FR-013 | payload의 대상 식별자 — `pinId` / 장소 식별자만 / 유형과 알림 식별자만 |
| 5 | FR-015 | 무효 토큰 처리 주체 — 서버 / 앱 폐기 요청 / 등록 시 대체 요청 |

특히 FR-009는 이슈 #275 본문 안에서도 두 갈래가 충돌했다 — 「범위」 4와 「완료 조건」은 "알림 탭으로 이동"이라 적고, 「논의 항목」 1은 "알림함 FR-005·FR-022가 `pinId`를 도착지로 쓰므로 푸시도 같은 식별자여야 두 경로의 도착지가 어긋나지 않는다"고 적어 최종 도착지를 가리켰다. 4번은 이 답에 종속되어 있었다.

### 2차 검증 (2026-09-01) — PASS · 16/16

사용자 확정으로 `[TBD]` 5건이 모두 해소되었고(spec §5 「확정된 항목」), 답이 갈린 FR-009는 저장 오류 유형의 도착지까지 한 단계 더 좁혀 확정했다. 확정 내용을 FR·TS·EC·SC·§2.3·§4에 반영해 두 실패 항목을 다시 검증했다.

추가로 발견해 함께 고친 것:

- **FR-008·FR-014·FR-015에 대응하는 테스트 시나리오가 없었다.** 「모든 기능 요구사항에 해당하는 명확한 테스트 시나리오가 있다」를 통과시키기 위해 TS-005(앱이 토큰 폐기를 요청하지 않는다) · TS-013(권한이 없으면 알림이 뜨지 않는다) · TS-014(기기 설정에 알림 항목이 하나만 있다)를 추가하고 TS 번호를 문서 순서대로 다시 매겼다. 현재 FR 15건이 모두 하나 이상의 TS로 덮인다.

## 잔여 사항 (spec 결함이 아님)

아래 3건은 spec의 미비가 아니라 **외부 의존이 아직 서지 않은 것**이며, §4 가정에 명시했다. `/mino-plan` 단계에서 서버 계약 대조와 함께 다뤄야 한다.

- 서버의 **FCM 토큰 등록 API가 없다.** 2026-08-31 조회 OpenAPI(오퍼레이션 25개)에 부재. FR-002·FR-003은 요구사항으로 확정하되 계약 자리는 비어 있다.
- **푸시 payload 스키마가 확정되지 않았다.** FR-013이 요구하는 "유형과 대상 식별자 하나"를 서버가 그 형태로 실어 주어야 도착지 판정이 성립한다.
- **도착지 화면이 아직 없다.** 알림 탭([SCR-007] · 이슈 #160)과 `:feature:notification` 모듈이 미머지라 FR-009·FR-012의 진입 경로를 끝까지 검증할 수 없다. 이슈 #275 완료 조건의 "실기기에서 푸시 수신 → 탭 → 알림 탭 도달"이 여기에 걸린다.
