두 항목이 실패했고, 둘 다 원인은 같은 `[TBD]` 5건이었다. 모두 이슈 #275가 「논의 항목 (스펙 단계에서 결정)」으로 넘긴 항목이다.

| # | 위치 | 미정이던 것 |
|---|---|---|
| 1 | FR-009 | 푸시 탭의 도착지 — 알림 탭 고정 / [SCR-007] FR-005와 같은 최종 도착지 |
| 2 | FR-011 | foreground 수신 시 시스템 알림을 띄우는가 |
| 3 | FR-008 | 알림 채널 구성 — 단일 / 유형 6종별 / 성격별 묶음 |
| 4 | FR-013 | payload의 대상 식별자 — `pinId` / 장소 식별자만 / 유형과 알림 식별자만 |
| 5 | FR-015 | 무효 토큰 처리 주체 — 서버 / 앱 폐기 요청 / 등록 시 대체 요청 |

특히 FR-009는 이슈 #275 본문 안에서도 두 갈래가 충돌했다 — 「범위」 4와 「완료 조건」은 "알림 탭으로 이동"이라 적고, 「논의 항목」 1은 "알림함 FR-005·FR-022가 `pinId`를 도착지로 쓰므로 푸시도 같은 식별자여야 두 경로의 도착지가 어긋나지 않는다"고 적어 최종 도착지를 가리켰다. 4번은 이 답에 종속되어 있었다.

### 2차 검증 (2026-09-01) — PASS · 16/16

사용자 확정으로 `[TBD]` 5건이 모두 해소되었고(spec §5 「확정된 항목」), 답이 갈린 FR-009는 저장 오류 유형의 도착지까지 한 단계 더 좁혀 확정했다. 확정 내용을 FR·TS·EC·SC·§2.3·§4에 반영해 두 실패 항목을 다시 검증했다.

추가로 발견해 함께 고친 것:

- **FR-008·FR-014·FR-015에 대응하는 테스트 시나리오가 없었다.** 「모든 기능 요구사항에 해당하는 명확한 테스트 시나리오가 있다」를 통과시키기 위해 TS-005(앱이 토큰 폐기를 요청하지 않는다) · TS-013(권한이 없으면 알림이 뜨지 않는다) · TS-014(기기 설정에 알림 항목이 하나만 있다)를 추가하고 TS 번호를 문서 순서대로 다시 매겼다. 현재 FR 15건이 모두 하나 이상의 TS로 덮인다.

### 3차 검증 (2026-09-03) — PASS · 16/16 (PRD 10.1.0 → 13.0.0 재대조)

spec 내용은 그대로이며, 기준 PRD 버전만 10.1.0 → 13.0.0으로 갱신했다(버전 1.0.0 → 1.0.1, PATCH). 그 사이 PRD 커밋 5건(11.0.0·11.1.0·12.0.0·12.1.0·13.0.0)을 모두 대조했으나 이 spec의 요구사항(FR-001~015)에 영향을 주는 변경은 없었다 — [SCR-006] 코멘트 시각 표기·[SYS-009] Nudge 바텀시트 스누즈·[SCR-003] 홈 덱 순회 축·[SCR-006] 시트 하한/나가기 도착지 재정의로, 모두 FCM 토큰·알림 채널·[SCR-007] 알림 유형/도착지·[SCR-008] 알림 권한·[SYS-004] 표시 기준 방과 무관하다. 16개 항목을 원문과 다시 대조해 전부 유지됨을 확인했다.

### 4차 검증 (2026-09-03) — PASS · 16/16 (1.0.1 → 1.0.2, PATCH)

plan 1.0.1이 완료 보고에서 제안한 2건을 반영했다. 체크를 전부 되돌리고 16개 항목을 원문과 다시 대조했다.

- **FR-013 재확정**: 장소 대상 알림의 도착지 키를 "장소 식별자 + 앱이 [SYS-004] 표시 기준 방을 읽음"에서 "핀 식별자(장소·방 쌍)"로 바꿨다. §5 Q4는 이전 답을 지우지 않고 1.0.2 재확정 답을 아래에 덧붙여 뒤집은 경위를 남겼다. 함께 맞춘 곳: EC-012·§2.3 푸시 메시지·§3.2 [SYS-004] 항목·§4 가정. 유저 시나리오·TS-008·완료 조건은 그대로다("그 장소의 장소 상세가 보인다").
- **§4 가정 해소**: "토큰 등록 API가 아직 없다"를 "존재한다(2026-09-03 확인)"로 갱신했다.
- 「구현 세부사항이 없다」 항목: 핀·장소 식별자는 [SCR-007] 알림함 spec이 이미 쓰는 도메인 개념이고, API 경로·필드명은 spec에 싣지 않았다 — 통과 유지.
- 「요구사항이 검증 가능하고 모호하지 않다」: FR-013의 새 문장만 읽고 "핀이 속한 방으로 열렸는가"를 판정할 수 있다 — 통과.

### 5차 검증 (2026-09-04) — PASS · 16/16 (1.0.2 → 1.0.3, PATCH)

`/mino-analyze` 발견 B1·C3를 반영했다. 체크를 전부 되돌리고 16개 항목을 원문과 다시 대조했다.

- **B1**: 헤더 **입력** 필드 끝에 "Q4는 1.0.2에서 재확정됨(§5 참조)"를 덧붙였다. 원문 입력의 "장소 식별자만 싣고 방은 앱이 정한다"가 현재 FR-013과 반대로 읽히는 혼동을 막는다. 입력 원문 자체는 지우지 않았다.
- **C3**: §4 가정에 "프로필 등록 전 설치에는 알림이 오지 않는다"를 추가했다. 온보딩 도중 알림을 누르는 상황은 재현할 수 없어 엣지 케이스가 아니라 가정으로 둔다 — 「엣지 케이스가 식별되어 있다」 항목은 발생 가능한 상황만 EC로 요구하므로 통과 유지.
- 요구사항·시나리오·범위는 손대지 않았다. 「의존성과 가정이 식별되어 있다」 항목은 가정 1건이 늘어 더 충실해졌다.
