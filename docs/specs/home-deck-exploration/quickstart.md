# 검증 가이드: [SCR-003] 홈 탭

**대상 스펙 경로**: `docs/specs/home-deck-exploration`

**계획서**: [plan.md](./plan.md)

이 문서는 홈 탭이 엔드투엔드로 동작함을 증명하는 **실행 가능한 검증 절차**다. 계약과 데이터 모델의 세부는 [`contracts/`](./contracts/)와 [`data-model.md`](./data-model.md)가 소유한다.

---

## 1. 선행 조건

- JDK / Android SDK가 잡힌 상태에서 저장소 루트에서 실행한다.
- 서버 계정은 필요 없다 — 정렬 3종과 라벨은 **mock**이 공급한다(R-001·R-002). mock은 아직 배포되지 않은 `GET /api/v1/rooms/{roomId}/cards`의 계약을 그대로 흉내 낸다.
- 위치 권한은 `가까운순` 전환 시점에 처음 요구된다. 거부 시나리오(EC-009)를 보려면 권한을 꺼 둔 채로 시작한다.

---

## 2. 빌드

헌법이 정한 빌드 확인의 최소선이다.

```sh
./gradlew :app:assembleQaDebug
```

> 로컬 `./gradlew lintDebug`는 JBR JIT 이슈로 데몬이 죽을 수 있다. 죽더라도 코드 문제가 아니며, 그렇다고 검증이 수행된 것도 아니다 — 헌법 §검증 장치의 한계.

## 3. 자동 검증

### 3.1 전환 규칙 (JVM 단위 테스트)

두 UseCase 모두 순수 함수라 Android 없이 검증된다. **TS-015~021·028a~c가 이 테스트로 그대로 옮겨진다.**

```sh
./gradlew :core:domain:test
```

**`ResolveNextDeckUseCase` — 자동 전환**

| 테스트 | 대응 |
|---|---|
| 덱을 소진하면 정렬을 유지한 채 다음 방으로 간다 | TS-015 |
| 지금 정렬로 모든 방을 확인해야 다음 정렬로 넘어가고, 첫 방부터 다시 훑는다 | TS-016 |
| 후보 0건 칸은 건너뛴다 | TS-017 |
| `pinCount == 0`인 방을 건너뛴다 | TS-019 |
| 방 순서를 받은 목록 그대로 훑는다(재배치하지 않는다) | TS-019a, FR-012 |
| 칩으로 건너뛴 칸을 순회가 다시 데려온다 — 앞선 정렬로 되돌아간다 | TS-021 |
| 남은 칸이 없으면 `AllExhausted` | TS-024 |
| `가까운순`을 **모든 방에 대해** 소진 처리한 입력에서 남은 칸을 고른다 | EC-009 |

**`ResolveRoomEntryDeckUseCase` — 수동 방 변경**

| 테스트 | 대응 |
|---|---|
| 고른 방의 `꾹 Pick`이 남아 있으면 그것을 고른다 | TS-028 |
| 고른 방의 `꾹 Pick`이 소진이면 그 방의 남은 덱 중 최고 순위를 고른다 | TS-028b |
| 고른 방의 세 칸이 모두 소진이면 `AllExhausted` | TS-028c, EC-020 |
| **어떤 입력에서도 `NextRoom`을 내지 않는다** | FR-024, SC-008 |
| `pinCount == 0`인 방을 골라도 다른 방으로 넘기지 않는다 | EC-020·022 |

## 4. 수동 검증 시나리오

앱을 실행해 홈 탭에서 확인한다.

```sh
./gradlew :app:installQaDebug
```

### 4.1 최초 진입 — 가이드 (유저 플로우 5)

1. 앱을 **새로 설치**하고 홈 탭에 진입한다.
2. 딤과 함께 안내 문구 **2개**가 뜬다 — `좌우로 스와이프하며 카드를 탐색해 보세요.` · `방 뱃지와 토끼를 클릭하면 방을 변경할 수 있어요` — **TS-029**
3. 딤 상태에서 카드를 스와이프하고 정렬 칩을 눌러 본다 → 아무 반응 없음 — **TS-030**
4. 우측 상단 닫기를 누른다 → 홈이 정상 상태가 된다.
5. 앱을 껐다 켜고 홈에 다시 들어간다 → 가이드가 뜨지 않는다 — **TS-031**

### 4.2 상단 셸 (FR-021)

가이드를 닫은 직후 화면 상단을 본다 → **방 뱃지·방 캐릭터·인사 문구(`꾹 눌러둔 장소, 다시 꺼내볼까요?`)·정렬 칩 3종**이 모두 보인다 — **TS-006**

정렬 칩은 왼쪽부터 `꾹 Pick` · `최신순` · `가까운순` 순서이고, 지금 보고 있는 덱의 정렬이 선택 상태다 — **FR-009, UX-004**

### 4.3 시작 방 (FR-022)

| 확인 | 기대 | 대응 |
|---|---|---|
| 새로 설치한 직후 | 개인방(`내 장소`)의 덱 | TS-032 |
| 다른 방을 보다 앱 종료 후 재실행 | 그 방의 덱 | TS-033 |
| 재진입 시 정렬 | **`꾹 Pick`으로 초기화** (소진 상태도 초기화) | spec §4 가정 |

### 4.4 스와이프 (유저 플로우 1)

1. 화면 **우측**에서 좌→우로 드래그 → 카드가 넘어간다 — **TS-001**
2. 이어서 우→좌로 드래그 → 방금 넘긴 카드가 돌아온다 — **TS-002**
3. 화면 **좌측**에서 좌우로 드래그 → 아무 일도 없다 — **TS-003**
4. 첫 카드에서 우→좌 → 아무 변화 없음 — **EC-001**
5. 조금만 끌다 손을 뗀다 → 카드가 제자리로, 넘김·상세 진입 모두 없음 — **EC-002·EC-006**
6. 전환 애니메이션 중에 한 번 더 드래그 → 한 장만 넘어간다 — **TS-007**

### 4.5 카드 조작 (유저 플로우 2)

1. `[...]`를 누른다 → **`다른 방 저장` 한 항목만** 그 카드 근처에 열린다 — **TS-008, UX-002**
   - `장소 가리기`가 보이면 **실패다.** PRD 8.0.0 §2에서 스펙아웃됐다(spec §3.2).
2. 메뉴 바깥을 탭 → 메뉴만 닫힌다 — **EC-005**
3. 메뉴가 열린 채 스와이프 → 메뉴만 닫히고 카드는 안 넘어간다 — **EC-004**
4. `다른 방 저장` 선택 → 「홈 방 시트」가 열리고, 현재 카드와 되돌리기 이력이 그대로다 — **TS-011**
5. 카드 본문 탭 → 장소 상세로 이동, 카드는 안 넘어감 — **TS-012**
6. 돌아온다 → 같은 카드가 최상단이고 **잔여 카드 수도 그대로다** — **TS-013**
   - 동시에 그 장소의 **경과일은 초기화됐다.** 홈을 나갔다 다시 들어와 `꾹 Pick`을 보면 그 장소가 뒤로 밀려 있다 — **TS-034**
   - 반대로 **그냥 넘기기만 한 카드는 순위가 그대로**여서 다시 들어와도 다시 나온다 — **TS-035**
7. 상세를 본 카드를 넘긴 뒤 곧바로 우→좌로 되돌린다 → 카드는 복구되지만 **경과일 초기화는 취소되지 않는다** — **EC-017**
8. 카드에 라벨 4종 중 하나가 보인다 — **TS-014**
   - 지표가 전부 0인 새 방이면 10장 모두 `가볼 만한 곳`이다. 정상이다(서버가 자격 미달분을 이 라벨로 흡수한다)

### 4.6 자동 전환 (유저 플로우 3 — **핵심**)

1. 한 덱을 끝까지 넘긴다 → **정렬 칩이 그대로인 채** 다음 방의 같은 정렬 덱이 오고, 뱃지·캐릭터가 교체되며 `{방 이름}방이에요.` 툴팁이 3초 뜬다 — **TS-015, FR-016**
2. 후보 0건인 칸은 건너뛴다 — **TS-017**
3. 장소가 있는 방을 모두 훑는다 → 그때 비로소 정렬이 다음으로 넘어가고 **첫 방부터** 다시 시작하며, 정렬 칩 표시가 옮겨진다 — **TS-016, UX-004**
   - 정렬이 바뀐 것 자체를 알리는 툴팁은 **없다.** 방이 함께 바뀌면 방 전환 툴팁만 뜬다 — **TS-018**
4. 장소 0개인 방은 건너뛴다 — **TS-019**
5. 방이 3개 이상인 계정에서 순회 순서를 본다 → 개인방 → 먼저 만든 공동방 → 나중에 만든 공동방 — **TS-019a**
6. 칩으로 칸을 건너뛴 뒤 그 정렬을 모든 방에서 소진 → 남아 있는 앞선 정렬의 **첫 방**으로 되돌아온다 — **TS-021, SC-002**
7. 잔여 2장이 되는 순간 → **실제로 다음에 올 칸**을 가리키는 툴팁이 3초 뜬다 — **TS-022·022a, SC-004**
   - 같은 정렬로 안 본 방이 남았으면 그 방을, 정렬이 넘어갈 차례면 `곧 {정렬 이름}으로 이동해요!` — **TS-022 / TS-022a**
   - 툴팁이 뜬 동안에도 카드를 계속 넘길 수 있다 — **UX-003**
8. `가까운순`의 마지막 방에서 잔여 2장 → 예고 툴팁이 **뜨지 않는다** — **TS-023**
9. 남은 칸이 하나도 없게 만든다 → 상단은 그대로, 카드 자리에만 일러스트와 완료 문구, 정렬 칩은 `꾹 Pick` 표시. **CTA 버튼이 없다** — **TS-024**
10. 완료 화면에서 가만히 둔다 → 스스로 다시 순환하지 않는다 — **EC-010**
11. 장소가 있는 방이 하나뿐인 계정 → 덱을 소진할 때마다 정렬이 넘어가고 방 전환 툴팁은 뜨지 않는다 — **EC-019**

**위치 권한 거부 (EC-009)**: 권한을 끈 채로 `가까운순` 전환을 유도한다 → 권한을 묻고, 거부하면 `가까운순`을 **모든 방에 대해** 건너뛴다. 남는 칸이 있으면 그리로 가고 없으면 곧바로 완료 안내다. **방마다 다시 묻지 않는다.**

### 4.7 방 직접 변경 (유저 플로우 4)

1. 방 뱃지를 누른다 → 「홈 방 시트」가 열린다 — **TS-025**
2. 닫고 방 캐릭터를 누른다 → 같은 시트 — **TS-026**
3. 시트가 3열 그리드이고 첫 칸이 `방 만들기`이며 **체크박스와 확정 버튼이 없다** — **TS-027**
4. `최신순`을 보던 중 다른 방을 고른다 → 정렬 칩이 `꾹 Pick`으로 되감기고 그 방의 `꾹 Pick` 덱, 방 전환 툴팁 3초 — **TS-028·028a**
5. `꾹 Pick`을 이미 소진한 방을 고른다 → **다른 방으로 튕기지 않고** 그 방의 남은 덱 중 최고 순위가 열리며 칩도 그 정렬로 표시된다 — **TS-028b, SC-008**
6. **장소가 0개인 방을 고른다** → 그 방의 뱃지·캐릭터를 단 채 완료 안내가 뜨고, 다른 방으로 넘어가지 않는다 — **TS-028c, EC-020**
   - 그 방이 시트에서 체크·비활성으로 막혀 있지 않다 — **EC-022**
7. 그 방을 한 번 더 고른다 → 덱이 다시 채워지지 않는다 — **EC-021**
8. 지금 보고 있는 방을 다시 고른다 → 시트만 닫히고 진행 상태 유지 — **EC-014**

### 4.7a `다른 방 저장` (유저 플로우 2 — 시트 교체)

1. 카드 `[...]` → `다른 방 저장` → **체크박스 리스트 시트**가 열린다(그리드가 아니다) — **TS-011**
2. 방을 하나도 고르지 않은 상태에서 `저장하기`가 비활성이다 — **EC-018**
3. 방 2개를 체크하고 `저장하기` → 두 방 모두에 저장되고, 덱과 되돌리기 이력이 그대로다 — **TS-011a**
4. 이미 그 장소가 저장된 방도 체크·비활성으로 막혀 있지 않다 — **TS-011b**
5. 시트를 닫고 방 뱃지를 눌러 「홈 방 시트」를 연다 → **저장이 방 전환으로 뒤바뀌지 않는다** — FR-005·FR-017

### 4.8 빈 상태 (FR-020)

장소가 하나도 없는 계정으로 진입 → 완료 안내가 아니라 **빈 상태 안내 + `[공동방 만들기]` CTA** — **EC-011**

가이드를 아직 안 닫은 상태라면 가이드가 먼저 뜨고, 닫은 뒤 빈 상태가 보인다 — **EC-016**

**§4.7의 6번과 헷갈리지 않는다.** 고른 방만 비어 있는 것은 완료 안내(CTA 없음)이고, 빈 상태(CTA 있음)는 **모든 방을 통틀어** 볼 장소가 없을 때다. 화면에 `[공동방 만들기]`가 있는지로 가른다.

### 4.9 시안 대조 (plan 3.0.0 디자인 개정)

값은 [`contracts/home-ui.md`](./contracts/home-ui.md) §5의 표가 소유한다. 대조 절차는 [`figma-design-fidelity.md`](../../conventions/figma-design-fidelity.md) §4를 따른다.

1. **방 캐릭터** — 방 색을 바꿔 가며 캐릭터가 12종으로 갈리는지 본다. 색마다 소품(모자·안경·헤드폰·리본 등)이 다르다 — 노드 `4306:63718`
   - 색을 고르지 않은 방은 `black` variant(소품 없음)
   - **`brown` 방은 시안에 대응 variant가 없다** — 협의 전까지 `black`으로 떨어진다(R-015)
2. **방 전환 툴팁** — 캐릭터 **왼쪽**에 놓이고 화살표가 오른쪽 변 세로 중앙에서 캐릭터를 가리킨다 — 노드 `2809:143382`
3. **완료 안내** — 209×209 일러스트 + `모든 장소를 다 봤어요!`. **문구는 spec FR-014 개정이 머지된 뒤에 확인한다**(R-018) — 개정 전이라면 이 항목은 미검증이다
4. **「홈 방 시트」 썸네일** — 기존 에셋 그대로다. 바뀐 것이 없으므로 대조만 하고 넘어간다 — 노드 `4306:63731`

- mock을 실서버로 바꾸는 지점은 [`contracts/deck-api.md`](./contracts/deck-api.md) §3.2의 세 파일이다.
- 서버팀과 남은 것은 `/cards` 배포 일정 하나다. 같은 문서 §5 참고.
- **「경과일 초기화 확인」은 홈 밖에서도 일어난다.** 지도·방 상세·알림에서 상세를 여는 경로는 각 화면 스펙의 몫이라 여기서 검증하지 않는다(spec §3.2).
