# 검증 가이드: [SCR-003] 홈 탭

**대상 스펙 경로**: `docs/specs/home-deck-exploration`

**계획서**: [plan.md](./plan.md)

이 문서는 홈 탭이 엔드투엔드로 동작함을 증명하는 **실행 가능한 검증 절차**다. 계약과 데이터 모델의 세부는 [`contracts/`](./contracts/)와 [`data-model.md`](./data-model.md)가 소유한다.

---

## 1. 선행 조건

- JDK / Android SDK가 잡힌 상태에서 저장소 루트에서 실행한다.
- 서버 계정은 필요 없다 — 정렬 3종과 라벨은 **mock**이 공급한다(R-001·R-002).
- 위치 권한은 `가까운순` 전환 시점에 처음 요구된다. 거부 시나리오(EC-009)를 보려면 권한을 꺼 둔 채로 시작한다.

---

## 2. 빌드

헌법이 정한 빌드 확인의 최소선이다.

```sh
./gradlew :app:assembleQaDebug
```

> 로컬 `./gradlew lintDebug`는 JBR JIT 이슈로 데몬이 죽을 수 있다. 죽더라도 코드 문제가 아니며, 그렇다고 검증이 수행된 것도 아니다 — 헌법 §검증 장치의 한계.

---

## 3. 자동 검증

### 3.1 전환 규칙 (JVM 단위 테스트)

`ResolveNextDeckUseCase`는 순수 함수라 Android 없이 검증된다. **TS-015~019·021이 이 테스트로 그대로 옮겨진다.**

```sh
./gradlew :core:domain:test
```

| 테스트 | 대응 |
|---|---|
| 같은 방에 미소진 덱이 있으면 우선순위 최고를 고른다 | TS-015, TS-016 |
| 후보 0건 덱은 건너뛴다 | TS-017 |
| 세 덱이 모두 소진돼야 방을 넘긴다 | TS-018 |
| `pinCount == 0`인 방을 건너뛴다 | TS-019 |
| 칩으로 건너뛴 덱도 방 전환 전에 다시 온다 | TS-021 |
| 마지막 방의 마지막 덱을 소진하면 `AllExhausted` | TS-024 |
| `가까운순`을 소진 처리한 입력에서 같은 방의 남은 덱을 고른다 | EC-009 |

### 3.2 화면 상태 (ViewModel 테스트)

```sh
./gradlew :feature:home:testDebugUnitTest
```

| 테스트 | 대응 |
|---|---|
| `isTransitioning`인 동안 스와이프 Intent를 버린다 | UX-001, TS-007 |
| `isGuideVisible`인 동안 `DismissGuide` 외 Intent를 버린다 | FR-019, TS-030 |
| 덱이 바뀌면 되돌리기 이력이 초기화된다 | EC-003 |
| 예고 툴팁은 같은 덱에서 두 번 뜨지 않는다 | spec §4 가정 |
| 현재 방을 다시 선택하면 덱을 재구성하지 않는다 | EC-014 |

## 4. 수동 검증 시나리오

앱을 실행해 홈 탭에서 확인한다.

```sh
./gradlew :app:installQaDebug
```

### 4.1 최초 진입 — 가이드 (유저 플로우 5)

1. 앱을 **새로 설치**하고 홈 탭에 진입한다.
2. 딤과 함께 안내 문구 **2개**가 뜬다 — `좌우로 스와이프하며 카드를 탐색해 보세요.` · `방 뱃지와 토끼를 클릭하면 방을 변경할 수 있어요` — **TS-029**
3. 딤 상태에서 카드를 스와이프하고 정렬 칩을 눌러 본다 → 아무 반응 없음 — **TS-030**
4. 우측 상단 닫기를 누른다 → 홈이 정상 상태가 된다.
5. 앱을 껐다 켜고 홈에 다시 들어간다 → 가이드가 뜨지 않는다 — **TS-031**

### 4.2 상단 셸 (FR-021)

가이드를 닫은 직후 화면 상단을 본다 → **방 뱃지·방 캐릭터·인사 문구(`꾹 눌러둔 장소, 다시 꺼내볼까요?`)·정렬 칩 3종**이 모두 보인다 — **TS-006**

정렬 칩은 왼쪽부터 `꾹 Pick` · `최신순` · `가까운순` 순서이고, 지금 보고 있는 덱의 정렬이 선택 상태다 — **FR-009, UX-004**

### 4.3 시작 방 (FR-022)

| 확인 | 기대 | 대응 |
|---|---|---|
| 새로 설치한 직후 | 개인방(`내 장소`)의 덱 | TS-032 |
| 다른 방을 보다 앱 종료 후 재실행 | 그 방의 덱 | TS-033 |
| 재진입 시 정렬 | **`꾹 Pick`으로 초기화** (소진 상태도 초기화) | spec §4 가정 |

### 4.4 스와이프 (유저 플로우 1)

1. 화면 **우측**에서 좌→우로 드래그 → 카드가 넘어간다 — **TS-001**
2. 이어서 우→좌로 드래그 → 방금 넘긴 카드가 돌아온다 — **TS-002**
3. 화면 **좌측**에서 좌우로 드래그 → 아무 일도 없다 — **TS-003**
4. 첫 카드에서 우→좌 → 아무 변화 없음 — **EC-001**
5. 조금만 끌다 손을 뗀다 → 카드가 제자리로, 넘김·상세 진입 모두 없음 — **EC-002·EC-006**
6. 전환 애니메이션 중에 한 번 더 드래그 → 한 장만 넘어간다 — **TS-007**

### 4.5 카드 조작 (유저 플로우 2)

1. `[...]`를 누른다 → **`다른 방 저장` 한 항목만** 그 카드 근처에 열린다 — **TS-008, UX-002**
   - `장소 가리기`가 보이면 **실패다.** PRD 8.0.0 §2에서 스펙아웃됐다(spec §3.2).
2. 메뉴 바깥을 탭 → 메뉴만 닫힌다 — **EC-005**
3. 메뉴가 열린 채 스와이프 → 메뉴만 닫히고 카드는 안 넘어간다 — **EC-004**
4. `다른 방 저장` 선택 → 「홈 방 시트」가 열리고, 현재 카드와 되돌리기 이력이 그대로다 — **TS-011**
5. 카드 본문 탭 → 장소 상세로 이동, 카드는 안 넘어감 — **TS-012**
6. 돌아온다 → 같은 카드가 최상단, 넘김 확인이 발생하지 않았다 — **TS-013**
7. 카드에 라벨 4종 중 하나가 보인다 — **TS-014**

### 4.6 자동 전환 (유저 플로우 3 — **핵심**)

1. 한 덱을 끝까지 넘긴다 → **다음 방이 아니라** 같은 방의 남은 덱 중 우선순위 최고로 전환되고, 정렬 칩 표시가 따라 옮겨진다 — **TS-015·016, UX-004**
2. 후보 0건인 정렬은 건너뛴다 — **TS-017**
3. 세 덱을 모두 소진 → 다음 방으로 넘어가고 칩이 `꾹 Pick`으로 돌아가며 `{방 이름}방이에요.` 툴팁이 3초 뜬다 — **TS-018, FR-016**
4. 장소 0개인 방은 건너뛴다 — **TS-019**
5. 칩으로 덱을 건너뛴 뒤 그 덱을 소진 → 방을 넘기지 않고 건너뛰었던 덱이 온다 — **TS-021, SC-002**
6. 잔여 2장이 되는 순간 → **실제로 다음에 올** 덱·방을 가리키는 툴팁이 3초 뜬다 — **TS-022, SC-004**
   - 툴팁이 뜬 동안에도 카드를 계속 넘길 수 있다 — **UX-003**
7. 마지막 방 마지막 덱의 잔여 2장 → 예고 툴팁이 **뜨지 않는다** — **TS-023**
8. 모두 소진 → 상단은 그대로, 카드 자리에만 일러스트와 `꾹 눌러둔 장소를 모두 둘러봤어요`. **CTA 버튼이 없다** — **TS-024**
9. 완료 화면에서 가만히 둔다 → 스스로 다시 순환하지 않는다 — **EC-010**

**위치 권한 거부 (EC-009)**: 권한을 끈 채로 `가까운순` 전환을 유도한다 → 권한을 묻고, 거부하면 `가까운순`을 건너뛰어 **같은 방의 남은 덱**으로 간다. 남은 덱이 없을 때만 다음 방으로 넘어간다.

### 4.7 방 직접 변경 (유저 플로우 4)

1. 방 뱃지를 누른다 → 시트가 열린다 — **TS-025**
2. 닫고 방 캐릭터를 누른다 → 같은 시트 — **TS-026**
3. 시트가 3열 그리드이고 첫 칸이 `방 만들기`이며 **체크박스와 확정 버튼이 없다** — **TS-027**
4. 방 카드를 누른다 → 즉시 그 방의 `꾹 Pick` 덱, 방 전환 툴팁 3초 — **TS-028**
5. 지금 보고 있는 방을 다시 고른다 → 시트만 닫히고 진행 상태 유지 — **EC-014**

### 4.8 빈 상태 (FR-020)

장소가 하나도 없는 계정으로 진입 → 완료 안내가 아니라 **빈 상태 안내 + `[공동방 만들기]` CTA** — **EC-011**

가이드를 아직 안 닫은 상태라면 가이드가 먼저 뜨고, 닫은 뒤 빈 상태가 보인다 — **EC-016**

## 5. 알려진 한계

- **정렬 3종과 라벨은 mock이다**(R-001·R-002). 실제 순위 산출은 검증 대상이 아니며, 검증하는 것은 "받은 순서를 그대로 덱으로 만드는가"까지다.
- mock을 실서버로 바꾸는 지점은 [`contracts/deck-api.md`](./contracts/deck-api.md) §3.2의 세 파일이다.
- 서버팀 협의가 끝나지 않은 항목 6건은 같은 문서 §4에 있다.
