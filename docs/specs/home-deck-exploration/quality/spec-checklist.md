### 3.0.0 개정 검증 노트

PRD 9.0.0의 「장소 확인 이벤트」 분리를 따라간 개정이다. **MAJOR인 이유**는 FR-007의 의미가 반전되고 TS-013의 검증 대상이 재정의됐기 때문이다.

**이 spec에서 처음으로 PRD가 먼저 바뀌고 spec이 따라갔다.** 1.0.0~2.0.0은 spec이 먼저 쓰이고 PRD가 뒤따랐다.

| 위치 | 2.0.0 | 3.0.0 |
|---|---|---|
| FR-007 | 상세를 열어본 것은 "확인"이 아니다 | **「경과일 초기화 확인」을 발생시킨다** (덱은 그대로) |
| FR-023 | (없음) | **신설** — 두 확인 이벤트의 독립을 요구사항으로 |
| FR-002 | 카드 1장 복구 | + **「카드 열람 확인」 취소**, ①은 되돌리지 않음 |
| FR-022 | 마지막 방에서 시작 | + **기기에 영속 저장**, 서버에 묻지 않음 |
| TS-013 | "클릭은 확인이 아니다" | "클릭은 **덱을** 넘기지 않는다" — 잔여 카드 수로 판정 |
| TS-034·035 | (없음) | **신설** — 클릭은 초기화하고, 넘김은 서버에 안 알린다 |
| EC-017 | (없음) | **신설** — 되돌려도 이미 나간 초기화는 취소되지 않는다 |
| §3.2 비목표 | `상위 30%`·`14일`·`3km` 명시 | **수치 제거**, 서버 소유 명시 + 홈 밖 진입 경로 항목 신설 |
| §3.2 `장소 가리기` | "넘긴 카드는 초기화로 안 온다" | **무너진 근거 삭제** |
| §4 가정 | 영속 저장은 가이드 이력 하나 | **둘** — 가이드 이력 + 마지막 방 |

**두 이벤트를 각각 독립으로 검증한다.** TS-013(넘김 아님) · TS-034(초기화 함) · TS-035(넘김은 서버에 안 알림) 셋이 한 조를 이루고, EC-017이 되돌리기의 취소 범위를 막는다. 하나로 뭉뚱그리면 "클릭했는데 덱이 넘어갔다"와 "클릭했는데 초기화가 안 됐다"를 구분할 수 없다.

**FR 번호는 당기지 않았다.** FR-023을 끝에 붙이고 FR-006 결번을 유지한다.
