### 4.0.0 개정 검증 노트

PRD 10.0.0·12.0.0 두 벌을 한 번에 흡수한 개정이다. **MAJOR인 이유**는 탐색 축이 뒤집혀 FR-011·012의 의미가 바뀌고 유저 플로우 3이 통째로 재정의됐기 때문이다.

| 위치 | 3.0.0 | 4.0.0 |
|---|---|---|
| 탐색 축 | 한 방의 세 덱 → 다음 방 | **(정렬, 방) 격자 — 정렬 우선, 그 안에서 방 순서** |
| FR-011 | 같은 방의 남은 덱 중 최고 순위 | **남은 칸 중 순서상 가장 앞선 것** |
| FR-012 | 세 덱 소진 시 다음 방 + `꾹 Pick` 초기화 | **정렬 유지 + 다음 방**, 순서는 개인방 먼저·생성 오래된 순 |
| FR-025 | (없음) | **신설** — 지금 정렬로 모든 방을 확인했을 때만 정렬 전환 |
| FR-024 | (없음) | **신설** — 수동 방 변경만 `꾹 Pick` 초기화, 범위를 고른 방 안으로 한정 |
| FR-005 | 「홈 방 시트」를 엶 | **「방 선택 시트」([SYS-002]형)** — 체크박스 복수 선택·`저장하기`·중복 미차단 |
| FR-013 | 방 전환 대상에서 건너뜀 | **자동 전환 한정**으로 축소(수동은 FR-024) |
| FR-014 | 모든 방의 모든 덱 소진 | **남은 칸의 유무**로 판정 + 정렬 칩 `꾹 Pick` 표시 |
| FR-015 | "다음에 올 덱 또는 방" | 다음 방 안내 / `곧 {정렬 이름}으로 이동해요!` 2갈래 |
| FR-016 | 방 전환 툴팁 규칙 | + **정렬만 바뀌는 전환에는 툴팁 없음** |
| EC-009 | 거부 시 같은 방의 남은 덱 | **`가까운순`을 모든 방에 대해 소진 처리** |
| §2.3 | "한 방은 덱 3개를 가진다" | **「탐색 격자(Grid)」 항목 신설**, 소진 정의에 "칩으로 건너뛴 칸은 소진 아님" 추가 |
| §4 가정 | 방 순서는 전달받은 목록 그대로 | **홈이 스스로 정한다**(개인방 먼저·생성 오래된 순) |

**수동 경로를 자동 경로와 별개로 검증한다.** TS-028a(정렬 초기화) · TS-028b(그 방의 남은 덱) · TS-028c(빈 방 → 그 방의 완료 안내) 셋과 EC-020~022가 한 조를 이룬다. 자동 전환에 맡기면 "방을 골랐는데 다른 방이 열린다"를 잡아낼 테스트가 없다.

**빈 상태(FR-020)와 완료 안내(FR-014)의 경계를 EC-020에 명문화했다.** 고른 방만 비어 있는 경우는 완료 안내이고, 빈 상태는 모든 방을 통틀어 볼 장소가 없을 때만이다(EC-011).

**FR 번호는 당기지 않았다.** FR-024·025를 끝에 붙이고 FR-006 결번을 유지한다.

**미해소로 남긴 것**: PRD [SCR-003] Flow E의 "방 순서는 서버가 내려준 방 목록 순서 그대로다" 한 줄이 같은 PRD의 「카드 덱」 정의·§5와 어긋난다. spec은 후자를 따랐고, PRD 쪽 정리는 별건이다 — spec §5 「PRD 결함 기록」 참고.

### 3.0.0 개정 검증 노트

PRD 9.0.0의 「장소 확인 이벤트」 분리를 따라간 개정이다. **MAJOR인 이유**는 FR-007의 의미가 반전되고 TS-013의 검증 대상이 재정의됐기 때문이다.

**이 spec에서 처음으로 PRD가 먼저 바뀌고 spec이 따라갔다.** 1.0.0~2.0.0은 spec이 먼저 쓰이고 PRD가 뒤따랐다.

| 위치 | 2.0.0 | 3.0.0 |
|---|---|---|
| FR-007 | 상세를 열어본 것은 "확인"이 아니다 | **「경과일 초기화 확인」을 발생시킨다** (덱은 그대로) |
| FR-023 | (없음) | **신설** — 두 확인 이벤트의 독립을 요구사항으로 |
| FR-002 | 카드 1장 복구 | + **「카드 열람 확인」 취소**, ①은 되돌리지 않음 |
| FR-022 | 마지막 방에서 시작 | + **기기에 영속 저장**, 서버에 묻지 않음 |
| TS-013 | "클릭은 확인이 아니다" | "클릭은 **덱을** 넘기지 않는다" — 잔여 카드 수로 판정 |
| TS-034·035 | (없음) | **신설** — 클릭은 초기화하고, 넘김은 서버에 안 알린다 |
| EC-017 | (없음) | **신설** — 되돌려도 이미 나간 초기화는 취소되지 않는다 |
| §3.2 비목표 | `상위 30%`·`14일`·`3km` 명시 | **수치 제거**, 서버 소유 명시 + 홈 밖 진입 경로 항목 신설 |
| §3.2 `장소 가리기` | "넘긴 카드는 초기화로 안 온다" | **무너진 근거 삭제** |
| §4 가정 | 영속 저장은 가이드 이력 하나 | **둘** — 가이드 이력 + 마지막 방 |

**두 이벤트를 각각 독립으로 검증한다.** TS-013(넘김 아님) · TS-034(초기화 함) · TS-035(넘김은 서버에 안 알림) 셋이 한 조를 이루고, EC-017이 되돌리기의 취소 범위를 막는다. 하나로 뭉뚱그리면 "클릭했는데 덱이 넘어갔다"와 "클릭했는데 초기화가 안 됐다"를 구분할 수 없다.

**FR 번호는 당기지 않았다.** FR-023을 끝에 붙이고 FR-006 결번을 유지한다.
