**입력**: 사용자 설명: "이슈 #235 「[SCR-003] 홈 탭 구현 — 카드 덱 탐색과 정렬·방 전환」. 홈 탭 전체를 구현한다 — 방 뱃지·캐릭터·인사 문구·정렬 칩·카드 덱을 한 화면으로 세우고, 좌우 스와이프만으로 한 방의 모든 정렬 덱을 훑고 방을 넘어가며, 모든 방의 모든 카드를 소진할 때까지 이어서 볼 수 있게 한다. 정렬 우선순위는 항상 `꾹 Pick` > `최신순` > `가까운순`이며, 덱을 소진하면 그 방에서 아직 소진되지 않은 덱 중 우선순위가 가장 높은 것으로 전환한다. 세 덱이 모두 소진되었을 때에만 다음 방으로 가고, 새 방은 언제나 `꾹 Pick`부터 시작한다."

> **이 스펙이 담는 것**: [SCR-003] **홈 탭 화면 전체**다 — 상단 셸(방 뱃지·캐릭터·인사 문구)·정렬 칩·카드 덱·방 변경 시트·최초 진입 가이드·완료/빈 상태까지 한 화면으로 선다. 카드 덱은 그중 가장 큰 조각이지 이 스펙의 전부가 아니다.
>
> **이슈 #145에서 승계한 범위**: 카드 덱 인터랙션(스와이프 3종·액션 메뉴·덱 구성·라벨 표시·되돌리기)은 폐기된 `home-card-deck` spec에서 확정된 그대로 가져왔다. 그 spec은 카드 덱만 다루고 홈 화면 셸을 비목표로 밀어냈으나, 이 spec은 **[SCR-003] 홈 탭 전체**를 담는다. 승계 항목과 새로 들어온 항목의 구분은 §5를 따른다.

## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 카드 덱 스와이프 탐색
사용자가 홈에 진입해 현재 방·현재 정렬의 카드 덱을 좌우 스와이프로 넘기고 되돌리며 열람한다.

**Figma**: [메인 — 데이터 있을 때 `꾹 Pick`](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95698&m=dev)

**진입 조건**: 홈 탭에 진입했고, 시작 방(앱 최초 실행이면 개인방 `내 장소`, 이후에는 마지막으로 보던 방)에 노출할 장소가 1개 이상 있다.

1. 홈 탭에 진입한다 → 시스템은 상단에 **방 뱃지·방 캐릭터·인사 문구**(`꾹 눌러둔 장소, 다시 꺼내볼까요?`)와 **정렬 칩 3종**을 노출하고, 그 아래에 남은 카드가 뒤로 겹쳐 보이는 스택 형태로 덱을 노출한다. 각 카드는 헤더(등록자 아바타 + **장소분류 라벨** 뱃지 + 더보기 `[...]`)·장소명·주소·대표 이미지 2칸 그리드로 구성된다.
2. 화면 우측 영역에서 왼쪽에서 오른쪽으로 드래그한다 → 시스템은 현재 카드를 덱에서 넘기고 다음 카드를 최상단에 노출한다.
3. 화면 우측 영역에서 오른쪽에서 왼쪽으로 드래그한다 → 시스템은 바로 직전에 넘긴 카드 1장을 최상단으로 복구한다.
4. 화면 좌측 영역에서 드래그한다 → 시스템은 아무 반응도 하지 않는다.

**완료 조건**: 사용자가 원하는 만큼 카드를 넘기거나 되돌리며 현재 덱을 열람한 상태.

### 유저 플로우 2 - 카드 액션과 장소 상세 진입
사용자가 카드의 `[...]` 버튼으로 다른 방 저장을 요청하고, 카드 본문을 눌러 장소 상세로 이동한다.

**Figma**: [메인 — 액션 메뉴 노출 상태](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95698&m=dev)

**진입 조건**: 덱에 카드가 노출되어 있다.

1. 카드의 `[...]` 버튼을 누른다 → 시스템은 `다른 방 저장` **한 항목만** 담은 메뉴를 그 카드 근처에 연다.
2. `다른 방 저장`을 선택한다 → 시스템은 메뉴를 닫고 「홈 방 시트」를 열어 담을 방을 고르게 한다. 덱의 진행 상태는 바뀌지 않는다.
3. 카드 본문을 누른다 → 시스템은 그 장소의 [SCR-006] 장소 상세 `Half`로 이동한다. 카드는 넘어가지 않고 덱의 진행 상태도 그대로다. **「경과일 초기화 확인」은 이동한 상세가 열리면서 기록한다** — 홈이 따로 내보내지 않는다.

**완료 조건**: 사용자가 카드를 넘기지 않고도 그 장소를 다른 방에 담거나 상세를 열어본 상태. 상세를 열어봤다면 그 장소의 경과일은 초기화되었지만 덱은 그대로다.

### 유저 플로우 3 - 정렬·방 자동 전환과 소진 완료
사용자가 덱을 소진할 때마다 시스템이 다음에 볼 덱을 스스로 정해 이어 붙이고, 볼 것이 모두 떨어지면 완료를 알린다. **이 스펙의 핵심 플로우다.**

**Figma**: [메인 — 정렬 칩](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95698&m=dev) · [모든 카드를 다 봤을 때 `002-3`](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3388-199413&m=dev)

**진입 조건**: 현재 방·현재 정렬의 덱을 열람 중이다.

1. 잔여 카드가 2장 이하가 된다 → 시스템은 **실제로 다음에 올 덱 또는 방**을 가리키는 「덱 소진 예고 툴팁」을 3초간 노출한 뒤 페이드아웃한다.
2. 현재 덱을 모두 소진한다 → 시스템은 **그 방에서 아직 소진되지 않은 덱 중 우선순위가 가장 높은 것**으로 전환하고, 상단 정렬 칩의 선택 표시를 그 정렬로 갱신한다.
3. 그 방의 세 덱이 모두 소진된다 → 시스템은 **다음 방**의 덱으로 전환하고, 정렬을 `꾹 Pick`으로 초기화한 뒤 「방 전환 툴팁」(`{방 이름}방이에요.`)을 3초간 노출한다.
4. 사용자가 상단 정렬 칩을 직접 누른다 → 시스템은 그 정렬의 덱으로 즉시 전환한다.
5. 모든 방의 모든 덱이 소진된다 → 시스템은 상단(방 뱃지·인사 문구·정렬 칩)을 그대로 둔 채 **카드 자리에만** 일러스트와 `꾹 눌러둔 장소를 모두 둘러봤어요`를 노출한다.

**완료 조건**: 사용자가 한 번도 직접 조작하지 않고도 볼 수 있는 모든 카드를 끝까지 훑었고, 더 볼 것이 없음을 안내받은 상태.

### 유저 플로우 5 - 홈 최초 진입 가이드
앱 생애에 한 번, 홈을 처음 연 사용자에게 조작 방법을 알려준다.

**Figma**: [홈 사용 가이드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=4334-216197&m=dev)

**진입 조건**: 홈 탭에 처음 진입했고, 가이드를 닫은 이력이 없다.

1. 홈 탭에 진입한다 → 시스템은 화면 전체에 딤을 덮고 카드 위에 손 아이콘과 안내 문구 **2개**를 노출한다 — `좌우로 스와이프하며 카드를 탐색해 보세요.` 와 `방 뱃지와 토끼를 클릭하면 방을 변경할 수 있어요`.
2. 딤이 덮인 상태에서 화면을 조작한다 → 시스템은 카드 스와이프·정렬 칩·방 변경 등 홈의 조작을 받지 않는다.
3. 우측 상단 닫기를 누른다 → 시스템은 딤과 안내를 걷어내고 홈을 정상 상태로 만들며, 닫은 이력을 영속 저장한다.
4. 이후 다시 홈에 들어온다 → 시스템은 가이드를 노출하지 않는다.

**완료 조건**: 사용자가 가이드를 닫았고, 이후 홈 진입에서 다시 보이지 않는 상태.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 화면 우측 영역에서 좌→우 스와이프가 발생하면 현재 카드를 넘기고 다음 카드를 최상단에 노출해야 한다. (근거: business-context.md 「카드 덱」 스와이프 방향별 동작)
- **FR-002**: 시스템은 반드시 화면 우측 영역에서 우→좌 스와이프가 발생하면 바로 직전에 넘긴 카드 1장을 최상단으로 복구하고, 그 카드의 **「카드 열람 확인」을 취소**해야 한다. 되돌리기는 **현재 덱에서 넘긴 카드가 남아 있는 한 넘긴 역순으로 이어지며**, 이미 발생한 「경과일 초기화 확인」은 되돌리지 않는다. (근거: business-context.md 「카드 덱」 스와이프 방향별 동작, 「장소 확인 이벤트」)
- **FR-003**: 시스템은 반드시 화면 좌측 영역에서 발생하는 스와이프 제스처를 카드 전환·복구에 반영하지 않아야 한다. (근거: business-context.md 「카드 덱」 스와이프 인식 영역)
- **FR-004**: 시스템은 반드시 현재 방·현재 정렬의 후보로 1개 덱을 **최대 10장**까지 구성해야 한다. 후보가 10개 미만이면 있는 만큼만 채운다. (근거: business-context.md 「카드 덱」 기본 구성)
- **FR-005**: 시스템은 반드시 카드의 `[...]` 버튼 클릭 시 `다른 방 저장` **한 항목만** 담은 메뉴를 노출해야 한다. 선택 시 메뉴를 닫고 「홈 방 시트」를 열며, 덱의 진행 상태를 바꾸지 않아야 한다. (근거: business-context.md 「카드 덱」 카드 액션 메뉴, [SCR-003] Flow C)
> **FR-006은 결번이다.** `장소 가리기`를 요구하던 항목이었으나 이 기능을 제공하지 않기로 확정되면서 삭제했다(PRD 8.0.0 §2 비목표). 번호는 재사용하지 않는다(§3.2·§5 참고).
- **FR-007**: 시스템은 반드시 카드 본문 클릭 시 그 장소의 [SCR-006] 장소 상세 `Half`로 이동해야 한다. 카드는 넘어가지 않고 덱의 진행 상태(잔여 카드·소진 여부·되돌리기 이력)도 바뀌지 않는다 — 클릭은 「카드 열람 확인」이 아니다. **「경과일 초기화 확인」을 홈이 일으키지는 않는다** — 이동한 상세가 열리면서 기록하며(`docs/specs/place-detail/spec.md` FR-026), 홈은 같은 기록을 따로 내보내지 않는다. (근거: business-context.md 「장소 확인 이벤트」 ① `장소 상세([SCR-006])를 연 시점에 발생한다`·`앱 전역에서 일어난다`, [SCR-003] Flow A·B)
- **FR-023**: 시스템은 반드시 **「경과일 초기화 확인」과 「카드 열람 확인」을 서로 독립으로 다뤄야** 한다. 카드를 넘기는 것은 서버에 알리지 않고 덱 소진 판정에만 쓰며, 카드를 눌러 상세를 여는 것은 덱의 진행 상태를 바꾸지 않는다. **홈은 두 이벤트 중 어느 것도 서버로 보내지 않는다** — ①의 기록은 [SCR-006]이 소유하고, ②는 클라이언트 전용이다. (근거: business-context.md 「장소 확인 이벤트」)
- **FR-008**: 시스템은 반드시 각 카드에 **장소분류 라벨** 1종(`친구들이 많이 본 곳` / `이야기 많은 곳` / `여럿이 저장한 곳` / `가볼 만한 곳`)을 표시해야 한다. (근거: business-context.md 「장소분류 라벨」)
- **FR-009**: 시스템은 반드시 상단에 정렬 칩 3종(`꾹 Pick`·`최신순`·`가까운순`)을 왼쪽에서 오른쪽 순서로 노출하고, 현재 보고 있는 덱의 정렬을 선택 상태로 표시해야 한다. (근거: business-context.md 「홈 카드 덱 정렬 기준」, Figma `2598-95698`)
- **FR-010**: 시스템은 반드시 사용자가 정렬 칩을 직접 누르면 그 정렬의 덱으로 즉시 전환해야 한다. (근거: business-context.md [SCR-003] Flow E)
- **FR-011**: 시스템은 반드시 현재 덱을 소진하면 **같은 방에서 아직 소진되지 않은 덱 중 우선순위가 가장 높은 것**으로 전환해야 한다. 우선순위는 항상 `꾹 Pick` > `최신순` > `가까운순`이며, 후보가 0건인 덱은 소진된 것으로 본다. **각 덱의 소진 여부는 전환이 일어나는 시점에 그때그때 판정해야 한다** — 방에 들어올 때 한 번 계산해 두고 재사용하지 않는다. (근거: 이슈 #235 §3·§4, §5 확정 항목)
- **FR-012**: 시스템은 반드시 현재 방의 세 덱이 모두 소진되었을 때에만 다음 방으로 전환해야 하며, 방이 바뀌면 정렬을 `꾹 Pick`으로 초기화해야 한다. (근거: 이슈 #235 §4, business-context.md 「카드 덱」 자동 방 전환)
- **FR-013**: 시스템은 반드시 저장 장소가 0개인 방을 방 전환 대상에서 건너뛰어야 한다. (근거: business-context.md 「카드 덱」 자동 방 전환)
- **FR-014**: 시스템은 반드시 모든 방의 모든 덱이 소진되면 상단(방 뱃지·인사 문구·정렬 칩)을 유지한 채 카드 자리에만 일러스트와 `꾹 눌러둔 장소를 모두 둘러봤어요`를 노출해야 하며, 이 화면에 CTA 버튼을 두지 않아야 한다. (근거: Figma `3388-199413`, business-context.md [SCR-003] Flow E)
- **FR-015**: 시스템은 반드시 현재 덱의 잔여 카드가 2장 이하가 되면 **실제로 다음에 올 덱 또는 방**을 가리키는 예고 툴팁을 노출하고 3초 뒤 사라지게 해야 한다. 예고할 대상이 없으면 노출하지 않는다. (근거: business-context.md 「덱 소진 예고 툴팁」, 이슈 #235 §6)
- **FR-016**: 시스템은 반드시 방이 바뀐 직후 방 캐릭터 옆에 `{방 이름}방이에요.` 툴팁을 노출하고 3초 뒤 사라지게 해야 한다. 수동 변경과 자동 전환 양쪽에서 같은 규칙을 적용한다. (근거: business-context.md 「방 전환 툴팁」)
- **FR-017**: 시스템은 반드시 상단 방 뱃지 또는 방 캐릭터 클릭 시 「홈 방 시트」를 열어야 한다. (근거: business-context.md [SCR-003] Flow F, Figma `2809-139468`)
- **FR-018**: 시스템은 반드시 「홈 방 시트」를 400dp 고정 높이의 3열 그리드로 노출하고, 각 칸을 70dp 썸네일 + 방 이름으로 구성하며 첫 칸을 `방 만들기`로 두어야 한다. 방 카드를 누르는 것이 곧 확정이며 체크박스와 확정 버튼을 두지 않는다. (근거: Figma `2809-139468`, business-context.md 「홈 방 시트」)
- **FR-019**: 시스템은 반드시 홈 탭 최초 진입 시 딤과 함께 안내 문구 2개(`좌우로 스와이프하며 카드를 탐색해 보세요.` · `방 뱃지와 토끼를 클릭하면 방을 변경할 수 있어요`)를 노출하고, 딤이 덮인 동안 홈의 조작을 받지 않아야 하며, 닫은 이력을 영속 저장해 앱 생애에 한 번만 노출해야 한다. (근거: Figma `4334-216197`, business-context.md [SCR-003] Flow H)
- **FR-020**: 시스템은 반드시 볼 수 있는 장소가 하나도 없을 때 완료 안내가 아닌 빈 상태 안내를 노출하고 `[공동방 만들기]` CTA를 제공해야 한다. (근거: business-context.md [SCR-003] Flow G)
- **FR-021**: 시스템은 반드시 상단에 현재 방의 뱃지와 방 캐릭터, 인사 문구(`꾹 눌러둔 장소, 다시 꺼내볼까요?`)를 노출해야 한다. (근거: Figma `2598-95698`, business-context.md [SCR-003] Flow A)
- **FR-022**: 시스템은 반드시 홈 탭을 **앱 최초 실행 시에는 개인방(`내 장소`)의 덱으로**, 그 이후에는 **마지막으로 보던 방의 덱으로** 시작해야 한다. 마지막으로 보던 방은 **기기에 영속 저장**하며 서버에 올리지도, 홈 진입 시 서버에 묻지도 않는다. (근거: business-context.md 「카드 덱」 시작 방, §5 확정 항목)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 카드 넘김·되돌림 전환은 다음 카드가 뒤에서 밀려 올라오는 애니메이션으로 표현하고, 애니메이션이 끝나기 전까지 추가 스와이프 입력을 무시한다. (근거: business-context.md "독립적 카드 소비 경험")
- **UX-002**: 카드 액션 메뉴는 항상 클릭한 `[...]` 버튼이 속한 카드 근처에서 열려, 어떤 카드에 대한 액션인지 혼동되지 않게 한다. (근거: Figma `2598-95698`)
- **UX-003**: 툴팁 2종은 노출되는 동안 사용자의 조작을 막지 않는다. 사용자가 카드를 계속 넘기면 툴팁은 그대로 3초를 채우고 사라진다. (근거: business-context.md 「방 전환 툴팁」·「덱 소진 예고 툴팁」)
- **UX-004**: 정렬 칩의 선택 표시는 언제나 지금 보고 있는 덱의 정렬과 일치한다. 자동 전환으로 정렬이 바뀐 경우에도 즉시 갱신되어, 화면에 보이는 칩과 실제 덱이 어긋나지 않는다. (근거: business-context.md [SCR-003] Flow E)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **방(Room)**: 장소를 모아 두는 단위. 대표 색상·캐릭터·이름을 가지며, 홈은 한 번에 한 방의 문맥만 보여준다. 저장 장소가 0개인 방은 홈 탐색에서 건너뛴다.
- **정렬 기준(Sort)**: 덱에 어떤 장소를 담을지 정하는 3종 기준. `꾹 Pick`·`최신순`·`가까운순`이며 **우선순위가 이 순서로 고정**되어 있다. 각 기준은 자기 후보 집합을 가지며 후보가 0건일 수 있다.
- **카드 덱(Deck)**: 한 방·한 정렬의 후보로 만들어지는 최대 10장의 열람 단위. 소진 상태(잔여 카드 수)와 되돌리기 이력을 가진다. **한 방은 정렬 3종에 대응하는 덱 3개를 가진다.**
- **장소 카드(Place Card)**: 덱을 이루는 한 장. 등록자 아바타·장소분류 라벨·장소명·주소·대표 이미지 2칸으로 구성된다. 저장 경과일은 표시하지 않는다.
- **소진(Exhausted)**: 그 덱의 카드를 모두 넘겼거나, 애초에 후보가 0건인 상태. 전환 대상을 고를 때 두 경우를 같게 다룬다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 사용자가 우측 영역 스와이프만으로, 별도 조작 없이 한 방의 세 덱을 모두 훑고 다음 방까지 넘어갈 수 있다.
- **SC-002**: 상단 정렬 칩으로 덱을 건너뛰어도, 방이 바뀌기 전에 건너뛴 덱의 카드를 모두 볼 수 있다.
- **SC-003**: 화면에 보이는 정렬 칩의 선택 상태와 실제 노출 중인 덱이 어긋나는 순간이 없다.
- **SC-004**: 예고 툴팁이 가리킨 대상과 실제로 다음에 온 덱·방이 항상 일치한다.
- **SC-005**: 연속 스와이프·애니메이션 중 입력으로 카드가 두 장 넘어가거나 전환이 끊기는 일이 없다.
- **SC-006**: 한 카드 위에서 스와이프·본문 클릭·`[...]` 세 조작이 서로를 오작동시키지 않는다.
- **SC-007**: 홈에 다시 들어온 사용자가 마지막으로 보던 방에서 이어 볼 수 있다.

### 3.2 비목표 항목 (Out of Scope)

- **정렬 3종의 후보 선정과 순위 산출**은 이 스펙이 정의하지 않는다. **서버가 소유한다** — 임계값도 후보 상한도 서버가 정하며, 홈은 기준 하나를 지정해 요청하고 **받은 순서를 그대로** 덱으로 만든다. 재정렬하지도 걸러내지도 않는다.
- **장소분류 라벨의 판정 로직**(클릭수·코멘트수·중복 저장 수 상위 판별)은 이 스펙이 정의하지 않는다. 홈은 전달받은 라벨 값을 표시만 한다.
- **경과일 초기화 값의 저장·반영**은 이 스펙이 정의하지 않는다. 홈은 「경과일 초기화 확인」이 일어났다는 사실을 알릴 뿐이고, 그 값을 언제 어떻게 순위에 반영할지는 서버의 소관이다.
- **홈 밖에서 발생하는 「경과일 초기화 확인」**은 이 스펙이 정의하지 않는다. 이 이벤트는 앱 전역에서 일어나지만, 지도·[SCR-005] 방 상세·[SCR-007] 알림에서 상세를 여는 경로는 각 화면의 스펙이 소유한다. 홈은 자기 카드 클릭 경로만 정한다.
- **`다른 방 저장`이 실제로 장소를 복제하는 처리**는 이 스펙이 정의하지 않는다. 홈은 「홈 방 시트」를 열고 선택을 전달하는 데까지 다룬다.
- **`장소 가리기` 액션**은 이 스펙이 정의하지 않는다. 카드를 현재 덱에서만 숨기는 액션은 PRD §2에서 **스펙아웃**됐다. 마음에 들지 않는 카드는 좌→우로 넘기면 그 덱에서 사라진다(FR-001). 특정 장소를 오래 안 보이게 하려면 [SCR-005] 방 상세에서 장소를 삭제한다.
- **카드 본문 클릭이 이동하는 [SCR-006] 장소 상세 `Half`의 내부**는 이 스펙이 정의하지 않는다.
- **`방 만들기` 이후의 공동방 생성 흐름**은 [SYS-001]·[SYS-009]가 정의한다.
- **바텀 네비게이션**은 [SYS-005]가 소유하며 이 스펙에서 새로 만들지 않는다.
- **위치 권한 요청 UI와 OS 다이얼로그 처리**는 [SYS-004]가 정의한다. 홈은 `가까운순` 전환 시점에 요청이 필요하다는 것과 거부 시의 덱 처리(EC-009)만 정한다.

## 4. 가정 (Assumptions)

- **"그 방에 남은 카드를 모두 보여준다"의 "모두"는 덱 단위다**(§5 확정) — 정렬 3종의 덱을 각각 한 벌씩(최대 10장씩) 훑으면 그 방을 다 본 것으로 본다. 방의 후보가 10개를 넘어도 덱을 다시 채우지 않는다.
- **한 장소가 여러 정렬 덱에 들어가면 그대로 두 번 노출된다**(§5 확정). `꾹 Pick`과 `가까운순`처럼 후보가 겹치는 정렬에서 같은 카드를 한 방에 두 번 볼 수 있으며, 덱 간 중복을 제거하지 않는다.
- 각 정렬의 후보 목록과 방 목록은 **홈이 전달받는다**고 가정한다. 홈이 직접 순위를 계산하지 않는다.
- 되돌리기는 **현재 덱 안에서 연속**으로 지원하며, 덱이 바뀌면 되돌리기 이력이 초기화된다고 가정한다. 원래는 1단계로 제한했으나 — 여러 장을 되돌리는 동작이 디자인에 없다는 이유였다 — 실기에서 두 번째 되돌리기가 아무 반응도 없어 고장으로 읽혔다. 넘긴 것을 되짚는 것이 이 제스처의 뜻이므로 넘긴 만큼 되돌아가게 한다.
- 되돌리기가 취소하는 것은 **「카드 열람 확인」뿐**이라고 가정한다(EC-017). 이미 서버로 나간 「경과일 초기화 확인」을 되돌리는 수단은 두지 않는다 — 상세를 연 사실 자체는 취소할 수 없고, PRD도 취소를 요구하지 않는다.
- 카드 본문 클릭과 스와이프는 **터치 슬롭으로 가른다**고 가정한다. 손가락이 임계 거리 이상 움직였으면 드래그, 아니면 탭이다.
- 예고 툴팁은 **잔여가 임계값 위로 다시 올라갔다 내려오면 재노출**한다고 가정한다. 원래는 한 덱당 1회로 굳혔으나 — 되돌릴 때마다 다시 뜨면 방해가 된다는 이유였다 — 되돌리기 뒤에는 잔여 2장에 아무 안내도 없어, 「잔여 2장이면 예고가 뜬다」는 규칙이 사용자에게만 조용히 깨졌다. 재노출의 조건은 「되돌렸다」가 아니라 **「덱이 임계값 위로 다시 길어졌다」**이므로, 되돌리지 않고 계속 넘기는 동안에는 여전히 한 번뿐이다.
- 방 순회 순서는 홈이 전달받은 방 목록의 순서를 그대로 따른다고 가정한다. 홈이 방을 재정렬하지 않는다.
- **홈에 다시 들어올 때 이어지는 것은 방(FR-022)까지**이고, 정렬은 `꾹 Pick`으로, 덱 소진 상태는 초기화된다고 가정한다. PRD가 이어 붙이라고 정한 것은 "마지막으로 보던 방" 하나뿐이며, 소진 이력까지 이어 붙이면 다시 들어온 사용자가 볼 카드 없이 완료 화면부터 만나게 된다.
- 홈의 진행 상태(현재 방·현재 정렬·덱 소진 여부·되돌리기 이력)는 **클라이언트 로컬 상태**로 관리하며 서버에 영구 저장하지 않는다고 가정한다. **기기에 영속 저장하는 것은 둘뿐이다** — 홈 사용 가이드를 닫은 이력(FR-019)과 마지막으로 보던 방(FR-022). (근거: business-context.md "독립적 카드 소비 경험", §5 확정 항목)

### 확정 항목

- Q : 홈에서 장소를 "확인했다"고 보는 기준은 무엇인가? -> A : **하나가 아니라 둘이다.** PRD 9.0.0의 「장소 확인 이벤트」를 그대로 따른다.

  | | 발생 | 쓰임 | 기록 | 범위 |
  |---|---|---|---|---|
  | **① 경과일 초기화 확인** | 장소 상세를 연 시점 | `꾹 Pick` 경과일 초기화 | 서버 | **앱 전역** |
  | **② 카드 열람 확인** | 카드를 좌→우로 넘김 | 덱 소진 판정 → 정렬·방 전환 | 클라이언트 | 홈만 |

  - **FR-007의 의미가 반전됐다.** 2.0.0은 *"상세를 열어본 것은 «확인»으로 보지 않는다"* 였으나, 3.0.0에서는 상세를 여는 것이 ①을 일으킨다. 다만 ②는 아니므로 **덱은 그대로**라는 부분은 유지된다.
  - **TS-013을 재정의하고 TS-034·TS-035를 신설**해 두 이벤트가 각각 독립으로 검증되게 했다. FR-023을 신설해 독립성 자체를 요구사항으로 세웠고, EC-017이 되돌리기의 취소 범위를 다룬다.
  - **되돌리기가 취소하는 것은 ②뿐이다.** 이미 서버로 나간 ①은 되돌리지 않는다(§4 가정).
  - 근거: PRD 9.0.0 §5, 서버 PR [mash-up-kr/Team-MINO-Node#94](https://github.com/mash-up-kr/Team-MINO-Node/pull/94).

- Q : ①의 기록을 홈이 내보내는가? -> A : **내보내지 않는다. [SCR-006] 장소 상세가 소유한다.** (4.0.0 확정)

  3.0.0은 홈이 `HomeDeckRepository.recordPlaceOpened`로 직접 기록하게 했다. 그 뒤 [SCR-006]이 배선되면서 `docs/specs/place-detail/spec.md` **FR-026**이 「상세가 열릴 때마다, 진입 경로와 무관하게」 기록을 가져갔고, 두 곳이 같은 `POST /api/v1/pins/{pinId}/accesses`를 치면서 **홈 카드 한 번 탭에 두 건이 쌓였다**. ①이 「앱 전역에서 일어난다」는 PRD의 규정은 어느 화면에서든 **한 번씩** 일어난다는 뜻이지 여러 화면이 겹쳐 부른다는 뜻이 아니므로, 소유자를 상세 하나로 두고 홈 쪽을 걷어낸다.

  - **FR-007에서 기록 요구를 덜어내고, FR-023을 「홈은 두 이벤트 중 어느 것도 서버로 보내지 않는다」로 다시 썼다.** TS-034는 「기록이 나간다」에서 **「홈이 중복해서 내보내지 않는다」**로 뒤집었고, EC-017의 기록 주체를 [SCR-006]으로 옮겼다. 탭이 덱을 건드리지 않는다는 것(TS-013)과 넘김이 서버와 무관하다는 것(TS-035)은 그대로다.
  - **`HomeDeckRepository.recordPlaceOpened`가 사라진다.** 홈이 이 기록을 서버로 흘릴 통로 자체가 없어져, 3.0.0에서 테스트가 지키던 FR-023의 독립성이 타입으로 보장된다.
  - **실패 처리의 어긋남도 함께 해소된다.** 홈 쪽만 기록 실패를 사용자에게 알렸는데(`onDomainFailure`), place-detail `EC-022`는 이 기록의 실패를 알리지도 재시도하지도 않는 것을 계약으로 둔다 — 순위 판정용 부가 신호이지 화면 구성의 전제가 아니기 때문이다.
  - 이 개정은 ①의 **발생 시점·범위·쓰임을 바꾸지 않는다.** 누가 보내는지만 정한다.
  - 근거: PRD 9.0.0 §1 「장소 확인 이벤트」 ①(현행 PRD까지 문구 변동 없음), `docs/specs/place-detail/spec.md` FR-026·EC-022·TS-038·TS-039, 같은 스펙 `tasks.md` 미결 6.

- Q : 정렬 3종의 임계값을 이 스펙이 규정하는가? -> A : **규정하지 않는다. 서버가 소유한다.** §3.2에서 `상위 30%`·`14일`·`3km` 수치를 걷어냈다. 홈은 기준 하나를 지정해 요청하고 받은 순서를 그대로 뿌린다. (PRD 9.0.0 §5 확정)

- Q : 「마지막으로 보던 방」을 어디에 저장하는가? -> A : **기기에 영속 저장한다.** 서버에 올리지도, 홈 진입 시 묻지도 않는다. 서버가 쥐면 방 목록 응답을 받아야 어느 덱을 부를지 알 수 있어 홈 첫 화면 호출이 직렬로 묶인다. 대가는 재설치·기기 교체 시 개인방부터 시작하는 것이고, 그 경로는 FR-022의 「앱 최초 실행」과 같다. FR-022와 §4 가정에 반영했다. (PRD 9.0.0 §5 확정)

작성 시점에 검토로 남겼던 4건을 2026-08-26 확정했다.

- Q : "그 방에 남은 카드를 모두 보여준다"의 "모두"는 덱 단위인가, 방의 장소 단위인가? -> A : **덱 단위.** 정렬 3종의 덱을 각각 한 벌씩(최대 10장씩) 훑으면 그 방을 다 본 것으로 본다. 방의 후보가 10개를 넘어도 덱을 다시 채우지 않으므로 「카드 덱」의 10장 상한과 충돌하지 않는다. §4 가정에 반영했다.
- Q : 한 장소가 여러 정렬 덱에 동시에 들어갈 때 중복 노출을 제거하는가? -> A : **제거하지 않는다.** `꾹 Pick`과 `가까운순`처럼 후보가 겹치는 정렬에서 같은 카드를 한 방에 두 번 볼 수 있고, 그대로 둔다. 덱은 각 정렬이 뽑아 준 후보를 그대로 담을 뿐 정렬 사이를 가로질러 걸러내지 않는다. §4 가정에 반영했다.
- Q : "소진되지 않은 덱"을 언제 판정하는가? -> A : **전환이 일어나는 시점에 그때그때 판정한다.** 방에 들어올 때 한 번 계산해 두고 재사용하지 않는다. `꾹 Pick`은 넘길 때마다, `가까운순`은 사용자가 이동하면 후보가 바뀌므로 매번 다시 본다. FR-011에 명문화했고 EC-013이 그 결과를 다룬다.
- Q : 액션 메뉴의 항목 수는 2개가 맞는가? -> A : **1개다. `장소 가리기` 기능을 제공하지 않는다.** 액션 메뉴에는 `다른 방 저장`만 남는다. 이에 따라 **FR-006을 삭제**하고(결번 유지) TS-009·TS-010·EC-008을 함께 지웠으며, FR-005·TS-008과 유저 플로우 2를 1항목 기준으로 다시 썼다.
  - **PRD MAJOR 개정이 따라붙는 것을 감수한 결정이다.** 유지하면 PRD를 손대지 않아도 됐지만 제공하지 않기로 확정했고, 그에 따라 PRD 8.0.0(PR [#244](https://github.com/mash-up-kr/Team-MINO-Android/pull/244))에서 네 곳이 개정됐다. 아래 「PRD 정합성 — 해소됨」 참고.

### PRD 정합성 — 해소됨

이 spec은 PRD보다 **먼저** 쓰였고 어긋난 항목이 그때마다 반영됐다. 3.0.0은 반대로 **PRD 9.0.0이 먼저 바뀐 것을 spec이 따라간 첫 개정**이다. **현재 기준 PRD 9.0.0과 어긋나는 항목이 없다.**

| 어긋났던 항목 | 반영 | 이 spec |
|---|---|---|
| Flow E 전환 규칙 — "`가까운순` 소진 → 곧바로 다음 방", "순환하지 않는다" | **PRD 7.0.0** (PR [#237](https://github.com/mash-up-kr/Team-MINO-Android/pull/237)) | FR-011·FR-012 |
| Flow D 예고 툴팁 대상 — 고정 순서 기준 | **PRD 7.0.0** | FR-015 |
| Flow H 코치마크 문구 — 1개만 기술 | **PRD 7.0.0** | FR-019 |
| Flow E 위치 권한 거부 — "곧바로 다음 방" | **PRD 7.0.0** | EC-009 |
| Flow E "전환 순서를 다시 시작" | **PRD 7.0.0** | FR-010·TS-021 |
| 카드 액션 메뉴에 `장소 가리기` 존재 | **PRD 8.0.0** (PR [#244](https://github.com/mash-up-kr/Team-MINO-Android/pull/244)) | FR-005 (FR-006 결번) |

**개정 대상이 아니었던 것**: 정렬 우선순위 3종의 순서, 방 전환 시 `꾹 Pick` 초기화, 시작 방 규칙(FR-022), 툴팁 유지 시간 3초, 완료 안내 화면 구성. 모두 처음부터 일치했다.

확정 1~3번(덱 단위·중복 허용·전환 시 판정)은 PRD가 규정하지 않은 세부라 개정 대상이 아니다.
