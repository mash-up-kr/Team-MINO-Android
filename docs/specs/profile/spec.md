## 1. 유저 시나리오 (User Scenarios) *(필수)*
### 유저 플로우 1 - 온보딩에서 프로필을 처음 만든다
앱을 처음 설치한 사용자가 스플래시 직후 프로필 설정 화면에서 닉네임과 아바타를 정하고 저장한다. 저장이 끝나야 앱을 쓰기 시작할 수 있으므로 건너뛸 수 없다.

**Figma**: [010-1 프로필 설정_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95662&m=dev) · [010-2 프로필 설정_입력 완료](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95709&m=dev)

**진입 조건**: 프로필이 없는 앱 설치에서 [SCR-001] 스플래시가 익명 세션 확보를 끝내고 프로필 설정 화면으로 자동 진입한 상태. 닉네임은 비어 있고, 상단 썸네일은 **아바타 목록에 없는 기본 아바타**를 보여주며, 닉네임 필드 아래에는 `최대 15자까지 입력할 수 있어요.`가 평상시 색으로 놓여 있다. `지우기`·`저장`은 모두 비활성이고 뒤로가기 버튼은 노출되지 않는다.

1. 사용자가 `이름 또는 닉네임` 필드에 한글·영문 2글자 이상을 입력한다 → 시스템이 오류 표시 없이 값을 받고 `저장`을 활성 상태로 바꾼다
2. 사용자가 `프로필 이미지 선택` 목록에서 아바타 1개를 누른다 → 시스템이 상단 썸네일을 즉시 그 아바타로 바꾼다. 이전에 고른 아바타가 있었다면 선택이 해제되어 언제나 하나만 선택 상태다(선택은 썸네일로 드러나며 칸에는 표시가 없다)
3. 사용자가 `저장`을 누른다 → 시스템이 닉네임과 아바타를 사용자 프로필로 보관하고, 개인방(`내 장소`) 생성을 트리거한 뒤 온보딩의 공동방 생성 스텝으로 이동한다

**완료 조건**: 이 앱 설치에 닉네임과 아바타를 가진 프로필이 1개 존재하고, 개인방(`내 장소`)이 생성되었으며, 화면이 온보딩의 공동방 생성 스텝으로 넘어가 있다. 온보딩은 앞으로만 흐르므로 이 이동 뒤에는 온보딩 안에서 프로필 설정 화면으로 되돌아오는 경로가 없다.

### 유저 플로우 2 - 마이페이지에서 프로필을 수정한다
이미 프로필이 있는 사용자가 마이페이지에서 같은 화면을 열어 닉네임이나 아바타를 바꾼다. 온보딩과 화면 구성은 같고 진입·이탈 동작만 다르다.

**Figma**: [008-1 마이페이지](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-124589&m=dev) · [010-2 프로필 설정_입력 완료](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95709&m=dev)

**진입 조건**: 프로필이 이미 있는 사용자가 [SCR-008] 마이페이지를 보고 있고, 프로필 영역에 현재 아바타와 닉네임이 표시되어 있다.

1. 사용자가 프로필 영역의 [연필]을 누른다 → 시스템이 프로필 설정 화면을 열고, 닉네임 필드와 아바타 선택 상태를 현재 저장된 값으로 채우며 뒤로가기를 활성으로 둔다
2. 사용자가 닉네임을 고치거나 다른 아바타를 고른다 → 시스템이 상단 썸네일과 `저장` 활성 상태를 입력에 맞춰 갱신한다
3. 사용자가 `저장`을 누른다 → 시스템이 바뀐 값을 프로필로 보관하고 마이페이지로 돌아가며, 마이페이지의 프로필 표기를 바뀐 값으로 보여준다

**완료 조건**: 저장된 프로필이 사용자가 입력한 닉네임·아바타와 같고, 화면이 마이페이지로 돌아와 바뀐 값을 표시하고 있다.

### 유저 플로우 3 - 닉네임 입력 오류를 고치고 입력을 초기화한다
사용자가 규칙에 맞지 않는 닉네임을 넣었을 때 화면이 이를 알려 주고, 상한을 넘는 입력은 아예 받지 않으며, `지우기`로 입력을 한 번에 되돌린다.

**Figma**: [010-3 프로필 설정_입력 오류](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95754&m=dev) · [010-1 프로필 설정_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95662&m=dev)

**진입 조건**: 프로필 설정 화면(진입점 무관)에서 사용자가 닉네임 필드에 입력하고 있는 상태.

1. 사용자가 규칙에 맞지 않는 닉네임(예: `민`, `abc1`, `ㄱㄱ`)을 입력한다 → 시스템이 입력 필드를 오류 상태(테두리 강조·경고 아이콘)로 바꾸고, 필드 아래 안내 문구 자리를 `한글·영문 2글자 이상을 입력해주세요.`로 바꿔 오류 색으로 보여 주며 `저장`을 비활성으로 유지한다
2. 사용자가 닉네임을 규칙에 맞게 고친다 → 시스템이 오류 표시를 걷어내고 안내 문구 자리를 평상시 문구 `최대 15자까지 입력할 수 있어요.`로 되돌리며 `저장`을 활성으로 바꾼다
3. 사용자가 15자를 채운 뒤에도 글자를 더 입력한다 → 시스템이 그 글자를 필드에 반영하지 않고, 값을 15자 그대로 둔 채 오류 표시나 별도 안내를 내지 않는다
4. 사용자가 `지우기`를 누른다 → 시스템이 닉네임 입력과 아바타 선택을 모두 비운 상태로 되돌리고, 상단 썸네일을 기본 아바타로 되돌리며 `저장`을 비활성으로 바꾼다

**완료 조건**: 화면의 닉네임·아바타 입력 상태와 `저장` 활성 여부가 사용자가 마지막으로 입력한 값의 유효성과 일치하고, 필드에 담긴 값이 15자를 넘지 않는다.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)
- **FR-001**: 시스템은 반드시 온보딩 진입과 마이페이지 진입에 같은 프로필 설정 화면을 제공한다. 화면 제목은 `프로필 설정`, 안내 문구는 `친구들에게 어떻게 보일까요?`이며, 상단 프로필 썸네일 · `이름 또는 닉네임` 입력 필드 · `프로필 이미지 선택` 아바타 목록 · `지우기`/`저장` 버튼으로 구성된다. **`이름 또는 닉네임`에는 필수 표시를 붙이고 `프로필 이미지 선택`에는 붙이지 않아, 둘 중 무엇이 필수인지가 화면에서 드러나게 한다.** (근거: 디자인 정책 노드 `2314-95662`·`2314-95761` — 닉네임 라벨에만 `*` 필수 마커가 있고 아바타 섹션 라벨에는 없다. PRD [SYS-011] "온보딩과 마이페이지가 같은 화면을 공유한다")
- **FR-002**: 시스템은 반드시 닉네임을 필수 입력으로 두고, 앞뒤 공백을 제외한 값이 **완성형 한글(`가`–`힣`)과 영문 대소문자로만 이루어진 2글자 이상**일 때만 유효한 것으로 판정한다. 자모 단독(`ㄱ`·`ㅏ`)·숫자·특수문자·이모지·공백은 무효이며, **내부 공백도 무효**다. **길이 상한 15자는 이 판정에 넣지 않는다** — 상한은 FR-014의 입력 차단이 지키므로 상한을 넘긴 값이 판정 대상이 되는 일 자체가 없다. (근거: PRD 10.0.0 [SYS-011] Flow A "닉네임은 한글·영문 2글자 이상 15자 이하", 디자인 정책 노드 `2314-95625` "한글·영문 2글자 이상 입력 필수", 플레이스홀더 `한글·영문 2글자 이상`, 서버 닉네임 정책 `2~15자`·허용 문자 `완성형 한글 + 영문 대소문자만`. §5에서 확정)
- **FR-003**: 시스템은 반드시 사용자가 고를 수 있는 아바타 12종을 `프로필 이미지 선택` 목록에 노출하고, 그중 **한 번에 하나만** 선택되게 한다. 기본 아바타는 이 목록에 넣지 않는다(FR-015). 아바타를 누르면 즉시 상단 프로필 썸네일이 그 아바타로 바뀌며, **선택 상태는 상단 프로필 썸네일로 드러난다 — 목록의 칸 자체에는 선택을 구별하는 시각 표시를 두지 않는다.** 다만 화면을 보지 않는 사용자도 무엇이 골라졌는지 알 수 있어야 하므로, 선택 여부는 보조 수단(화면 낭독 등)에 전달한다. 아바타 선택은 선택 입력이다. (근거: 디자인 정책 노드 `2314-95631` "하나만 선택 가능 / 선택하면 상단의 프로필 썸네일이 실시간 변경", 노드 `2314-95672` 아바타 3×4 그리드 — 원본에 선택된 칸을 구별하는 표현이 없다. §5에서 확정)
- **FR-004**: 시스템은 반드시 닉네임이 유효할 때만 `저장`을 활성 상태로 두고, 그 밖의 경우(비어 있음·오류 상태)에는 비활성으로 유지한다. 아바타 선택 여부는 `저장` 활성 조건에 영향을 주지 않는다. (근거: 디자인 정책 노드 `2314-95655` "'이름 또는 닉네임' 정상 입력 시 활성화")
- **FR-005**: 시스템은 반드시 **닉네임이 유효하고 아바타도 선택되어 있을 때만** `지우기`를 활성 상태로 두고, 눌렀을 때 닉네임 입력과 아바타 선택을 모두 초기 상태로 되돌리며 상단 썸네일을 기본 아바타로 되돌린다. (근거: 디자인 정책 노드 `2314-95649` "'이름 또는 닉네임' 정상 입력, 프로필 이미지 선택 시 활성화 / 클릭 시 1, 2 초기화")
- **FR-006**: 시스템은 반드시 마이페이지에서 진입했을 때 현재 저장된 닉네임과 아바타로 입력 상태를 미리 채운다. (근거: PRD [SCR-008] Flow A "프로필 영역의 [연필] 클릭 ➔ [SYS-011] 호출")
- **FR-007**: 시스템은 반드시 저장 시 닉네임(앞뒤 공백 제외)과 선택된 아바타를 현재 익명 세션 사용자의 **단일 공통 프로필**로 보관하고, 앱 안의 모든 프로필 표기 지점이 이 값을 사용하게 한다. (근거: PRD 비목표 "방별 프로필 분리 — [SYS-011]의 단일 공통 프로필을 모든 방에서 함께 사용한다")
- **FR-008**: 시스템은 반드시 온보딩 진입에서 저장이 완료되면 개인방(`내 장소`) 생성을 트리거한 뒤 온보딩의 공동방 생성 스텝으로 이동시킨다. 이동한 뒤에는 온보딩 안에서 프로필 설정 화면으로 되돌아오는 경로를 두지 않는다. (근거: 디자인 정책 노드 `2314-95655` "최초 접속 시 : 클릭 시 001로 이동", PRD [SCR-002] Flow A, PRD 5.0.0 §5 "온보딩에서는 뒤로가기를 표출하지 않는다 — 프로필 설정으로 되돌아가는 경로는 없앤다")
- **FR-009**: 시스템은 반드시 마이페이지 진입에서 저장이 완료되면 마이페이지로 돌아가고, 마이페이지의 프로필 표기를 저장한 값으로 즉시 갱신한다. (근거: 디자인 정책 노드 `2314-95655` "008[마이페이지]에서 접속 시 : 008[마이페이지]로 이동", PRD [SCR-008] Flow A)
- **FR-010**: 시스템은 반드시 온보딩 진입에서는 **뒤로가기를 노출하지 않아** 화면을 벗어나지 못하게 하고, 마이페이지 진입에서는 뒤로가기를 활성으로 둔다. (근거: 디자인 정책 노드 `2314-95643` "최초 접속 시 : 비활성화 / 008[마이페이지]에서 접속 시 : 활성화" — 화면을 벗어나지 못하게 한다는 목적은 같고 표현만 숨김으로 확정했다. PRD [SYS-001]도 온보딩에서 뒤로가기를 표출하지 않는다. §5에서 확정)
- **FR-011**: 시스템은 반드시 닉네임 필드 아래 안내 문구 자리에 **평상시에는 `최대 15자까지 입력할 수 있어요.`** 를 두고, **닉네임이 유효하지 않은 동안에는 같은 자리를 `한글·영문 2글자 이상을 입력해주세요.`로 바꿔** 오류 색으로 보여 주며 입력 필드도 오류 상태(테두리 강조·경고 아이콘)로 표시한다. 값이 유효해지면 오류 표시를 걷어내고 평상시 문구로 되돌린다. 두 문구가 동시에 보이지 않는다. (근거: 디자인 정책 노드 `2314-95662`·`2314-95754` — 안내 문구 자리가 하나뿐이고 오류 상태에서 색만 바뀐다. 문구를 오류 사유에 맞게 가르는 것은 §5에서 확정)
- **FR-012**: 시스템은 반드시 저장이 실패하면 프로필 설정 화면과 사용자가 입력한 값을 그대로 유지한 채 실패를 알리고, 후속 화면으로 이동하지 않는다. (근거: PRD [SYS-011] Flow C — 저장 성공을 전제로만 후속 분기가 정의됨)
- **FR-013**: 시스템은 반드시 마이페이지 진입에서 뒤로가기를 누르면 저장하지 않은 수정 내용을 버리고 마이페이지로 돌아간다. (근거: 디자인 정책 노드 `2314-95643` — 확인 모달이 설계되어 있지 않음)
- **FR-014**: 시스템은 반드시 닉네임 입력 필드가 **15자를 넘는 값을 받지 않게** 한다. 15자가 찬 뒤에 누른 글자는 필드에 반영되지 않고, 붙여넣기는 앞 15자까지만 반영한다. 상한 초과는 오류가 아니므로 오류 상태로 바꾸거나 오류 문구를 띄우지 않는다. (근거: PRD 10.0.0 [SYS-011] Flow A `15자 이하`, 디자인 정책 `[005]` 주석 #3 `닉네임` 최대 15자. §5에서 확정)
- **FR-015**: 시스템은 반드시 **`프로필 이미지 선택` 목록의 12종에 속하지 않는 기본 아바타 1종**을 두고, 아바타를 고르지 않은 동안 상단 프로필 썸네일에 그 기본 아바타를 보여 준다. 아바타를 고르지 않은 채 저장하면 기본 아바타가 그대로 프로필 아바타로 보관되며, 12종 중 하나로 바꿔치지 않는다. `지우기`로 선택을 되돌렸을 때도 썸네일은 기본 아바타로 돌아간다. (근거: 디자인 정책 노드 `2314-95665` — 기본 썸네일이 목록 첫 항목과 배경색도 생김새도 다른 별개 아바타다. 서버도 아바타 색을 선택 12색에 기본 1색을 더한 13개로 정의한다. §5에서 확정)

### 2.2 핵심 UX 규칙 (Core UX Rules)
- **UX-001**: 닉네임 오류는 별도 팝업·토스트·상단 배너가 아니라 입력 필드 바로 아래 안내 문구 자리에 표시한다. 오류가 없을 때 같은 자리에는 평상시 색의 안내 문구가 놓인다. 자리를 하나만 쓰므로 문구가 늘거나 줄어 화면이 흔들리지 않는다. (근거: 디자인 정책 노드 `2314-95754` / `2314-95662`)
- **UX-002**: 닉네임 유효성 판정과 `저장` 활성 상태 변화는 사용자가 글자를 입력·삭제할 때마다 반영하며, 별도 확인 조작(포커스 이동·버튼 클릭)을 요구하지 않는다. (근거: 디자인 정책 노드 `2314-95655`)
- **UX-003**: 저장 요청이 끝나기 전에는 같은 요청이 다시 만들어지지 않게 하고, 처리 중에는 `저장`을 다시 누를 수 없게 한다.
- **UX-004**: 비활성 상태의 `저장`·`지우기`는 눌러도 아무 반응을 내지 않는다. 비활성 이유를 별도 안내로 띄우지 않는다. (근거: 디자인 정책 노드 `2314-95662` — 비활성 상태에 안내 요소가 없음)
- **UX-005**: 아바타를 고르면 상단 프로필 썸네일이 같은 화면 안에서 즉시 바뀐다. 미리보기를 위한 별도 화면 이동이나 확인 단계를 두지 않는다. (근거: 디자인 정책 노드 `2314-95631`)
- **UX-006**: 프로필 설정 화면에서는 바텀 네비게이션을 노출하지 않는다. (근거: PRD [SCR-002] 화면 특성, 디자인 정책 노드 `2314-95662` — 하단이 Action Area로 채워짐)
- **UX-007**: 닉네임 필드에 글자 수 카운터(`n/15`)를 두지 않는다. 상한은 평상시 안내 문구 `최대 15자까지 입력할 수 있어요.`가 미리 알려 주고, 실제로는 더 입력되지 않는 것으로만 드러난다 — 상한에 닿았다고 오류로 바뀌거나 별도 안내가 뜨지 않는다. 하한·문자 규칙은 플레이스홀더 `한글·영문 2글자 이상`과 오류 문구가 맡는다. (근거: 디자인 정책 노드 `2314-95662`·`2314-95754` — 카운터 노드가 없고 안내 문구 자리에 `최대 15자까지 입력할 수 있어요.` 하나가 놓인다. §5에서 확정)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **프로필 (Profile)**: 사용자가 다른 사람에게 보이는 이름과 얼굴. 닉네임과 아바타 하나로 이루어지며, 하나의 익명 세션(앱 설치)에 하나만 존재한다. 방·장소·코멘트 어디에서든 같은 프로필이 쓰인다.
- **아바타 (Avatar)**: 앱이 제공하는 고정 캐릭터 이미지. 사용자가 고를 수 있는 **12종**과, 아무것도 고르지 않았을 때 쓰이는 **기본 아바타 1종**을 합쳐 모두 13종이다. 사용자가 직접 이미지를 올리지 않으며, 프로필은 언제나 이 13종 중 하나를 가리킨다.
- **개인방 (`내 장소`)**: 프로필이 처음 저장될 때 함께 생기는 사용자 전용 저장 공간. 이 스펙은 프로필 저장이 개인방 생성을 촉발한다는 사실만 다루고, 개인방의 구성과 동작은 방 스펙이 정의한다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)
- **SC-001**: 앱을 처음 켠 사용자가 프로필 설정 화면에 진입한 뒤 **60초 이내**에 저장을 마치고 다음 온보딩 스텝으로 넘어간다.
- **SC-002**: 온보딩에 진입한 사용자의 **95% 이상**이 이 화면을 이탈하지 않고 프로필 저장까지 도달한다.
- **SC-003**: 닉네임을 고쳐 저장한 뒤, 앱 안의 모든 프로필 표기 지점(마이페이지 헤더·코멘트 작성자·방 멤버 아바타·[SCR-006] 장소 상세 헤더의 등록자 표기)이 **앱을 다시 켜지 않고도** 바뀐 값을 보여 준다.
- **SC-004**: 유효하지 않은 닉네임(2글자 미만, 15자 초과, 자모 단독, 공백·숫자·특수문자·이모지 포함)으로 저장이 시도되는 경우가 **0건**이다. 서버가 닉네임 형식을 이유로 저장을 거절하는 일이 없다.
- **SC-005**: 아바타를 누른 시점부터 상단 프로필 썸네일이 바뀌기까지 사용자가 추가로 하는 조작이 **0회**다.
- **SC-006**: 프로필 저장이 실패한 경우, 사용자가 화면을 다시 채워 넣지 않고 **입력한 값 그대로** 재시도할 수 있다.

### 3.2 비목표 항목 (Out of Scope)
- 개인방(`내 장소`)의 생성 규칙·표시·삭제 제약은 방 스펙이 정의한다. 이 문서는 프로필 저장이 개인방 생성을 촉발한다는 사실까지만 다룬다.
- 온보딩의 나머지 스텝(공동방 생성 · 친구 초대 · 공유 방법 튜토리얼)과 스텝 간 진행 규칙은 온보딩 스펙이 정의한다.
- 마이페이지의 프로필 영역을 뺀 나머지 항목(알림 설정 · 위치 설정 · 약관 및 동의 · 앱 리뷰)은 마이페이지 스펙이 정의한다.
- 아바타 13종(선택 12종 + 기본 1종)의 이미지 에셋과 시각 규격(크기·간격·선택 표시 스타일)은 디자인 시스템이 정의한다.
- 프로필이 다른 화면에 어떻게 그려지는지(코멘트 작성자 표기, 방 멤버 아바타 겹침·카운터 규칙)는 각 화면의 스펙이 정의한다.
- 닉네임 금칙어·비속어 필터, 닉네임 중복 제한 같은 내용 정책은 서버가 정의한다.
- 프로필 이미지 직접 업로드·촬영, 방마다 다른 프로필을 두는 것은 MVP 비목표이므로 이 문서가 다루지 않는다.
- 익명 계정 식별자의 발급과 세션 유지 방식은 익명 세션 스펙이 정의한다. 이 문서는 세션이 유효하다는 전제 위에서만 프로필을 다룬다.
- 프로필을 저장한 뒤 온보딩의 나머지 스텝을 마치기 전에 앱을 종료했다가 다시 실행했을 때 사용자를 어느 화면으로 보낼지는 스플래시·온보딩 스펙이 정의한다. 이 문서는 프로필이 없는 앱 설치에서의 온보딩 진입만 다룬다.
- 초대 링크로 앱에 들어온 프로필 미생성 사용자의 방 참여 처리와 그 시점은 초대 링크 스펙이 정의한다. 이 문서는 그 사용자도 온보딩의 프로필 설정을 그대로 거친다는 사실까지만 다룬다.
- 익명 세션을 실제 계정으로 승격해 재설치·기기 변경 후에도 프로필을 이어가는 것은 MVP 비목표다. (PRD 비목표 "소셜 로그인 / OAuth 2.0")
- 저장 실패를 사용자에게 알리는 표현의 구체적 형태는 프로젝트 공통 에러 처리 규약을 따르며 이 문서가 따로 정의하지 않는다.

## 4. 가정 (Assumptions)
- 프로필은 회원가입 없이 **인증 제공자가 발급한 익명 계정 식별자**에 귀속된다. 서버는 앱이 보낸 값을 그대로 믿지 않고 서명된 증명을 검증해 요청자를 특정한다. (PRD 핵심 원칙 "비회원 익명 세션")
- 프로필을 만들 수 있는 세션은 이 화면에 오기 전에 [SCR-001] 스플래시가 이미 확보해 두었다. 세션을 확보하기 전에는 스플래시가 어느 화면으로도 들여보내지 않으므로(PRD 5.0.0 [SCR-001] Flow E), 이 문서의 모든 흐름은 유효한 세션을 전제한다. (§5에서 확정)
- 세션은 기기가 아니라 **앱 설치**에 묶인다. 앱을 지웠다 다시 설치하면 이전 프로필로 돌아갈 수 없고 복구 수단도 없다. 이때 재설치임을 알리는 안내를 따로 두지 않고 최초 실행과 똑같이 온보딩의 프로필 설정으로 진입한다. (§5에서 확정)
- 설치가 살아 있는 동안 세션은 만료되지 않는다. 미접속 기간이 아무리 길어도 서버가 세션을 자동 무효화하지 않으므로, 마이페이지에서 프로필을 수정하는 흐름에 무효 세션을 감지해 재발급하는 갈래를 두지 않는다. (PRD 5.0.0 핵심 원칙 "비회원 익명 세션", §5에서 확정)
- 온보딩은 앞으로만 흐른다. 공동방 생성 스텝에 뒤로가기가 없으므로 프로필 저장 뒤 온보딩 안에서 이 화면으로 되돌아오는 일은 일어나지 않고, 이 문서도 복귀 시의 화면 상태를 정의하지 않는다. (PRD 5.0.0 [SYS-001] Flow E, §5에서 확정)
- 초대 링크를 받고 들어온 프로필 미생성 사용자도 이 화면을 온보딩 진입으로 본다. 저장 후 분기는 FR-008과 같아 공동방 생성 스텝으로 이어지고, 초대받은 방 참여는 온보딩이 끝난 뒤 초대 링크 스펙이 처리한다. (PRD [SYS-010] Flow A, §5에서 확정)
- 닉네임 중복은 허용한다. 디자인에 중복 검사 결과를 알리는 상태가 없으므로 유일성을 요구하지 않는 것으로 본다.
- 닉네임의 `한글·영문`은 **완성형 한글 음절(`가`–`힣`)** 과 영문 알파벳만을 뜻한다. 자모 단독(`ㄱ`·`ㅏ`)·숫자·특수문자·이모지·공백은 유효하지 않은 문자다. 공동방 이름이 숫자를 허용하는 것과 달리 디자인 문구에 숫자가 빠져 있는 것을 그대로 따르며, 이 해석은 서버의 허용 문자 정책(`완성형 한글 + 영문 대소문자만`)과도 같다. (§5에서 확정)
- 닉네임의 앞뒤 공백은 길이 판정과 보관 양쪽에서 제외한다.
- **닉네임 규칙은 이제 서버 정책과 정확히 같다.** 길이 `2~15자`(앞뒤 공백 제외), 허용 문자는 완성형 한글과 영문 대소문자, 공백은 내부까지 불허, 앞뒤 공백은 거절이 아니라 제거 후 판정·보관, 중복 허용 — 여섯 항목이 모두 일치한다. 2.0.0까지 남아 있던 상한 어긋남은 3.0.0이, 공백 어긋남은 서버가 허용 문자에서 공백을 빼면서 없어졌다. 클라이언트 판정을 통과한 값이 서버에서 형식을 이유로 거절되는 경로는 남아 있지 않다.
- **서버는 등록(`POST`)에서 닉네임과 아바타를 모두 필수로 받고, 수정(`PATCH`)에서는 둘 다 선택으로 받되 최소 한 필드를 요구한다.** 이 화면은 두 값을 한 폼으로 다뤄 언제나 함께 보내므로 양쪽 조건을 그대로 만족한다 — 아바타를 고르지 않아도 기본 아바타(FR-015)가 실려 나가기 때문에 아바타가 빈 채로 등록 요청이 만들어지는 일이 없다.
- 아바타 목록의 칸에는 선택된 항목을 구별하는 시각 표시를 두지 않는다. 디자인 원본에 그 표현이 없으므로 만들지 않고, 선택은 상단 썸네일이 드러낸다. (§5에서 확정)
- 아바타는 앱에 포함된 고정 13종(선택 12종 + 기본 1종)이며, 목록을 서버에서 내려받지 않는다. 선택 목록은 12종만 담는다. (디자인 정책 노드 `2314-95672`의 3×4 그리드, 노드 `2314-95665`의 기본 썸네일)
- 아바타를 고르지 않고 저장하면 상단 썸네일에 처음부터 보이던 기본 아바타가 프로필 아바타로 보관된다. `프로필 이미지 선택`에는 필수 표시가 없고 `저장` 활성 조건에도 들어가지 않으므로 선택 입력이다. (§5에서 확정, FR-015)
- **기본 아바타는 "고르지 않았다"를 뜻하는 어엿한 값이지, 화면에만 있는 자리 표시가 아니다.** 저장·조회·앱 안의 모든 프로필 표기가 이 값을 12종과 똑같이 다루므로, 사용자가 화면에서 본 얼굴과 저장된 얼굴이 어긋나지 않는다. 서버 표현에 이 값에 대응하는 자리가 이미 있다(`avatar.color`의 13번째 값). (§5에서 확정)
- 마이페이지에서 수정 중 뒤로가기를 누를 때 확인 모달을 띄우지 않는다. 디자인에 해당 모달이 없다. (§5에서 확정)
- 프로필 저장은 서버 반영을 포함하며, 사용자는 저장 시점에 네트워크에 연결되어 있다고 가정한다. 오프라인 저장·나중에 동기화는 다루지 않는다.
- 저장 실패의 사용자 안내는 프로젝트 공통 에러 처리 규약(`docs/conventions/error_handling.md`)이 제공하는 표현을 그대로 쓴다.
- 온보딩의 프로필 설정 스텝에는 `건너뛰기`가 없다. 디자인 정책 노드 `2314-95611`의 주석 1~5에 건너뛰기 항목이 없고, PRD [SCR-002] Flow A가 "건너뛰기 불가"로 못박고 있다.
- 닉네임 길이 상한은 15자이지만, 좁은 자리에 15자가 다 들어가지 않을 때의 말줄임 처리는 그 화면을 정의하는 스펙이 책임진다. 이 문서는 입력 쪽 상한만 정한다.
- 15자를 세는 단위는 코드 유닛이 아니라 **사용자가 보는 문자**다. 조합 중인 한글이 낱자 수로 세어지면 15자를 채우기 전에 입력이 막혀 TS-017이 어긋난다. 세는 수단은 구현이 정한다.
- 상한을 판정이 아니라 입력 차단으로 다뤄도 마이페이지 진입에서 미리 채워지는 기존 닉네임이 상한을 넘는 일은 없다. 프로필을 저장하는 경로가 이 화면 하나뿐이라 15자를 넘는 값이 보관될 수 없기 때문이다.

  → **A**: **그런 상황이 생기지 않는다.** PRD 5.0.0이 "설치가 살아 있는 동안 세션은 만료되지 않는다"로 확정해 앱에 무효 세션을 감지·재발급하는 경로 자체가 없다. 이 문서는 세션이 유효하다는 전제를 그대로 유지한다. (§4 가정 반영)
- **Q**: 초대 링크로 들어온 프로필 미생성 사용자는 프로필을 저장한 뒤 어디로 가는가? — PRD [SYS-010] Flow A는 "온보딩의 프로필 설정을 먼저 완료한 뒤 방에 참여"까지만 말한다.
  → **A**: **온보딩을 그대로 태운다.** 저장 후 FR-008과 같이 공동방 생성 스텝으로 이어지고, 초대받은 방 참여는 온보딩이 끝난 뒤 처리한다. 이 경로를 위한 별도 분기를 두지 않는다. (§4 가정, §3.2 비목표 반영)
- **Q**: 프로필만 저장하고 온보딩을 끝내기 전에 앱을 종료했다가 다시 실행하면 프로필 설정 화면을 다시 보여주는가?
  → **A**: **이 스펙의 범위 밖으로 둔다.** 재실행 시의 진입 화면은 스플래시·온보딩 스펙이 정하며, 이 문서는 프로필이 없는 앱 설치에서의 온보딩 진입만 다룬다. (§3.2 비목표 반영)
