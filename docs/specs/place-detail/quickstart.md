**대상 스펙 경로**: `docs/specs/place-detail`

**계획서**: [plan.md](./plan.md)

구현이 엔드투엔드로 동작함을 증명하는 절차. 계약과 데이터 형태는 [contracts/](./contracts/)·[data-model.md](./data-model.md)를 참조하고 여기서 되풀이하지 않는다.

## 1. 선행 조건

| 항목 | 내용 |

## 2. 실행

### 2.1 빌드

```sh
./gradlew :app:assembleQaDebug
```

헌법이 정한 빌드 확인의 최소선이다([constitution.md](../../constitution.md) 「개발 워크플로와 품질 게이트」). 로컬 `lintDebug`는 JBR 이슈로 데몬이 죽을 수 있고, 그 경우 `-XX:-TieredCompilation`으로 회피한다.

### 2.2 화면 단독 실행

진입형 Activity라 `adb`로 직접 띄울 수 있다. `pinId`는 서버에서 하나 확보한다.

```sh
# 방 목록에서 roomId 하나 → 그 방의 핀 목록에서 pinId 하나
adb shell am start -n com.mino.gguk.qa/team.mino.feature.placedetail.PlaceDetailActivity \
  --es place_detail_pin_id "<pinId>"
```

컴포넌트 이름은 `<applicationId>/<Activity의 정규화된 클래스 이름>`이다. 클래스 이름의 `team.mino…`는 패키지이지 applicationId가 아니므로 그 자리에 쓰지 않는다.

> **applicationId는 `com.mino.gguk`이고 `qa` 플레이버가 `.qa`를 붙인다**(`build-logic`의 `ProductFlavors.kt`). 위 절차가 쓰는 `assembleQaDebug` 산출물은 `com.mino.gguk.qa`이고, `prod` 빌드라면 `com.mino.gguk`이다. debug 빌드 타입에는 접미사가 없다. 확실치 않으면 `adb shell pm list packages | grep gguk`로 확인한다.

### 2.3 Compose Preview

`PlaceDetailScreenPreview`로 상태별 렌더링을 코드 실행 없이 본다 — 로딩(`place == null`), 이미지 0장, 코멘트 0건, 코멘트 다수, 축소형 헤더, 원문 링크 없음.

## 3. 검증 시나리오

spec의 테스트 시나리오와 1:1로 대응한다. **유저 플로우 7(TS-042~TS-049)은 이번 범위가 아니다**([research.md D10](./research.md)).

### 3.1 진입과 `Half` (유저 플로우 1)

| 확인 | 기대 | spec |
|---|---|---|
| 시트가 올라온 높이 | 369dp 고정. 장소명·이미지 장수·코멘트 수를 바꿔도 변하지 않는다 | TS-001 · SC-002 |
| 마커 | 선택 핀 형태, 색은 그 방의 대표 색상 | TS-002 |
| 헤더 | 등록자 아바타 · 라벨 · [나가기]가 한 줄, 그 아래 장소명·주소 각 한 줄 | TS-003 |
| 긴 장소명·주소 | 한 줄 유지 + `...` 생략, 시트 높이 불변 | TS-004 |
| 액션 버튼 | 3종이 한 행, 가로 스크롤로 `다른방에 공유` 전체 노출 | TS-005 |
| 라벨 | `가볼 만한 곳` — **서버가 값을 주지 않아 항상 기본값이다**([research.md D12](./research.md)) | TS-009 |
| 저장 경과일·카테고리 | 화면 어디에도 없다 | TS-008 |
| 바텀 네비게이션 | 보이지 않는다 — 진입형이라 애초에 그려지지 않는다 | TS-010 |
| [저장된 방] 버튼 | **항상 비활성**(이번 범위 보류). 중복 저장 장소에서도 비활성인 것이 spec과 어긋난 상태다 | TS-040 부분 |
| 지도 위 버튼 행 | [현재 위치]와 그 왼쪽 [저장된 방]이 우측 하단에 놓이고 `Full`로 올리면 함께 사라진다. **[현재 위치]는 눌러도 아무 일이 없다**([research.md D16](./research.md)) | FR-023 |

**「경과일 초기화 확인」 확인 방법**(TS-038·TS-039): 화면 진입 시 `POST /api/v1/pins/{pinId}/accesses`가 1회 나가는지 네트워크 로그로 본다. 비행기 모드로 진입해 **실패해도 화면이 정상적으로 그려지는지** 함께 확인한다(EC-022).

### 3.2 `Full` 승격과 헤더 전환 (유저 플로우 2)

| 확인 | 기대 | spec |
|---|---|---|
| 위로 드래그 | `Full`로 승격, `친구들의 코멘트`가 화면에 들어온다 | TS-011 |
| 아래로 스크롤 | 축소형 헤더(장소명 + [나가기])가 상단 고정 | TS-012 |
| 최상단 복귀 | 확장형으로 되돌아온다 | TS-013 |
| 아래로 드래그 | `Half`(369dp)로 내려가고 지도가 보인다 | TS-014 |
| 조금만 드래그 | `Peek`으로 머물지 않는다 — `Half` 유지 또는 닫힘 | TS-015 |
| 짧은 콘텐츠 | 이미지 0장 + 코멘트 0건이면 스크롤이 없어 확장형 유지 | EC-007 |

### 3.3 캐러셀 (유저 플로우 3)

이미지 3장 장소로 TS-016·TS-017, 1장으로 EC-008, 0장으로 EC-009(캐러셀 영역 자체가 없고 코멘트가 바로 이어짐)를 본다.

### 3.4 코멘트 (유저 플로우 4)

| 확인 | 기대 | spec |
|---|---|---|
| 카운터 | 12자 입력 → `12/200` | TS-020 |
| 200자 도달 | 더 입력해도 `200/200` 고정 | EC-011 |
| [등록] 활성 | 빈 입력·공백만이면 비활성, 1자 이상이면 활성 | TS-022 · EC-012 |
| 등록 | 목록 맨 아래에 추가되고 입력창·카운터 초기화, 추가 스크롤 없이 보인다 | TS-023 · UX-007 |
| 빈 상태 | 캐릭터 일러스트 + `아직 코멘트가 없어요!` | TS-019 |
| 내 코멘트 | 우측 [⋮] → `댓글 삭제` → 확인 절차 없이 즉시 사라짐 | TS-025 |
| 남의 코멘트 | [⋮]가 없다 — 서버 `canDelete`가 근거 | TS-026 |
| 마지막 삭제 | 빈 상태로 전환 | EC-014 |
| 긴 코멘트 | 200자 코멘트가 잘리지 않고 전문 노출 | TS-027 |

**역방향 페이징 확인**(D11): 코멘트가 서버 기본 페이지 크기(20건)를 넘는 장소에서, 위로 스크롤할 때 **더 오래된** 코멘트가 목록 **앞에** 붙는지 본다. 전체 나열 순서는 오래된 것이 위여야 한다(FR-010).

**방 소속 확인**(TS-024): 같은 장소가 A·B방에 있고 A방에만 코멘트가 있을 때, B방의 `pinId`로 열면 빈 상태여야 한다. 핀이 방마다 다르므로 자연히 성립한다([research.md D4](./research.md)).

### 3.5 외부 연동 (유저 플로우 5)

| 확인 | 기대 | spec |
|---|---|---|
| [장소보기] | 외부 지도 앱이 그 장소로 열린다 | TS-028 |
| 지도 앱 미설치 | 브라우저로 대체 — 아무 반응 없이 끝나지 않는다 | TS-029 · SC-004 |
| [원문보기] | 원문 링크가 외부 앱·브라우저로 열린다 | TS-030 |
| 원문 링크 없음 | [원문보기]가 비활성 | EC-017 |
| 복귀 | `Full` 상태·스크롤 위치·캐러셀 페이지·입력 중이던 코멘트가 그대로 | TS-031 · UX-009 |

### 3.6 다른 방에 공유 (유저 플로우 6)

| 확인 | 기대 | spec |
|---|---|---|
| 시트 호출 | 방 선택 시트가 뜨고 상단에 장소 썸네일·이름·주소 | TS-032 |
| 공유 | 토스트 후 대상 방으로 이동하지 않고 장소 상세 유지 | TS-033 |
| 이미 저장된 방 | **이번 라운드에서는 확인할 수 없다** — 방 목록은 실제 `getRooms()`로 받지만 `hasPlace`가 없어 체크·비활성 표시가 붙지 않는다([research.md D15](./research.md)). T061·T062 이후 확인 | FR-018 |
| 모든 방에 저장됨 | 카드 전부 체크·비활성, [공유하기]도 비활성. 안내 문구 없음 | TS-034 · EC-019 |

시트의 시각 표현·높이는 [SYS-003] 소관으로 `[TBD]`다([research.md D13](./research.md)) — 이 절은 **동작**만 검증한다.
