## 발견된 문제

### 검증 (2026-08-28, spec 2.4.0 — 앱 실행 상태와 공유 수신)

최종 미통과 항목 없음. `[TBD]` 잔여 0건이다. 검증 과정에서 1건이 실패했고 이번 개정 안에서 해소했다(아래 「검증 중 해소」).

**개정의 계기**

구현된 시트를 실기기에서 확인하던 중, **꾹이 이미 실행 중일 때 공유하면 꾹의 화면이 전면으로 올라온 뒤 그 위에 시트가 뜨는** 동작이 드러났다. spec을 되짚어 보니 §4 가정에 *"이 시트는 앱이 이미 실행 중이든 아니든 같은 모습으로 뜨며, 사용자가 보고 있던 꾹의 화면 상태에 영향을 주지 않는다"* 가 **이미 있었으나, 요구사항(FR)으로도 테스트 시나리오(TS)로도 내려오지 않은 채 가정에만 머물러 있었다.**

그 결과 하위 산출물 전체가 같은 구멍을 물려받았다.

- `contracts/share-intent.md` §1 — Activity 속성 표에 태스크 소속을 정하는 속성이 없다
- 구현 — 앱의 기존 태스크에 얹히는 상태로 만들어졌다
- `quickstart.md` §4 — 진입 검증 절차가 모두 앱을 완전히 종료시킨 뒤 재현하도록 짜여 있어, 실행 중 상태를 한 번도 밟지 않는다

**가정은 요구사항이 아니다.** 가정에만 적힌 사실은 검증 대상이 되지 않아 구현·계약·검증 어디에서도 걸리지 않는다는 것이 이번 개정의 교훈이다.

**갱신됨**

- **헤더** — 버전 2.3.1 → **2.4.0**(MINOR), 최종 수정일 2026-08-28. 기준 PRD 버전은 **6.0.0으로 변동 없다**(이번 실행에서 `business-context.md` 재확인, 어긋남 0건). 개정 입력을 **입력** 항목에 덧붙였다.
- **FR-003** — 기존 문장("앱의 다른 화면으로 전환하지 않는다")을 유지한 채, *"꾹이 이미 실행 중이어서 앱의 화면이 뒤에 남아 있는 경우에도 그 화면을 전면으로 끌어올리지 않으며, 시트 뒤에는 공유를 시작한 외부 앱이 그대로 보인다"* 를 덧붙였다. **요구사항의 경계를 넓힌 것이 아니라 §4 가정이 이미 정해 둔 범위를 요구사항 문장 안으로 끌어올린 것**이므로 MINOR로 다뤘다.
- **유저 플로우 1, 1단계** — *"앱이 꺼져 있었더라도 스플래시를 거치지 않고, 앱이 켜져 있었더라도 꾹의 화면이 앞으로 나오지 않으며"* 로 서술을 양쪽 상태에 대해 대칭으로 맞췄다. 종전에는 꺼져 있는 경우만 언급했다.
- **§4 가정** — 해당 문장에 `(FR-003·TS-027·TS-028)` 참조를 달고, 2.3.1까지 이 문장이 검증 근거를 갖지 못했던 사실을 명시했다.

**추가됨**

- **TS-027** 앱이 실행 중일 때의 공유 수신 (FR-003, UX-001) — 백그라운드의 꾹 화면이 전면으로 나오지 않고 외부 앱 위에 시트만 얹히는가
- **TS-028** 앱이 실행 중일 때의 저장 후 복귀 (FR-011) — 저장 후 백그라운드의 꾹 화면이 아니라 공유를 시작한 외부 앱으로 돌아가는가
- **EC-013** 시트가 떠 있는 동안 또 다른 공유가 들어온다 (FR-003, FR-012) — 아래 「검증 중 해소」 참조

**검증 중 해소 — 「엣지 케이스가 식별되어 있다」 1차 미통과**

이번 개정이 연 영역(앱의 실행·태스크 상태)을 기준으로 EC 목록을 다시 훑자, **시트가 떠 있는 동안 또 다른 공유가 들어오는 경우**가 어디에도 정의되어 있지 않았다. 그럼에도 `contracts/share-intent.md` §1은 *"공유가 연달아 들어와도 시트가 겹치지 않는다"* 를 이미 결론으로 적고 있었다 — **spec에 근거가 없는 결정을 계약이 혼자 내리고 있던 상태**로, 헌법 I(단일 출처)에 어긋나며 이번에 놓친 것과 같은 모양의 구멍이다. EC-013을 신설해 판단의 출처를 spec으로 되돌렸고, 결론은 계약이 적어둔 것과 같아 **구현 변경을 유발하지 않는다.**

- 번호는 EC-012가 아니라 **EC-013**을 썼다. EC-012는 2.3.0에서 철회된 번호이며 §5 Q7이 그 번호를 철회된 의미로 참조하고 있어 재사용할 수 없다(아래 「비고」).

**FR ↔ TS 커버리지 재확인**

- FR-001~FR-017·FR-019 **18개 전 항목**이 하나 이상의 TS로 연결된다. 미연결 0건.
- TS 25건 → **27건**, EC 9건 → **10건**. UX 11건·SC 6건은 2.3.1과 같다. 이번 개정에서 철회·삭제된 항목은 없다.

### 후속 확인 필요 (spec 외부)

이번 개정에서 새로 생긴 것 —

- **`contracts/share-intent.md` §1** — Activity 속성 표에 **태스크 소속을 정하는 속성이 빠져 있다.** FR-003의 보강된 문장과 TS-027·TS-028이 이 속성 없이는 성립하지 않는다. `launchMode`의 근거 문구도 태스크 분리를 전제로 다시 써야 한다.
- **`quickstart.md` §4** — 진입 검증 절차가 전부 앱을 완전히 종료시킨 뒤 재현하도록 짜여 있다. TS-027·TS-028을 밟는 절차(앱을 띄워둔 채 공유)가 없다.
- **`tasks.md`** — 매니페스트를 작성한 작업이 완료 표시된 상태이므로, 위 두 문서와 구현을 함께 고치는 후속 작업 항목이 필요하다. 실기기 검증 작업(T056)이 TS-027·TS-028을 포함하도록 갱신해야 한다.

2.3.1에서 이월된 것 (이번 실행에서 해소되지 않았다) —

- **PRD 내부 불일치**: `business-context.md`의 「장소」 중복 규칙(§1 데이터 및 도메인 용어)에 *"「방 선택 시트」는 미정이다"* 가 남아 있으나, 같은 문서의 「방 선택 시트」 정의와 §5 확정 항목은 [SYS-002] 전면 선택 가능 / [SYS-003]·[SCR-003] 체크·비활성으로 **이미 확정**했다. 5.0.0부터 이어진 잔존 문장이며, 이 spec은 상세 정의 쪽을 근거로 삼는다(FR-016). PRD 개정 시 정리가 필요하다.
- **디자인**: Figma `013-1` 주석 ③의 제목이 여전히 `'공유하기' 버튼 클릭`이다. 시안의 실제 버튼과 PRD 「방 선택 시트」 CTA 문구는 [SYS-002]에 대해 `저장하기`로 확정되어 있으므로(spec §5 Q1) 주석 제목 갱신이 필요하다.
- **디자인**: 방 0개 상태(FR-013)의 시트 화면이 Figma `013-1`에 없다. 안내 문구와 시각 표현이 디자인 확정 대상으로 남아 있으며, spec은 §4 가정으로 그 경계를 표시해 두었다.
- **[SCR-001] 스플래시 spec**: PRD 6.0.0 Flow E의 "세션 확보 전에는 어느 화면으로도 들여보내지 않는다"가 **외부 공유 수신에는 적용되지 않는다**는 이 spec의 FR-019·§5 Q6 결정과 대조해, 스플래시 spec 작성 시 양쪽 서술이 어긋나지 않는지 확인해야 한다.
