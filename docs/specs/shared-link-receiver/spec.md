## 1. 유저 시나리오 (User Scenarios) *(필수)*
### 유저 플로우 1 - 외부 앱에서 공유한 게시물을 방에 저장한다
인스타그램 등 외부 앱에서 게시물을 공유해 꾹을 선택하면, 앱 화면으로 완전히 전환되지 않은 채 방 선택 바텀시트만 떠오른다. 사용자는 저장할 방을 고르고 저장한 뒤 곧바로 원래 앱으로 돌아간다. 꾹에서 장소를 추가하는 유일한 정식 경로다.

**Figma**: [013-1-1 외부 공유 시 바텀시트_peek](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176010) · [013-1-2 full_4개](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176059) · [013-1-3 full_4개 이상](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176034) · [013-2 방 선택 완료 후 저장 피드백](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-173819)

**진입 조건**: 온보딩을 마쳐 개인방(`내 장소`)을 보유한 사용자가, 인스타그램 등 외부 앱의 게시물에서 [공유]를 눌러 OS 공유 시트를 연 상태.

1. OS 공유 시트에서 `꾹`을 선택한다 → 딤 처리된 배경 위로 방 선택 바텀시트가 `Peek` 단계로 곧바로 떠오른다. 앱이 꺼져 있었더라도 스플래시를 거치지 않으며, 링크 분석도 아직 하지 않는다.
2. 시트 헤더(`게시물 저장` / `장소를 저장할 방을 선택해주세요.`) 아래의 방 카드 목록을 확인한다 → 개인방과 공동방 전체가 카드로 표시된다.
3. 저장할 방의 카드를 눌러 체크한다(복수 선택 가능) → 선택된 카드의 체크박스가 채워지고, 하나 이상 선택된 시점에 하단 [저장하기]가 활성화된다.
4. [저장하기]를 누른다 → 선택한 모든 방에 대한 저장 요청이 접수되고 시트가 닫힌다. 링크 분석과 저장은 이 시점 이후에 이뤄진다.
5. 저장 결과를 확인한다 → `저장이 완료됐습니다.` 토스트가 화면 하단에 표출되고, 토스트가 사라지면 꾹은 화면에서 물러나 사용자는 공유를 시작한 외부 앱으로 돌아간다.

**완료 조건**: 사용자가 선택한 모든 방에 대한 저장 요청이 접수되었고, 시트가 닫혔으며, 사용자가 공유를 시작한 외부 앱으로 복귀해 있다.

### 유저 플로우 2 - 시트를 끌어올려 방을 훑고 고른다
방이 많은 사용자는 `Peek` 상태에서 보이는 카드만으로는 원하는 방을 찾을 수 없다. 시트를 위로 끌어올려 목록 전체를 펼치고 스크롤해 방을 고른다.

**Figma**: [013-1-1 외부 공유 시 바텀시트_peek](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176010) · [013-1-2 full_4개](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176059) · [013-1-3 full_4개 이상](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-176034)

**진입 조건**: 방 선택 시트가 `Peek` 단계로 표출되어 있고, 보유한 방이 3개를 넘는다.

1. 시트 상단의 핸들 또는 시트 영역을 위로 드래그한다 → 시트가 `Full` 단계로 승격되어 방 카드가 더 많이 보인다.
2. 방 목록을 위아래로 스크롤한다 → 목록만 스크롤되고 헤더와 하단 [저장하기] 영역은 자리에 고정된다.
3. 목록 아래쪽의 방을 체크한다 → 체크박스가 채워지고 [저장하기]가 활성화된다.
4. 체크했던 방을 다시 눌러 해제한다 → 선택 개수가 줄고, 선택이 0개가 되면 [저장하기]가 비활성으로 돌아간다.
5. 시트를 아래로 드래그한다 → 시트가 `Peek` 단계로 되돌아가고, 이미 고른 방의 선택 상태는 유지된다.

**완료 조건**: 사용자가 보유한 모든 방을 목록에서 확인할 수 있었고, 저장 대상으로 고른 방들이 선택된 상태로 남아 있다.

### 유저 플로우 3 - 저장에 실패한 사실을 알림함에서 확인한다
링크 분석과 저장은 [저장하기] 이후에 이뤄지므로, 결과는 사용자가 이미 외부 앱으로 돌아간 뒤에 확정된다. 사용자를 공유 흐름에 붙잡아 두는 대신, 실패·중복 사실은 알림함에서 뒤늦게 확인하게 한다.

**Figma**: [002-1 홈_다른 방 저장 클릭 후 중복 저장 시](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2862-175522) · [013-2 방 선택 완료 후 저장 피드백](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-173819)

**진입 조건**: 사용자가 방을 선택하고 [저장하기]를 눌러 시트가 닫힌 뒤, 저장이 정상 완료되지 못한 상태.

1. 저장 완료 토스트를 보고 외부 앱으로 돌아간다 → 꾹은 백그라운드에서 저장 결과를 확정한다.
2. 나중에 꾹을 열어 알림 탭에 들어간다 → 저장하지 못한 건에 대한 알림이 시간순 목록에 쌓여 있다.
3. 실패 알림(`장소를 저장하지 못했어요.`) 또는 중복 알림(`이미 저장해둔 곳이에요`)을 확인한다 → 어떤 공유가 왜 저장되지 않았는지 알 수 있다.

**완료 조건**: 저장되지 않은 모든 건에 대해 알림함에 사유를 담은 알림이 하나씩 남아 있다.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 외부 앱이 링크·텍스트를 공유할 때 OS 공유 시트의 공유 대상 목록에 꾹을 노출하고, 선택되면 공유된 데이터를 넘겨받는다. (근거: PRD 6.0.0 [SYS-002] Flow A / Figma `013-1` 설명 "인스타그램에서 외부 공유 클릭 > gguk 앱 선택 시 장소를 저장하고자하는 방을 선택할 수 있는 화면")
- **FR-002**: 시스템은 반드시 공유받은 데이터에서 URL을 추출하며, URL이 여러 개면 가장 앞에 등장하는 하나만 저장 대상으로 삼는다. (근거: PRD 6.0.0 [SYS-002] Flow A 「URL 추출 규칙」 — "여러 개면 첫 번째 것만")
- **FR-003**: 시스템은 반드시 공유 수신 시 앱의 다른 화면으로 전환하지 않고, 딤 처리된 배경 위에 방 선택 바텀시트만 표출한다. (근거: Figma `013-1-1`~`013-1-3` — 시트 뒤에 앱 화면 없이 딤 배경만 존재)
- **FR-004**: 시스템은 반드시 시트 헤더에 제목 `게시물 저장`과 안내 문구 `장소를 저장할 방을 선택해주세요.`를 노출한다. (근거: Figma `013-1-1` 헤더 / PRD 6.0.0 [SYS-002] Flow A)
- **FR-005**: 시스템은 반드시 사용자가 속한 개인방과 공동방 전체를 카드 목록으로 노출하고, 개인방(`내 장소`)을 목록 최상단에 고정한다. (근거: Figma `013-1` 주석 ②·PRD 6.0.0 [SYS-002] Flow A "개인방 + 공동방 전체 목록")
- **FR-006**: 시스템은 반드시 각 방 카드에 방 썸네일, 방 이름, 방 설명(공동방에 한함), 그 방에 저장된 장소 수, 선택용 체크박스를 노출한다. (근거: PRD 6.0.0 「방 선택 시트」 방 카드 구성 — 멤버 아바타는 넣지 않는다 / Figma `013-1-2`·`013-1-3` 방 카드)
- **FR-007**: 시스템은 반드시 방 카드를 체크박스로 복수 선택·해제할 수 있게 하고, 시트 단계 전환과 목록 스크롤 후에도 선택 상태를 유지한다. (근거: Figma `013-1` 주석 ② "체크박스를 활용하여 원하는 방을 복수 선택/비선택할 수 있다")
- **FR-008**: 시스템은 반드시 시트 높이를 하단 액션 영역을 포함한 고정값 2단계로 유지하며, 보유한 방 개수와 무관하게 같은 단계 구성을 쓴다 — `Peek` 436dp(카드 2개 온전 + 3번째 잘림), `Full` 612dp(방 4개), `Full` 644dp(방 5개 이상, 5번째 카드 잘림). 방 개수가 시트에 담기는 양을 넘으면 시트 높이는 그대로 두고 방 목록만 세로로 스크롤한다. (근거: Figma `013-1` 주석 ① / PRD 6.0.0 「방 선택 시트」 높이 정의 — "방 개수가 적어도 단계 구성은 같다")
- **FR-009**: 시스템은 반드시 방이 하나도 선택되지 않은 동안 하단 [저장하기] 버튼을 비활성 상태로 두고, 하나 이상 선택된 시점에 활성화한다. (근거: Figma `013-1` 주석 ③ "장소 카드를 하나라도 선택 시 활성화된다")
- **FR-010**: 시스템은 반드시 하단 버튼의 문구를 `저장하기`로 노출하고, 이 버튼이 눌리면 선택된 모든 방에 같은 장소를 저장한 뒤 시트를 닫고 `저장이 완료됐습니다.` 토스트를 표출한다. (근거: PRD 6.0.0 「방 선택 시트」 CTA 문구 — [SYS-002]는 `저장하기` / Figma `013-1-2`·`013-1-3` 하단 버튼·`013-2` 저장 완료 Toast / §5 Q1)
- **FR-011**: 시스템은 반드시 저장 완료 토스트가 사라지면 꾹의 화면을 남기지 않고 물러나, 공유를 시작한 외부 앱으로 사용자를 되돌린다. (근거: PRD 6.0.0 [SYS-002] Flow A — "시트가 닫히며 직전에 쓰던 외부 앱으로 돌아간다" / Figma `013-2`)
- **FR-012**: 시스템은 반드시 사용자가 시트를 닫으면(뒤로가기·딤 영역 탭·아래로 드래그) 아무 방에도 저장하지 않고 종료한다. (근거: PRD 6.0.0 「방 선택 시트」 — 저장은 [저장하기] 클릭으로만 실행된다)
- **FR-013**: 시스템은 반드시 저장할 방이 하나도 없는 사용자가 공유를 보냈을 때도 다른 경우와 같은 방 선택 바텀시트를 표출하되, 방 카드 목록 자리에 저장할 방이 없다는 안내를 노출하고 [저장하기]를 비활성 상태로 유지한다. 온보딩을 비롯한 다른 화면으로 전환하지 않고, 공유받은 링크를 보관해 두었다가 나중에 저장하지도 않는다. (근거: PRD 6.0.0 [SCR-002] Flow A — 개인방은 프로필 설정 완료 시 자동 생성되므로, 앱을 설치하고 한 번도 실행하지 않은 사용자는 개인방조차 없는 상태로 공유를 보낼 수 있다 / §5 Q3)
- **FR-014**: 시스템은 반드시 링크 분석 또는 저장이 실패하면 그 방에 장소를 저장하지 않고, 알림함에 `장소를 저장하지 못했어요.` 오류 알림을 남긴다. (근거: PRD 6.0.0 [SYS-002] Flow B)
- **FR-015**: 시스템은 반드시 선택된 방에 같은 장소가 이미 저장되어 있으면 중복 저장하지 않고, 알림함에 `이미 저장해둔 곳이에요` 중복 저장 알림을 남긴다. (근거: PRD 6.0.0 [SYS-002] Flow B / Figma `002-1` 주석 ④ "알림함에서 중복 저장 알림")
- **FR-016**: 시스템은 반드시 이미 그 장소가 저장되어 있는 방의 카드도 다른 방과 구분 없이 선택 가능한 상태로 노출하며, 시트 안에서는 중복 여부를 표시하지도 선택을 막지도 않는다. 중복 저장이 성립하지 않고 알림함에 중복 알림이 남는 것(FR-015)은 저장 실행 이후에 전달된다. (근거: PRD 6.0.0 「방 선택 시트」 '이미 저장된 방' — 진입점별로 갈라 [SYS-002] 외부 공유 수신은 전면 선택 가능으로 확정 / PRD 6.0.0 [SYS-002] Flow A — "이미 저장되어 있는 방도 가려내지 않고 전면 선택 가능하게 둔다" / Figma `013-1` 주석 ② — 체크·비활성 문장이 삭제되어 전면 선택 가능과 일치 / FR-017 — 시트를 그리는 시점에는 링크 분석 전이라 중복을 판정할 수 없다 / §5 Q5)
- **FR-017**: 시스템은 반드시 공유받은 링크의 분석을 [저장하기] 실행 이후에 수행한다 — 시트는 분석 결과를 기다리지 않고 곧바로 표출되며, 분석 결과에 따른 성공·중복·실패는 FR-014·FR-015의 알림으로 전달된다. (근거: PRD 6.0.0 [SYS-002] Flow A — "링크 분석은 시트를 그리기 전이 아니라 [저장하기] 이후에 돈다" / §5 Q2)
- **FR-019**: 시스템은 반드시 외부 공유 수신으로 앱이 시작될 때 스플래시를 거치지 않고, 저장된 익명 세션을 네트워크 요청 없이 로컬에서 복원한 뒤 시트를 표출한다. 복원할 세션이 없으면 세션을 새로 확보하지 않고 FR-013의 경로로 넘긴다. (근거: PRD 6.0.0 「비회원 익명 세션」 — 세션은 앱 설치에 묶이고 설치가 살아 있는 동안 만료되지 않는다 / [SCR-001] Flow A — "재실행은 저장된 세션을 네트워크 없이 복원"하며 최초 확보는 스플래시가 맡는다 / [SCR-001] Flow E의 화면 진입 차단은 스플래시를 거치는 앱 실행 경로의 규칙이며, 스플래시를 거치지 않는 이 진입점에는 적용되지 않는다 / §5 Q6)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 시트가 떠 있는 동안 배경은 딤 처리되고 앱의 다른 화면은 노출되지 않는다 — 사용자는 공유 흐름 안에 있다는 사실을 잃지 않는다. (근거: Figma `013-1-1`~`013-1-3`)
- **UX-002**: 비활성 [저장하기]는 눌러도 아무 반응이 없으며, 활성 상태와 시각적으로 구분된다. (근거: Figma `013-1-2`(비활성)·`013-1-3`(활성) 하단 버튼)
- **UX-003**: 방 카드의 선택·비선택 상태는 체크박스로 구분되며, 카드 영역 어디를 눌러도 선택이 토글된다. (근거: Figma `013-1-3` 방 카드 체크박스)
- **UX-004**: 방 목록을 스크롤하는 동안 헤더와 하단 액션 영역은 자리에 고정되어, 어느 위치에서도 [저장하기]에 바로 닿을 수 있다. (근거: Figma `013-1-3` — 헤더·액션 영역이 목록 밖에 있다)
- **UX-005**: 방이 시트에 다 담기지 않을 때는 마지막에 보이는 카드가 잘린 채 노출되어 더 스크롤할 수 있음을 알린다. (근거: Figma `013-1` 주석 ① "스크롤 어포던스를 위해 5번째 카드는 짤리게 보여진다")
- **UX-006**: 저장 완료 토스트는 체크 아이콘과 함께 화면 하단에서 40dp 띄운 위치에 표출되고, 사용자의 추가 조작 없이 사라진다. (근거: PRD 6.0.0 [SYS-002] Flow A — `저장이 완료됐습니다.` + 체크 아이콘 + 하단 40dp / Figma `013-2` Snackbar 배치)
- **UX-007**: 저장 실패·중복은 공유 흐름을 멈춰 세우지 않는다 — 시트 안에서 오류를 묻지 않고 알림함에 사유를 남겨, 사용자는 저장 조작을 끝내고 외부 앱으로 돌아간다. (근거: PRD 6.0.0 [SYS-002] Flow B)
- **UX-008**: 저장 조작은 방 선택과 [저장하기] 클릭 두 종류뿐이며, 시트 안에서 방을 새로 만들거나 장소 정보를 편집하는 경로는 제공하지 않는다. (근거: Figma `013-1-1`~`013-1-3` — 시트에 다른 조작 요소가 없다)
- **UX-009**: 시트 표출과 [저장하기] 클릭 사이에 로딩·대기 표현을 두지 않는다 — 링크 분석을 기다리지 않으므로 사용자는 진입 즉시 방을 고를 수 있다. (근거: §5 Q2 / Figma `013-1-1`~`013-1-3`에 대기 상태 화면이 없다)
- **UX-010**: 외부 공유 진입에는 브랜드 스플래시도, 세션 확보를 위한 대기도 끼어들지 않는다 — 사용자는 OS 공유 시트에서 꾹을 고른 직후 방 선택 시트를 만난다. (근거: PRD 6.0.0 [SCR-001] Flow A — 3초 브랜드 노출은 앱 실행 경로의 것이다 / §5 Q6)
- **UX-011**: 저장할 방이 없는 사용자도 다른 사용자와 같은 시트를 만나며, 공유 흐름 한가운데에서 온보딩 같은 다른 화면으로 끌려가지 않는다 — 지금은 저장할 수 없다는 사실만 시트 안에서 전달받고 스스로 시트를 닫는다. (근거: §5 Q3)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **공유 링크 (Shared Link)**: 외부 앱이 넘겨준 원문 URL. 장소로 변환되는 입력이자, 저장된 장소의 `원문 링크`로 함께 보관된다.
- **장소 (Place)**: 공유 링크 분석으로 만들어진 결과물. 장소명·주소·좌표·카테고리·대표 이미지·등록자·원문 링크를 가지며, 방에 담겨야 비로소 사용자에게 보인다.
- **방 (Room)**: 장소를 담는 단위. 개인방과 공동방으로 나뉘며, 이 시트에서는 썸네일·이름·설명·저장된 장소 수·해당 장소의 저장 여부가 쓰인다.
- **저장 선택 (Save Selection)**: 한 번의 공유에서 사용자가 고른 방들의 집합. 저장 실행의 단위이며, 방마다 성공·중복·실패 중 하나의 결과를 가진다.
- **익명 세션 (Anonymous Session)**: 회원가입 없이 이용자를 구분하는 근거이며 앱 설치에 묶인다. 설치가 살아 있는 동안 만료되지 않는다. 이 시트는 이미 확보된 세션을 로컬에서 복원해 "누가·어느 방에 저장하는가"를 정할 뿐, 세션을 새로 발급하지도 무효 세션을 재발급하지도 않는다.
- **알림 (Notification)**: 저장이 성립하지 않은 건에 대해 사후에 사유를 전달하는 기록. 중복 저장 알림과 저장 오류 알림 두 종류가 이 기능에서 발생한다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: OS 공유 시트에서 꾹을 선택한 뒤 방 선택 시트가 조작 가능한 상태로 보이기까지 1초 이내다.
- **SC-002**: 시트 표출부터 저장 완료까지 필요한 조작이 방 선택 1회 + [저장하기] 1회, 총 2회를 넘지 않는다(방이 `Peek`에 보이는 경우).
- **SC-003**: 저장을 시도한 사용자의 90% 이상이 첫 시도에 원하는 방 전부에 장소를 저장한다.
- **SC-004**: 저장이 성립하지 않은 건의 100%에 대해 알림함에 사유 알림이 남아, 사용자가 "저장했는데 목록에 없다"를 스스로 확인할 수 있다.
- **SC-005**: 저장 완료 후 사용자가 외부 앱으로 돌아가기 위해 추가로 해야 하는 조작이 0회다.
- **SC-006**: 방을 5개 이상 보유한 사용자도 시트 안에서 자기 방 전체를 확인할 수 있다(목록에서 누락되는 방 0개).

### 3.2 비목표 항목 (Out of Scope)

- 공유 링크에서 장소를 뽑아내는 분석 규칙과 정확도(지원 도메인, 본문 파싱 기준, 한국 내 판정)는 서버가 정의한다.
- 알림함의 목록·상세·저장 실패 사유 안내 화면은 [SCR-007] 알림 탭 스펙이 정의한다. 이 문서는 어떤 알림이 발생하는지까지만 정의한다.
- [SYS-003] 다른 방에 공유 시트(`Full` 676dp 단일 고정, 대상 장소 카드 노출, 새 방 만들기 포함)는 같은 방 선택 규칙을 쓰지만 이 문서가 정의하지 않는다.
- [SCR-002] 온보딩의 공유 방법 튜토리얼에서 쓰이는 연습용 가상 화면은 이 문서가 정의하지 않는다.
- 방 생성·편집([SYS-001])과 방 썸네일 콜라주·멤버 아바타 구성 규칙은 PRD의 공통 정의를 따르며 이 문서가 재정의하지 않는다.
- 저장된 장소가 지도·홈 카드·방 상세에 어떻게 나타나는지는 각 화면 스펙이 정의한다.
- 앱 안에서 URL을 직접 입력해 장소를 추가하는 경로는 PRD 비목표이므로 다루지 않는다.
- 익명 세션의 최초 확보와 확보 실패 처리([SCR-001] Flow B~E — 로딩 스피너, 네트워크 오류·일시적 오류 토스트, 확보 전 화면 진입 차단)는 스플래시 스펙이 정의한다. 세션은 설치가 살아 있는 동안 만료되지 않아 무효화·재발급 규칙 자체가 없다(PRD 6.0.0). 이 문서는 이미 확보된 세션을 로컬에서 복원해 쓰는 데까지만 다룬다.
- [SCR-003] 홈 카드의 `다른 방 저장`이 쓰는 「홈 방 시트」(그리드형 400dp)는 이 문서가 정의하지 않는다. 링크 수신·분석이 없고 시트도 다르므로 [SYS-002]가 아니다.
- [SCR-006] 장소 상세의 [저장된 방]이 여는 「저장된 방 시트」(442dp)는 이 문서가 정의하지 않는다. 저장할 방을 고르는 시트가 아니라 이미 저장된 방으로 문맥을 옮기는 시트여서 체크박스도 CTA도 없다.

## 4. 가정 (Assumptions)

- 인스타그램은 대표 사례일 뿐이며, 링크를 텍스트로 공유하는 모든 외부 앱에 대해 동일하게 동작한다. 인스타그램 전용 예외 처리는 두지 않는다.
- Figma 주석에 `px`로 적힌 높이값(436/612/644)은 375 폭 디자인 프레임 기준의 `dp`로 읽는다. PRD 6.0.0 「방 선택 시트」도 같은 값을 dp로 기재하고 있다.
- 한 번의 공유로 저장되는 장소는 1개다. 공유 데이터에 URL이 여러 개 있어도 장소를 여러 개 만들지 않는다.
- 공유 데이터는 텍스트(URL 포함) 형태로 전달된다. 이미지·동영상 파일 자체가 공유된 경우는 URL 없음(EC-002)과 같게 다룬다.
- 온보딩(프로필 설정)을 마친 사용자는 개인방 `내 장소`를 자동으로 갖고 있으므로, 정상 사용자에게 방 목록이 비는 일은 없다. 방 0개(FR-013)는 앱을 설치하고 한 번도 실행하지 않았거나 온보딩 도중 이탈한 사용자에게만 나타나는 상태다.
- 중복·실패 알림 문구는 PRD 6.0.0 [SYS-002] Flow B의 표기(`이미 저장해둔 곳이에요` / `장소를 저장하지 못했어요.`)를 그대로 따른다.
- 방 목록에는 필터·정렬·검색을 두지 않는다. PRD와 디자인 어디에도 정렬 기준이 없으므로 앱이 방 리스트에서 쓰는 기본 순서(개인방 최상단 + 그 아래 공동방)를 그대로 쓴다.
- 저장은 선택한 방마다 독립적으로 성립한다. 한 방의 실패가 다른 방의 저장을 되돌리지 않는다(TS-019).
- 이 시트는 앱이 이미 실행 중이든 아니든 같은 모습으로 뜨며, 사용자가 보고 있던 꾹의 화면 상태에 영향을 주지 않는다.
- 방 카드는 체크박스뿐 아니라 카드 영역 전체가 선택 조작 대상이다. 디자인에 탭 영역 표기가 없어, 목록형 다중 선택의 일반적인 동작을 기본값으로 삼는다.
- `저장하기`를 누른 뒤 저장 결과가 확정되기 전에 사용자가 앱을 떠나도 저장 요청은 취소되지 않는다.
- 저장 완료 토스트는 저장 성공을 보장하는 표시가 아니라 "요청을 접수했다"는 피드백이다. 실제 성패는 알림함으로 전달된다(FR-014·FR-015).
- 방이 4개 미만일 때의 `Full` 높이는 612dp를 쓴다. PRD 6.0.0이 `Full` 값을 "방 4개 612dp / 방 5개 이상 644dp" 두 가지로만 적어, 5개 미만 구간을 612dp 하나로 묶은 것으로 읽는다.
- 익명 세션은 앱 설치에 묶여 재설치하면 복구되지 않는다(PRD 6.0.0 「비회원 익명 세션」). 따라서 재설치 직후의 공유 수신은 온보딩 미완료와 구분할 실익이 없어 같은 경로로 다룬다.
- 한 번 복원된 세션이 저장 실행 시점에 무효가 되는 경우는 다루지 않는다. PRD 6.0.0이 "설치가 살아 있는 동안 세션은 만료되지 않으며, 앱에 무효 세션을 감지해 재발급하는 경로를 두지 않는다"를 확정했으므로, 세션 자체를 사유로 한 저장 실패는 성립하지 않는다. 그 밖의 사유로 저장이 성립하지 않는 경우는 모두 FR-014의 오류 알림 경로를 쓴다.
- 외부 공유 수신은 PRD 6.0.0 [SCR-001] Flow E가 세운 "익명 세션은 항상 확보되어 있다"는 앱 전체 전제가 성립하지 않을 수 있는 유일한 진입점이다. 스플래시를 거치지 않으므로(FR-019·UX-010) 세션이 아직 없는 상태로 공유가 들어올 수 있고, 그때는 별도 경로를 만들지 않고 FR-013의 방 0개 처리로 수렴시킨다.
- 방 개수는 개인방을 포함한 총 방 수로 센다. 온보딩을 마친 사용자는 개인방을 갖고 있으므로 최솟값은 1개다.
- 방 0개 상태에서 노출하는 안내의 정확한 문구와 시각 표현은 디자인 확정 대상이다. 이 문서는 "저장할 방이 없어 지금은 저장할 수 없다"는 사실이 시트 안에서 전달되고 [저장하기]가 비활성이라는 데까지만 규정한다.
- 방 0개 상태의 시트에도 온보딩으로 이동하는 조작은 두지 않는다(UX-008). 사용자는 시트를 닫고 꾹을 직접 실행해 온보딩을 마친 뒤 다시 공유한다.
- 복원할 세션이 없어 방 목록을 조회할 수조차 없는 경우(EC-011)와 세션은 있으나 방이 0개인 경우를 사용자에게 구분해 보이지 않는다. 두 경우 모두 같은 안내를 노출한다.
- 시트 표출 시점에는 링크 분석 전이라 어느 방이 중복인지 알 수 없으므로(FR-017), 방 카드의 `저장된 장소 수`(FR-006)는 방 전체의 장소 수일 뿐 이번 공유의 중복 여부를 뜻하지 않는다.

### 해소된 항목

- **Q1. 하단 CTA 문구를 `저장하기`(디자인 시안)와 `공유하기`(PRD [SYS-002]·디자인 주석 ③) 중 어느 쪽으로 확정하는가?**
  → **A. `저장하기`.** 디자인 시안의 버튼 문구를 따르며, 헤더 `게시물 저장`·토스트 `저장이 완료됐습니다.`와 일관된다. PRD 4.1.0이 이를 반영해 [SYS-002]는 `저장하기` / [SYS-003]은 `공유하기`로 맥락별 분리를 확정했다. (반영: FR-010)
- **Q2. 공유받은 링크의 장소 분석은 시트 표출 전에 끝나는가, 저장 실행 이후에 이뤄지는가?**
  → **A. 저장 실행 이후.** 시트는 분석을 기다리지 않고 즉시 표출되며 대기 표현을 두지 않는다. PRD 4.1.0이 같은 결론으로 확정했다([SYS-002] Flow A). 그 귀결로 시트 표출 시점에는 중복 여부를 판정할 수 없어, "이미 저장된 방" 규칙은 Q5로 되돌아갔다. (반영: FR-017, UX-009, 유저 플로우 1·2·3)
- **Q3. 온보딩을 마치지 않아 저장할 방이 0개인 사용자가 외부 공유를 보내면 무엇을 보여주는가?** (① 온보딩으로 보내고 공유 폐기 / ② 온보딩 완료 후 시트로 이어붙임 / ③ 빈 목록 시트 + 저장 불가 안내)
  → **A. ③ 빈 목록 시트 + 저장 불가 안내.** 앱을 설치하고 한 번도 실행하지 않아 개인방조차 만들어지지 않은 사용자가 있을 수 있으므로, 이 상태를 예외 경로가 아니라 시트의 한 상태로 다룬다. 시트는 평소와 같이 표출하고 방 카드 자리에 저장할 방이 없다는 안내를 노출하며 [저장하기]는 비활성으로 둔다. 온보딩으로 화면을 전환하지 않아 FR-003(다른 화면으로 전환하지 않는다)과 UX-010(공유 진입에 다른 흐름을 끼우지 않는다)이 예외 없이 성립하고, 공유받은 링크를 보관하지 않아 상태 보존 부담도 생기지 않는다. 그 대가로 사용자는 시트를 닫고 꾹을 직접 실행해 온보딩을 마친 뒤 다시 공유해야 한다. 2.1.0에서 확인한 대로 재설치 직후(EC-011)와 세션 미복원(FR-019)도 같은 경로로 수렴한다. (반영: FR-013, UX-011, EC-004, EC-011, TS-024, TS-025)
- **Q4. 보유한 방이 3개 이하일 때 시트 높이를 어떻게 정하는가?** (① 카드 수만큼 축소하고 단계 전환 없음 / ② `Peek` 436dp 유지하고 남는 공간을 비움)
  → **A. 별도 구간을 두지 않는다.** 1.1.0에서 "`Peek` 436dp 한 단계 고정, 단계 전환 없음"(FR-018)으로 확정했으나, **PRD 4.1.0이 이를 반려**했다 — "방 개수와 무관하게 현행 2단을 유지한다. spec FR-018을 PRD 쪽으로 맞춘다." 2.0.0에서 FR-018·EC-010·TS-020·TS-021을 철회하고 FR-008을 원복했다. 방이 적으면 카드 아래 공간이 빌 뿐 단계 구성은 같다. (반영: FR-008, EC-005, TS-020, TS-021)
- **Q5. 이미 그 장소가 저장되어 있는 방의 카드를 시트에서 어떻게 보이는가?** (① 전면 선택 가능 + 사후 중복 알림 / ② 시트 표출과 별개로 중복 조회를 먼저 돌려 체크·비활성 표시)
  → **A. ① 전면 선택 가능 + 사후 중복 알림.** PRD 4.2.0 당시 「미확정 항목」의 (b)안에 해당하며, **PRD 5.0.0이 이를 그대로 확정했다** — [SYS-002]만 전면 선택 가능으로 열고, 이미 저장된 장소를 다뤄 시점상 중복을 알 수 있는 [SYS-003]·[SCR-003]은 체크·비활성을 유지한다. Q2에서 링크 분석을 [저장하기] 이후로 확정한 이상 시트를 그리는 시점에는 장소가 무엇인지조차 모르므로 중복 판정이 성립하지 않는다. ②(PRD (c)안)를 택하면 표출 전 분석·조회가 필요해져 SC-001·UX-009를 되돌리거나, 사용자가 이미 체크한 카드가 뒤늦게 비활성되는 상태가 생긴다. 중복 저장이 성립하지 않고 알림함에 중복 알림이 남는다는 결론(FR-015)은 어느 쪽이든 같다. (반영: FR-016, EC-006, TS-026)
  - **후속 해소(2.3.0)**: PRD 5.0.0이 이 항목을 「확정된 항목」으로 옮겨 「방 선택 시트」의 '이미 저장된 방'을 진입점별로 갈랐고([SYS-002] 전면 선택 가능 / [SYS-003]·[SCR-003] 체크·비활성), Figma `013-1` 주석 ②에서도 "이미 저장이 되어있는 방은 체크박스가 선택된 상태에서 비활성화 처리 되어있다"는 문장이 삭제되어 이 결정과 어긋나는 근거가 남지 않았다.
- **Q6. 외부 공유 수신이 앱을 콜드 스타트할 때 익명 세션을 어떻게 다루는가?** (① 로컬 복원만 하고 스플래시를 거치지 않음 / ② 공유 수신도 스플래시를 거쳐 세션 확보 / ③ 시트는 즉시 띄우고 [저장하기] 시점에 세션 확인)
  → **A. ① 로컬 복원만.** 저장된 익명 세션을 네트워크 없이 복원해 시트를 즉시 띄우고, 복원할 세션이 없으면 세션을 새로 확보하지 않고 Q3의 경로로 넘긴다. 공유 흐름 한가운데에 브랜드 스플래시나 세션 확보 대기를 끼워 넣지 않아 SC-001(1초 이내 표출)과 UX-009를 지킨다. PRD 4.2.0이 「비회원 디바이스 세션」을 「비회원 익명 세션」으로 바꾸면서 세션 확보 주체를 [SCR-001] 스플래시로 명시해 새로 생긴 항목이다. (반영: FR-019, UX-010, EC-011, TS-022, TS-023)
  - **5.0.0 재확인(2.3.0)**: PRD 5.0.0이 [SCR-001] Flow E에 "세션을 확보하기 전에는 어느 화면으로도 들여보내지 않는다"와 "「비회원 익명 세션」은 항상 확보되어 있다는 것을 앱 전체의 전제로 둔다"를 신설했다. **외부 공유 수신은 스플래시를 거치지 않아 그 전제가 성립하지 않을 수 있는 유일한 진입점**이며, 이 예외를 없애려면 공유 흐름에 세션 확보 대기를 끼워 넣어 UX-010·SC-001을 되돌리거나(② 안) 시트 대신 앱 실행으로 넘겨 FR-003·FR-013·UX-011을 폐기해야 한다(③ 안). 둘 다 택하지 않고 ①을 유지하며, 세션이 없는 경우는 Q3의 방 0개 경로로 수렴시킨다.
- **Q7. PRD 5.0.0이 세션 자동 무효화를 하지 않기로 확정한 뒤에도, 복원된 세션이 저장 실행 시점에 무효로 판정되는 경우를 계속 다루는가?**
  → **A. 다루지 않는다.** PRD 5.0.0이 "설치가 살아 있는 동안 세션은 만료되지 않으며, 미접속 기간이 아무리 길어도 서버가 세션을 자동으로 무효화하지 않아 앱에 무효 세션 감지·재발급 경로를 만들지 않는다"를 확정 항목으로 올렸다. 2.2.0의 EC-012(세션은 복원됐으나 저장 시점에 서버가 무효로 판정)는 이 확정 아래에서 성립하지 않으므로 철회하고, 대응하는 §4 가정도 함께 걷어냈다. 세션 이외의 사유로 저장이 성립하지 않는 경우는 이전과 같이 FR-014의 오류 알림 경로를 쓴다. (반영: EC-012 삭제, §4 가정, §3.2 비목표)
