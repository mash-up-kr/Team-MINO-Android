## 1. 유저 시나리오 (User Scenarios)

### 유저 플로우 1 - 방 상세 진입 & 지도·바텀시트 탐색
방 리스트에서 방을 선택한 사용자가 그 방에 저장된 장소를 지도와 바텀시트로 탐색한다.

**Figma**: [004 방 상세 annotation](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2400-270425&m=dev) · [헤더/장소 수 인디케이터](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125341&m=dev)

**진입 조건**: 사용자가 [SCR-004] 방 리스트 탭에서 방 카드를 선택했다.

1. 방 상세 진입 → 해당 방의 장소만 표시된 지도 초기화 + 바텀시트가 `Half`(256dp) 상태로 표출(진입 기본값은 `Half`) → 상단에 방 제목·설명·장소 수 인디케이터(`{N}개`, 상한 초과 시 `999+개`)·멤버 아바타 표시
2. 사용자가 시트를 위로 드래그 → `Full`로 전환, 장소 목록 전체 표출
3. 사용자가 시트를 아래로 드래그 → `Peek`(88dp, 헤더만)로 전환
4. 사용자가 장소 카드/마커를 선택 → [SCR-006] 장소 상세로 이동
5. 사용자가 [X] 클릭 → 현재 시트 상태를 유지한 채 [SCR-004] 방 리스트로 복귀(방 상세 `Half`→방 리스트 `Half`, `Full`→`Full`)

**완료 조건**: 사용자가 방에 저장된 장소를 확인했거나, 장소 상세로 이동했거나, 방 리스트로 복귀했다.

### 유저 플로우 2 - 정렬·필터·뷰 전환
사용자가 방에 저장된 장소를 원하는 기준으로 정렬·필터링하고, 리스트형/카드형 중 원하는 형태로 조회한다.

**Figma**: [정렬 드롭다운 펼친 상태](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125333&m=dev) · [카테고리 칩 3종 고정](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3510-125317&m=dev)

**진입 조건**: 방 상세 시트가 `Half` 또는 `Full` 상태다.

1. 사용자가 정렬 드롭다운(펼침 시 표시 순서: 꾹 Pick/전체/최신순/거리순/코멘트순) 선택 → 장소 목록이 해당 기준으로 재정렬
2. 사용자가 카테고리 칩(`전체`/`카페`/`음식점` 3종 고정) 선택 → 장소 목록이 해당 카테고리로 필터링
3. 사용자가 뷰 토글의 좌측 아이콘 클릭 → 리스트형으로 전환
4. 사용자가 뷰 토글의 우측 아이콘 클릭 → 카드형으로 전환

**완료 조건**: 사용자가 원하는 정렬·필터·뷰 형태로 장소 목록을 확인했다.

### 유저 플로우 3 - 장소 액션 (다른 방에 공유 / 장소 삭제)
사용자가 장소 카드의 더보기 메뉴를 통해 장소를 다른 방에 공유하거나 삭제한다.

**Figma**: [004-2 다른 방에 공유](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3225-91770&m=dev) · [004-2-2 다른 방에 공유 클릭](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2862-175295&m=dev) · [더보기 메뉴 목업](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3222-87768&m=dev)

**진입 조건**: 장소 목록이 표시된 상태다.

1. 사용자가 장소 카드의 [...] 클릭 → 액션 메뉴 표출(다른 방에 공유 / 장소 삭제)
2. **[다른 방에 공유] 선택** → [SYS-003] 방 선택 바텀시트 호출(전체 높이 676px, 슬라이드 영역 416px 고정, 모든 방 중복 선택 가능) → 방 선택 후 [공유하기] 클릭 → 선택한 방에 저장 → 완료 토스트 3초 노출 후 자동 사라짐 → 방 상세 화면 유지(대상 방으로 이동하지 않음)
3. **[장소 삭제] 선택** → 확인 모달 표출(`이 장소를 삭제할까요?` / `장소에 등록된 사진과 댓글이 모두 삭제되며, 다시 되돌릴 수 없어요.`) → [삭제] 클릭 → 해당 방에서만 장소 제거

**완료 조건**: 장소가 다른 방에 공유되었거나, 해당 방에서 삭제되었다.

### 유저 플로우 4 - 멤버 & 방 관리
방 상세에서 친구를 초대하거나, 방 정보를 편집하거나, 방을 나간다.

**Figma**: [친구 초대 참여자 목록](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125613&m=dev)

**진입 조건**: 방 상세 화면에 진입한 상태다.

1. 사용자가 [친구 +] 클릭 → [SYS-006] 초대 링크 생성 바텀시트(참여자 목록 포함, 424dp 고정, 참여자 목록 스크롤 영역 288dp 고정) 호출
2. 사용자가 더보기[⋮] 클릭 → [방 편집](방장 전용) 또는 [나가기] 메뉴 표출
   - **더보기 버튼 위치**: `Peek` 상태에서는 상단에, 그 외 상태(`Half`/`Full`)에서는 하단에 표기
3. **[방 편집] 선택**(방장 전용) → [SYS-001] 방 편집 폼 호출(기존 값이 채워진 상태) → 값 수정 → [방 편집 완료] → 방 상세로 복귀하며 완료 스낵바(`방 편집이 완료되었어요`) 표출
4. **[나가기] 선택** → [SYS-007] 나가기 플로우 호출(개인방은 이 메뉴 자체를 노출하지 않는다)

**완료 조건**: 초대 링크가 생성되었거나, 방 정보가 수정되었거나, 사용자가 방을 나갔다.

## 2. 요구사항 (Requirements)
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 방 상세 진입 시 해당 방에 저장된 장소만 표시된 지도를 초기화하고, 바텀시트를 `Half`(256dp) 상태로 표출하며, 상단에 방 제목·설명·장소 수 인디케이터(`{N}개`, 999개 초과 시 `999+개`)·멤버 아바타를 표시해야 한다. (근거: PRD [SCR-005] Flow A, Figma [node 2542-125341](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125341&m=dev))
- **FR-002**: 시스템은 반드시 바텀시트를 `Peek`(88dp) / `Half`(256dp) / `Full`(전체 화면) 세 단계로 드래그 전환할 수 있도록 해야 한다. (근거: PRD 「3단 바텀시트」 정의)
- **FR-003**: 시스템은 반드시 더보기[⋮] 버튼을 `Peek` 상태에서는 상단에, 그 외 상태에서는 하단에 표기해야 한다. (근거: PRD [SCR-005] Flow A)
- **FR-004**: 시스템은 반드시 [X] 클릭 시 현재 시트 상태를 유지한 채 [SCR-004] 방 리스트로 복귀해야 한다. (근거: PRD [SCR-005] Flow A)
- **FR-005**: 시스템은 반드시 정렬 드롭다운(펼침 시 표시 순서 `꾹 Pick`/`전체`/`최신순`/`거리순`/`코멘트순`)을 제공하고, 선택에 따라 장소 목록을 재정렬해야 한다. (근거: PRD [SCR-004]/[SCR-005] 공통 정렬 드롭다운 정의, Figma [node 2542-125333](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125333&m=dev) 펼친 상태 목업, 디자이너 컨펌 2026-08-25 — [node 2542-125408](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2542-125408&m=dev)은 낡은 시안으로 확인됨)
- **FR-006**: 시스템은 반드시 카테고리 칩(`전체`/`카페`/`음식점` 3종 고정, 기본값 `전체`)을 제공하고, 선택에 따라 장소 목록을 필터링해야 한다. (근거: PRD 「카테고리 필터」 정의, 비목표 "저장 값 기반 동적 카테고리 생성" 항목; Figma [node 3510-125317](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3510-125317&m=dev)·[node 3222-87768](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3222-87768&m=dev) 목업에서 3종 고정 확인)
- **FR-007**: 시스템은 반드시 리스트형/카드형 뷰 토글을 제공해야 한다(좌측 아이콘=리스트형, 우측 아이콘=카드형). (근거: PRD [SCR-005] Flow B)
- **FR-008**: 시스템은 반드시 장소 카드의 [...] 클릭 시 다른 방에 공유·장소 삭제 액션 메뉴를 표출해야 한다. (근거: PRD [SCR-005] Flow C)
- **FR-009**: 시스템은 반드시 [다른 방에 공유] 선택 시 [SYS-003] 방 선택 바텀시트를 호출하고, 방 선택 후 [공유하기] 클릭 시 선택한 방에 장소를 저장하며 완료 토스트를 3초간 노출하고 현재 화면을 유지해야 한다. (근거: PRD [SCR-005] Flow C, Figma [node 3225-91770](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3225-91770&m=dev)/[node 2862-175295](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2862-175295&m=dev))
- **FR-010**: 시스템은 반드시 [장소 삭제] 선택 시 확인 모달을 표출하고, 확인 시 해당 방에서만 장소를 제거해야 한다. (근거: PRD [SCR-005] Flow C)

- **FR-012**: 시스템은 반드시 더보기→[방 편집] 클릭 시(방장 전용) [SYS-001] 방 편집 폼을 호출하고, 완료 시 완료 스낵바(`방 편집이 완료되었어요`)를 표출해야 한다. (근거: PRD [SCR-005] Flow D)
- **FR-013**: 시스템은 반드시 더보기→[나가기] 클릭 시 [SYS-007] 나가기 플로우를 호출해야 하며, 개인방에서는 이 메뉴 자체를 노출하지 않아야 한다. (근거: PRD [SCR-005] Flow D)
- **FR-014**: 시스템은 반드시 장소 카드의 더보기[...] 메뉴를 "다른 방에 공유"·"장소 삭제" 2개 항목으로만 구성해야 하며, "장소 이동" 항목은 포함하지 않는다. (근거: PRD [SCR-005] Flow C — Figma [node 3222-87768](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3222-87768&m=dev)에 보이는 "장소 이동"은 재사용 Menu 컴포넌트의 커스터마이징되지 않은 기본 라벨로 확인됨)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 장소 삭제 확인 모달의 문구는 PRD에 명시된 문구(`이 장소를 삭제할까요?` / `장소에 등록된 사진과 댓글이 모두 삭제되며, 다시 되돌릴 수 없어요.`)를 그대로 사용한다. (근거: PRD [SCR-005] Flow C)
- **UX-002**: 다른 방에 공유 완료 토스트는 3초 후 자동으로 사라지며, 사용자를 다른 화면으로 이동시키지 않는다. (근거: PRD [SCR-005] Flow C, [SYS-003])
- **UX-003**: 방 상세와 방 리스트 간 이동 시 바텀시트 단계(`Peek`/`Half`/`Full`)는 그대로 유지된다 — 사용자가 보던 밀도를 화면 전환으로 잃지 않는다. (근거: PRD [SCR-005] Flow A)

### 2.3 주요 도메인 (Core Domain)

- **방 상세 (Room Detail)**: 방 하나에 속한 장소 전체를 지도·리스트·카드로 탐색하는 화면. 개인방·공동방 모두에서 재사용되며, 개인방일 때만 나가기 메뉴가 숨겨진다.
- **장소 액션 (Place Action)**: 장소 카드의 더보기[⋮]에서 제공되는 부가 동작. 다른 방에 공유·장소 삭제 2개로 확정되었다.

## 3. 범위 (Scope)
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 방 상세 진입 후 3초 이내에 지도와 `Half` 시트가 렌더링된다.
- **SC-002**: 사용자가 드래그 한 번으로 `Peek`↔`Half`↔`Full` 각 인접 단계를 전환할 수 있다.
- **SC-003**: 장소 삭제 확인 후 목록에 즉시 반영되어, 삭제된 장소가 다시 조회되지 않는다.
- **SC-004**: 다른 방에 공유가 완료될 때까지 사용자가 방 상세 화면을 벗어나지 않는다.

### 3.2 비목표 항목 (Out of Scope)

- [SCR-006] 장소 상세 화면 자체의 구성(코멘트, 이미지 갤러리 등)은 이 spec의 범위가 아니다.
- 공동방 생성/편집 폼의 입력 필드·검증 규칙 자체는 `group-room-form` spec([SYS-001])이 정의한다.
- 초대 링크 생성·공유 로직 자체는 [SYS-006]이 정의한다. 이 spec은 그 진입점(친구 + 버튼)만 다룬다.
- 방 나가기·방장 권한 위임 정책 자체는 [SYS-007]이 정의한다.
- 지도 카메라 초기화, 마커 색상 판별 규칙 자체는 [SYS-004]가 정의한다.
- 바텀 네비게이션([SYS-005]) 자체의 탭 전환 동작은 이 spec의 범위가 아니다.
- 3단 바텀시트의 드래그 제스처 인식·높이 전환 애니메이션 메커니즘 자체는 디자인 시스템 공용 컴포넌트(이슈 #144)가 정의한다.

## 4. 가정 (Assumptions)

- 대표 색상·캐릭터 표시 규칙은 [SYS-004] 정의를 그대로 따른다.
- 카테고리 칩은 [SCR-004] 방 리스트와 동일하게 `전체`/`카페`/`음식점` 3종 고정이다. Figma 주석([node 2400-270425](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2400-270425&m=dev) 항목 9)에는 "저장 값 기반 동적 생성" 문구가 남아 있으나, PRD가 목표/비목표 양쪽에서 3종 고정을 확정하고 동적 생성을 MVP 비목표로 명시했으므로 PRD를 따른다.
- `Peek`(88dp)/`Half`(256dp) 고정 높이 값은 PRD 디자인 정책 보드 확정값을 그대로 사용한다.
- 방 상세 진입 시 기본 시트 상태는 항상 `Half`다(방 리스트 진입 시 기본값인 `Peek`과 다르다).

## 5. TBD 확인 기록

- Q: 장소 카드 더보기 메뉴에 "장소 이동" 옵션을 포함해야 하는가? (Figma 목업 [node 3222-87768](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3222-87768&m=dev)에는 "다른 방에 공유"/"장소 삭제"와 함께 "장소 이동"이 보이지만, PRD business-context.md [SCR-005] Flow C에는 2개 옵션만 명시됨)
  -> A: 포함하지 않는다. 장소 카드 더보기는 "다른 방에 공유"/"장소 삭제" 2개로 확정(PRD 그대로). 화면 상단 더보기(방 편집/방 나가기)와는 별개 메뉴이며, "장소 이동"은 재사용 Menu 컴포넌트의 커스터마이징 안 된 기본 라벨로 확인되어 반영하지 않는다.
- Q: [다른 방에 공유] 시트에서, 장소가 이미 저장돼 있는 방은 어떻게 보여줘야 하는가? (PRD가 최근 개정되며 이 부분이 "아직 안 정했다"는 식으로 다시 적혔음)
  -> A: 지금까지 확정돼 있던 대로 **체크된 채 눌러도 반응 없는(비활성) 상태**로 보여준다 — 바뀌는 것 없음.
     PRD의 그 문구는 사실 **다른 기능**(외부 앱에서 새로 공유받은 링크를 저장할 때) 얘기다. 그 기능은 "일단 방부터 고르게 하고, 저장 버튼을 누른 뒤에야 뒤에서 게시물 내용을 분석"하는 방식으로 최근 바뀌면서, 방을 고르는 화면에서는 아직 분석 전이라 "이 장소가 이미 어느 방에 있는지" 알 방법이 없어졌다 — 그래서 그 화면만 "정하지 못함"으로 남긴 것.
     반면 "다른 방에 공유"는 **이미 저장·분석까지 끝난 장소를 다른 방에도 복사**하는 기능이라, 방을 고르는 시점에 이미 "이 장소가 어느 방에 있는지" 전부 알고 있다. 그래서 저 미확정 문구가 애초에 이 화면에는 해당하지 않는다.
     Figma 목업([node 2862-175295](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2862-175295&m=dev), "004-2-2 다른 방에 공유 클릭")을 봐도 이미 저장된 방("민호야 잘하자") 카드만 체크박스가 회색+반투명으로 그려져 있어 — 디자인도 처음부터 이 화면은 비활성 처리로 만들어져 있었다. (확인 2026-08-18, Figma 실물 대조)
- Q: 카테고리 칩은 저장된 장소 기반 동적 생성인가, 고정 3종인가? (Figma 주석 [node 2400-270425](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2400-270425&m=dev) 항목 9는 "인스타에서 가져온 저장 값에서 추가되는 형식"이라 적어 동적 생성을 시사하나, PRD는 목표·비목표 양쪽에서 `전체`/`카페`/`음식점` 3종 고정을 확정하고 동적 생성을 MVP 비목표로 명시)
