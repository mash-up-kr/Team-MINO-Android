### 4.0.0 범위 축소 검증 노트

- **축소 배경**: 이슈 #145 본문이 애초에 "PRD [SCR-003] Flow A~F를 이번 범위에 포함한다"로 적혀 있어 spec이 홈 탭 전체를 담게 되었고, PRD 3.0.0 → 4.0.0 개정이 그 범위를 더 깊게 만들었다. 실제 의도는 카드덱 인터랙션이었으므로 홈 화면 셸을 분리했다.
- **남긴 것**: FR 8개(스와이프 3종 · 액션 메뉴 · 장소 가리기 · 덱 구성 · `장소 더 보기` 노출 · 덱 재구성) + UX 2개. 카드덱이 장소 목록을 입력으로 받아 내부에서 완결하는 동작만.
- **이관한 것**: FR 12개 + UX 1개 → 홈 화면 셸 spec. 결정 내용은 §5 「이관 전에 확정된 결정」에 근거째로 보존했으므로 셸 spec이 그대로 인용할 수 있다.
- **번호 재부여**: `plan.md`·`tasks.md`가 없어 하위 참조가 없으므로 FR을 001~008로 연속 재부여하고 §5에 구→신 매핑표를 남겼다. TS/EC도 재부여했다.
- **경계 검증**: FR-004의 `다른 방 장소 저장`은 메뉴 항목 노출과 선택 전달까지만 책임진다. 디자인상 메뉴에 두 항목이 함께 있어 항목 자체는 남겼고, 그 이후(시트·저장·피드백)는 §3.2 비목표와 §4 가정에 명시했다. [SYS-002] 방 선택 시트는 이슈 #158 소유임을 함께 적었다.
- **단독 검증 가능성**: SC-005로 "홈 화면 셸 없이 목록만 주입해 단독 검증 가능"을 성과 기준에 넣어, 셸 진행에 블로킹되지 않는 범위임을 문서로 못박았다.

### 4.1.0 반영 검증 노트

develop을 fast-forward로 당겨 PRD 4.1.0을 기준으로 재대조했다. **4.0.0의 서술 중 2건이 틀린 것으로 확인되어 정정했다.**

| # | 4.0.0 서술 | PRD 4.1.0 | 조치 |
|---|---|---|---|
| 1 | 카드에 **카테고리 태그**(`전체`/`카페`/`음식점`) 표시 | 「장소분류 라벨」 4종 신설. "카테고리 필터와 다른 축"임을 명시 | **틀린 서술 정정** — §2.3 도메인 재작성, 신규 **FR-009**(라벨 표시), TS-015·016 추가, §4 가정 2건 정정 |
| 2 | `다른 방 저장` 시트 = [SYS-002] 방 선택 시트, **이슈 #158 소유** | 「홈 방 시트」 신설(홈 전용 그리드 400dp). "이 경로는 [SYS-002]가 아니다", "[SCR-003] 홈 탭은 「방 선택 시트」를 쓰지 않는다" | **틀린 서술 정정** — §3.2·§4에서 소유자를 **홈 화면 셸**로 수정 |
| 3 | 메뉴 항목 = `장소 가리기` / `다른 방 장소 저장` | `다른 방 저장`과 `장소 가리기` | 명칭 단축·순서 통일 (문서 전역) |

- **범위 경계는 유지했다.** 시트 소유자가 #158 → 홈 셸로 바뀌었지만 카드덱의 책임(메뉴 항목 노출 + 선택 전달)은 그대로다. 시트가 홈 전용이 되었어도 카드덱 밖의 컴포넌트인 것은 동일하다.
- **4:2:2:2 재확인**: 2.0.0에서 폐기한 것은 4종의 **구성 비율**이었고, 4종 자체는 「장소분류 라벨」로 살아 있다. §4 가정에서 "#111 컴포넌트가 4종 스타일이면 그대로 쓸 수 있다"로 정정했다 — 4.0.0에는 "카테고리 태그 기준으로 조정 필요"라는 반대 서술이 남아 있었다.
- FR-009의 판정 로직(클릭수·코멘트수·중복 저장 상위)은 §3.2 비목표로 두었다. 카드덱은 전달받은 라벨 값을 표시만 한다.
