# 검증 가이드: 홈 탭 카드덱(Card Deck)

**대상 스펙 경로**: `docs/specs/home-card-deck` · **계획서**: [plan.md](./plan.md)

카드덱이 엔드투엔드로 동작함을 증명하는 실행 절차다. 계약·모델의 세부는 복제하지 않고 링크로 지목한다.

---

## 선행 조건

- `:feature:home`에 `HomeCard`가 이동되어 있다([research.md](./research.md) D3).
- **서버 연동은 필요 없다.** spec SC-005가 "홈 화면 셸 없이 목록만 주입해 단독 검증 가능"을 성과 기준으로 두었고, 설계도 그에 맞춰 카드덱을 상태 호이스팅 컴포넌트로 잡았다([research.md](./research.md) D1). 검증은 **고정 목록 주입**으로 수행한다.
- `PlaceCard.label`은 API 미제공 상태이므로([contracts/card-feed-repository.md](./contracts/card-feed-repository.md) TBD-1) 검증용 목록에서는 4종을 직접 채워 넣는다.

## 셋업

```sh
./gradlew :app:assembleQaDebug
```

빌드 확인의 최소선은 헌법 §개발 워크플로와 품질 게이트가 정한 이 커맨드다. 로컬 `lintDebug`는 JBR JIT 이슈로 죽을 수 있으며, 죽었다고 검증이 수행된 것은 아니다.

## 검증 시나리오

`@Preview`와 sample 화면에 **고정 목록을 주입한 카드덱**을 띄워 아래를 순서대로 확인한다. 각 항목의 판정 문구는 [spec.md](./spec.md)의 TS/EC가 소유한다.

### A. 스와이프 탐색 — TS-001·002·003, EC-001·002

1. 카드 3장 이상인 목록을 주입한다.
2. **우측 영역**에서 좌→우 드래그 → 다음 카드가 최상단에 온다.
3. 이어서 우→좌 드래그 → 방금 넘긴 카드가 복구된다.
4. 첫 카드에서 우→좌 드래그 → 아무 변화가 없다.
5. **좌측 영역**에서 좌우 드래그 → 아무 변화가 없다.
6. 임계값 미만으로 살짝 끌다 손을 뗀다 → 카드가 원위치한다.

### B. 덱 구성 — TS-004·005·006

목록 크기를 바꿔가며 주입한다.

| 주입 | 기대 |
|---|---|
| 12개 | 덱이 정확히 10장 |
| 4개 | 덱이 4장 |
| 0개 | 카드가 하나도 그려지지 않음 |

### C. 덱 보충 — TS-007·008·018, EC-003·004

1. 10장 덱에서 8장을 넘긴다 → 잔여 2장이 되는 순간 `장소 더 보기` 버튼이 나타난다.
2. 버튼을 누른다 → `onLoadMore` 콜백이 발생한다(로그·스낵바로 확인).
3. 직전 덱에서 넘긴 카드를 **제외한** 새 목록을 주입한다 → 그 카드들이 보이지 않는다.
4. 마지막 카드까지 넘겨 덱을 비운다 → 빈 화면이 되고 `장소 더 보기` 버튼은 그대로 남는다(10장으로 구성된 덱이므로). **빈 상태 안내 문구가 뜨지 않는다**(홈 셸 소관).
5. **TS-018** — 10장 덱을 다시 주입하고 `장소 가리기`로 카드를 빼 잔여 2장을 만든다 → 버튼이 나타난다. 판정 기준이 구성 시점 장수(10장)이므로 가리기로 줄어든 것은 영향이 없다.

> 3의 "제외"는 실제로는 서버가 한다([research.md](./research.md) D7). 검증에서는 제외된 목록을 사람이 만들어 주입한다.

### C-2. 10장 미만 덱에서는 보충 버튼이 없다 — TS-017, EC-003·006

1. 장소 **4개**만 담은 목록을 주입한다 → 덱이 4장으로 구성된다.
2. 카드를 넘겨 잔여 2장을 만든다 → **`장소 더 보기` 버튼이 나타나지 않는다.**
3. 계속 넘겨 덱을 완전히 비운다 → 빈 화면이 되지만 **끝까지 버튼이 없다.**
4. 마지막 1장을 `장소 가리기`로 빼는 경로로 반복해도 결과는 같다(EC-006).

> 방에 장소가 4개뿐이라 더 꺼낼 카드가 없는 상황이다. 버튼을 눌러도 채울 것이 없으므로 아예 노출하지 않는다(FR-007). 이 상태에서 다음에 무엇을 보여줄지(자동 방 전환)는 홈 셸 소관이다.

### D. 카드 액션 — TS-010~014, EC-005·006·007

1. 카드의 `[...]`를 누른다 → `다른 방 저장`·`장소 가리기` 두 항목이 **그 카드 근처**에 열린다.
2. `장소 가리기` → 카드가 덱에서 사라지고 다음 카드가 온다.
3. 그 장소를 포함한 새 목록을 주입 → 다시 카드로 보인다.
4. `다른 방 저장` → 메뉴가 닫히고 `onSaveToOtherRoom` 콜백만 발생한다. **현재 카드와 되돌리기 이력이 그대로다.**
5. 메뉴를 연 채 우측 영역을 스와이프 → 메뉴만 닫히고 카드는 넘어가지 않는다.
6. 메뉴를 연 채 바깥을 탭 → 아무 일 없이 메뉴만 닫힌다.
7. 마지막 1장을 `장소 가리기` → 덱이 비고 `장소 더 보기` 버튼이 유지된다(**10장 덱일 때**. 10장 미만 덱은 C-2 참고).

### E. 라벨 표시 — TS-015·016

라벨 4종을 각각 지정한 카드 4장을 주입하고 차례로 넘기며, 각 카드에 지정한 라벨이 그대로 표시되는지 본다.

### F. 애니메이션 — TS-009, UX-001

전환 애니메이션이 끝나기 전에 한 번 더 드래그한다 → 두 번째 입력이 무시되어 **카드가 한 장만** 넘어간다.

## 확인 신호 관찰

`onCardConfirmed`는 카드를 넘긴 시점에 **1회만** 발생해야 한다(계약 C-01). 되돌리기로 카드를 복구해도 이미 나간 신호는 취소되지 않는다(C-02). 로그로 호출 횟수를 세어 확인한다.

## 이 가이드가 검증하지 않는 것

spec §3.2 비목표 — 정렬 칩, 방 변경·전환, 빈 상태·완료 화면, 「홈 방 시트」와 복제 저장, 라벨 판정 로직, 서버 큐레이션. 전부 홈 화면 셸 몫이며 별도 spec에서 검증한다.
