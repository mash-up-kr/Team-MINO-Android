## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 카드덱 스와이프 탐색 & 덱 보충
카드덱을 받은 사용자가 화면 우측 영역의 스와이프만으로 카드를 한 장씩 넘겨보고, 필요하면 직전 카드로 되돌아가며, 덱이 줄어들면 새 카드로 이어 본다.

**Figma**: [002 홈 - 카드덱 스택](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95706) · [002-2-1 넘기기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99672) · [002-2-2 넘기기 취소](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99704) · [002-2-3 데이터 2개 이하일 때](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99592)

**진입 조건**: 카드덱이 장소 목록을 1개 이상 전달받았다.

1. 카드덱이 장소 목록을 전달받는다 → 시스템은 남은 카드가 뒤로 겹쳐 보이는 스택 형태로 덱을 노출한다. 목록이 10개를 넘으면 앞에서 10장까지만 덱으로 만든다. 각 카드는 장소명·주소·대표 이미지·**장소분류 라벨**·등록자·저장 경과일(`저장한 지 N일째`)을 담는다.
2. 사용자가 화면 우측 영역에서 왼쪽에서 오른쪽으로 드래그한다 → 시스템은 현재 카드를 덱에서 넘기고 다음 카드를 최상단에 노출한다.
3. 사용자가 화면 우측 영역에서 오른쪽에서 왼쪽으로 드래그한다 → 시스템은 바로 직전에 넘긴 카드 1장을 최상단으로 복구한다.
4. 잔여 카드가 2장 이하가 된다 → 시스템은 `장소 더 보기` Floating Button을 노출한다.
5. 사용자가 `장소 더 보기` 버튼을 누른다 → 시스템은 새 목록을 요청하고, 목록을 받으면 방금 본 카드를 제외해 덱을 다시 채운다.

**완료 조건**: 사용자가 원하는 만큼 카드를 넘기거나 되돌리며 열람하고, 덱이 줄어들면 새 카드로 이어 볼 수 있는 상태.

### 유저 플로우 2 - 카드 액션(다른 방 저장 / 장소 가리기)
사용자가 카드의 [...] 버튼으로 액션 메뉴를 열어, 현재 카드를 덱에서만 숨기거나 다른 방 저장을 요청한다.

**Figma**: [...] 버튼 진입점은 [002 홈 - 카드덱 스택](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95706)에 노출되어 있으나, 액션 메뉴(다른 방 저장/장소 가리기) 자체는 아직 Figma 시안이 없다 — 이번 스펙 대상 신규 UI.

**진입 조건**: 카드덱에 카드가 1장 이상 노출되어 있다.

1. 사용자가 카드의 [...] 버튼을 클릭한다 → 시스템은 `다른 방 저장` / `장소 가리기` 두 항목을 담은 메뉴를 해당 카드 근처에 노출한다.
2. 사용자가 `장소 가리기`를 선택한다 → 시스템은 해당 카드를 현재 덱에서만 제거하고 다음 카드를 노출한다. 이후 새 목록에 그 장소가 다시 들어오면 정상적으로 카드가 된다.
3. 사용자가 `다른 방 저장`을 선택한다 → 시스템은 메뉴를 닫고 그 선택을 **덱 밖으로 전달하는 데서 끝난다.** 저장 대상 방 선택 시트와 복제 저장은 이 spec이 정의하지 않는다.

**완료 조건**: 선택한 액션이 처리되거나 밖으로 전달되고, 카드덱 열람이 중단 없이 이어지는 상태.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 화면 우측 영역에서 좌→우 스와이프가 발생하면 현재 카드를 넘기고 다음 카드를 최상단에 노출해야 한다. (근거: business-context.md [SCR-003] Flow A)
- **FR-002**: 시스템은 반드시 화면 우측 영역에서 우→좌 스와이프가 발생하면 바로 직전에 넘긴 카드 1장을 최상단으로 복구해야 한다. (근거: business-context.md [SCR-003] Flow A)
- **FR-003**: 시스템은 반드시 화면 좌측 영역에서 발생하는 스와이프 제스처를 카드 전환·복구에 반영하지 않아야 한다. (근거: business-context.md 「카드 덱」 스와이프 인식 영역 정의)
- **FR-004**: 시스템은 반드시 카드의 [...] 버튼 클릭 시 `다른 방 저장` / `장소 가리기` 두 항목을 담은 메뉴를 노출해야 한다. `다른 방 저장` 선택 시에는 메뉴를 닫고 그 요청을 덱 밖으로 전달하는 데서 끝나야 하며, 덱의 진행 상태(현재 카드·되돌리기 이력)를 바꾸지 않아야 한다. (근거: 사용자 입력, business-context.md [SCR-003] Flow C)
- **FR-005**: 시스템은 반드시 `장소 가리기` 선택 시 해당 카드를 **현재 덱에서만** 제거하고 다음 카드를 노출해야 하며, 이후 전달받은 새 목록에 그 장소가 포함되어 있으면 다시 카드로 노출해야 한다. (근거: business-context.md §5 확정 항목 "장소 가리기는 현재 덱에서만 제외")
- **FR-006**: 시스템은 반드시 전달받은 장소 목록으로 1개 덱을 **최대 10장**까지 구성해야 한다. 목록이 10개 미만이면 있는 만큼만(4개면 4장) 채우고, 0개면 덱을 구성하지 않아야 한다. (근거: business-context.md 「카드 덱」 정의)
- **FR-007**: 시스템은 반드시 현재 덱의 **잔여 카드가 2장 이하**가 되면 `장소 더 보기` Floating Button을 노출해야 한다. (근거: business-context.md [SCR-003] Flow D, 「카드 덱」 정의)
- **FR-008**: 시스템은 반드시 `장소 더 보기` 버튼 클릭으로 새 목록을 전달받으면 **직전 덱에서 이미 넘긴 카드를 제외해** 덱을 다시 채워야 한다. (근거: business-context.md 「카드 덱」 동적 새로고침 Floating Button 정의)
- **FR-009**: 시스템은 반드시 각 카드에 **장소분류 라벨** 1종(`친구들이 많이 본 곳` / `이야기 많은 곳` / `여럿이 저장한 곳` / `가볼 만한 곳`)을 표시해야 한다. 라벨 값은 장소 목록과 함께 전달받으며, 카드덱은 그 값을 표시하는 책임만 진다. (근거: business-context.md 「장소분류 라벨」 정의, [SCR-003] Flow A)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 카드 넘김·되돌림 전환은 다음 카드가 뒤에서 밀려 올라오는 애니메이션으로 표현하고, 애니메이션이 끝나기 전까지 추가 스와이프 입력을 무시한다. (근거: business-context.md "독립적 카드 소비 경험")
- **UX-002**: 카드 액션 메뉴(다른 방 저장/장소 가리기)는 항상 클릭한 [...] 버튼이 속한 카드 근처에서 열려, 어떤 카드에 대한 액션인지 혼동되지 않게 한다. (근거: 사용자 입력)

### 2.3 주요 도메인 (Core Domain)

- **카드덱**: 전달받은 장소 목록으로 만들어지는, 최대 10장의 장소 카드 열람 단위. 목록이 10개 미만이면 있는 만큼만 채워지고 0개면 구성되지 않는다. 소진 상태(잔여 카드 수)와 되돌리기 이력을 가진다. 어떤 방·어떤 정렬로 목록이 만들어졌는지는 덱이 알지 못한다.
- **장소 카드**: 장소명·주소·대표 이미지·장소분류 라벨·등록자·저장 경과일(`저장한 지 N일째`)로 구성되는 열람 단위 항목. 저장 경과일을 보여주는 화면은 홈 카드뿐이다.
- **장소분류 라벨**: 장소 하나가 지금 왜 눈에 띄는지를 한 마디로 붙여주는 4종 고정 표시 — `친구들이 많이 본 곳`(클릭수 상위) / `이야기 많은 곳`(코멘트수 상위) / `여럿이 저장한 곳`(중복 저장 상위) / `가볼 만한 곳`(위 셋에 걸리지 않은 장소의 기본값). **카테고리 필터(`카페`·`음식점`)와도, 정렬 기준 3종과도 다른 축**이며, 카드덱은 전달받은 값을 표시만 한다.
- **카드 액션**: 카드 한 장에 대해 사용자가 선택할 수 있는 부가 동작. `장소 가리기`(현재 덱에서만 제거 — 덱이 스스로 처리)와 `다른 방 저장`(덱 밖으로 전달)이 있다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 사용자가 우측 영역 스와이프만으로, 별도 설명 없이 첫 카드 열람부터 덱 소진까지 완료할 수 있다.
- **SC-002**: 덱 소진 임박(잔여 2장 이하) 시점에 `장소 더 보기` 버튼이 노출되어, 사용자가 별도 탐색 없이 다음 덱을 이어 볼 수 있다.
- **SC-003**: 전달받은 목록 크기와 무관하게 덱이 예측 가능하게 구성된다 — 10개 이상이면 10장, 미만이면 있는 만큼, 0개면 구성하지 않는다.
- **SC-004**: 연속 스와이프·애니메이션 중 입력으로 카드가 두 장 넘어가거나 전환이 끊기는 일이 없다.
- **SC-005**: 카드덱을 홈 화면 셸 없이도 목록만 주입해 단독으로 동작·검증할 수 있다.

### 3.2 비목표 항목 (Out of Scope)

- **장소 목록의 조회·정렬·방 컨텍스트는 이 스펙이 정의하지 않는다.** 카드덱은 장소 목록을 **입력으로 받고**, 새 목록이 필요하면 요청 신호를 밖으로 보내는 데서 끝난다. 어떤 방의 장소인지, 어떤 정렬 기준으로 뽑혔는지는 홈 화면 셸의 몫이다.
- `다른 방 저장`이 호출하는 시트와 복제 저장 처리는 이 스펙이 정의하지 않는다. 카드덱은 메뉴 항목 노출과 선택 전달까지만 다룬다. 이 경로가 쓰는 시트는 PRD 4.1.0에서 신설된 **「홈 방 시트」**(홈 탭 전용 그리드형, 70dp 3열, 첫 칸 `방 만들기`, 400dp 고정)이며 **홈 화면 셸이 소유**한다 — [SYS-002] 외부 공유 수신의 「방 선택 시트」도, 이슈 #158도 아니다.
- 장소분류 라벨의 **판정 로직**(클릭수·코멘트수·중복 저장 수 상위 판별)은 이 스펙이 정의하지 않는다. 카드덱은 목록과 함께 전달받은 라벨 값을 표시만 한다.
- 정렬 칩·방 변경 시트·방 전환 툴팁·빈 상태 안내·완료 안내 화면·자동 방·정렬 전환·`꾹 Pick` 경과일 초기화는 모두 이 스펙 범위 밖이다. 3.0.0까지 포함되어 있었으나 4.0.0에서 홈 화면 셸 spec으로 이관했다(§5 참고).
- 정렬 알고리즘(꾹 Pick·최신순·가까운순)의 순위 산출 로직은 이 스펙이 정의하지 않는다.
- 카드 자체의 시각 스타일(4종 카테고리 카드 컴포넌트)은 이 스펙이 정의하지 않는다. 이미 구현된 컴포넌트(#111)를 덱 인터랙션에 배선하는 것만 다룬다.

## 4. 가정 (Assumptions)

- 카드 자체의 시각 컴포넌트는 이미 구현되어 있다고 가정한다(#111). 그 컴포넌트가 4종(가볼 만한 곳/이야기 많은 곳/여럿이 저장한 곳/친구들이 많이 본 곳) 스타일로 만들어졌다면 **그대로 쓸 수 있다** — PRD 4.1.0에서 폐기된 것은 4종의 4:2:2:2 구성 비율이고, 4종 자체는 「장소분류 라벨」로 유지되기 때문이다.
- 카드덱은 **장소 목록을 입력으로 주입받는 단위**로 만든다고 가정한다. 목록을 누가 어떻게 채우는지에 의존하지 않으므로, 홈 화면 셸이 완성되기 전에도 고정 목록으로 단독 검증할 수 있다.
- `다른 방 저장` 선택 이후의 동작은 **외부에 위임**한다고 가정한다. 카드덱은 "이 장소를 다른 방에 저장하고 싶다"는 선택을 밖으로 알리는 경계까지만 책임진다. 디자인상 메뉴에 두 항목이 함께 노출되므로 항목 자체는 남기되, 「홈 방 시트」 호출·저장·완료 토스트·이미 저장된 방의 체크·비활성 처리는 이 spec이 다루지 않는다.
- 액션 메뉴의 항목 **순서**는 PRD 「카드 덱」 표기 순서(`다른 방 저장` → `장소 가리기`)를 따랐다고 가정한다. 메뉴 자체의 Figma 시안이 아직 없어 시안이 나오면 조정할 수 있다.
- 장소분류 라벨은 장소 목록의 각 항목에 **이미 부여된 채로** 전달된다고 가정한다. 카드덱이 클릭수·코멘트수를 직접 집계해 판정하지 않는다.
- `장소 더 보기` 버튼 클릭 시 새 목록을 어디서 가져오는지도 외부 위임이며, 카드덱은 받은 목록으로 덱을 재구성하는 책임만 진다고 가정한다.
- `장소 더 보기`가 제외하는 "방금 본 카드"는 직전 덱에서 이미 넘긴 카드들을 뜻하며, 그 제외는 다음 덱 1회에만 적용된다고 가정한다.
- 카드덱의 진행 상태(현재 카드 위치·되돌리기 이력)는 클라이언트 로컬 상태로만 관리하며 서버에 영구 저장하지 않는다. (근거: business-context.md "독립적 카드 소비 경험")
- 되돌리기는 **1단계**만 지원한다고 가정한다. 여러 장을 연속으로 되돌리는 동작은 디자인에 근거가 없다.
- 카드에 노출되는 분류 표시는 「장소분류 라벨」 4종이며, 카테고리 필터(`카페`·`음식점`)는 카드덱이 다루지 않는다고 가정한다. 두 축은 PRD에서 명시적으로 분리되어 있다.
- 덱이 빈 상태일 때 무엇을 안내할지(빈 상태 화면·완료 화면)는 홈 화면 셸이 정하며, 카드덱은 카드를 노출하지 않는 상태를 유지하는 것으로 충분하다고 가정한다.

### 4.1.0 — PRD 4.1.0 반영

develop 머지 후 PRD가 4.0.0 → 4.1.0으로 올라가면서 카드덱에 닿는 변경 3건을 반영했다.

- Q : 카드에 표시되는 분류 값은 무엇인가? -> A : (2026-08-18 PRD 4.1.0 반영) **「장소분류 라벨」 4종**이다. 4.0.0까지 이 spec이 적어둔 "카테고리 태그(`전체`/`카페`/`음식점`)"는 **틀린 서술**이었다. PRD는 라벨이 카테고리 필터와도, 정렬 기준 3종과도 **다른 축**임을 명시한다. 2.0.0에서 폐기된 것은 4종의 **4:2:2:2 구성 비율**이었고, 4종 자체는 장소마다 붙는 라벨로 유지된다. → FR-009 신설.
- Q : 카드 액션 메뉴의 항목 명칭은? -> A : (2026-08-18 PRD 4.1.0 반영) `다른 방 장소 저장` → **`다른 방 저장`** 으로 단축되었다. 표기 순서도 PRD 「카드 덱」을 따라 `다른 방 저장` → `장소 가리기`로 맞췄다.
- Q : `다른 방 저장`은 어떤 시트를 호출하는가? -> A : (2026-08-18 PRD 4.1.0 반영) **「홈 방 시트」**(홈 탭 전용 그리드형 400dp)다. 4.0.0까지 적어둔 "[SYS-002] 방 선택 시트, 이슈 #158 소유"는 **틀린 서술**이었다. PRD는 "이 경로는 [SYS-002]가 아니다", "[SCR-003] 홈 탭은 「방 선택 시트」를 쓰지 않는다"라고 못박는다. 시트 소유자는 #158이 아니라 **홈 화면 셸**이며, 카드덱의 경계(선택 전달까지)는 그대로다.

- Q : 덱 10장은 어떤 비율로 채우는가? -> A : (2026-08-16 PRD §5 반영) `가볼만한 곳 4 / 이야기 많은 곳 2 / 여럿이 저장한 곳 2 / 친구들이 많이 본 곳 2` 버킷 구성은 **구버전 주석으로 폐기**되었다. 덱은 전달받은 목록 순서대로 최대 10장까지 채운다.
- Q : `장소 가리기`는 어느 범위까지 적용되는가? -> A : (2026-08-16 PRD §5 반영) 현재 덱에서만 제외한다. 새 목록에 다시 들어오면 정상 노출되며, 영구 제외는 MVP 범위 밖이다.
- Q : `다른 방 저장`을 카드덱이 어디까지 책임지는가? -> A : (2026-08-17 확정) **메뉴 항목 노출과 선택 전달까지만.** 순수 카드덱 UI로 범위를 잡았으므로 시트·저장·완료 피드백은 홈 화면 셸과 #158 소관이다.

### 이관 전에 확정된 결정 (기록 보존)

아래는 3.0.0까지 이 spec에서 확정했던 내용이다. 요구사항은 이관됐지만 **결정 근거를 잃지 않도록 남긴다.** 홈 화면 셸 spec이 그대로 인용할 수 있다.

- Q : 덱을 모두 소진했을 때(새로고침 없이) 어떤 화면을 보여줘야 하는가? -> A : (2026-08-17 재확정) 현재 정렬에서 다음으로 볼 방이 있으면 안내 화면 없이 그 방의 덱으로 자동 전환한다(저장 장소 0개인 방은 건너뜀). 모든 방을 소진하면 정렬 기준을 `꾹 Pick` → `최신순` → `가까운순` 순서로 자동 전환하고, `가까운순`까지 다 확인했을 때에만 `꾹 눌러둔 장소를 모두 둘러봤어요` 상태 화면을 노출한다.
- Q : 정렬이 자동 전환될 때 상단 정렬 칩 표시는 어떻게 되는가? -> A : (2026-08-17 확정) 칩의 선택 표시도 새 기준으로 함께 갱신한다.
- Q : `가까운순`(반경 3km)으로 자동 전환하려는데 위치 권한이 없으면 어떻게 하는가? -> A : (2026-08-17 확정) 그 시점에 위치 권한을 요청한다. 허용하면 `가까운순` 덱을 노출하고, 거부하면 `가까운순`을 건너뛰어 완료 상태 화면으로 넘어간다.
- Q : `꾹 Pick`에서 "정렬 초기화(저장 30일째 → 0일째)"된다는 디자인 주석은 무엇을 초기화한다는 뜻인가? -> A : (2026-08-17 확정) 카드를 넘겨 확인한 시점에 그 장소의 `꾹 Pick` 순위 판정용 경과일이 0일로 초기화되고, 경과일이 다시 쌓여 오래된 상위 30%에 재진입하면 다시 노출된다. 되돌리기로 복구하면 초기화도 취소된다.
- Q : `꾹 Pick` 순위 판정의 기준 날짜는 방 생성일인가 장소 저장일인가? -> A : (2026-08-17 확정) **장소 저장일**이다. 방 생성일은 방마다 값이 하나뿐이라 장소 간 순위를 만들 수 없다.
- Q : 경과일 초기화가 표시값(`저장한 지 N일째`)까지 0일로 만드는가? -> A : (2026-08-17 확정) 아니다. **홈 탭 `꾹 Pick` 순위 판정값에만** 적용되며, 표시값과 `최신순`·`가까운순` 판정은 실제 저장일 기준을 유지한다.
- Q : `다른 방 저장`은 어떤 시트를 쓰고 방을 몇 개까지 고를 수 있는가? -> A : (2026-08-16 PRD 반영) 홈의 방 변경 시트가 아니라 [SYS-002] 방 선택 시트를 호출하며, 체크박스로 **복수 선택**한다. 이미 저장된 방은 체크·비활성으로 노출한다.
