## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 카드덱 스와이프 탐색
홈 탭에 진입한 사용자가 화면 우측 영역의 스와이프만으로 카드를 한 장씩 넘겨보고, 필요하면 직전 카드로 되돌아간다.

**Figma**: [002 홈 - 카드덱 스택](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95706) · [002-1-1 메인_꾹Pick](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99774) · [002-2-1 넘기기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99672) · [002-2-2 넘기기 취소](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99704)

**진입 조건**: 사용자가 홈 탭에 있고, 현재 방에 노출 가능한 장소 카드가 1장 이상 있다.

1. 사용자가 홈 탭에 진입한다 → 시스템은 현재 방의 뱃지·캐릭터와 함께, 남은 카드가 뒤로 겹쳐 보이는 스택 형태로 카드덱을 노출한다.
2. 사용자가 화면 우측 영역에서 왼쪽에서 오른쪽으로 드래그한다 → 시스템은 현재 카드를 덱에서 넘기고 다음 카드를 최상단에 노출한다.
3. 사용자가 화면 우측 영역에서 오른쪽에서 왼쪽으로 드래그한다 → 시스템은 바로 직전에 넘긴 카드 1장을 최상단으로 복구한다.

**완료 조건**: 사용자가 원하는 만큼 카드를 넘기거나 되돌리며 열람을 마친 상태.

### 유저 플로우 2 - 카드 액션(장소 가리기 / 다른 방 장소 저장)
사용자가 카드의 [...] 버튼으로 현재 카드를 덱에서만 숨기거나, 다른 방에 복제 저장한다.

**Figma**: [...] 버튼 진입점은 [002 홈 - 카드덱 스택](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2598-95706)에 노출되어 있으나, 액션 메뉴(장소 가리기/다른 방 장소 저장) 자체는 아직 Figma 시안이 없다 — 이번 스펙 대상 신규 UI. 저장 대상 방 선택은 [002-4-1 방변경](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-100314) · [002-4-1 공동방 만들기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2331-61945) 시안을 그대로 재사용한다.

**진입 조건**: 카드덱에 카드가 1장 이상 노출되어 있다.

1. 사용자가 카드의 [...] 버튼을 클릭한다 → 시스템은 `장소 가리기` / `다른 방 장소 저장` 두 액션을 담은 메뉴를 노출한다.
2. 사용자가 `장소 가리기`를 선택한다 → 시스템은 해당 카드를 덱에서 제거하고 다음 카드를 노출한다.
3. 사용자가 `다른 방 장소 저장`을 선택한다 → 시스템은 002-4-1 방변경 바텀시트를 열어 저장 대상 방을 고르게 한다.
4. 사용자가 방변경 바텀시트에서 방을 선택한다 → 시스템은 해당 장소를 선택한 방에 복제 저장하고, 원래 카드덱의 진행 상태(현재 카드·되돌리기 이력)는 그대로 유지한다.

**완료 조건**: 선택한 액션이 처리되고 카드덱 열람이 중단 없이 이어지는 상태.

**Figma**: [002-1 홈 normal](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99774)

### 유저 플로우 4 - 덱 새로고침 & 자동 방 전환
카드를 계속 넘기던 사용자가 덱을 다 소진하면, 직접 새로고침하거나 자동으로 다음 방으로 넘어간다.

**Figma**: [002-2-3 데이터 2개 이하일 때](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-99592) · [002-2-4 자동 방 전환](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-100268) · [002-5-1 방 전환 툴팁](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-100403)

**진입 조건**: 사용자가 같은 방의 카드덱을 계속 넘기고 있다.

1. 사용자가 카드를 계속 넘겨 덱 10장 중 8장 이상을 소진한다(잔여 2장 이하) → 시스템은 새로고침 Floating Button을 노출한다.
2. 사용자가 새로고침 버튼을 클릭한다 → 시스템은 같은 방의 새 10장으로 덱을 다시 채운다.
3. 사용자가 새로고침 없이 10장을 모두 소진한다 → 시스템은 `꾹 눌러둔 장소를 모두 둘러봤어요` 문구와 일러스트레이션이 담긴 소진 안내 화면을 먼저 노출한 뒤, 다음 방의 덱을 자동으로 불러오고 방 전환 툴팁을 노출한 뒤 5초 후 사라지게 한다.

**완료 조건**: 덱이 새 10장(같은 방 또는 다음 방)으로 채워진 상태.

**테스트 시나리오**

| ID | 시나리오 | Given | When | Then | 관련 FR |
|---|---|---|---|---|---|
| TS-010 | 새로고침 버튼 노출 | 덱 10장 중 8장 소진(잔여 2장) | 카드 1장을 더 넘김 | 새로고침 Floating Button이 노출된다 | FR-010 |
| TS-011 | 새로고침 클릭 | 새로고침 버튼이 노출된 상태 | 새로고침 버튼 클릭 | 같은 방의 새 10장(4/2/2/2 구성)으로 덱이 채워진다 | FR-011 |
| TS-012 | 10장 완전 소진 시 자동 방 전환 | 새로고침 없이 마지막 10번째 카드까지 도달 | 마지막 카드를 넘김 | `꾹 눌러둔 장소를 모두 둘러봤어요` 소진 안내 화면이 먼저 노출된 뒤, 다음 방의 덱이 자동으로 로드되고 방 전환 툴팁이 노출된다 | FR-012 |

**엣지 케이스**

| ID | 상황 | 처리 | 관련 FR |

| EC-006 | 사용자가 속한 방이 1개뿐인 상태에서 10장을 모두 소진(전환할 다음 방이 없음) | 같은 방을 자동으로 재로드하지 않고 `꾹 눌러둔 장소를 모두 둘러봤어요` 안내 화면을 유지한다. 이미 노출되어 있는 새로고침 버튼을 눌러야 같은 방의 새 10장으로 재로드된다 | FR-010, FR-011, FR-012 |

### 유저 플로우 5 - 수동 방 변경 & 빈 상태
사용자가 방 뱃지·캐릭터를 눌러 원하는 방으로 직접 이동하거나, 볼 장소가 없는 방에서 안내를 받는다.

**Figma**: [002-4-1 방변경](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-100314) · [002-6-1 데이터 없을 때](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1604-100388) · [002-6-2 CTA 클릭 시 공동방 만들기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=1728-120806)

**진입 조건**: 사용자가 홈 탭 카드덱 화면에 있다.

1. 사용자가 상단 방 뱃지 또는 캐릭터를 클릭한다 → 시스템은 방 변경 바텀시트(방 리스트)를 연다.
2. 사용자가 바텀시트에서 다른 방을 선택한다 → 시스템은 뱃지·캐릭터를 해당 방 것으로 교체하고, 방 전환 툴팁을 5초 노출한 뒤 사라지게 하며, 새 방의 카드덱으로 재로드한다.
3. 재로드한 방(또는 홈 진입 시 현재 방)에 열람 가능한 장소가 없다 → 시스템은 안내 문구(`꾹 눌러둔 장소, 다시 꺼내볼까요?`)와 CTA를 노출한다.

**완료 조건**: 선택한 방의 카드덱이 노출되거나, 빈 상태 안내가 노출된 상태.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 화면 우측 영역에서 좌→우 스와이프가 발생하면 현재 카드를 넘기고 다음 카드를 최상단에 노출해야 한다. (근거: business-context.md [SCR-003] Flow A)
- **FR-002**: 시스템은 반드시 화면 우측 영역에서 우→좌 스와이프가 발생하면 바로 직전에 넘긴 카드 1장을 최상단으로 복구해야 한다. (근거: business-context.md [SCR-003] Flow A)
- **FR-003**: 시스템은 반드시 화면 좌측 영역에서 발생하는 스와이프 제스처를 카드 전환·복구에 반영하지 않아야 한다. (근거: business-context.md "카드 덱" 정의, GitHub #142)
- **FR-004**: 시스템은 반드시 카드의 [...] 버튼 클릭 시 `장소 가리기` / `다른 방 장소 저장` 두 액션을 담은 메뉴를 노출해야 한다. (근거: 사용자 입력)
- **FR-005**: 시스템은 반드시 `장소 가리기` 선택 시 해당 카드를 현재 덱에서 제거하고 다음 카드를 노출해야 한다. (근거: 사용자 입력)
- **FR-006**: 시스템은 반드시 `다른 방 장소 저장` 선택 시 002-4-1 방변경 바텀시트를 열어 저장 대상 방을 선택하게 해야 한다. (근거: 사용자 입력)
- **FR-007**: 시스템은 반드시 방변경 바텀시트에서 방을 선택하면 해당 장소를 선택한 방에 복제 저장하고, 원래 카드덱의 진행 상태를 그대로 유지해야 한다. 이미 해당 장소가 저장되어 있는 방은 바텀시트에서 체크(✓) 표시와 비활성 상태로 노출되어 재선택할 수 없어야 한다. (근거: 사용자 입력, business-context.md [SYS-003])
- **FR-008**: 시스템은 반드시 상단 정렬 칩(꾹 Pick/최신순/가까운순) 선택 시 해당 기준으로 카드덱을 다시 불러오고 되돌리기 이력을 초기화해야 한다. (근거: business-context.md [SCR-003] Flow B)
- **FR-009**: 시스템은 반드시 기본 카드덱을 최대 10장으로 구성하되, 가볼 만한 곳 4장 / 이야기 많은 곳 2장 / 여럿이 저장한 곳 2장 / 친구들이 많이 본 곳 2장 비율로 채워야 한다. (근거: 사용자 입력)
- **FR-010**: 시스템은 반드시 덱 10장 중 8장 이상이 소진되면(잔여 2장 이하) 새로고침 Floating Button을 노출해야 한다. (근거: business-context.md [SCR-003] Flow C)
- **FR-011**: 시스템은 반드시 새로고침 버튼 클릭 시 같은 방의 새 10장으로 덱을 다시 채워야 한다. (근거: business-context.md [SCR-003] Flow C)
- **FR-012**: 시스템은 반드시 새로고침 없이 10장을 모두 소진하면 `꾹 눌러둔 장소를 모두 둘러봤어요` 문구와 일러스트레이션이 담긴 소진 안내 화면을 노출해야 한다. 전환할 다음 방이 있으면 화면 노출 뒤 다음 방의 덱을 자동으로 불러와야 하고, 전환할 다음 방이 없으면(사용자가 속한 방이 1개뿐일 때) 자동으로 재로드하지 않고 이 화면을 유지하며 사용자가 새로고침 버튼(FR-011)을 눌러야 같은 방의 새 10장으로 재로드해야 한다. (근거: business-context.md [SCR-003] Flow D, 사용자 확인)
- **FR-013**: 시스템은 반드시 상단 방 뱃지 또는 캐릭터 클릭 시 방 변경 바텀시트(방 리스트)를 열어야 한다. (근거: business-context.md [SCR-003] Flow E)
- **FR-014**: 시스템은 반드시 방 변경 바텀시트에서 방을 선택하면 뱃지·캐릭터를 해당 방의 것으로 교체하고 카드덱을 재로드해야 한다. (근거: business-context.md [SCR-003] Flow E)
- **FR-015**: 시스템은 반드시 방이 자동 전환되거나 수동으로 변경되면 방 전환 툴팁을 노출한 뒤 5초 후 사라지게 해야 한다. (근거: business-context.md "방 전환 툴팁" 정의)
- **FR-016**: 시스템은 반드시 열람 가능한 장소가 없는 상태에서 안내 문구와 CTA를 노출해야 한다. (근거: business-context.md [SCR-003] Flow F)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 카드 넘김·되돌림 전환은 다음 카드가 뒤에서 밀려 올라오는 애니메이션으로 표현하고, 애니메이션이 끝나기 전까지 추가 스와이프 입력을 무시한다. (근거: business-context.md "독립적 카드 소비 경험")
- **UX-002**: 카드 액션 메뉴(장소 가리기/다른 방 저장)는 항상 클릭한 [...] 버튼이 속한 카드 근처에서 열려, 어떤 카드에 대한 액션인지 혼동되지 않게 한다. (근거: 사용자 입력)
- **UX-003**: 방이 전환되면(자동·수동 모두) 이전 방에서 쌓인 되돌리기 이력은 새 방으로 넘어가지 않는다. (근거: business-context.md [SCR-003] Flow B의 "Undo 이력 초기화"와 동일한 원칙 적용)

### 2.3 주요 도메인 (Core Domain)

- **카드덱**: 한 방에서 최대 10장의 장소 카드로 구성되는 열람 단위. 정렬 기준과 소진 상태(잔여 카드 수)를 가진다.
- **장소 카드**: 장소명·주소·대표 이미지·카테고리 태그(가볼 만한 곳/이야기 많은 곳/여럿이 저장한 곳/친구들이 많이 본 곳)·등록자로 구성되는 열람 단위 항목.
- **카드 액션**: 카드 한 장에 대해 사용자가 선택할 수 있는 부가 동작. `장소 가리기`(현재 덱에서만 제거)와 `다른 방 장소 저장`(다른 방에 복제)이 있다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 사용자가 우측 영역 스와이프만으로, 별도 설명 없이 첫 카드 열람부터 10장 소진까지 완료할 수 있다.
- **SC-002**: 사용자가 카드 [...] 액션에서 `다른 방 장소 저장`을 선택했을 때, 홈 화면을 벗어나지 않고 저장까지 완료할 수 있다.
- **SC-003**: 덱 소진(8장 이상 소진) 시점에 새로고침 버튼이 노출되어, 사용자가 별도 탐색 없이 다음 10장을 이어 볼 수 있다.
- **SC-004**: 기본 덱 10장의 카테고리 구성 비율(4/2/2/2)이 새로고침·방 전환 시마다 동일하게 유지된다.

### 3.2 비목표 항목 (Out of Scope)

- 정렬 알고리즘(꾹 Pick 랭킹 공식, 최신순 14일/가까운순 3km 기준)의 산출 로직 자체는 이 스펙이 정의하지 않는다. 이 스펙은 정렬 칩 선택에 따른 프론트엔드 상호작용만 다룬다.
- 방 리스트 바텀시트(3단 Peek/Half/Full)의 상세 동작은 이 스펙이 정의하지 않는다. 이 스펙은 카드덱에서 여는 진입점(방 변경 바텀시트 호출)까지만 다룬다.
- 다른 방 저장(장소 복제)의 서버 저장 처리·오류 코드 체계는 이 스펙이 정의하지 않는다.
- 공동방 생성 유도(Nudge·Ghost Card)의 상세 동작은 이 스펙이 정의하지 않는다. 이 스펙은 빈 상태 CTA가 그 플로우로 연결된다는 사실까지만 다룬다.

## 4. 가정 (Assumptions)

- 카드 자체의 시각 컴포넌트(4종 카테고리 스타일)는 이미 구현되어 있다고 가정한다(#111). 이 스펙은 그 컴포넌트를 실제 덱 스와이프·액션 인터랙션에 배선하는 것을 다룬다.
- 002-4-1 방변경 바텀시트는 이 스펙 구현 시점까지 별도로 준비되지 않았을 수 있어, 신규 구현이 필요할 수 있다고 가정한다.
- 사용자는 이미 1개 이상의 방(개인방 포함)에 속해 있는 상태로 홈 탭에 진입한다.
- 카드덱의 진행 상태(현재 카드 위치·되돌리기 이력)는 클라이언트 로컬 상태로만 관리하며 서버에 영구 저장하지 않는다. (근거: business-context.md "독립적 카드 소비 경험")
- 소진 안내 화면(`꾹 눌러둔 장소를 모두 둘러봤어요`)은 전환할 다음 방이 있을 때만 짧게 노출된 뒤 자동으로 다음 방 전환으로 넘어간다고 가정한다. 정확한 노출 시간은 디자인 시안이 확정되면 반영한다. 전환할 다음 방이 없을 때는 이 화면이 유지되며, 사용자가 새로고침 버튼을 눌러야 같은 방의 새 10장으로 재로드된다.
