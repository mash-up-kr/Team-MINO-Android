## 검증 근거

- **`[TBD]` 마커 0건** — `spec.md` 전문에서 `[TBD` 검색 결과 0건. 1.2.0 개정에서 새로 연 미확정 항목도 없다(§5 「검토 필요」 비어 있음).
- **모든 기능 요구사항에 대응 테스트 시나리오** — FR-001~019 19건 전부가 TS-001~022 중 최소 1건에 매핑된다. 이번 개정에서 늘어난 매핑은 FR-018→TS-005·TS-020, FR-019→TS-022이고, 의미가 바뀐 FR-005는 TS-005에 더해 **TS-021**(조작 없는 자동 복구)로 검증된다.
- **UX 규칙의 검증 가능성** — 재정의된 UX-002는 "재시도 조작 0개"라는 형태로 **SC-011**과 TS-021이 받고, UX-003의 지연 표현은 TS-022·EC-009가 받는다. UX-001의 원인 2종 구분은 **SC-012**로 계측된다.
- **기준 PRD 정합** — PRD 5.0.0 [SCR-001] Flow A~E와 대조했다. Flow B(지연)→FR-019·EC-009, Flow C·D(실패 원인 2종)→FR-018·UX-001, Flow E(진입 차단 + 자동 재시도, 재시도 버튼 없음)→FR-005·FR-016·UX-002. PRD §1 「설치가 살아 있는 동안 세션은 만료되지 않는다」→FR-017. 4.2.0 시점에 PRD 측에 남아 있던 `TBD:`(실패 상태 진입 허용 범위)는 5.0.0에서 확정되어 해소됐다.
- **구체값의 소유권 분리** — 토스트 문구·3초/10초 임계·표시 위치는 PRD와 진입 화면 스펙이 갖고, 이 spec은 상태 구분과 정책만 서술한다(§3.2 비목표에 명시). FR-019는 임계 시간을 스스로 정하지 않고 "진입 화면 스펙이 정한다"고 위임하므로 두 문서가 같은 값을 중복 관리하지 않는다.
- **구현 세부사항 부재** — 요구사항·UX 규칙·성공 기준 본문에 SDK·라이브러리·헤더·예외 타입명이 없고, PRD가 쓰는 "로딩 스피너" 같은 시각 표현도 "진행 중임을 알리는 표현"으로 중립화했다. 헤더의 **입력**·**개정 입력** 필드는 사용자 원문을 보존하는 기록 필드이므로 이 판정에서 제외한다.
- **가정의 명시** — PRD가 정하지 않은 자동 재시도의 간격·종료 조건은 요구사항으로 승격하지 않고 §4 가정에 "상한 없음 + 실패가 이어질수록 간격을 늘림"으로 기록했다.
