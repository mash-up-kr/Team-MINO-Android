(최초 작성 입력: GitHub 이슈 [#149](https://github.com/mash-up-kr/Team-MINO-Android/issues/149) "스플래시 화면 구현 (SCR-001)" / 3.0.0에서 PRD 5.0.0 `[SCR-001]` Flow A~E와 대조해 정합화)

**개정 입력(4.0.0)**: 사용자 설명: "프로필 없음 부분 개정해줘" — 앱 진입 판정의 근거를 `프로필 없음` 하나에서 **`프로필 등록 여부`와 `온보딩 완료 표시` 둘**로 바꿨다. 프로필을 저장한 뒤 온보딩을 끝내지 못한 사용자가 메인 탭으로 밀려나 남은 스텝을 영영 보지 못하던 것을 막는다.

**개정 입력(5.0.0)**: 사용자 설명: "3안으로 간다" — 오프라인 **재실행**이 네트워크 없이 완결된다는 약속을 걷어냈다. 앱 진입 판정이 서버 조회를 포함하므로 오프라인에서는 판정 자체가 불가능하며, `FR-011`의 "네트워크 없이"는 **세션 복원에만** 걸린다.

> **이 개정은 PRD를 거스른다.** PRD [SCR-001] Flow A·E가 *"재실행은 저장된 세션을 네트워크 없이 복원하므로 Flow B~E를 타지 않는다. 이 경로는 최초 실행 전용이다"* 라고 적었으나, 진입 판정이 `프로필 등록 여부`를 서버에 물어야 성립하므로 그 문장은 성립하지 않는다. **명세를 구현 동작에 맞추는 선택이며 그 대가는 §5 TBD-5가 든다.** `4.0.0`과 `5.0.0` 사이에서 `FR-011`의 의미가 좁아지고 `EC-002`·`TS-016`이 재정의됐다.

> 이 개정의 근거는 이 문서 밖에 있다. **어떤 조건에서 온보딩을 띄우는지는 `docs/specs/onboarding-flow`(FR-021·FR-022)가 소유하고, 이 문서는 그 판정을 소비한다** — 소유권 규칙은 [ADR 2026-08-29 앱 진입 화면 판정](../../adr/2026-08-29-onboarding-entry-decision-owned-by-onboarding.md)이 정했다. `3.0.2`와 `4.0.0` 사이에서 `FR-002`·`FR-003`·`FR-004`·`SC-002`의 의미가 바뀌었으므로, 이 spec을 근거로 만든 하위 문서는 `4.0.0` 기준으로 다시 확인해야 한다.

## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 브랜드 노출 및 자동 전환
사용자가 앱을 실행하면 브랜드 스플래시 화면이 잠시 노출되고, 그동안 앱이 「비회원 익명 세션」을 확보한 뒤 사용자 상태에 맞는 다음 화면으로 자동 이동한다. 갈 곳은 **온보딩을 끝냈는지**로 갈린다.

**Figma**: [스플래시 화면(012-1)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134659) · [스플래시 디자인 정책](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134725)

**진입 조건**: 사용자가 앱 아이콘을 눌러 앱을 실행한다(콜드 스타트).

1. 사용자가 앱을 실행한다 → 시스템은 로고 캐릭터 5종·`gguk` 워드마크·태그라인(`친구랑 같이 가고싶은 곳은, 꾹!`)이 담긴 스플래시 화면을 노출한다.
2. 시스템은 스플래시를 노출하는 동안 「비회원 익명 세션」을 확보한다 — 첫 서버 요청보다 먼저, 서버 요청과 구분되는 단계로 수행한다.
3. 최초 실행이다 → 시스템은 익명 세션을 새로 발급받는다. 이 대기는 3초 노출 안에 흡수된다.
4. 재실행이다 → 시스템은 저장된 세션을 네트워크 없이 복원한다. **다만 앱 진입 판정은 여전히 네트워크를 필요로 하므로, 대기가 없는 것은 세션 복원 구간뿐이다.**
5. 3초가 지나고 세션 확보와 앱 진입 판정이 모두 끝난다 → 시스템은 다음 화면으로 자동 전환한다.
6. 프로필이 없다(설치 후 첫 실행) → 시스템은 온보딩([SCR-002])으로 이동한다. 온보딩은 첫 스텝인 프로필 설정([SYS-011])부터 시작한다.
7. 프로필은 있으나 온보딩 완료 표시가 없다(온보딩을 끝내지 못하고 앱을 껐다) → 시스템은 온보딩([SCR-002])으로 이동한다. **어느 스텝부터 이어갈지는 온보딩이 정한다.**
8. 프로필이 있고 온보딩 완료 표시도 있다 → 시스템은 직전 세션의 메인 탭으로 이동한다.

**완료 조건**: 익명 세션이 확보된 채 스플래시 화면이 사라지고, 이 설치의 온보딩 진행 상태에 맞는 화면(온보딩 또는 메인 탭)이 노출된 상태.

### 유저 플로우 2 - 진입 지점 확보 지연 및 실패 안내
익명 세션 확보와 앱 진입 판정을 묶어 **진입 지점 확보**라 한다. 그것이 정상 속도로 끝나지 않으면, 사용자가 앱이 멈춘 것으로 오해하지 않도록 진행 중임을 알리고 끝내 실패하면 원인에 맞는 안내를 표출한다. 진입 지점이 확보되기 전에는 어느 화면으로도 들여보내지 않는다.

> **4.0.0까지 이 플로우는 「최초 실행 전용」이었다.** 판정이 서버 조회를 포함하므로 **오프라인 재실행도 이 플로우를 탄다** — 세션은 복원되지만 판정이 끝나지 않아 같은 안내와 재시도를 거친다(EC-002·TS-016 · §5 TBD-5).

**Figma**: [스플래시_로딩 중](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-166720) · [스플래시_네트워크 에러](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-166743) · [스플래시_일시적 오류](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-166766) · [스플래시 디자인 정책](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134725)

**진입 조건**: 스플래시가 노출된 상태에서 진입 지점 확보(세션 확보 + 앱 진입 판정)가 3초 안에 완료되지 않는다. 최초 실행은 세션 발급이, 오프라인 재실행은 판정이 그 원인이 된다.

1. 3초가 지나도 진입 지점이 확보되지 않는다 → 시스템은 자동 전환하지 않고 스플래시를 유지한 채 로딩 스피너를 노출한다(실패가 아니라 정상 경로가 느린 상태다).
2. 스피너 노출 후 10초가 더 지난다(앱 실행 기준 13초) → 시스템은 스피너를 감추고 일시적 오류 토스트 `일시적인 오류가 발생했어요`를 표출한다.
3. 네트워크 끊김·연결 오류로 세션을 확보하지 못한다 → 시스템은 토스트 `네트워크 연결을 확인해주세요`를 표출한다.
4. 네트워크 외의 사유로 세션 확보에 실패한다 → 시스템은 토스트 `일시적인 오류가 발생했어요`를 표출한다.
5. 어느 경우에도 시스템은 브랜드 스플래시 화면을 유지한 채 안내만 얹고, 진입 지점 확보를 자동으로 재시도한다. 사용자가 누르는 재시도 버튼은 두지 않는다.
6. 재시도가 성공한다 → 시스템은 사용자가 앱을 다시 실행하지 않아도 유저 플로우 1의 전환을 이어간다.

**완료 조건**: 사용자가 앱의 현재 상태(진행 중 / 네트워크 문제 / 일시적 문제)를 화면에서 알 수 있고, 진입 지점이 확보되는 즉시 별도 조작 없이 다음 화면으로 넘어가는 상태.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 앱 실행 직후 로고 캐릭터·`gguk` 워드마크·태그라인이 담긴 스플래시 화면을 최소 3초간 노출해야 한다. (근거: business-context.md [SCR-001] Flow A, Figma 012-1)
- **FR-002**: 시스템은 반드시 스플래시 노출 중 「비회원 익명 세션」을 첫 서버 요청보다 먼저·구분되는 단계로 확보하고 **앱 진입 판정**(프로필 등록 여부와 온보딩 완료 표시)을 수행해, 최소 노출 시간과 판정이 모두 끝나면 그 결과에 따라 다음 화면으로 자동 전환해야 한다. (근거: business-context.md [SCR-001] Flow A "첫 서버 요청보다 먼저, 서버 요청과 구분되는 단계로 세션을 확보한다" / 판정 근거가 둘인 이유는 `docs/specs/onboarding-flow` FR-022 — §4 참고)
- **FR-003**: 시스템은 반드시 **온보딩을 끝내지 않은 설치**이면 온보딩([SCR-002])으로 이동해야 한다. 끝내지 않은 설치란 프로필이 등록되지 않았거나 온보딩 완료 표시가 없는 설치를 말하며, 둘 중 하나라도 없으면 여기에 해당한다. **어느 스텝부터 여는지는 온보딩이 정하고 이 화면은 관여하지 않는다.** (근거: business-context.md [SCR-001] Flow A / `docs/specs/onboarding-flow` FR-003·FR-021·FR-022·FR-023 · [ADR 2026-08-29](../../adr/2026-08-29-onboarding-entry-decision-owned-by-onboarding.md))
- **FR-004**: 시스템은 반드시 **온보딩을 끝낸 설치**이면(프로필이 등록되어 있고 온보딩 완료 표시도 있으면) 직전 세션의 메인 탭으로 이동해야 한다. (근거: business-context.md [SCR-001] Flow A / `docs/specs/onboarding-flow` FR-021)
- **FR-005**: 시스템은 반드시 스플래시 화면에서 사용자의 터치·제스처 입력이 다음 화면으로의 전환에 영향을 주지 않게 해야 한다(전환은 오직 시간 경과와 세션·앱 진입 판정 결과로만 트리거된다). (근거: business-context.md [SCR-001] "자동으로 다음 화면 이동")
- **FR-006**: 시스템은 반드시 3초가 지나도 **진입 지점**(세션 확보 + 앱 진입 판정)이 확보되지 않으면 자동 전환하지 않고 스플래시를 유지한 채 로딩 스피너를 노출해야 한다. (근거: business-context.md [SCR-001] Flow B. PRD는 이 조건을 세션 확보로만 적었으나 판정도 같은 대기에 속한다 — §5 TBD-5)
- **FR-007**: 시스템은 반드시 스피너 노출 후 10초가 더 지나도 진입 지점이 확보되지 않으면(앱 실행 기준 13초) 스피너를 감추고 일시적 오류 토스트 `일시적인 오류가 발생했어요`를 표출해야 한다. (근거: business-context.md [SCR-001] Flow B "스피너 노출 후 10초가 더 지나면 스피너를 감추고 Flow D의 일시적 오류 토스트를 표출한다")
- **FR-008**: 시스템은 반드시 네트워크 끊김·연결 오류로 세션을 확보하지 못하면 토스트 `네트워크 연결을 확인해주세요`를 표출해야 한다. (근거: business-context.md [SCR-001] Flow C)
- **FR-009**: 시스템은 반드시 네트워크 외의 사유로 세션 확보에 실패하면 토스트 `일시적인 오류가 발생했어요`를 표출해야 한다. (근거: business-context.md [SCR-001] Flow D)
- **FR-010**: 시스템은 반드시 **진입 지점을 확보하기 전에는** 어느 화면으로도 진입시키지 않고 스플래시에 머무른 채 자동으로 재시도하며, 확보되는 즉시 전환을 이어가야 한다. 사용자가 누르는 재시도 버튼은 두지 않는다. **세션이 복원된 재실행이라도 앱 진입 판정이 끝나지 않았으면 진입시키지 않는다.** (근거: business-context.md [SCR-001] Flow E · §5 TBD-5)
- **FR-011**: 시스템은 반드시 재실행에서 **저장된 세션을 네트워크 없이 복원**해, 세션 발급을 기다리는 구간을 두지 않아야 한다. **이 보장은 세션 복원에 한정된다** — 뒤이은 앱 진입 판정은 네트워크를 필요로 하므로, 재실행이라도 오프라인이면 지연·실패 경로(FR-006~FR-010)를 탄다. (근거: business-context.md [SCR-001] Flow A·E는 재실행이 Flow B~E를 타지 않는다고 적었으나 판정 조회를 셈에 넣지 않았다 — §5 TBD-5)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 스플래시 화면에는 다음 화면으로 넘어가기 위한 버튼이나 안내 문구를 두지 않는다 — 전환은 전적으로 자동이며, 실패 상태에서도 재시도 버튼을 두지 않는다. (근거: business-context.md [SCR-001] Flow A·E)
- **UX-002**: 세션·앱 진입 판정이 3초보다 먼저 끝나더라도 최소 3초는 스플래시를 유지해, 브랜드 노출 시간이 기기 성능에 따라 짧아지지 않게 한다. (근거: business-context.md [SCR-001] "3초간 노출")
- **UX-003**: 오류 토스트는 스크린 하단에서 40dp 간격을 띄운 위치에 표출한다. (근거: business-context.md [SCR-001] Flow E "스크린 하단에서 40px 띄운 위치". PRD 수치는 Figma 시안 기준 px이며, 375pt 1배율 시안의 40px은 Android의 40dp에 대응한다 — §4 참고)
- **UX-004**: 지연·실패 상황에서도 브랜드 스플래시 화면을 유지하며, 별도의 에러 전용 화면으로 전환하지 않는다 — 로딩 스피너와 토스트만 화면 위에 얹는다. (근거: Figma 012-2·012-3·012-4가 모두 012-1과 동일한 스플래시 배경 위에 표현됨)
- **UX-005**: 로딩 스피너는 진입 지점 확보가 최소 노출 시간 3초를 넘겨 지연될 때만 노출하며, 그 안에 완료되는 경우에는 한 번도 노출하지 않는다(짧은 깜빡임 방지). (근거: business-context.md [SCR-001] Flow B "실패가 아니라 정상 경로가 느린 상태다")
- **UX-006**: 오류 토스트는 실패가 이어지는 동안 반복 표출하되, 직전 표출로부터 최소 10초 간격을 둔다 — 상황이 계속되고 있음을 알리면서도 토스트가 연달아 쌓이지 않게 한다. (근거: §5 TBD-3 확정. PRD가 정하지 않은 영역이다)
- **UX-007**: 오류 토스트 문구는 세션 확보 실패임을 드러낸다. `장소를 불러오지 못했습니다` 같은 데이터 조회 실패 문구로 뭉뚱그리지 않는다 — 사용자가 취할 행동이 어긋난다. (근거: business-context.md [SCR-001] Flow E)

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 세션 확보와 앱 진입 판정이 정상 완료되는 경우, 앱 실행 후 스플래시 화면이 3초(±0.5초 이내) 노출된 뒤 다음 화면으로 전환된다.
- **SC-002**: 앱 진입 판정이 100% 정확해, 온보딩을 끝내지 않은 사용자가 메인 탭으로 진입하거나 온보딩을 끝낸 사용자가 온보딩으로 되돌아가는 경우가 **0건**이다. 특히 **프로필을 저장한 뒤 온보딩을 중단한 사용자가 남은 스텝을 보지 못한 채 메인 탭에 도착하는 경우가 0건**이다.
- **SC-003**: 진입 지점 확보가 지연되거나 실패해도 사용자가 앱이 멈췄다고 오해할 여지가 없다 — 3초 초과 시 로딩 스피너로, 13초 초과·실패 시 토스트로 반드시 현재 상태를 알린다. 오프라인 재실행도 같다.
- **SC-004**: 실패 상황에서 원인 유형(네트워크 / 그 외)에 맞는 토스트가 표출되어, 사용자가 네트워크를 확인해야 하는 상황인지 아닌지 구분할 수 있다.
- **SC-005**: 실패 원인이 해소되면(예: 네트워크 복구) 사용자가 앱을 다시 실행하지 않아도 다음 화면으로 진입한다.
- **SC-006**: 진입 지점이 확보되지 않은 상태로 스플래시 밖의 화면이 노출되는 경우가 0건이다 — 「익명 세션은 항상 확보되어 있다」와 「진입 판정은 항상 끝나 있다」가 앱 전체의 전제로 성립한다.

### 3.2 비목표 항목 (Out of Scope)

- 온보딩([SCR-002])과 프로필 설정([SYS-011])의 화면 구성·진행 로직은 이 스펙이 정의하지 않는다. 이 스펙은 스플래시에서 그 화면으로의 진입 시점까지만 다룬다.
- **온보딩을 띄우는 조건 자체도 이 스펙이 소유하지 않는다.** `docs/specs/onboarding-flow`(FR-021·FR-022)가 그 판정 기준을 정하고, 이 스펙은 그것을 **소비**해 전환을 실행한다. 온보딩의 스텝 구성이 바뀌어 판정 근거가 늘거나 줄면 개정의 출발점은 그 문서이며, 이 문서는 따라 고친다. 소유권 규칙은 [ADR 2026-08-29](../../adr/2026-08-29-onboarding-entry-decision-owned-by-onboarding.md)가 정했다.
- 온보딩을 중단한 사용자가 **어느 스텝부터 이어가는지**는 `docs/specs/onboarding-flow` FR-023이 정의한다. 이 스펙은 온보딩으로 보낸다는 사실까지만 다룬다.
- 온보딩 완료 표시를 **기록하는 시점과 방법**은 `docs/specs/onboarding-flow` FR-024가 정의한다. 이 스펙은 그 값을 읽기만 한다.
- 메인 탭([SYS-005])의 탭 구성과 상태 복원 로직 자체는 이 스펙이 정의하지 않는다. 이 스펙은 스플래시에서 메인 탭으로의 진입 시점까지만 다룬다.
- 「비회원 익명 세션」의 발급 방식(인증 제공자 연동, 익명 계정 식별자 발급·보관, 서명 검증)은 이 스펙이 정의하지 않는다. 스플래시는 세션 확보의 성공·실패 결과만 소비한다.
- 프로필 데이터 저장·조회의 구현 방식(로컬 저장소, 서버 동기화 등)은 이 스펙이 정의하지 않는다.
- 로딩 스피너·토스트 컴포넌트 자체의 디자인 규격(크기, 색, 노출 지속 시간)은 공용 디자인 시스템의 소관이며 이 스펙이 정의하지 않는다. 문구와 표출 위치는 PRD가 확정했으므로 이 스펙이 그대로 인용한다.
- 익명 세션을 실제 계정으로 승격해 재설치·기기 변경 후에도 데이터를 잇는 것은 MVP 범위 밖이다. (근거: business-context.md 비목표)
- 초대 링크(딥링크)를 통한 앱 진입 시나리오([SYS-010])는 이 스펙이 정의하지 않는다.

## 4. 가정 (Assumptions)

- 이용자 구분의 근거는 앱이 만든 기기 식별자가 아니라 인증 제공자가 발급한 익명 계정 식별자이며, 세션은 기기가 아니라 앱 설치에 묶인다고 가정한다. (근거: business-context.md 핵심 원칙 "비회원 익명 세션")
- 설치가 살아 있는 동안 익명 세션은 만료되지 않으므로, 스플래시에 "무효 세션 감지 후 재발급" 경로를 두지 않는다고 가정한다. (근거: business-context.md TBD 확정 항목)
- 최초 실행의 익명 세션 발급은 네트워크를 필요로 하고, 재실행의 세션 복원은 네트워크를 필요로 하지 않는다고 가정한다. **그러나 지연·실패 경로가 최초 실행 전용인 것은 아니다** — 앱 진입 판정이 서버 조회를 포함하므로 오프라인 재실행도 그 경로를 탄다(§5 TBD-5).
- **오프라인 사용자는 최초 실행이든 재실행이든 앱을 이용할 수 없다.** PRD는 이 비용을 최초 실행에만 수용했으나, 진입 판정이 서버 조회인 이상 재실행도 같은 결과가 된다. 이 스펙은 우회 경로를 두지 않는다(§5 TBD-5).
- 프로필 존재 여부 판정은 세션이 확보된 뒤에 가능하다고 가정한다 — 따라서 세션 확보 실패는 곧 앱 진입 판정 불가를 뜻한다.
- **온보딩 완료 표시는 이 앱 설치 안에 기록되어 있고, 읽는 데 네트워크가 필요하지 않다고 가정한다.** 그 값의 원천과 기록 시점은 `docs/specs/onboarding-flow`가 소유한다(FR-024). 따라서 이 값을 읽는 것은 지연·실패 경로(FR-006~FR-010)를 만들지 않으며, 판정이 늦어지는 유일한 원인은 여전히 세션 확보와 프로필 조회다.
- **두 근거를 확인하는 순서에 제약이 있다고 가정한다.** 프로필 등록 여부를 먼저 확인해야 하며, 그 이유와 구속력은 [ADR 2026-08-29](../../adr/2026-08-29-onboarding-entry-decision-owned-by-onboarding.md)가 소유한다. 이 문서는 순서가 사용자에게 드러나지 않는 내부 제약임을 기록만 하고 요구사항으로 세우지 않는다.
- 앱을 지웠다 다시 설치하면 프로필과 온보딩 완료 표시가 함께 사라져 온보딩을 처음부터 거친다고 가정한다. 세션이 기기가 아니라 앱 설치에 묶여 있기 때문이다(business-context.md 「비회원 익명 세션」).
- 직전 세션의 메인 탭 상태(마지막으로 보고 있던 탭)는 이미 [SYS-005] 바텀 네비게이션이 보존하고 있다고 가정하며, 이 스펙은 그 상태로 진입하는 것만 다룬다.
- 스플래시는 앱의 런처 진입점이며, 항상 콜드 스타트에만 노출된다(백그라운드 복귀 시에는 노출되지 않는다)고 가정한다.
- 스플래시 화면은 로딩 스피너를 제외하면 정적 이미지·텍스트로만 구성되며 별도의 애니메이션 요구사항은 없다고 가정한다(Figma 012-1 시안이 정적 레이아웃이다).
- PRD의 수치 표기는 Figma 시안을 기준으로 쓰였고 Android 단위계로 쓰인 것이 아니다. 따라서 토스트 표출 위치의 `40px`(PRD [SCR-001] Flow E)은 375pt 1배율 시안 기준값이며, Android 산출물인 이 스펙은 이를 `40dp`로 옮겨 적는다. PRD 쪽에 정정할 것은 없다.
- 자동 재시도의 간격과 횟수 상한 같은 세부 정책은 이 스펙이 정하지 않으며, 재시도가 이어지는 동안 사용자가 현재 상태를 알 수 있으면 충족된 것으로 본다.

## 5. TBD 기록 (Resolved Clarifications)

### 해소된 항목

- **TBD-1** Q: 로딩 스피너를 노출하기 시작하는 지연 임계 시간은 몇 초이며, "10초 경과"는 앱 실행 시점부터 세는가 스피너 노출 시점부터 세는가?
  → A(2.0.0 시점): 3초 후 스피너, 10초는 앱 실행 시점부터(총 10초).
  → **A(3.0.0 확정, PRD 5.0.0 대조로 정정)**: 3초 후 스피너, **스피너 노출 후 10초를 더** 센다(앱 실행 기준 **총 13초**). 2.0.0의 답은 PRD 5.0.0 `[SCR-001]` Flow B와 어긋나 폐기했다. → FR-006, FR-007, SC-003 반영
- **TBD-2** Q: 오류 토스트가 표출된 뒤 앱은 어떤 상태로 남는가 — 스플래시에 머문 채 백그라운드에서 자동 재시도하는가, 사용자에게 재시도 수단을 주는가, 아니면 아무 행동 없이 대기하는가?
  → A: 스플래시를 유지한 채 자동으로 재시도하며, 성공하는 순간 다음 화면으로 전환한다. 재시도 버튼은 두지 않는다. PRD 5.0.0 Flow E가 같은 결론을 이미 확정해 두었음을 3.0.0에서 확인했다. → FR-010, SC-005, SC-006 반영
- **TBD-3** Q: 오류 토스트 표출 후 재시도가 다시 실패하면 토스트를 반복 표출하는가, 아니면 한 번만 표출하는가?
  → A: 실패가 이어지는 동안 반복 표출하되 직전 표출로부터 최소 10초 간격을 둔다. PRD가 정하지 않은 영역이라 이 스펙에서 확정했다. → UX-006 반영

- **TBD-4** Q: 앱 진입 판정의 근거는 `프로필 없음` 하나로 충분한가? PRD [SCR-001] Flow A는 최초 실행 기준을 그렇게만 적고 있다.
  → **A(4.0.0 확정)**: **충분하지 않다. `프로필 등록 여부`와 `온보딩 완료 표시` 둘을 함께 본다.** 프로필 저장은 온보딩 네 스텝 중 첫 스텝일 뿐이라, 그 하나를 완료 조건으로 쓰면 프로필을 저장한 뒤 앱을 껐다 켠 사용자가 메인 탭으로 밀려나 남은 세 스텝을 영영 보지 못한다.
  - 이 판정의 **소유자는 이 문서가 아니다.** `docs/specs/onboarding-flow` 1.2.0 §3.2가 판정 기준의 소유권을 그 문서(FR-021·FR-022)로 못박았고, 이 문서는 소비자다. 일반화된 규칙은 [ADR 2026-08-29](../../adr/2026-08-29-onboarding-entry-decision-owned-by-onboarding.md)가 갖는다.
  - **PRD [SCR-001] Flow A는 아직 이 결정을 반영하지 않았다**(9.0.0 기준). 그 문장의 "최초 실행(프로필 없음)"이 온보딩이 1스텝이던 시절의 서술로 남아 있어 개정이 필요하다. → FR-002, FR-003, FR-004, SC-002 반영

- **TBD-5** Q: 오프라인 **재실행**은 어떻게 되는가? PRD [SCR-001] Flow A·E는 "재실행은 저장된 세션을 네트워크 없이 복원하므로 Flow B~E를 타지 않는다. 이 경로는 최초 실행 전용이다"라고 적었다.
  → **A(5.0.0 확정)**: **그 약속을 걷어낸다.** 세션은 네트워크 없이 복원되지만 **앱 진입 판정(`프로필 등록 여부`)이 서버 조회**라 오프라인에서는 끝나지 않는다. 판정이 끝나기 전에는 어느 화면으로도 들여보내지 않으므로(FR-010), 오프라인 재실행 사용자는 스플래시에 머문 채 3초 스피너·13초 토스트를 거치며 재시도하고 **네트워크가 돌아올 때까지 앱을 쓸 수 없다.**
  - **명세를 구현 동작에 맞춘 선택이다.** 세 안을 검토했다 — ①완료 표시가 있으면 서버 조회를 생략해 오프라인 재실행을 살린다 ②네트워크 실패 시 완료 표시로 폴백한다 ③현행 동작을 명세로 승인한다. **③을 골랐다.**
  - **대가는 정상 유저 시나리오 하나가 막히는 것이다.** 오프라인 재실행은 흔한 경로이고, PRD가 오프라인 이용 불가를 수용한 범위는 최초 실행뿐이었다. ①을 고르면 이 대가가 사라지는 대신 저장값이 손상된 이례 조합(`프로필 없음 + 완료 표시 있음`)을 진입 시점에 감지하지 못한다.
  - **PRD [SCR-001] Flow A·E의 개정이 필요하다.** 이 spec은 그 문장을 따르지 않는 유일한 항목을 갖게 됐다. → FR-006, FR-007, FR-010, FR-011, EC-002, EC-006, TS-016, SC-003, SC-006 반영

### PRD 재대조 이력

- **4.0.0 (2026-08-29)**: 기준 PRD는 `9.0.0`으로 그대로다. 이번 개정은 PRD 변경이 아니라 **형제 spec(`docs/specs/onboarding-flow` 1.2.0)의 소유권 판정**에서 왔다. 대조 결과 **PRD [SCR-001] Flow A가 이 spec과 어긋난 상태로 남는다** — 그 문장은 최초 실행 기준을 여전히 `프로필 없음`으로만 적고 있다. PRD 개정이 필요하며, 이 spec은 온보딩 spec을 따랐다(§5 TBD-4).
- **5.0.0 (2026-08-29)**: 기준 PRD는 `9.0.0`으로 그대로다. **이 개정으로 PRD와 어긋나는 항목이 하나 더 생겼다** — [SCR-001] Flow A·E의 "재실행은 … Flow B~E를 타지 않는다. 이 경로는 최초 실행 전용이다"가 성립하지 않는다(§5 TBD-5). 4.0.0에서 기록한 어긋남([SCR-001] Flow A의 `프로필 없음` 판정 기준)과 함께 **PRD 개정 대상이 2건**이 됐다.
- **4.0.0 (2026-08-29)**: 기준 PRD를 5.0.0 → 9.0.0으로 갱신했다. `[SCR-001]`·`[SCR-002]`·`[SYS-011]`과 핵심 원칙 「비회원 익명 세션」이 5.0.0과 **문자 단위로 동일**해 요구사항 변동이 없다. 6.0.0~9.0.0 개정은 홈 덱 전환 규칙·카드 액션 메뉴·홈 확인 이벤트에 한정된다.
