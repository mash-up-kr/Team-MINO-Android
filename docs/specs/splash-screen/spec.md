## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 브랜드 노출 및 자동 전환
사용자가 앱을 실행하면 브랜드 스플래시 화면이 잠시 노출되고, 그동안 앱이 디바이스 세션을 확보한 뒤 사용자 상태에 맞는 다음 화면으로 자동 이동한다.

**Figma**: [스플래시 화면(012-1)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134659) · [스플래시 디자인 정책(012-1)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134725)

**진입 조건**: 사용자가 앱 아이콘을 눌러 앱을 실행한다(콜드 스타트).

1. 사용자가 앱을 실행한다 → 시스템은 로고 캐릭터 5종·`gguk` 워드마크·태그라인(`친구랑 같이 가고싶은 곳은, 꾹!`)이 담긴 스플래시 화면을 노출한다.
2. 시스템은 스플래시를 노출하는 동안 디바이스 세션을 확보하고 프로필 존재 여부를 판정한다.
3. 3초가 지나고 세션·프로필 판정이 모두 끝난다 → 시스템은 다음 화면으로 자동 전환한다.
4. 프로필이 없다(최초 실행) → 시스템은 온보딩([SCR-002])의 첫 스텝인 프로필 설정([SYS-011])으로 이동한다.
5. 프로필이 있다(재실행) → 시스템은 직전 세션의 메인 탭으로 이동한다.

**완료 조건**: 스플래시 화면이 사라지고, 사용자 상태에 맞는 화면(프로필 설정 또는 메인 탭)이 노출된 상태.

### 유저 플로우 2 - 세션 확보 지연 및 실패 안내
세션 확보가 정상 속도로 끝나지 않으면, 사용자가 앱이 멈춘 것으로 오해하지 않도록 진행 중임을 알리고 끝내 실패하면 원인에 맞는 안내를 표출한다.

**Figma**: [스플래시 디자인 정책(012-2 로딩 중 · 012-3 네트워크 에러 · 012-4 일시적 오류)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-134725)

**진입 조건**: 스플래시가 노출된 상태에서 디바이스 세션 확보가 정상 속도로 완료되지 않는다.

1. 최소 노출 시간 3초가 지났는데도 세션 확보가 끝나지 않는다 → 시스템은 스플래시 화면 위에 로딩 스피너를 노출한다.
2. 지연이 이어져 앱 실행 후 10초가 경과한다 → 시스템은 일시적 오류 토스트를 표출하고 로딩 스피너를 제거한다.
3. 세션 확보가 네트워크 끊김·네트워크 에러로 실패한다 → 시스템은 네트워크 연결 에러 토스트를 표출한다.
4. 세션 확보가 네트워크 에러 외의 사유로 실패한다 → 시스템은 일시적 오류 토스트를 표출한다.
5. 어느 경우에도 시스템은 브랜드 스플래시 화면을 유지한 채 안내만 얹고, 세션 확보를 자동으로 재시도한다.
6. 재시도가 성공한다 → 시스템은 사용자가 앱을 다시 실행하지 않아도 다음 화면으로 전환한다.

**완료 조건**: 사용자가 앱의 현재 상태(진행 중 / 네트워크 문제 / 일시적 문제)를 화면에서 알 수 있고, 상황이 해소되면 별도 조작 없이 다음 화면으로 넘어가는 상태.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 앱 실행 직후 로고 캐릭터·`gguk` 워드마크·태그라인이 담긴 스플래시 화면을 최소 3초간 노출해야 한다. (근거: business-context.md [SCR-001] Flow A, Figma 012-1)
- **FR-002**: 시스템은 반드시 스플래시 노출 중 디바이스 세션을 확보하고 프로필 존재 여부를 판정해, 최소 노출 시간과 판정이 모두 끝나면 그 결과에 따라 다음 화면으로 자동 전환해야 한다. (근거: business-context.md [SCR-001] Flow A, 핵심 원칙 "비회원 디바이스 세션", Figma 012-1)
- **FR-003**: 시스템은 반드시 프로필이 없는 최초 실행이면 온보딩([SCR-002])의 첫 스텝인 프로필 설정([SYS-011])으로 이동해야 한다. (근거: business-context.md [SCR-001] Flow A, Figma 012-1 "3초뒤 010[프로필 설정]으로 이동합니다")
- **FR-004**: 시스템은 반드시 프로필이 있는 재실행이면 직전 세션의 메인 탭으로 이동해야 한다. (근거: business-context.md [SCR-001] Flow A)
- **FR-005**: 시스템은 반드시 스플래시 화면에서 사용자의 터치·제스처 입력이 다음 화면으로의 전환에 영향을 주지 않게 해야 한다(전환은 오직 시간 경과와 세션·프로필 판정 결과로만 트리거된다). (근거: business-context.md [SCR-001] "자동으로 다음 화면 이동")
- **FR-006**: 시스템은 반드시 최소 노출 시간 3초가 지났는데도 세션 확보가 끝나지 않으면 스플래시 화면 위에 로딩 스피너를 노출해야 한다. (근거: Figma 012-2 "정상적인 세션 발급이 느릴 경우 사용되는 화면")
- **FR-007**: 시스템은 반드시 앱 실행 시점부터 10초가 경과할 때까지 세션 확보가 끝나지 않으면 일시적 오류 토스트를 표출하고 로딩 스피너를 제거해야 한다. (근거: Figma 012-2 "10초 경과 시 일시적 오류 토스트를 표출하고, 로딩스피너는 사라집니다")
- **FR-008**: 시스템은 반드시 네트워크 끊김 또는 네트워크 에러로 세션 확보에 실패하면 네트워크 연결 에러 토스트를 표출해야 한다. (근거: Figma 012-3 "네트워크 끊김 또는 에러 상황 시 화면")
- **FR-009**: 시스템은 반드시 네트워크 에러 외의 사유로 세션 확보에 실패하면 일시적 오류 토스트를 표출해야 한다. (근거: Figma 012-4 "네트워크 에러 외 실패 케이스에 사용되는 화면")
- **FR-010**: 시스템은 반드시 세션 확보가 실패하거나 10초를 초과한 뒤에도 스플래시 화면을 유지한 채 세션 확보를 자동으로 재시도하고, 성공하면 사용자의 별도 조작 없이 다음 화면으로 전환해야 한다. (근거: TBD-2 확정, UX-001 "전환 버튼을 두지 않는다")

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 스플래시 화면에는 다음 화면으로 넘어가기 위한 버튼이나 안내 문구를 두지 않는다 — 전환은 전적으로 자동이다. (근거: business-context.md [SCR-001] Flow A)
- **UX-002**: 세션·프로필 판정이 3초보다 먼저 끝나더라도 최소 3초는 스플래시를 유지해, 브랜드 노출 시간이 기기 성능에 따라 짧아지지 않게 한다. (근거: business-context.md [SCR-001] "3초간 노출")
- **UX-003**: 오류 토스트는 스크린 하단에서 40dp 간격을 띄운 위치에 표출한다. (근거: Figma 012-3·012-4 "스크린 하단에서 40px 간격을 띄워 toast 모달을 표출합니다", 375pt 1배율 기준 40px = 40dp)
- **UX-004**: 지연·실패 상황에서도 브랜드 스플래시 화면을 유지하며, 별도의 에러 전용 화면으로 전환하지 않는다 — 로딩 스피너와 토스트만 화면 위에 얹는다. (근거: Figma 012-2·012-3·012-4가 모두 012-1과 동일한 스플래시 배경 위에 표현됨)
- **UX-005**: 로딩 스피너는 최소 노출 시간 3초를 넘겨 지연될 때만 노출하며, 그 안에 완료되는 경우에는 한 번도 노출하지 않는다(짧은 깜빡임 방지). (근거: Figma 012-2 "정상적인 세션 발급이 느릴 경우 사용되는 화면")
- **UX-006**: 오류 토스트는 실패가 이어지는 동안 반복 표출하되, 직전 표출로부터 최소 10초 간격을 둔다 — 상황이 계속되고 있음을 알리면서도 토스트가 연달아 쌓이지 않게 한다. (근거: TBD-3 확정)

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 세션·프로필 판정이 정상 완료되는 경우, 앱 실행 후 스플래시 화면이 3초(±0.5초 이내) 노출된 뒤 다음 화면으로 전환된다.
- **SC-002**: 프로필 유무 판정이 100% 정확해, 최초 실행 사용자가 메인 탭으로 잘못 진입하거나 기존 사용자가 프로필 설정으로 잘못 진입하는 경우가 없다.
- **SC-003**: 세션 확보가 지연되거나 실패해도 사용자가 앱이 멈췄다고 오해할 여지가 없다 — 지연 시에는 로딩 스피너로, 10초 초과·실패 시에는 토스트로 반드시 현재 상태를 알린다.
- **SC-004**: 실패 상황에서 원인 유형(네트워크 / 그 외)에 맞는 토스트가 표출되어, 사용자가 네트워크를 확인해야 하는 상황인지 아닌지 구분할 수 있다.
- **SC-005**: 실패 원인이 해소되면(예: 네트워크 복구) 사용자가 앱을 다시 실행하지 않아도 다음 화면으로 진입한다.

### 3.2 비목표 항목 (Out of Scope)

- 온보딩([SCR-002])과 프로필 설정([SYS-011])의 화면 구성·진행 로직은 이 스펙이 정의하지 않는다. 이 스펙은 스플래시에서 그 화면으로의 진입 시점까지만 다룬다.
- 메인 탭([SYS-005])의 탭 구성과 상태 복원 로직 자체는 이 스펙이 정의하지 않는다. 이 스펙은 스플래시에서 메인 탭으로의 진입 시점까지만 다룬다.
- 디바이스 세션의 발급 방식(식별자 생성, 인증 프로토콜, 갱신 주기)은 이 스펙이 정의하지 않는다. 스플래시는 세션 확보의 성공·실패 결과만 소비한다.
- 프로필 데이터 저장·조회의 구현 방식(로컬 저장소, 서버 동기화 등)은 이 스펙이 정의하지 않는다.
- 로딩 스피너·토스트 컴포넌트 자체의 디자인 규격(크기, 색, 노출 시간)은 공용 디자인 시스템의 소관이며 이 스펙이 정의하지 않는다. 이 스펙은 무엇을 언제 어디에 띄우는지만 정한다.
- 초대 링크(딥링크)를 통한 앱 진입 시나리오([SYS-010])는 이 스펙이 정의하지 않는다. PRD상에서도 앱 미설치·프로필 미생성·기존 사용자 3가지 분기가 아직 확정되지 않은 열린 질문이다.

## 4. 가정 (Assumptions)

- 디바이스 세션 확보는 네트워크를 필요로 하며, 그래서 네트워크 상태가 스플래시의 지연·실패 분기를 좌우한다고 가정한다.
- 이미 유효한 디바이스 세션이 저장되어 있으면 재발급 없이 즉시 통과한다고 가정한다(EC-002).
- 프로필 존재 여부 판정은 세션이 확보된 뒤에 가능하다고 가정한다 — 따라서 세션 확보 실패는 곧 프로필 판정 불가를 뜻한다.
- 직전 세션의 메인 탭 상태(마지막으로 보고 있던 탭)는 이미 [SYS-005] 바텀 네비게이션이 보존하고 있다고 가정하며, 이 스펙은 그 상태로 진입하는 것만 다룬다.
- 스플래시는 앱의 런처 진입점이며, 항상 콜드 스타트에만 노출된다(백그라운드 복귀 시에는 노출되지 않는다)고 가정한다.
- 스플래시 화면은 로딩 스피너를 제외하면 정적 이미지·텍스트로만 구성되며 별도의 애니메이션 요구사항은 없다고 가정한다(Figma 012-1 시안이 정적 레이아웃이다).
- Figma 정책의 `40px`은 375pt 1배율 시안 기준값이므로 Android에서 `40dp`로 대응한다고 가정한다.
- 자동 재시도의 간격과 횟수 상한 같은 세부 정책은 이 스펙이 정하지 않으며, 재시도가 이어지는 동안 사용자가 현재 상태를 알 수 있으면 충족된 것으로 본다.

### 해소된 항목

- **TBD-1** Q: 로딩 스피너를 노출하기 시작하는 지연 임계 시간은 몇 초이며, "10초 경과"는 앱 실행 시점부터 세는가 스피너 노출 시점부터 세는가?

- **TBD-2** Q: 오류 토스트가 표출된 뒤 앱은 어떤 상태로 남는가 — 스플래시에 머문 채 백그라운드에서 자동 재시도하는가, 사용자에게 재시도 수단을 주는가, 아니면 아무 행동 없이 대기하는가?
