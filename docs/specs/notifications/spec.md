## 1. 유저 시나리오 (User Scenarios) *(필수)*
### 유저 플로우 1 - 알림 목록 조회
알림 탭에 들어가 지금까지 받은 알림을 최신순으로 훑어본다. 각 알림은 무슨 일이 있었는지(유형 문구)와 그 대상이 무엇인지(장소명 또는 방 이름), 그리고 얼마나 지났는지를 한 줄로 보여준다.

**Figma**: [007-1-2 알림_알림 활성](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3037-90987&m=dev) · [007-1-3 알림_Empty state](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3037-90978&m=dev)

**진입 조건**: 프로필 설정을 마친 사용자가 바텀 네비게이션의 세 번째 탭(`알림`)을 누른다.

1. `알림` 탭 선택 → 상단에 `알림` 제목이 있는 알림 목록 화면으로 전환한다
2. 목록이 그려짐 → 받은 알림 중 최신 20건을 나열하고, 각 행에 썸네일·유형 문구·대상 이름·경과 시간을 표시한다
3. 목록 끝까지 스크롤 → 다음 20건이 아래에 이어 붙으며, 남은 알림이 없을 때까지 반복한다
4. 다른 탭으로 이동했다가 `알림` 탭으로 복귀 → 직전 스크롤 위치를 유지한 목록을 다시 보여준다

**완료 조건**: 사용자가 받은 알림 전체를 최신순으로 확인할 수 있고, 각 알림의 유형·대상·경과 시간이 화면에 드러나 있다. 모든 알림은 읽음 여부와 무관하게 같은 형태로 보인다.

### 유저 플로우 2 - 알림 클릭 후 대상 화면 이동
알림을 눌러 그 알림이 가리키는 화면으로 곧바로 이동한다. 유형에 따라 도착지가 다르다.

**Figma**: [007-1-2 알림_알림 활성](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3037-90987&m=dev)

**진입 조건**: 알림 목록에 알림이 1건 이상 있다.

1. 장소 대상 알림(중복 저장 / 위치 기반 리마인드 / 코멘트 기반 리마인드) 클릭 → 그 장소의 장소 상세 화면으로 이동한다
2. 방 대상 알림(공동방 참가 ① / 공동방 참가 ②) 클릭 → 그 공동방의 방 상세 화면으로 이동한다
3. 저장 오류 알림 클릭 → 저장 오류 안내 화면으로 이동한다 (유저 플로우 3)
4. 이동한 화면에서 뒤로가기 → 알림 목록으로 돌아온다

목록에 있는 모든 알림은 이 세 갈래 중 하나로 이동한다. 위치 기반 대표 알림은 목록에 행이 없으므로(FR-019) 여기서 다루지 않는다.

**완료 조건**: 사용자가 알림 한 번의 클릭으로 그 알림이 가리키는 대상 화면에 도달한다.

### 유저 플로우 3 - 저장 오류 안내 확인
저장에 실패한 이유를 알고 싶은 사용자가 저장 오류 알림을 눌러, 어떤 게시물이 저장되지 않는지 안내를 읽는다.

**Figma**: [007-2 저장 오류 시](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3037-91057&m=dev)

**진입 조건**: 알림 목록에 `장소를 저장하지 못했어요.` 알림이 있다.

1. 저장 오류 알림 클릭 → 저장 오류 안내 화면으로 이동한다
2. 화면이 그려짐 → 스팟 일러스트와 `확인해주세요` 제목, 그리고 실패 조건 3줄을 표시한다
3. 상단 [뒤로가기] 클릭 → 알림 목록으로 돌아온다

**완료 조건**: 사용자가 `현재 한국 내 장소만 지원됩니다.` / `사진 속 장소인식은 아직 지원하지 않습니다` / `본문에 주소나 장소명을 포함해주세요` 세 가지 안내를 모두 확인할 수 있다.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)
- **FR-001**: 시스템은 반드시 알림 탭에서 사용자가 받은 알림을 발생 시각 기준 최신순으로 나열한다. (근거: 디자인 정책 `007-1-2 알림_알림 활성`(3037-90987) / PRD [SCR-007] Flow A)
- **FR-002**: 시스템은 반드시 각 알림 행을 썸네일 · 유형 문구 · 대상 이름(장소명 또는 공동방 이름) · 경과 시간 네 요소로 구성해 표시한다. (근거: 디자인 정책 `007-1-2`(3037-90987) 알림 Card 구성)
- **FR-003**: 시스템은 반드시 알림의 경과 시간을 다음 규칙으로 표기한다 — 1시간 미만 `방금`, 24시간 미만 `N시간 전`, 7일 미만 `N일 전`, 그 이상 `N월 N일`. (근거: 디자인 정책 주석 `시간 구분`(3037-93098))
- **FR-004**: 시스템은 반드시 아래 6종의 알림 유형을 각각 지정된 문구로 표시한다. (근거: 디자인 정책 주석 3037-93062 · 3037-93068 · 3037-93074 · 3037-93080 · 3037-93086 · 3037-93092)

    | 유형 | 유형 문구 | 대상 이름 |
    |---|---|---|
    | 중복 저장 | `이미 저장해둔 곳이에요` | 장소명 |
    | 저장 오류 | `장소를 저장하지 못했어요.` | `잠시 후 다시 시도해주세요` |
    | 위치 기반 리마인드 | `근처에 저장한 장소가 있어요` | 장소명 |
    | 코멘트 기반 리마인드 | `코멘트가 제일 많이 달린 장소에요` | 장소명 |
    | 공동방 참가 ① | `{참가자 이름}님이 들어왔어요` | 공동방 이름 |
    | 공동방 참가 ② | `방에 참가했어요` | 공동방 이름 |

- **FR-005**: 시스템은 반드시 알림을 클릭했을 때 유형별로 지정된 화면으로 이동시킨다 — 중복 저장 · 위치 기반 리마인드 · 코멘트 기반 리마인드는 해당 장소의 장소 상세로, 공동방 참가 ①② 는 해당 공동방의 방 상세로 이동한다. (근거: 디자인 정책 주석 3037-93062~3037-93092 / PRD [SCR-007] Flow C)
- **FR-006**: 시스템은 반드시 받은 알림이 0건일 때 목록 대신 스팟 일러스트와 `받은 알림이 없어요` 문구를 표시한다. (근거: 디자인 정책 `007-1-3 알림_Empty state`(3037-90978), 주석 3037-93179)
- **FR-010**: 시스템은 반드시 저장 오류 알림을 클릭했을 때 스팟 일러스트와 `확인해주세요` 제목, 그리고 `현재 한국 내 장소만 지원됩니다.` · `사진 속 장소인식은 아직 지원하지 않습니다` · `본문에 주소나 장소명을 포함해주세요` 세 줄의 안내로 구성된 저장 오류 안내 화면을 표시한다. (근거: 디자인 정책 `007-2 저장 오류 시`(3037-91057), 주석 3037-93218)
- **FR-011**: 시스템은 반드시 저장 오류 안내 화면에서 뒤로가기 시 알림 목록으로 되돌리며, 이 화면에서도 바텀 네비게이션을 계속 노출한다. (근거: 디자인 정책 `007-2 저장 오류 시`(3037-91057) — 상단 뒤로가기 버튼과 하단 네비게이션이 함께 존재)
- **FR-012**: 시스템은 반드시 장소를 대상으로 하는 알림(중복 저장 · 위치 기반 · 코멘트 기반)에는 그 장소의 대표 이미지를 썸네일로, 장소 이미지가 없는 알림(저장 오류 · 공동방 참가 ①②)에는 기본 아이콘 썸네일을 표시한다. (근거: 디자인 정책 `007-1-2`(3037-90987) 알림 Card 썸네일 구성)
- **FR-014**: 시스템은 반드시 위치 기반 리마인드 알림을 위치 권한을 허용한 사용자에게만 표시한다. (근거: 디자인 정책 주석 3037-93074)
- **FR-015**: 시스템은 반드시 알림 화면을 바텀 네비게이션의 세 번째 탭으로 제공하고, 다른 탭을 다녀와도 알림 목록의 스크롤 위치를 유지한다. (근거: PRD [SYS-005] Flow A, [SCR-007] 시스템 연동)
- **FR-016**: 시스템은 반드시 알림 목록의 모든 알림을 읽음 여부와 무관하게 동일한 형태로 표시한다 — 행 스타일(배경·문구 색·굵기)의 차이, 안 읽음 표시(점·강조), 바텀 네비게이션 `알림` 탭의 건수 배지 중 어느 것도 두지 않는다. (근거: 사용자 확정 §5 Q1 — 디자인 시안 `007-1-2`(3037-90987)·`007-1-3`(3037-90978)에 읽음 여부 표기가 없다)
- **FR-017**: 시스템은 반드시 알림 목록 화면에서 알림 권한과 관련된 어떤 유도 UI도 노출하지 않는다 — 목록은 화면 최상단부터 시작하며, 권한 허용 여부가 알림 탭의 화면 구성을 바꾸지 않는다. (근거: 사용자 확정 §5 Q2 — 권한 유도 배너가 디자인에서 제거되었다)
- **FR-018**: 시스템은 반드시 알림 목록을 최신순 20건 단위로 나누어 표시하고, 사용자가 목록 끝에 도달하면 다음 20건을 이어 붙인다. 기간이나 총 건수의 상한은 두지 않아, 사용자는 스크롤을 이어 가는 것만으로 받은 알림 전체에 도달할 수 있다. (근거: 사용자 확정 §5 Q3 — 서버 조회가 기본 20건 단위 페이징으로 제공된다)
- **FR-019**: 시스템은 반드시 위치 기반 대표 알림(`근처에 저장한 곳 N개가 있어요` + `반경 3km`)을 알림함 목록에 행으로 싣지 않는다. 반경 3km 내 대상 장소가 여러 개일 때 목록에는 개별 장소 행만 들어가며, 대표 알림은 앱 밖 알림으로만 존재해 그것을 탭하면 알림 탭으로 진입한다. (근거: 디자인 정책 주석 3037-93074 — "대표 알림을 주고, 리스트에는 개별로 표시한다" / 사용자 확정 §5 Q4 — 시안이 아니라 주석을 따른다)

### 2.2 핵심 UX 규칙 (Core UX Rules)
- **UX-001**: 알림 목록을 불러오는 동안에는 빈 상태 문구(`받은 알림이 없어요`)를 표시하지 않는다. 빈 상태는 조회가 끝나고 결과가 0건임이 확정된 뒤에만 노출한다. (근거: 디자인 정책 `007-1-3`(3037-90978) — Empty state는 "알림이 없는 상태"로 정의됨)
- **UX-002**: 목록 조회에 실패했을 때는 빈 상태가 아니라 재시도할 수 있는 오류 상태를 보여준다. 사용자가 "알림이 없다"와 "알림을 못 불러왔다"를 구분할 수 있어야 한다. (근거: PRD [SCR-007] Flow D — 빈 상태는 알림 0건에만 해당)
- **UX-005**: 알림 행 전체가 클릭 영역이다. 썸네일·문구·시간 중 어디를 눌러도 같은 대상 화면으로 이동한다. (근거: 디자인 정책 주석 3037-93062 — "클릭하면 해당 장소 상세로 이동한다")
- **UX-006**: 이동 대상이 사라진 알림(삭제된 장소, 나간 방)을 눌렀을 때는 빈 화면으로 넘어가지 않고 알림 목록에 머문 채 사유를 알린다. (근거: PRD [SCR-007] Flow C의 이동 규칙 — 도달 불가 대상에 대한 처리 보강)
- **UX-007**: 알림 유형 문구와 대상 이름은 한 행 안에서 각각 한 줄로 표시하고, 길이가 넘치면 줄바꿈 대신 말줄임으로 처리해 모든 행의 높이를 동일하게 유지한다. (근거: 디자인 정책 `007-1-2`(3037-90987) — 모든 알림 Card가 같은 높이)
- **UX-008**: 저장 오류 안내 화면은 알림 목록을 대체하지 않고 그 위에 쌓이는 화면이며, 이탈 후 알림 탭으로 돌아오면 안내 화면이 아니라 알림 목록이 보인다. (근거: 디자인 정책 `007-2`(3037-91057) — 상단 뒤로가기 + 하단 네비게이션 동시 노출)
- **UX-009**: 알림함은 사용자에게 "처리해야 할 것이 남았다"는 압박을 주지 않는다. 안 읽은 알림 수를 세어 보여주거나 확인을 유도하는 표시를 두지 않으며, 알림 목록은 지나간 사건을 훑어보는 기록으로만 기능한다. (근거: 사용자 확정 §5 Q1 — 읽음/안 읽음을 구분하지 않는다)
- **UX-010**: 알림 탭은 OS 알림 권한 상태에 따라 화면 구성을 바꾸지 않는다. 권한이 없어 알림을 받지 못하는 사용자도 알림 탭에서는 목록만 보며, 권한을 켜도록 권하는 일은 [SCR-008] 마이페이지가 맡는다. (근거: 사용자 확정 §5 Q2 — 권한 유도 배너 제거)
- **UX-011**: 추가 20건을 이어 붙이는 일은 사용자가 따로 조작하지 않아도 일어난다 — `더 보기` 버튼이나 새로고침을 요구하지 않고, 이어 붙이는 동안에도 이미 읽고 있던 행의 화면상 위치가 흔들리지 않는다. (근거: 사용자 확정 §5 Q4 — 스크롤에 따른 추가 로드)
- **UX-012**: 추가로 이어 붙이는 데 실패하는 것은 목록 전체를 못 불러온 것과 다르게 다룬다. 이미 본 알림을 지우고 오류 화면으로 덮지 않으며, 실패는 목록 끝에서만 알린다. (근거: UX-002의 오류·빈 상태 구분 원칙을 부분 실패로 확장)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **알림 (Notification)**: 사용자에게 전달된 사건 한 건. 유형, 발생 시각, 대상 이름(장소명 또는 공동방 이름), 썸네일 이미지, 그리고 클릭 시 도달할 대상 참조를 가진다. 목록에서는 발생 시각 기준 최신순으로 정렬된다. 읽음 여부는 이 도메인의 속성이 아니다 — 알림은 읽힌 것과 읽히지 않은 것으로 나뉘지 않는다.
- **알림 유형 (Notification Type)**: 알림이 어떤 사건인지 나타내는 분류. 중복 저장 / 저장 오류 / 위치 기반 리마인드 / 코멘트 기반 리마인드 / 공동방 참가 ① / 공동방 참가 ② 6종으로 고정되며, 유형이 곧 표시 문구와 이동 대상을 결정한다. 위치 기반 대표 알림은 이 목록의 유형이 아니다 — 여러 건을 묶어 앱 밖으로 한 번만 알리는 발송 방식이고, 알림함에 남는 것은 개별 리마인드뿐이다.
- **알림 대상 (Notification Target)**: 알림이 가리키는 것. 장소이거나 공동방이며, 목록의 모든 알림은 둘 중 하나를 가진다. 대상이 삭제되었거나 접근 권한을 잃은 경우가 존재한다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)
- **SC-001**: 알림 탭을 누른 뒤 2초 이내에 알림 목록의 첫 화면이 그려진다.
- **SC-002**: 알림 목록을 스크롤할 때 눈에 띄는 끊김 없이 이어진다 — 스크롤 중 프레임 드랍이 관찰되지 않는다.
- **SC-003**: FR-004의 6종 행이 모두 디자인 정책 시안(3037-90987)의 문구와 100% 일치하게 렌더링되고, 그 밖의 행(위치 기반 대표)은 목록에 나타나지 않는다.
- **SC-004**: 사용자는 알림 목록에서 대상 화면까지 **1회의 탭**으로 도달한다 — 중간에 추가 확인 단계가 없다.
- **SC-005**: 경과 시간 표기가 FR-003의 네 구간 경계값(59분 / 60분 / 23시간 59분 / 24시간 / 6일 23시간 / 7일)에서 모두 규칙대로 전환된다.
- **SC-007**: 저장에 실패한 사용자가 알림 클릭 한 번으로 실패 조건 3가지를 모두 읽을 수 있어, 저장 실패 사유를 묻는 문의가 알림함 밖의 경로로 발생하지 않는다.
- **SC-008**: 알림이 0건인 사용자가 빈 화면이 아니라 `받은 알림이 없어요` 안내를 보게 되어, 알림 탭이 고장 났다고 오인하지 않는다.
- **SC-009**: 알림 탭이 가지는 화면 상태는 목록 · 빈 상태 · 오류 세 가지뿐이다 — 알림 권한 허용 여부나 읽음 여부에 따라 늘어나는 화면 변형이 없다.
- **SC-010**: 알림이 20건을 넘는 사용자가 `더 보기` 같은 추가 조작 없이 스크롤만으로 받은 알림 전체에 도달한다 — 도달하지 못하고 끊기는 구간이 없다.
- **SC-011**: 알림 탭 첫 진입에서 화면을 채우는 데 필요한 건수만 불러온다 — 첫 화면을 그리기 위해 20건을 넘는 알림을 기다리지 않는다(SC-001의 2초를 지키는 근거).

### 3.2 비목표 항목 (Out of Scope)
- **알림을 언제 만들어 보낼지는 서버가 정의한다.** 위치 기반·코멘트 기반 리마인드의 발송 주기와 판정 시점, 반경 3km·코멘트 최다 장소의 계산 방식은 이 문서의 범위가 아니다. 이 스펙은 전달받은 알림을 어떻게 보여주고 어디로 보낼지만 정의한다.
- **OS 푸시 메시지의 수신·표시는 이 문서가 정의하지 않는다.** 앱 밖에서 뜨는 시스템 알림의 형태·채널·토큰 관리는 별도 범위이며, 여기서는 앱 안의 알림함 화면만 다룬다.
- **알림 권한과 관련된 모든 것은 [SCR-008] 마이페이지 스펙이 정의한다.** 권한 요청 동선도, 시스템 설정 화면으로 보내는 동작도 알림 탭에는 없다. 알림 탭은 권한 상태를 읽지도 않는다.
- **이동 대상 화면의 내용은 각자의 스펙이 정의한다.** [SCR-005] 방 상세와 [SCR-006] 장소 상세가 무엇을 보여주는지는 여기서 정의하지 않으며, 이 문서는 "그 화면으로 보낸다"까지만 책임진다.
- **바텀 네비게이션 자체의 동작은 [SYS-005]가 정의한다.** 탭 구성·전환·비노출 조건은 그쪽 규칙을 따르고, 이 문서는 알림 탭이 세 번째 자리에 있다는 사실만 전제한다.
- **알림 삭제·읽음 처리·알림별 수신 설정은 이 문서가 정의하지 않는다.** 디자인에 해당 동선이 없으며, MVP 알림함은 조회와 이동만 제공한다. 읽음/안 읽음이라는 상태 자체를 두지 않으므로(FR-016) `모두 읽음` 같은 일괄 처리도 성립하지 않는다.
- **저장 실패의 원인 판정과 오류 문구의 산출은 [SYS-002] 외부 공유 수신이 정의한다.** 이 문서는 실패했다는 알림을 받아 고정된 안내 화면을 보여주는 데까지만 관여한다.

## 4. 가정 (Assumptions)
- **알림 목록은 서버가 제공한다.** 클라이언트는 목록을 만들지 않고, 어떤 알림을 누구에게 줄지의 판정도 서버가 끝낸 뒤 전달한다고 본다. 목록은 최신순으로 정렬된 상태로, 기본 20건 단위의 페이징 형태로 내려온다.
- **한 묶음의 크기 20건은 서버가 정한 기본값을 따른다.** 화면이 이 숫자를 정하지 않으므로, 서버 기본값이 바뀌면 화면에 한 번에 이어 붙는 건수도 함께 바뀐다. FR-018의 `20`은 이 기본값을 가리킨다.
- **알림 목록에는 기간·총량 상한이 없다.** 오래된 알림이 서버에서 사라지는 보관 정책이 있다면 그것은 서버가 정하는 일이며, 화면은 서버가 주는 만큼을 끝까지 보여준다.
- **알림 유형 문구는 유형에 의해 결정되고, 가변 부분은 대상 이름과 참가자 이름뿐이다.** FR-004의 문구는 고정 문자열로 취급한다.
- **시안과 디자인 주석이 어긋나면 주석을 따른다.** 시안은 특정 시점의 화면을 그린 것이고 주석은 규칙을 적은 것이므로, 규칙 쪽을 최신 의도로 본다. 위치 기반 대표 알림의 목록 행 존치 여부(FR-019)를 이 기준으로 판정했다.
- **대표 알림은 발송을 묶는 방식일 뿐 알림함의 기록이 아니다.** 반경 3km 내 여러 장소를 한 번에 알릴 때 앱 밖 알림을 한 건으로 줄이는 수단이며, 알림함에는 개별 리마인드가 각각 남는다. 언제 묶어 보낼지의 판정과 앱 밖 알림의 표시는 이 문서 범위 밖이고, 그 알림을 탭해 알림 탭으로 들어오는 것까지만 여기서 다룬다.
- **권한 유도 배너 제거는 디자인 확정 사항이지 잠정 보류가 아니다.** 사용자가 시안에서 배너를 걷어냈다고 확인해 주었으므로, 배너를 되살릴 여지를 남기지 않고 관련 요구사항·시나리오를 스펙에서 완전히 걷어냈다. 되살아난다면 그때 스펙을 다시 개정한다.
- **알림 권한을 허용하지 않아 알림을 받지 못하는 사용자도 알림 탭을 연다.** 이 경우 목록은 대개 비어 있고 빈 상태만 보이지만, 알림 탭은 그 이유를 설명하거나 권한을 켜도록 권하지 않는다(UX-010).
- **저장 오류 안내 화면은 알림 탭 안의 화면이다.** 시안(3037-91057)에 상단 뒤로가기와 하단 바텀 네비게이션이 함께 있어, 탭을 벗어나는 별도 화면이 아니라 알림 탭 내부에서 쌓이는 화면으로 본다.
- **경과 시간은 기기의 로컬 시간대를 기준으로 계산한다.** 서버가 주는 발생 시각을 사용자의 현재 시각과 비교한다.
- **`N월 N일` 표기는 연도를 포함하지 않는다.** 시안(`8월 10일`, `7월10일`)에 연도가 없어, 해가 바뀐 알림도 같은 형식으로 표기한다고 본다.
- **알림함에는 방 대표 색상·캐릭터를 반영하지 않는다.** 다른 화면과 달리 시안의 알림 행에 방 색상 요소가 없어, 공동방 참가 알림도 기본 아이콘 썸네일을 쓴다.
- **사용자는 온라인 상태에서 알림함을 연다.** 오프라인 캐시로 지난 알림을 보여주는 것은 전제하지 않으며, 조회 실패 시 UX-002의 오류 상태로 처리한다.
- **알림 탭 진입은 항상 목록의 맨 위에서 시작한다.** 단, FR-015의 탭 상태 보존이 적용되는 재진입은 예외다.

- **Q**: [FR-016] 알림 목록에서 읽음/안 읽음 상태를 구분해 표시하는가? — 디자인 시안에 읽음 여부를 나타내는 표기가 없다. *(PRD 3.1.0 §5 미확정 항목과 동일한 질문)*

- **Q**: [EC-006] 알림이 0건인 빈 상태 화면에서도 권한 유도 배너를 노출하는가? — `007-1-3 알림_Empty state`(3037-90978) 시안에는 배너가 없다.
  → **A**: **질문 자체가 소멸했다 — 권한 유도 배너를 디자인에서 제거했다.** 알림 탭은 권한 상태에 따라 화면 구성을 바꾸지 않으며, 권한 유도는 [SCR-008] 마이페이지가 전담한다. 이에 따라 구 유저 플로우 2(권한 유도 배너) 전체와 FR-007·FR-008·FR-009·FR-013, UX-003·UX-004, TS-013~TS-019, EC-006·EC-007·EC-008, SC-006, 도메인 `배너 노출 상태`를 스펙에서 삭제하고 FR-017·UX-010·TS-035·EC-015로 대체했다.
- **Q**: [EC-003] 알림 목록에 싣는 범위는 어디까지인가? — 전체 일괄 로드 / 스크롤에 따른 추가 로드 / 최근 N일·N건 상한 중 무엇인지 디자인·PRD 어디에도 없다. 서버 조회 API의 형태와 직결된다.
  → **A**: **스크롤에 따른 추가 로드.** 서버 조회가 기본 20건 단위 페이징으로 개발될 예정이며, 기간·총량 상한은 두지 않는다. *(반영: FR-018, UX-011·UX-012, TS-036~TS-039, EC-003·EC-016·EC-017·EC-018, §3.1 SC-010·SC-011, §4 가정 3건)*

- **Q**: [EC-002] 위치 기반 대표 알림(`근처에 저장한 곳 N개가 있어요` + `반경 3km`)이 알림함 목록에도 한 행으로 남는가? — 주석(3037-93074)은 "대표 알림을 주고, 리스트에는 개별로 표시한다"인데 `007-1-1`(3037-90907) 시안에는 대표 행과 개별 행이 함께 있고 `007-1-2`(3037-90987)에는 대표 행이 없어 시안 간에도 어긋난다.
  → **A**: **주석을 따른다 — 대표 알림은 목록에 행으로 남지 않는다.** 시안과 주석이 어긋나면 주석이 우선이며, `007-1-1`의 대표 행은 구버전 표현으로 본다. 대표 알림은 앱 밖 알림으로만 존재하고 알림함에는 개별 리마인드만 들어간다. *(반영: FR-019, TS-040, EC-002, FR-004 표에서 대표 행 삭제, FR-005·TS-026·유저 플로우 2 스텝에서 대표 알림 이동 규칙 삭제, §2.3 알림 유형·알림 대상, §3.1 SC-003, §4 가정 2건)*
