## 검증 결과

**16개 항목 전부 통과.** 1.0.0에서 실패했던 3개 항목이 모두 해소되었다 — 원인이었던 `[TBD]` 4건이 1.1.0 개정에서 Q1(읽음/안 읽음 무구분)·Q2(권한 유도 배너 제거)·Q3(20건 단위 추가 로드)·Q4(대표 알림은 주석 기준으로 목록 미표시)로 전부 확정되었다.

### 판정 근거가 갈릴 수 있었던 항목

- **`구현 세부사항이 명세로 새어 들어오지 않았다`** — Q3에서 페이징이 들어왔으나 본문은 API·요청 파라미터·커서 형식을 다루지 않고 사용자가 관찰하는 동작(20건 단위로 이어 붙음, 상한 없음, 실패 시 목록 유지)으로만 서술했다. `20건`이 서버 기본값이라는 사실은 §4 가정에 격리했다. 통과.
- **`요구사항이 검증 가능하고 모호하지 않다`** — FR-001~FR-019 전부가 문장만 읽고 통과·실패를 판정할 수 있다. 1.0.0에서 이 항목을 떨어뜨린 FR-016은 "읽음 여부와 무관하게 동일한 형태로 표시하며 행 스타일·안 읽음 표시·탭 배지를 두지 않는다"로 재작성되어 관찰 가능한 부정형 조건이 되었다.
- **`엣지 케이스가 식별되어 있다`** — Q3·Q4 확정으로 EC-016(추가 로드 실패)·EC-017(로드 중 새 알림 도착)·EC-018(20건 이하)이 새로 식별되었다. 부분 실패를 전체 오류와 분리해 다루는 규칙(UX-012)이 함께 들어왔다.

## PRD와의 어긋남 (별도 조치 필요)

`spec.md` 1.1.0이 `docs/prd/business-context.md` 3.1.0과 어긋났다. spec 자체는 PASS이나, PRD 쪽 갱신 없이 Plan 단계로 넘어가면 두 문서가 갈라진 채로 굳는다.

- **[SCR-007] Flow B「알림 권한 유도 배너」** — 배너 노출·설정 바로가기·7일 재표시가 그대로 남아 있다. spec에서는 전부 삭제되었다.
- **§공용 컴포넌트 「알림 유도 배너 (Notification Opt-in Banner)」** — 컴포넌트 정의 자체가 살아 있다.
- **[SCR-008] Flow C 및 §5 답변** — "알림에 한해서는 [SCR-007] 알림 탭 상단 배너의 `설정 바로가기`가 같은 역할을 한다"가 성립하지 않게 되어, 마이페이지 스위치의 설정 화면 유도 UI가 유일한 경로가 된다.
- **[SCR-007] Flow A의 `TBD:` 읽음/안 읽음** 및 **§5 미확정 항목** — spec에서 "구분하지 않음"으로 확정되었으므로 PRD에도 반영해야 한다.
- **[SCR-007] Flow A 목록 로딩 범위** — PRD에는 조회 범위 서술이 없다. spec에서 "20건 단위 추가 로드, 상한 없음"으로 확정되었다.
- **[SCR-007] Flow C 위치 기반 예외** — PRD의 "대표 알림을 클릭하면 알림함 화면으로 이동한다"는 목록 행 클릭이 아니라 앱 밖 알림 탭으로 읽어야 한다. spec은 대표 알림이 목록에 행으로 남지 않음을 명시했다(FR-019).
