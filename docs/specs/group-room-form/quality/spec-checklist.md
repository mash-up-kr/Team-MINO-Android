## 발견된 문제

### 1차 검증 (2026-08-21) — spec 3.1.0

**전 항목 통과.** 3.0.0에 대한 통과 기록은 근거로 삼지 않고 전 항목을 다시 대조했다.

**추적성 확인**

| 대상 | 결과 |
|---|---|
| `[TBD]` 마커 | 본문 0건 |
| 기능 요구사항 | FR-001 ~ FR-025 전 항목이 테스트 시나리오·엣지 케이스 행에서 참조됨 (미커버 0건) |
| 핵심 UX 규칙 | UX-001 ~ UX-009 전 항목이 참조됨 (미커버 0건) |
| 테스트 시나리오 | 45건 / 엣지 케이스 25건 / 성공 기준 SC-001 ~ SC-008 |
| ID 중복 | 0건 |
| 미해소 질문 | `§5 검토 대기` 0건 |

**이번 개정에서 바뀐 것 (MINOR)**

방 이름 검증에서 한글 자모 단독(`ㄱ`·`ㅏ`)의 취급을 확정했다.

| 대상 | 3.0.0 | 3.1.0 |
|---|---|---|
| FR-004 | 허용 문자를 `한글·영문·숫자·공백`으로 적고 자모를 다루지 않음 | `한글(완성형·자모)·영문·숫자·공백` |
| EC-025 | (없음) | 자모 단독은 오류가 아니다 |
| §4 가정 | (없음) | 자모를 포함하는 이유와 그 대가를 기록 |

**MINOR 판정 근거**

3.0.0까지의 FR-004는 **자모를 배제한 적이 없다.** "한글"이 무엇인지가 한 번도 명시되지 않았고, 유일하게 문자 종류를 다루는 EC-005는 이모지만 언급한다. 따라서 이 개정은 확정된 판정을 뒤집는 것이 아니라 모호했던 경계를 정하는 것이며, 함께 엣지 케이스가 하나 늘어난다 — 버전 규칙의 "새 요구사항·엣지 케이스·가정 추가"에 해당한다.

**기존 항목 중 판정이 뒤집히는 것은 없다.** TS-008(`민호야 잘하자^^`)·TS-010·EC-005(이모지)는 모두 자모와 무관한 문자를 다루므로 결과가 그대로다.

**판정 근거를 남기는 항목**

- **안내 문구는 손대지 않았다.** 필드 아래 문구(`한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)`)는 Figma `2314-95377`이 소유한 라이팅이다. 자모를 반영해 고칠지는 디자이너 협의 대상이며, 이 개정의 범위가 아니다.
- **저장되는 값의 범위가 넓어진다.** `ㄱㄱㄱ` 같은 방 이름이 유효해진다. 이것을 대가로 받아들인 이유는 §4 가정과 §5 답변에 적었다 — FR-004가 오류 판정을 **입력 즉시** 하도록 정한 이상, 자모를 배제하면 한글을 치는 동안 매 글자 오류가 번쩍인다.
