## 발견된 문제

### 2차 검증 (2026-08-24) — spec 3.2.0

**전 항목 통과.** 3.1.0에 대한 통과 기록은 근거로 삼지 않고 전 항목을 다시 대조했다.

**추적성 확인**

| 대상 | 결과 |
|---|---|
| `[TBD]` 마커 | 본문 0건 |
| 기능 요구사항 | FR-001 ~ FR-025 전 항목이 테스트 시나리오·엣지 케이스 행에서 참조됨 (미커버 0건) |
| 핵심 UX 규칙 | UX-001 ~ UX-009 전 항목이 참조됨 (미커버 0건) |
| 테스트 시나리오 | 45건 / 엣지 케이스 25건 / 성공 기준 SC-001 ~ SC-008 |
| ID 중복 | 0건 |
| 미해소 질문 | `§5 검토 대기` 0건 |

수치는 3.1.0과 같다 — 이번 개정이 요구사항·시나리오·엣지 케이스를 하나도 늘리거나 줄이지 않았기 때문이다.

**이번 개정에서 바뀐 것 (MINOR)**

`/mino-plan` 1.4.0이 Figma 재대조 중 넘긴 검토 대상 2건을 닫았다. **요구사항 문장은 한 건도 바뀌지 않았고**, 바뀐 것은 어느 Figma 보드를 근거로 삼는지다.

| 대상 | 3.1.0 | 3.2.0 |
|---|---|---|
| §4 가정 | 편집 보드 계열의 취급을 다루지 않음 | 3건 추가 — FR-013의 근거가 PRD라는 것 · 명세 보드 우선 · 빈 이름 CTA 표기가 FR-007을 뒤집지 않는다는 것 |
| FR-009 근거 | Figma `2314-95339`, `2792-151339` | Figma `2314-95339`, `2542-125922` (명세 보드로 교체) |
| FR-013 근거 | Figma `2792-151339` / PRD [SYS-001] Flow D | PRD [SYS-001] Flow D 우선 · Figma는 §4 가정으로 지목 |
| 유저 플로우 4 Figma | User Flow 보드 4개 | 편집 명세 보드 `2542-125922`를 앞에 달고, 두 계열의 우선순위를 한 줄로 밝힘 |

**MINOR 판정 근거**

§4에 가정 3건이 실제로 늘어나 버전 규칙의 "새 요구사항·엣지 케이스·가정 추가"에 해당한다. FR·UX·TS·EC·SC 어느 항목도 의미가 바뀌지 않았으므로 MAJOR가 아니고, 가정이 늘어난 이상 "표현 명확화"에 그치는 PATCH도 아니다.

**판정 근거를 남기는 항목**

- **FR-013을 흔들지 않은 이유.** 편집 명세 보드가 기존 값을 그리지 않게 된 것은 컴포넌트 교체의 부산물로 보이고, "기존 값이 채워진 상태로 진입"은 PRD [SYS-001] Flow D가 문장으로 받친다. Figma 한 보드의 렌더 상태를 근거로 PRD가 정한 동작을 뒤집지 않는다.
- **TS-018을 손대지 않았다.** 기대 결과(`야호` / `야호호` / `red` · 카운터 `3/30`)는 FR-013에서 그대로 도출되며, 그 근거가 Figma에서 PRD로 옮겨진 것과 무관하다.
- **빈 이름 CTA 활성 표기를 엣지 케이스로 올리지 않았다.** 정지 화면 한 장은 상태 전이의 근거가 아니고, 활성 조건은 이미 FR-007이 정하고 TS-001·TS-005·TS-020이 검증한다. 새 EC를 만들면 디자인 렌더 오류를 요구사항으로 승격시키는 셈이 된다.

### 1차 검증 (2026-08-21) — spec 3.1.0

**전 항목 통과.** 3.0.0에 대한 통과 기록은 근거로 삼지 않고 전 항목을 다시 대조했다.

**이번 개정에서 바뀐 것 (MINOR)**

방 이름 검증에서 한글 자모 단독(`ㄱ`·`ㅏ`)의 취급을 확정했다 — FR-004를 `한글(완성형·자모)·영문·숫자·공백`으로 고치고 EC-025를 신설했으며, 자모를 포함하는 이유와 그 대가를 §4 가정에 적었다.

**MINOR 판정 근거**

3.0.0까지의 FR-004는 **자모를 배제한 적이 없다.** "한글"이 무엇인지가 한 번도 명시되지 않았고, 유일하게 문자 종류를 다루는 EC-005는 이모지만 언급한다. 따라서 이 개정은 확정된 판정을 뒤집는 것이 아니라 모호했던 경계를 정하는 것이며, 함께 엣지 케이스가 하나 늘어난다. TS-008·TS-010·EC-005는 자모와 무관한 문자를 다루므로 판정이 그대로다.

**판정 근거를 남기는 항목**

- **안내 문구는 손대지 않았다.** 필드 아래 문구(`한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)`)는 Figma `2314-95377`이 소유한 라이팅이다. 자모를 반영해 고칠지는 디자이너 협의 대상이며, 이 개정의 범위가 아니다.
- **저장되는 값의 범위가 넓어진다.** `ㄱㄱㄱ` 같은 방 이름이 유효해진다. 이것을 대가로 받아들인 이유는 §4 가정과 §5 답변에 적었다.
