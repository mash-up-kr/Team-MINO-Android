### 1차 검증 (2026-08-21) — spec 2.1.1

**전 항목 통과.** 2.1.0에 대한 통과 기록은 근거로 삼지 않고 전 항목을 다시 대조했다.

**추적성 확인**

| 대상 | 결과 |
|---|---|
| `[TBD]` 마커 | 본문 0건 |
| 기능 요구사항 | FR-001 ~ FR-024 전 항목이 하나 이상의 테스트 시나리오 행에서 참조됨 (미커버 0건) |
| 핵심 UX 규칙 | UX-001 ~ UX-009 전 항목이 테스트 시나리오 또는 엣지 케이스 행에서 참조됨 (미커버 0건) |
| 테스트 시나리오 | 43건 / 엣지 케이스 24건 / 성공 기준 SC-001 ~ SC-008 |
| 미해소 질문 | `§5 검토 대기` 0건 |

**이번 개정에서 바뀐 것 (PATCH)**

Figma 라이팅 개정을 반영했다. 표출 조건·버튼 구성·각 버튼의 결과는 그대로이므로 요구사항의 경계는 바뀌지 않았다.

| 대상 | 2.1.0 | 2.1.1 | 근거 |
|---|---|---|---|
| 생성 이탈 모달 제목 | `공동방 만들기를 취소하시겠어요?` | `공동방 만들기 화면에서 나가시겠어요?` | `3798-167987` |
| 편집 이탈 모달 제목 | `공동방 편집을 취소하시겠어요?` | `공동방 편집 화면에서 나가시겠어요?` | `3832-213758` |
| 저장 모달 제목 | `공동방을 저장하시겠어요?` | 변동 없음 | `3798-167742` |
| 버튼 구성 | [취소]·[나가기] / [취소]·[저장하기] | 변동 없음 | 스크린샷 대조 |

**함께 정리한 용어**

스펙이 쓰던 '취소 확인 모달'을 **'이탈 확인 모달'**로 바꿨다(생성 이탈 확인 모달 / 편집 이탈 확인 모달). 바뀐 제목에 '취소'가 없는 데다, 모달 안의 [취소] 버튼은 '나가지 않기'를 뜻해 **같은 낱말이 문서 안에서 서로 반대 의미로 쓰이고** 있었다. FR 번호와 TS·EC ID는 그대로 두었고, `§5`의 과거 질문 문구는 당시 기록이므로 손대지 않았다.

**판정 근거를 남기는 항목**

- 본문에 남은 '취소'는 모두 **버튼 라벨 [취소]** 이거나 **Figma 프레임 이름**(`001-1-4 공동방_생성 취소 여부 묻기` 등)이다. 프레임 이름은 실제 Figma 값이므로 스펙이 임의로 바꾸지 않았다.
- UX-009가 "두 확인 모달"로 적혀 있어 모달이 3종이 된 2.1.0 이후와 어긋나 있었다. 이번 검증에서 "확인 모달 3종"으로 정정했다.

## 후속 조치 (spec 외부)

PRD 5.0.0과 이 spec 2.1.1이 어긋난 채로 남은 지점이다. **PRD 갱신이 필요하다.**

| # | PRD 위치 | PRD 5.0.0의 서술 | spec 2.1.1의 결정 |

| 1 | [SYS-001] Flow C | 홈 탭 방 변경 시트 진입 시 "홈 탭으로 돌아와 생성된 방의 덱으로 전환" | 새로 만든 방의 방 상세로 이동 (FR-011) |
