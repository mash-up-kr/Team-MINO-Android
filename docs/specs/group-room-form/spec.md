## 1. 유저 시나리오 (User Scenarios) *(필수)*
### 유저 플로우 1 - 방 정보 입력

공동방을 만들거나 고칠 때 공통으로 쓰는 단일 폼이다. 방 이름·방 설명·대표 색상을 입력하면 상단 미리보기 카드가 즉시 바뀌고, 필수 항목인 방 이름이 채워지는 순간 하단 CTA가 활성화된다. 진입점이 어디든 폼의 구성과 규칙은 같다.

**Figma**: [001-1 공동방 명세 보드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95243&m=dev) · [001-1-1 공동방_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95301&m=dev) · [001-1-2 공동방_입력 완료](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95339&m=dev)

**진입 조건**: 아래 **생성 진입점 7개** 또는 **편집 진입점 1개** 중 하나로 폼에 진입한 상태.

1. 폼 진입 → 상단 타이틀이 `공동방 만들기`로 표시되고, 미리보기 카드에 기본 썸네일과 안내 문구(`방 이름을 입력해 주세요.` / `어떤 장소들을 모으는 방인가요?`)가 표시되며, 방 이름 필드에 필수 표기(`*`)가 붙고 하단 CTA는 비활성 상태다
2. 방 이름 입력 → 미리보기 카드의 이름이 즉시 같은 값으로 바뀌며, CTA가 활성화된다. 방 이름에는 글자 수 카운터가 없고, 상한 안내는 필드 아래 문구가 대신한다
3. 방 설명 입력 → 카운터가 `n/30`으로 갱신되고 미리보기 카드의 설명이 즉시 같은 값으로 바뀐다
4. 대표 색상 칩 선택 → 선택한 칩에만 체크 표시가 남고, 미리보기 카드 썸네일이 해당 색과 **그 색에 대응하는 대표 캐릭터**로 함께 바뀐다
5. 다른 색상 칩 선택 → 이전 선택이 해제되고 새 칩으로 교체되며, 썸네일의 색과 캐릭터가 함께 교체된다

**완료 조건**: 방 이름이 오류 없이 1자 이상 입력되어 하단 CTA가 활성 상태이고, 미리보기 카드가 현재 입력값(이름·설명·색상)과 일치한다.

### 유저 플로우 2 - 방 이름 입력 오류

방 이름에 허용되지 않는 문자가 섞이면 그 자리에서 오류를 알리고, 나머지 항목을 아무리 채워도 방을 만들 수 없게 막는다.

**Figma**: [001-1-3 공동방_입력 오류](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95377&m=dev) · [001-1 공동방 명세 보드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95243&m=dev)

**진입 조건**: 생성 또는 편집 폼에서 방 이름 필드를 입력 중이다.

1. 방 이름에 한글·영문·숫자·공백이 아닌 문자를 입력한다(예: `민호야 잘하자^^`) → 방 이름 필드가 오류 상태로 바뀌고 필드 우측에 오류 아이콘이 나타나며, 필드 아래 안내 문구 `한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)`가 오류 색으로 전환된다
2. 대표 색상을 고르고 방 설명을 입력한다 → 오류가 남아 있는 한 CTA는 계속 비활성 상태다
3. 허용되지 않는 문자를 지운다 → 오류 상태와 오류 아이콘이 해제되고 안내 문구가 기본 색으로 돌아오며 CTA가 활성화된다

**완료 조건**: 방 이름 필드에 오류 상태가 남아 있지 않고, 오류 상태였던 동안 CTA가 한 번도 활성화되지 않았다.

### 유저 플로우 3 - 공동방 생성 완료와 진입점별 후속 이동

[방 생성하기]를 누르면 곧바로 방이 만들어지지 않고 **저장 확인 모달**이 한 번 끼어든다. [저장하기]로 확인해야 공동방이 만들어지며, 사용자를 어디로 데려다 놓을지는 폼에 들어온 진입점이 정한다. 같은 폼이지만 끝나는 자리가 다르다.

**진입 조건**: 생성 폼에서 유저 플로우 1을 마쳐 CTA `방 생성하기`가 활성 상태다.

1. [방 생성하기] 클릭 → 폼 위에 저장 확인 모달이 얹힌다. 제목 `공동방을 저장하시겠어요?`와 버튼 [취소]·[저장하기]만 보이고(본문 문구 없음) 뒤의 폼은 딤 처리된다
2. 모달에서 [취소] 클릭 → 모달만 닫히고 폼과 입력값이 그대로 남는다. 방은 만들어지지 않는다
3. 모달에서 [저장하기] 클릭 → 입력한 이름·설명·대표 색상으로 공동방이 만들어지고, 만든 사용자가 그 방의 방장이 된다
4. 온보딩에서 진입했다면 → 온보딩의 '친구 초대' 스텝(`친구들을 초대해볼까요?`)으로 이동한다
5. 장소 복제(다른 방에 공유) 시트에서 진입했다면 → 복제 시트로 되돌아가고, 새로 만든 방이 개인방 바로 아래(두 번째)에 놓인 채 선택 가능한 상태가 된다. 보고 있던 장소는 자동으로 복제되지 않는다
6. 그 밖의 생성 진입점(방 리스트 탭 [+] · Nudge 바텀시트 · Ghost Card · 홈 탭 빈 상태 CTA · 홈 방 시트 [방 만들기])에서 진입했다면 → 새로 만든 방의 방 상세로 이동하고 `방 생성 완료!` 스낵바가 표출된다

**완료 조건**: 입력값 그대로의 공동방이 내 방 목록에 존재하고, 사용자가 진입점에 대응하는 화면에 도착해 있으며, 폼 화면과 저장 확인 모달은 뒤로가기 대상으로 남지 않는다.

### 유저 플로우 4 - 방장의 방 편집

방장은 방 상세의 더보기에서 같은 폼을 다시 열어 방 이름·설명·대표 색상을 고친다. 생성과 다른 점은 기존 값이 채워진 채 열리고, CTA 라벨이 `방 편집 완료`이며, **저장 확인 모달을 거치지 않고 바로 반영된다**는 것이다. 저장하지 않고 빠져나가는 길은 유저 플로우 5가 다룬다.

### 유저 플로우 5 - 폼에서 빠져나가기 (건너뛰기·뒤로가기)

방을 만들거나 고치지 않고 폼을 떠나는 길이다. 온보딩에서는 뒤로가기가 아예 없고 [건너뛰기] 하나로만 벗어나며, 그 밖의 진입점에서는 뒤로가기가 **이탈 확인 모달**을 거쳐 원래 있던 자리로 돌려보낸다. 모달은 생성용과 편집용 두 벌이고, 어느 쪽이든 **잃을 것이 있을 때만** 뜬다 — 생성은 무언가 입력했을 때, 편집은 진입 시점의 값에서 무언가 바뀌었을 때다.

**Figma**: [001-1-4 공동방_생성 취소 여부 묻기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3798-167946&m=dev) · [001-1-5 공동방_편집 취소 여부 묻기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=3832-213717&m=dev) · [001-1 공동방 명세 보드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95243&m=dev) · [001-1-1 공동방_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95301&m=dev)

**진입 조건**: 생성 또는 편집 폼을 보고 있다.

1. 온보딩에서 진입했다면 → 우상단에 [건너뛰기]가 보이고, 좌상단 뒤로가기는 **표출되지 않는다**
2. [건너뛰기] 클릭 → 방을 만들지 않고 온보딩의 공유 방법 튜토리얼 스텝으로 이동한다(친구 초대 스텝은 건너뛴다)
3. 온보딩이 아닌 진입점이라면 → [건너뛰기]가 보이지 않고 좌상단 뒤로가기가 보인다
4. 방 이름·방 설명·대표 색상 중 하나라도 입력한 상태에서 뒤로가기 클릭 → 생성 이탈 확인 모달이 표출된다. 제목 `공동방 만들기 화면에서 나가시겠어요?`와 버튼 [취소]·[나가기]만 보인다(본문 문구 없음)
5. 모달에서 [취소] 클릭 → 모달만 닫히고 폼과 입력값이 그대로 남는다
6. 모달에서 [나가기] 클릭 → 방을 만들지 않고 입력값을 버린 채 폼을 연 진입점 화면으로 되돌아간다
7. 아무것도 입력하지 않은 상태에서 뒤로가기 클릭 → 모달 없이 즉시 진입점 화면으로 되돌아간다

9. 편집 이탈 확인 모달에서 [취소] 클릭 → 모달만 닫히고 고치던 값이 그대로 남는다. [나가기] 클릭 → 고친 값을 버린 채 방 상세로 돌아가고 방 정보는 편집 전 그대로다
10. 편집 폼에서 아무것도 고치지 않은 채 뒤로가기 클릭 → 모달 없이 즉시 방 상세로 돌아간다

(근거: Figma `3832-213717` `001-1-5 공동방_편집 취소 여부 묻기` / `2314-95243` 주석 7이 뒤로가기를 폼 공통 규칙으로 규정 / §5 TBD 답변)
- **FR-022**: 시스템은 반드시 온보딩 첫 공동방 생성 스텝에서 뒤로가기를 노출하지 않고, OS 뒤로 제스처로도 이전 온보딩 스텝으로 되돌아갈 수 없게 한다. 이 스텝을 벗어나는 수단은 [건너뛰기] 하나다. (근거: PRD §5 확정 "(5.0.0 재정의) 온보딩에서는 뒤로가기를 표출하지 않는다" / Figma `2314-95243` 주석 7 "최초 앱 접속 시(온보딩 시)에는 표출하지 않는다")
- **FR-023**: 시스템은 반드시 방의 대표 캐릭터를 선택된 대표 색상에 대응하는 캐릭터로 부여하고, 폼에는 캐릭터를 따로 고르는 입력을 두지 않으며, 색상이 바뀌면 미리보기 카드와 방 썸네일의 캐릭터도 함께 바뀐다. (근거: PRD 데이터 용어 "방마다 고유한 대표 색상과 대표 캐릭터가 지정된다", 「방 썸네일」 "장소 0개: 대표 색상 + 캐릭터 조합" / §5 TBD 답변)
- **FR-012**: 시스템은 반드시 생성 완료 후 도착한 화면에 `방 생성 완료!` 피드백을 표출한다. (근거: Figma `2792-150362`)
- **FR-013**: 시스템은 반드시 편집 진입 시 폼의 방 이름·방 설명·대표 색상을 대상 방의 현재 값으로 채운 상태로 열고, 입력 상한·필수 여부·오류 판정 규칙을 생성과 동일하게 적용한다. (근거: Figma `2792-151339` / PRD [SYS-001] Flow D "Flow A와 동일한 폼에 기존 값이 채워진 상태로 진입")
- **FR-014**: 시스템은 반드시 방 편집 진입점인 방 상세 더보기 [편집] 메뉴를 공동방의 방장에게만 노출하고, 개인방(`내 장소`)의 방 상세에서는 더보기 메뉴 자체를 노출하지 않는다. (근거: Figma `2792-150974` / PRD [SCR-005] Flow D "더보기 [⋮] ➔ [편집] *(방장 전용)*", "개인방은 메뉴 비노출" / §5 TBD 답변)
- **FR-015**: 시스템은 반드시 편집 CTA가 눌리면 방 정보를 수정하고 편집 직전에 보던 방 상세로 복귀하며 `방 편집이 완료되었어요` 피드백을 표출한다. (근거: Figma `2792-151001` / PRD [SYS-001] Flow D)
- **FR-016**: 시스템은 반드시 편집된 방 이름·방 설명·대표 색상을 그 방을 표시하는 모든 자리(방 상세 헤더, 방 목록 카드, 지도 마커, 방 뱃지)에 동일하게 반영한다. (근거: PRD 데이터 용어 "대표 색상 — 마커·뱃지·툴팁 색상의 기준이 된다")
- **FR-017**: 시스템은 반드시 온보딩에서 진입한 경우에만 [건너뛰기]를 노출하고, [건너뛰기]가 눌리면 공동방을 만들지 않은 채 온보딩의 공유 방법 튜토리얼 스텝으로 이동한다. (근거: Figma `2314-95243` 주석 6 "최초 앱 접속 시에만 활성화 / 클릭 시 000[튜토리얼]로 이동" / PRD [SCR-002] Flow B)
- **FR-018**: 시스템은 반드시 이탈이 확정되면(이탈 확인 모달의 [나가기], 또는 모달을 거치지 않는 빈 폼의 뒤로가기) 방을 만들지 않은 채 폼을 연 진입점 화면으로 되돌리고, 저장하지 않은 입력값은 버린다. (근거: PRD [SYS-001] Flow E "[나가기] 클릭 시 호출한 화면으로 되돌아간다" / Figma `2314-95243` 주석 7)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 생성·편집 요청을 처리하는 동안 확정 버튼(생성은 저장 확인 모달의 [저장하기], 편집은 CTA `방 편집 완료`)을 다시 눌러도 요청이 추가로 발생하지 않게 하고, 같은 조작으로 방이 둘 이상 만들어지지 않는다. (근거: PRD [SYS-001] Flow C — 생성은 1회성 결과를 갖는다)
- **UX-002**: 입력 오류는 화면 상단 배너나 토스트가 아니라 해당 입력 필드의 테두리 상태와 필드 바로 아래 안내 문구의 색 전환으로만 표시한다. (근거: Figma `2314-95377`)
- **UX-003**: 생성·편집 요청이 실패해도 사용자가 이미 입력한 방 이름·방 설명·대표 색상은 지우지 않고 폼에 그대로 남긴다. (근거: 프로젝트 에러 처리 규약 — 실패는 입력 소실로 이어지지 않는다)
- **UX-004**: CTA가 비활성 상태일 때는 눌러도 화면 전환·피드백이 발생하지 않는다. (근거: Figma `2314-95301`, `2314-95377` — 비활성 CTA 상태)
- **UX-005**: 입력 영역은 세로로 스크롤되고 CTA는 화면 하단 액션 영역에 고정되어, 폼 어느 위치에 있든 CTA가 보인다. (근거: Figma `2314-95301` Scroll Bar + Action Area)
- **UX-006**: 생성·편집 완료 피드백은 이동한 화면 위에 얹혀 표출되고, 사용자의 추가 조작 없이 사라지며 그동안에도 화면 조작을 막지 않는다. (근거: Figma `2792-150362`, `2792-151001`)
- **UX-007**: 미리보기 카드와 방 설명의 글자 수 표시는 입력 확정을 기다리지 않고 글자 단위 입력마다 갱신한다. (근거: Figma `2314-95243` 주석 1·3 — 글자 수 표시를 갖는 필드는 방 설명뿐이다)
- **UX-008**: 확인 모달 3종(저장·생성 이탈·편집 이탈)은 폼 위에 딤 오버레이와 함께 얹히고, 떠 있는 동안 뒤의 폼 입력을 받지 않으며, 둘 이상이 동시에 표출되지 않는다. 세 모달은 본문 문구 없이 제목 한 줄과 버튼 2개로 같은 구성을 쓴다. (근거: Figma `3798-167701`·`3798-167946`·`3832-213717` — 폼 전체를 덮는 오버레이 위에 동일 구성의 모달을 배치)
- **UX-009**: 확인 모달 3종은 화면 밖 영역이나 뒤로가기로 닫혔을 때 파괴적 선택([저장하기]·[나가기])이 아니라 [취소]와 같게 동작한다. (근거: 확인 모달의 목적 — 사용자가 명시적으로 고르지 않은 결과를 만들지 않는다)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **공동방 (Group Room)**: 사용자가 직접 만드는 장소 저장 공간. 방 이름(필수, 15자 이내), 방 설명(선택, 30자 이내), 대표 색상(선택, 12종 중 1개 또는 기본 회색), 대표 캐릭터(대표 색상에서 파생), 방장, 멤버 목록을 갖는다. 개인방과 달리 초대·나가기·방장 위임의 대상이 된다.
- **대표 색상 (Room Color)**: 12종 팔레트 중 방에 부여하는 단일 색. 방 썸네일·지도 마커·방 뱃지·툴팁 색의 기준이 되며, 선택하지 않은 방은 회색을 갖는다.
- **대표 캐릭터 (Room Character)**: 방 썸네일에 대표 색상과 함께 표시되는 캐릭터 일러스트. 사용자가 따로 고르는 값이 아니라 선택된 대표 색상에서 파생되며, 색상이 바뀌면 함께 바뀐다.
- **방장 (Room Owner)**: 방을 만들었거나 권한을 위임받은 사용자. 이 스펙에서는 방 정보를 편집할 수 있는 유일한 주체다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)
- **SC-001**: 사용자가 폼 진입부터 공동방 생성 완료까지 방 이름 입력 · CTA 클릭 · 저장 확인 모달 [저장하기] 3개 조작만으로 끝낼 수 있다.
- **SC-002**: 방 이름·방 설명을 입력하는 동안 미리보기 카드와 방 설명의 글자 수 표시가 한 글자 뒤처지지 않고, 사용자가 입력을 멈춘 시점에 화면 값과 입력값이 항상 일치한다.
- **SC-003**: 방 이름 15자·방 설명 30자를 넘는 값이 저장되는 경우가 0건이며, 허용되지 않는 문자가 포함된 방 이름으로 방이 만들어지는 경우가 0건이다.
- **SC-004**: 생성·편집 완료 후 사용자가 도착한 화면에서 방 이름·설명·대표 색상이 방금 입력한 값과 100% 일치한다.
- **SC-005**: 같은 생성 조작으로 방이 둘 이상 만들어지는 중복 생성이 0건이다.
- **SC-006**: 방장이 아닌 사용자에게 방 편집 진입점이 노출되는 경우가 0건이다.
- **SC-007**: 저장 확인 모달의 [저장하기]를 거치지 않고 공동방이 만들어지는 경우가 0건이고, 입력값이 있는 생성 폼 또는 변경이 있는 편집 폼에서 이탈 확인 모달 없이 입력이 사라지는 경우가 0건이다.
- **SC-008**: 온보딩 첫 공동방 생성 스텝에서 사용자가 이전 스텝으로 되돌아가는 경우가 0건이다.

### 3.2 비목표 항목 (Out of Scope)

- 공동방의 초대 링크 생성·복사·공유 동작은 PRD [SYS-006] 스펙이 정의한다. 이 문서는 생성 완료 후 온보딩 친구 초대 스텝으로 이동한다는 사실까지만 다룬다.
- 방 나가기와 방장 권한 위임, 방 삭제는 PRD [SYS-007] 스펙이 정의한다. 이 문서는 더보기 메뉴에 [나가기]가 함께 있다는 사실까지만 다룬다.
- 방 리스트 탭·방 상세·홈 탭의 화면 구성(3단 바텀시트 높이, 지도·마커, 목록 정렬·필터, 카드 덱, 홈 방 시트 그리드)은 각각 PRD [SCR-004] · [SCR-005] · [SCR-003] 스펙이 정의한다. 이 문서는 그 화면들이 폼의 진입점·복귀점이라는 사실만 다룬다.
- 생성 완료 후 도착한 방 상세에서 우상단 [x]를 눌렀을 때의 이동처는 PRD [SCR-005] 방 상세 스펙이 정의한다. 이 문서의 범위는 생성 완료 후 방 상세까지 데려다 놓는 데서 끝난다.
- 개인방(`내 장소`)의 자동 생성 시점과 프로필 설정 폼은 PRD [SYS-011] 스펙이 정의한다.
- 공동방 0개 사용자에게 노출되는 Nudge 바텀시트·Ghost Card·홈 탭 빈 상태 CTA의 노출·해제 조건은 PRD [SYS-009] 스펙이 정의한다. 이 문서는 그 셋이 폼의 진입점이라는 사실과 각각의 도착점만 다룬다.
- 온보딩의 공유 방법 튜토리얼 스텝 구성(5스텝, dot 인디케이터, 완료 후 홈 탭 진입)은 PRD [SCR-002] Flow D가 정의한다. 이 문서는 [건너뛰기]가 그 스텝으로 보낸다는 사실까지만 다룬다.
- 대표 색상과 대표 캐릭터의 대응 관계(어느 색에 어느 캐릭터가 붙는지)와 캐릭터 에셋은 디자인 시스템이 정의한다. 이 문서는 캐릭터가 색상에서 파생된다는 규칙만 다룬다.
- 확인 모달·스낵바 컴포넌트의 형태·치수·딤 농도는 디자인 시스템이 정의한다. 이 문서는 모달의 표출 조건·문구·버튼 구성과 각 버튼의 결과만 다룬다.
- 장소 복제(다른 방에 공유) 시트의 방 목록 표출·복제 실행·중복 방 비활성 처리는 PRD [SYS-003] 스펙이 정의한다. 이 문서는 그 시트에서 폼이 열리고 다시 그 시트로 돌아온다는 사실만 다룬다.
- 대표 색상 12종의 실제 색값과 컴포넌트 형태는 디자인 시스템이 정의한다.
- 생성·편집 실패 시 사용자에게 보여줄 구체적 문구와 실패 유형 구분은 프로젝트 에러 처리 규약과 서버 계약이 정의한다.

## 4. 가정 (Assumptions)

- 방 이름의 중복을 검사하지 않는다. 같은 이름의 방을 여러 개 가질 수 있다 — Figma·PRD 어디에도 중복 검사나 그에 따른 오류 상태가 없다.
- 방 설명에는 문자 종류 제한이 없고 길이 제한만 적용된다 — 허용 문자 안내가 방 이름 필드에만 붙어 있다.
- 대표 색상은 이미 선택된 칩을 다시 눌러도 해제되지 않으며, 다른 칩을 눌러야 교체된다 — Figma에 해제 상태 전환이 없고, 미선택은 진입 직후 상태로만 존재한다.
- 방 이름 오류 판정은 입력 즉시 이뤄지며 CTA를 눌러야 드러나지 않는다 — `2314-95377`이 CTA 비활성 상태에서 이미 오류를 표시하고 있다.

  → **A**: **생성은 `공동방 만들기`, 편집은 `방 편집`이다.** 두 화면의 상단 바를 각각 확인해 확정했다 — 생성(`2314-95336`)은 뒤로가기 · `공동방 만들기` · `건너뛰기`, 편집(`2542-125957`)은 뒤로가기 · `방 편집` · 우측 액션 없음이다. 2.1.1의 가정이 근거로 삼은 `2792-150324`는 그 뒤의 디자인 개정으로 낡았다. 타이틀이 진입 맥락을 가르는 가시 요소이므로 CTA 라벨(FR-009)과 같은 격의 요구사항으로 올렸다. (FR-025, TS-044, 유저 플로우 1·4에 반영, §4 가정에서 제거)

- **Q**: 방 이름의 '한글'에 자모 단독(`ㄱ`·`ㅏ`)이 포함되는가? 3.0.0까지의 FR-004는 허용 문자를 "한글·영문·숫자·공백"으로만 적어 자모의 취급을 다루지 않았다.
  → **A**: **포함된다.** 자모를 배제하면 IME로 한글을 치는 동안 **조합 중인 글자마다 오류가 번쩍인다** — FR-004가 오류 판정을 입력 즉시 하도록 정했기 때문에 조합이 끝나기를 기다릴 수 없다. 그 대가로 `ㄱㄱㄱ` 같은 이름이 저장될 수 있으나, 사용자가 의도해서 그렇게 두는 경우까지 막을 이유가 없다. 이모지는 그대로 오류다(EC-005). (FR-004, EC-025, §4 가정에 반영)
