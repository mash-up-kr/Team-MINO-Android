## 1. 유저 시나리오 (User Scenarios) *(필수)*
### 유저 플로우 1 - 방 정보 입력

공동방을 만들거나 고칠 때 공통으로 쓰는 단일 폼이다. 방 이름·방 설명·대표 색상을 입력하면 상단 미리보기 카드가 즉시 바뀌고, 필수 항목인 방 이름이 채워지는 순간 하단 CTA가 활성화된다. 진입점이 어디든 폼의 구성과 규칙은 같다.

**Figma**: [001-1 공동방 명세 보드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95243&m=dev) · [001-1-1 공동방_기본](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95301&m=dev) · [001-1-2 공동방_입력 완료](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95339&m=dev)

**진입 조건**: 온보딩 첫 공동방 생성 스텝, 생성 유도 바텀시트, 방 리스트 탭 헤더 [+], 홈 탭 방 변경 시트 [방 만들기], 장소 복제(다른 방에 공유) 시트, 방 상세 더보기 [방 편집] 중 하나로 폼에 진입한 상태.

1. 폼 진입 → 미리보기 카드에 기본 썸네일과 안내 문구(`방 이름을 입력해 주세요.` / `어떤 장소들을 모으는 방인가요?`)가 표시되고, 방 이름 필드에 필수 표기(`*`)가 붙으며, 하단 CTA는 비활성 상태다
2. 방 이름 입력 → 카운터가 `n/15`로 갱신되고 미리보기 카드의 이름이 즉시 같은 값으로 바뀌며, CTA가 활성화된다
3. 방 설명 입력 → 카운터가 `n/30`으로 갱신되고 미리보기 카드의 설명이 즉시 같은 값으로 바뀐다
4. 대표 색상 칩 선택 → 선택한 칩에만 체크 표시가 남고 미리보기 카드 썸네일이 해당 색으로 바뀐다
5. 다른 색상 칩 선택 → 이전 선택이 해제되고 새 칩으로 교체된다

**완료 조건**: 방 이름이 오류 없이 1자 이상 입력되어 하단 CTA가 활성 상태이고, 미리보기 카드가 현재 입력값(이름·설명·색상)과 일치한다.

### 유저 플로우 2 - 방 이름 입력 오류

방 이름에 허용되지 않는 문자가 섞이면 그 자리에서 오류를 알리고, 나머지 항목을 아무리 채워도 방을 만들 수 없게 막는다.

**Figma**: [001-1-3 공동방_입력 오류](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95377&m=dev) · [001-1 공동방 명세 보드](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2314-95243&m=dev)

**진입 조건**: 생성 또는 편집 폼에서 방 이름 필드를 입력 중이다.

1. 방 이름에 한글·영문·숫자·공백이 아닌 문자를 입력한다(예: `민호야 잘하자^^`) → 방 이름 필드가 오류 상태로 바뀌고 필드 우측에 오류 아이콘이 나타나며, 필드 아래 안내 문구 `한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)`가 오류 색으로 전환된다
2. 대표 색상을 고르고 방 설명을 입력한다 → 오류가 남아 있는 한 CTA는 계속 비활성 상태다
3. 허용되지 않는 문자를 지운다 → 오류 상태와 오류 아이콘이 해제되고 안내 문구가 기본 색으로 돌아오며 CTA가 활성화된다

**완료 조건**: 방 이름 필드에 오류 상태가 남아 있지 않고, 오류 상태였던 동안 CTA가 한 번도 활성화되지 않았다.

### 유저 플로우 3 - 공동방 생성 완료와 진입점별 후속 이동

[방 생성하기]를 누르면 공동방이 만들어지고, 사용자를 어디로 데려다 놓을지는 폼에 들어온 진입점이 정한다. 같은 폼이지만 끝나는 자리가 다르다.

**Figma**: [온보딩 공동방 만들기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-149043&m=dev) · [온보딩 친구 초대](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-149757&m=dev) · [001-1 공동방 생성 유도 바텀시트](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-149650&m=dev) · [002-4-1 방변경 시트](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-150143&m=dev) · [002-4-1 공동방 만들기](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-150248&m=dev) · [생성 완료 후 방 상세](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-150362&m=dev)

**진입 조건**: 생성 폼에서 유저 플로우 1을 마쳐 CTA `방 생성하기`가 활성 상태다.

1. [방 생성하기] 클릭 → 입력한 이름·설명·대표 색상으로 공동방이 만들어지고, 만든 사용자가 그 방의 방장이 된다
2. 온보딩에서 진입했다면 → 온보딩의 '친구 초대' 스텝(`친구들을 초대해볼까요?`)으로 이동한다
3. 방 리스트 탭 [+] 또는 생성 유도 바텀시트에서 진입했다면 → 새로 만든 방의 방 상세로 이동하고 `방 생성 완료!` 스낵바가 표출된다
4. 장소 복제(다른 방에 공유) 시트에서 진입했다면 → 복제 시트로 되돌아가고, 새로 만든 방이 선택 가능한 방 목록에 포함된 상태가 된다. 보고 있던 장소는 자동으로 복제되지 않는다
5. 홈 탭 방 변경 시트에서 진입했다면 → 새로 만든 방의 방 상세로 이동하고 `방 생성 완료!` 스낵바가 표출된다. 방 리스트 탭 [+]·생성 유도 바텀시트와 같은 도착점이다

**완료 조건**: 입력값 그대로의 공동방이 내 방 목록에 존재하고, 사용자가 진입점에 대응하는 화면에 도착해 있으며, 폼 화면은 뒤로가기 대상으로 남지 않는다.

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)
- **FR-001**: 시스템은 반드시 방 이름·방 설명·대표 색상 세 항목과 상단 미리보기 카드, 하단 CTA로 구성된 하나의 폼을 제공하고, 생성과 편집이 진입점과 무관하게 이 폼을 공유한다. (근거: PRD [SYS-001] "생성과 편집이 같은 화면을 공유하므로 진입점과 무관하게 하나로 유지한다" / Figma `2314-95301`, `2792-150324`)
- **FR-002**: 시스템은 반드시 방 이름을 유일한 필수 입력으로 두고, 비어 있을 때 안내 문구 `방 이름을 입력해 주세요.`와 필수 표기(`*`)를 노출한다. (근거: Figma `2314-95243` 주석 2 "필수 요구 사항" / PRD [SYS-001] Flow A "필수 항목은 방 이름 하나다")
- **FR-003**: 시스템은 반드시 방 이름을 공백 포함 15자까지만 입력받고, 입력한 글자 수를 `n/15` 형태로 표시한다. (근거: Figma `2314-95243` 주석 2 "공백 포함 15자 이내" / PRD [SYS-001] Flow A)
- **FR-004**: 시스템은 반드시 방 이름에 한글·영문·숫자·공백 외의 문자가 포함되면 해당 필드를 오류 상태로 표시하고, 오류가 해소될 때까지 CTA를 비활성 상태로 유지한다. (근거: Figma `2314-95377` 오류 안내 `한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)` / PRD [SYS-001] Flow B)
- **FR-005**: 시스템은 반드시 방 설명을 선택 입력으로 두고, 안내 문구 `어떤 장소들을 모으는 방인가요?`를 노출하며, 공백 포함 30자까지만 입력받고 글자 수를 `n/30` 형태로 표시한다. (근거: Figma `2314-95339` 및 `2314-95243` 주석 3 / PRD [SYS-001] Flow A "방 설명 30자")
- **FR-006**: 시스템은 반드시 대표 색상 12종(red / red orange / orange / lime / green / cyan / violet / pink / blue / brown / light blue / purple) 중 하나만 선택하게 하고, 하나도 선택하지 않으면 회색을 대표 색상으로 적용한다. (근거: Figma `2314-95243` 주석 4 "컬러칩 복수 선택 불가능" / PRD 데이터 용어 "12종 팔레트", "고르지 않으면 기본값인 회색이 적용된다")
- **FR-007**: 시스템은 반드시 방 이름이 오류 없이 1자 이상 입력된 경우에만 하단 CTA를 활성화하고, 방 설명·대표 색상의 입력 여부는 활성화 조건에 포함하지 않는다. (근거: Figma `2314-95243` 주석 5 "방 이름을 정상 입력 시 3, 4번을 입력하지 않더라도 활성화")
- **FR-008**: 시스템은 반드시 상단 미리보기 카드에 현재 입력된 방 이름·방 설명·대표 색상을 반영하고, 입력과 삭제를 즉시 카드에 반영한다. (근거: Figma `2314-95243` 주석 1 "방 이름, 방 설명, 방 색상 입력/삭제가 실시간으로 반영")

- **FR-014**: 시스템은 반드시 방 편집 진입점인 방 상세 더보기 [방 편집] 메뉴를 공동방의 방장에게만 노출하고, 개인방(`내 장소`)의 방 상세에서는 더보기 메뉴 자체를 노출하지 않는다. (근거: Figma `2792-150974` / PRD [SCR-005] Flow D "더보기 [⋮] ➔ [편집] *(방장 전용)*" / §5 TBD 답변)
- **FR-015**: 시스템은 반드시 편집 CTA가 눌리면 방 정보를 수정하고 편집 직전에 보던 방 상세로 복귀하며 `방 편집이 완료되었어요` 피드백을 표출한다. (근거: Figma `2792-151001` / PRD [SYS-001] Flow D)
- **FR-016**: 시스템은 반드시 편집된 방 이름·방 설명·대표 색상을 그 방을 표시하는 모든 자리(방 상세 헤더, 방 목록 카드, 지도 마커, 방 뱃지)에 동일하게 반영한다. (근거: PRD 데이터 용어 "대표 색상 — 마커·뱃지·툴팁 색상의 기준이 된다")
- **FR-017**: 시스템은 반드시 온보딩에서 진입한 경우에만 [건너뛰기]를 노출하고, [건너뛰기]가 눌리면 공동방을 만들지 않은 채 온보딩의 공유 방법 튜토리얼 스텝으로 이동한다. (근거: Figma `2314-95243` 주석 6 "최초 앱 접속 시에만 활성화 / 클릭 시 000[튜토리얼]로 이동" / PRD [SCR-002] Flow B)
- **FR-018**: 시스템은 반드시 뒤로가기가 눌리면 방을 만들거나 수정하지 않은 채 폼을 연 진입점 화면으로 되돌리고, 저장하지 않은 입력 변경은 폐기 여부를 묻지 않고 그대로 버린다. (근거: Figma `2314-95243` 주석 7 / §5 TBD 답변)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 생성·편집 요청을 처리하는 동안 CTA를 다시 눌러도 요청이 추가로 발생하지 않게 하고, 같은 조작으로 방이 둘 이상 만들어지지 않는다. (근거: PRD [SYS-001] Flow C — 생성은 1회성 결과를 갖는다)
- **UX-002**: 입력 오류는 화면 상단 배너나 토스트가 아니라 해당 입력 필드의 테두리 상태와 필드 바로 아래 안내 문구의 색 전환으로만 표시한다. (근거: Figma `2314-95377`)
- **UX-003**: 생성·편집 요청이 실패해도 사용자가 이미 입력한 방 이름·방 설명·대표 색상은 지우지 않고 폼에 그대로 남긴다. (근거: 프로젝트 에러 처리 규약 — 실패는 입력 소실로 이어지지 않는다)
- **UX-004**: CTA가 비활성 상태일 때는 눌러도 화면 전환·피드백이 발생하지 않는다. (근거: Figma `2314-95301`, `2314-95377` — 비활성 CTA 상태)
- **UX-005**: 입력 영역은 세로로 스크롤되고 CTA는 화면 하단 액션 영역에 고정되어, 폼 어느 위치에 있든 CTA가 보인다. (근거: Figma `2314-95301` Scroll Bar + Action Area)
- **UX-006**: 생성·편집 완료 피드백은 이동한 화면 위에 얹혀 표출되고, 사용자의 추가 조작 없이 사라지며 그동안에도 화면 조작을 막지 않는다. (근거: Figma `2792-150362`, `2792-151001`)
- **UX-007**: 방 이름·방 설명의 글자 수 표시와 미리보기 카드는 입력 확정을 기다리지 않고 글자 단위 입력마다 갱신한다. (근거: Figma `2314-95243` 주석 1·3)

### 2.3 주요 도메인 (Core Domain) *(데이터를 다루는 기능일 경우 포함)*

- **공동방 (Group Room)**: 사용자가 직접 만드는 장소 저장 공간. 방 이름(필수, 15자 이내), 방 설명(선택, 30자 이내), 대표 색상(선택, 12종 중 1개 또는 기본 회색), 방장, 멤버 목록을 갖는다. 개인방과 달리 초대·나가기·방장 위임의 대상이 된다.
- **대표 색상 (Room Color)**: 12종 팔레트 중 방에 부여하는 단일 색. 방 썸네일·지도 마커·방 뱃지·툴팁 색의 기준이 되며, 선택하지 않은 방은 회색을 갖는다.
- **방장 (Room Owner)**: 방을 만들었거나 권한을 위임받은 사용자. 이 스펙에서는 방 정보를 편집할 수 있는 유일한 주체다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)
- **SC-001**: 사용자가 폼 진입부터 공동방 생성 완료까지 방 이름 입력과 CTA 클릭 2개 조작만으로 끝낼 수 있다.
- **SC-002**: 방 이름·방 설명을 입력하는 동안 글자 수 표시와 미리보기 카드가 한 글자 뒤처지지 않고, 사용자가 입력을 멈춘 시점에 화면 값과 입력값이 항상 일치한다.
- **SC-003**: 방 이름 15자·방 설명 30자를 넘는 값이 저장되는 경우가 0건이며, 허용되지 않는 문자가 포함된 방 이름으로 방이 만들어지는 경우가 0건이다.
- **SC-004**: 생성·편집 완료 후 사용자가 도착한 화면에서 방 이름·설명·대표 색상이 방금 입력한 값과 100% 일치한다.
- **SC-005**: 같은 생성 조작으로 방이 둘 이상 만들어지는 중복 생성이 0건이다.
- **SC-006**: 방장이 아닌 사용자에게 방 편집 진입점이 노출되는 경우가 0건이다.

### 3.2 비목표 항목 (Out of Scope)

- 공동방의 초대 링크 생성·복사·공유 동작은 PRD [SYS-006] 스펙이 정의한다. 이 문서는 생성 완료 후 온보딩 친구 초대 스텝으로 이동한다는 사실까지만 다룬다.
- 방 나가기와 방장 권한 위임, 방 삭제는 PRD [SYS-007] 스펙이 정의한다. 이 문서는 더보기 메뉴에 [방 나가기]가 함께 있다는 사실까지만 다룬다.
- 방 리스트 탭·방 상세·홈 탭의 화면 구성(3단 바텀시트 높이, 지도·마커, 목록 정렬·필터, 카드 덱)은 각각 PRD [SCR-004] · [SCR-005] · [SCR-003] 스펙이 정의한다. 이 문서는 그 화면들이 폼의 진입점·복귀점이라는 사실만 다룬다.
- 생성 완료 후 도착한 방 상세에서 우상단 [x]를 눌렀을 때의 이동처는 PRD [SCR-005] 방 상세 스펙이 정의한다. 이 문서의 범위는 생성 완료 후 방 상세까지 데려다 놓는 데서 끝난다.
- 개인방(`내 장소`)의 자동 생성 시점과 프로필 설정 폼은 PRD [SYS-011] 스펙이 정의한다.
- 공동방 0개 사용자에게 노출되는 생성 유도 바텀시트와 Ghost Card의 노출·해제 조건은 PRD [SYS-009] 스펙이 정의한다. 이 문서는 그 진입점에서 폼이 열린다는 사실만 다룬다.
- 온보딩의 공유 방법 튜토리얼 스텝 구성은 PRD [SCR-002] Flow D가 정의한다.
- 장소 복제(다른 방에 공유) 시트의 방 목록 표출·복제 실행·중복 방 비활성 처리는 PRD [SYS-003] 스펙이 정의한다. 이 문서는 그 시트에서 폼이 열리고 다시 그 시트로 돌아온다는 사실만 다룬다.
- 대표 색상 12종의 실제 색값과 컴포넌트 형태는 디자인 시스템이 정의한다.
- 생성·편집 실패 시 사용자에게 보여줄 구체적 문구와 실패 유형 구분은 프로젝트 에러 처리 규약과 서버 계약이 정의한다.

## 4. 가정 (Assumptions)

- 방 이름의 중복을 검사하지 않는다. 같은 이름의 방을 여러 개 가질 수 있다 — Figma·PRD 어디에도 중복 검사나 그에 따른 오류 상태가 없다.
- 방 설명에는 문자 종류 제한이 없고 길이 제한만 적용된다 — 허용 문자 안내가 방 이름 필드에만 붙어 있다.
- 대표 색상은 이미 선택된 칩을 다시 눌러도 해제되지 않으며, 다른 칩을 눌러야 교체된다 — Figma에 해제 상태 전환이 없고, 미선택은 진입 직후 상태로만 존재한다.
- 방 이름 오류 판정은 입력 즉시 이뤄지며 CTA를 눌러야 드러나지 않는다 — `2314-95377`이 CTA 비활성 상태에서 이미 오류를 표시하고 있다.
- 방 설명 글자 수 표시의 상한은 30자다. Figma 주석의 `0/20` 표기는 오기로 보고, 화면(`0/30`)과 PRD(30자)를 따른다.
- 방 이름이 오류 상태인 동안에도 미리보기 카드는 현재 입력값을 그대로 반영한다. `2314-95377`의 미리보기가 오류 문자열을 뺀 값으로 그려진 것은 디자인 표기 누락으로 본다.
- 편집 화면의 상단 타이틀은 생성과 동일하게 `공동방 만들기`로 그려져 있으나(`2792-150324`), 편집 맥락에 맞는 타이틀을 쓰는 것이 자연스럽다고 보고 디자인 확인 대상으로 남긴다. 이 스펙은 타이틀 문구를 확정하지 않는다.
- 생성·편집은 온라인 상태에서 이뤄지며 서버가 방 정보를 보관한다. 오프라인 상태의 임시 저장이나 재시도 큐는 다루지 않는다.
- 방 이름·방 설명의 글자 수는 사용자가 보는 문자 단위로 센다.
- 장소 복제(다른 방에 공유) 시트가 폼의 진입점이 된 이상, 생성 완료 후에는 복제 시트로 되돌아가고 보고 있던 장소는 자동 복제하지 않는다고 본다 — PRD [SYS-003]이 "탐색 중이던 화면 Context를 유지한다"와 "복제 후에도 대상 방으로 이동하지 않는다"를 원칙으로 두고 있어, 새 방을 만든 것만으로 복제까지 일어나는 것은 그 원칙과 어긋난다. 이 동선은 Figma에 화면이 없으므로 디자인 확인 대상이다.
- 방장이 아닌 멤버에게는 [방 편집]만 감추고 더보기 메뉴 자체는 노출한다 — [방 나가기]가 멤버에게도 필요하기 때문이다(`2792-151222`).

### 답변 완료

- **Q**: 개인방(`내 장소`)의 방 상세에서도 [방 편집]을 노출해 이름·설명·색상을 고칠 수 있게 하는가?
  → **A**: **노출하지 않는다.** 개인방은 더보기 메뉴 자체를 노출하지 않으며, 방 편집은 공동방 전용이다. (FR-014, EC-013에 반영)
- **Q**: Figma `001-1` 주석 7이 뒤로가기 대상으로 적은 `011[다른 방에 공유]`처럼, 장소 복제 시트도 공동방 생성 폼의 진입점인가?
  → **A**: **진입점에 포함한다.** 진입점은 온보딩·생성 유도 바텀시트·방 리스트 탭 [+]·홈 탭 방 변경 시트·장소 복제 시트 5개다. 생성 완료 후에는 복제 시트로 복귀하며 보고 있던 장소를 자동 복제하지 않는다. (FR-011, FR-019, EC-016에 반영 / 후속 동선은 §4 가정 참고)
- **Q**: 홈 탭 방 변경 시트에서 공동방 생성을 마쳤을 때 어디로 이동하는가? Figma User Flow 보드(`2792-150248` → `2792-150362`)는 새로 만든 방의 **방 상세**로 이동하며 `방 생성 완료!` 스낵바를 표출하고, PRD [SYS-001] Flow C는 **홈 탭으로 복귀해 새 방의 덱으로 전환**한다고 적어 두 산출물이 상충한다. 어느 쪽을 따르는가?
  → **A**: **Figma를 따라 새로 만든 방의 방 상세로 이동한다.** 방 리스트 탭 [+]·생성 유도 바텀시트와 같은 도착점이며, 홈 탭으로 복귀하지 않는다. 도착한 방 상세에서 우상단 [x]를 누르면 방 리스트로 이동하나, 그 동선은 이 스펙의 범위가 아니라 PRD [SCR-005] 방 상세 스펙이 정의한다. PRD [SYS-001] Flow C는 이 결정에 맞춰 갱신 대상이다. (FR-011, TS-027, §3.2에 반영)
- **Q**: 편집 폼에서 값을 고친 뒤 저장하지 않고 뒤로가기(또는 OS 뒤로 제스처)를 눌렀을 때, 변경을 확인 없이 폐기하는가 아니면 폐기 여부를 묻는 확인 모달을 표출하는가?
  → **A**: **폐기 여부를 묻지 않는다.** 확인 모달 없이 즉시 폼을 닫고 고친 값은 버린다. (FR-018, EC-012, TS-028에 반영)
