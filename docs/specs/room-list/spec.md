## 1. 유저 시나리오 (User Scenarios)

### 유저 플로우 1 - 지도 & 3단 바텀시트 탐색 (개인방만 있는 경우)
공동방이 하나도 없는 사용자가 방 리스트 탭에 진입해 지도와 바텀시트로 개인방(내 장소)의 장소를 탐색한다.

**Figma**: [방 리스트 (개인방만)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2370-114745&m=dev) · [Peek](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2661-157242&m=dev) · [Half](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2661-157338&m=dev) · [Full](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2661-157259&m=dev)

**진입 조건**: 사용자가 바텀 네비게이션에서 방 리스트 탭을 선택했고, 소유한 공동방이 0개다(개인방만 존재).

1. 방 리스트 탭 진입 → 지도 초기화(이 시점에 위치 권한 요청) 및 개인방 장소 마커 표시, 시트가 `Peek`(90dp, 헤더만) 상태로 표출
2. 사용자가 시트를 위로 드래그 → `Half`(244dp)로 전환, 정렬 드롭다운·카테고리 칩(전체/카페/음식점)과 개인방 카드가 표시

4. 사용자가 시트를 더 위로 드래그 → `Full`로 승격, 개인방 카드가 리스트 형태로 전체 표출
5. 사용자가 개인방 카드를 선택 → [SCR-005] 방 상세로 이동

**완료 조건**: 사용자가 지도·바텀시트를 통해 개인방의 장소를 확인했거나 방 상세로 이동했다.

### 유저 플로우 2 - 지도 & 3단 바텀시트 탐색 (개인방 + 공동방이 있는 경우)
공동방을 하나 이상 보유한 사용자가 방 리스트 탭에서 개인방과 공동방을 함께 탐색한다.

**진입 조건**: 사용자가 방 리스트 탭을 선택했고, 개인방 외에 공동방을 1개 이상 소유하고 있다.

1. 방 리스트 탭 진입 → 지도에 개인방·공동방 모든 장소 마커 표시, 시트가 `Peek`(90dp) 상태로 표출

6. 사용자가 방 카드를 선택 → [SCR-005] 방 상세로 이동

### 유저 플로우 4 - 공동방 생성 유도 (Nudge & Ghost Card)
공동방이 하나도 없는 사용자가 첫 공동방을 만들도록 유도받는다.

**진입 조건**: 방 리스트 탭 진입 시점에 사용자의 공동방 개수가 0이다.

1. 방 리스트 탭 진입, 공동방 0개 확인 → 생성 유도 바텀시트(Nudge)가 자동으로 위에 표출(`공동방을 생성해보세요!` / `"저번에 말한 거기가 어디였지?" 더 이상 묻지 마세요.`)
2. 사용자가 [공동방 만들기] 클릭 → 유저 플로우 3의 공동방 생성 폼 호출로 이어짐
3. 사용자가 [나중에 만들래요] 클릭 → Nudge 시트가 닫히고 방 리스트 화면(Peek 상태)이 유지됨
4. Nudge를 닫은 이후에도 방 리스트 하단에는 `공동방 만들기` Ghost Card가 상시 노출됨
5. 사용자가 Ghost Card를 클릭 → 유저 플로우 3의 공동방 생성 폼 호출로 이어짐

**완료 조건**: 사용자가 Nudge를 닫았거나 Nudge/Ghost Card를 통해 공동방 생성을 시작했다.

## 2. 요구사항 (Requirements)
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 방 리스트 탭 진입 시 지도를 초기화하고, 사용자가 속한 모든 방(개인방+공동방)의 장소 마커를 표시해야 한다. (근거: PRD [SCR-004] Flow A, [SYS-004])
- **FR-002**: 시스템은 반드시 하단 방 리스트 시트를 `Peek`(90dp) / `Half`(공동방 0개: 244dp, 1개: 348dp, N개 이상: 380dp) / `Full`(전체 화면) 세 단계로 드래그 전환할 수 있도록 해야 한다. (근거: PRD 「3단 바텀시트」 정의)
- **FR-003**: 시스템은 반드시 `Peek`/`Half` 단계에서 정렬 드롭다운과 카테고리 칩(전체/카페/음식점)을 제공하고, 선택에 따라 지도 위 마커를 필터링해야 한다. (근거: Figma Peek 노드 2661-157242/2661-158108, Half 노드 2661-157338)
- **FR-004**: 시스템은 반드시 `Full` 단계에서 개인방(`내 장소`)을 최상단에 고정하고, 나머지 방을 정렬 칩(전체/최근 저장 순/코멘트 순) 기준으로 정렬한 카드 목록(방 썸네일·이름·설명·장소 개수·멤버 아바타)으로 표시해야 한다. (근거: PRD [SCR-004] Flow B, Figma Full 노드 2661-157259/2661-158125)
- **FR-005**: 시스템은 반드시 방 카드 선택 시 해당 방의 [SCR-005] 방 상세로 이동해야 한다. (근거: PRD [SCR-004] Flow B)
- **FR-006**: 시스템은 반드시 `Full` 시트 우상단 [+] 버튼 클릭 시 공동방 생성 폼([SYS-001])을 호출하고, 생성 완료 시 새로 만든 방의 상세로 이동해야 한다. (근거: PRD [SCR-004] Flow C)
- **FR-007**: 시스템은 반드시 공동방이 0개인 상태로 탭에 진입할 때마다(같은 세션 내 재진입 포함) 공동방 생성 유도 Nudge 바텀시트를 자동으로 표출해야 한다. (근거: PRD [SYS-009] Flow A)
- **FR-008**: 시스템은 반드시 공동방이 0개인 상태에서 방 리스트 하단에 `공동방 만들기` Ghost Card를 상시 노출해야 한다. (근거: PRD [SYS-009] Flow B)
- **FR-009**: 시스템은 반드시 `Half` 단계에서 공동방 카드가 3개 이상일 때 세 번째 카드를 일부 잘리게 표시해 스크롤 가능함을 암시해야 한다. (근거: PRD 「3단 바텀시트」 정의, Figma 2661-159182)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 시트는 바텀 네비게이션 위로 드래그해 승격하며, `Full` 단계에서는 현재 위치 버튼을 숨긴다. (근거: PRD 「현재 위치 버튼」 정의)
- **UX-002**: 시트 각 단계의 높이는 화면 비율이 아니라 콘텐츠에 따라 정해진 고정 dp 값을 사용한다(FR-002 참고). (근거: PRD 「3단 바텀시트」 정의)
- **UX-003**: Nudge 바텀시트를 닫아도 방 리스트 화면은 유지되며, Ghost Card는 계속 노출된다. (근거: PRD [SYS-009] Flow A·B)

### 2.3 주요 도메인 (Core Domain)

- **방 (Room)**: 개인방(`내 장소`, 자동 생성·삭제 불가·최상단 고정) 또는 공동방(사용자가 생성, 대표 색상·캐릭터를 가짐)으로 구분된다. 방 리스트 탭은 사용자가 속한 모든 방을 이 두 유형으로 나누어 노출한다.
- **바텀시트 단계 (Sheet State)**: `Peek`/`Half`/`Full` 3단계 상태값. 각 상태는 화면·공동방 개수에 따라 고정 dp 높이를 가진다.

## 3. 범위 (Scope)
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 방 리스트 탭 진입 후 3초 이내에 지도와 `Peek` 시트가 렌더링된다.
- **SC-002**: 사용자가 드래그 한 번으로 `Peek`↔`Half`↔`Full` 각 인접 단계를 전환할 수 있다.
- **SC-003**: 공동방 0개 사용자가 Nudge 또는 Ghost Card를 거쳐 첫 공동방 생성 폼에 도달하는 비율을 측정할 수 있다.
- **SC-004**: 방 카드 선택부터 [SCR-005] 방 상세 진입까지 화면 전환이 지연 없이 이루어진다.

### 3.2 비목표 항목 (Out of Scope)

- 3단 바텀시트의 드래그 제스처 인식·높이 전환 애니메이션 메커니즘 자체는 디자인 시스템 공용 컴포넌트(이슈 #144)가 정의한다. 이 spec은 그 안에 담기는 헤더·칩·카드 등 room-list 전용 콘텐츠만 정의한다.
- 공동방 생성/편집 폼의 입력 필드·검증 규칙·완료 후 폼 자체 동작은 `group-room-form` spec([SYS-001], 이슈 #146)이 정의한다.
- 지도 카메라 초기화, 커스텀 마커 색상 판별 규칙 자체는 [SYS-004]가 정의하며 이 spec에서 재정의하지 않는다.
- [SCR-005] 방 상세 화면 내부 구성은 이 spec의 범위가 아니다.
- 바텀 네비게이션([SYS-005]) 자체의 탭 전환 동작은 이 spec의 범위가 아니다.

---

## 4. 가정 (Assumptions)

- 대표 색상·캐릭터 표시 규칙은 [SYS-004] 정의를 그대로 따른다.
- 정렬 드롭다운·정렬 칩의 옵션 값(꾹 Pick 등 카드덱 기준과 달리, 방 리스트는 「전체/최근 저장 순/코멘트 순」)은 PRD에 명시된 값을 그대로 사용한다.
- `Half` 단계의 공동방 개수 문턱값(0/1/N개)과 높이(244dp/348dp/380dp)는 PRD 고정값을 그대로 따른다.
- Nudge 바텀시트의 문구는 PRD에 명시된 문구를 그대로 사용한다.
- 위치 권한이 거부된 경우의 지도 초기 위치는 [SYS-004]의 기본 정책을 따른다(이 spec에서 별도 정의하지 않음).
