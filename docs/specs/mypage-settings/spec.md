## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 마이페이지 조회 및 프로필 수정
사용자가 마이페이지 탭에서 자신의 프로필·설정 현황을 확인하고, 닉네임·아바타를 수정한다.

**Figma**: [마이페이지 메인](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151806&m=dev) · [프로필 설정](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151449&m=dev)

**진입 조건**: 프로필(닉네임+아바타)이 이미 생성되어 있는 사용자가 바텀 네비게이션의 마이페이지 탭을 선택한 상태

1. 마이페이지 탭 선택 → 프로필 요약(닉네임·아바타), 앱 설정(다크모드·알림 설정·위치 설정), 서비스 정보(약관 및 동의·앱 리뷰 남기기) 3개 섹션이 노출된다
2. 프로필 영역의 [연필] 아이콘 클릭 → 기존 닉네임·아바타가 채워진 프로필 설정 화면으로 이동한다
3. 닉네임을 수정하거나 아바타를 다시 선택 → 유효한 값이면 [저장] 버튼이 활성화된다
4. [지우기] 클릭 → 닉네임 입력값과 아바타 선택을 한 번에 초기화한다
5. [저장] 클릭 → 마이페이지로 복귀하고, 변경된 닉네임·아바타가 즉시 반영된다

**완료 조건**: 마이페이지 프로필 영역에 최신 닉네임·아바타가 표시된다

| TS-003 | 닉네임 변경 저장 | 프로필 설정 화면에서 닉네임을 유효한 값으로 변경함 | [저장] 클릭 | 마이페이지로 복귀하며 새 닉네임이 즉시 표시됨 | FR-003 |

### 유저 플로우 2 - 다크모드 변경

**Figma**: [마이페이지 메인](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151806&m=dev) · [다크모드 선택](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151659&m=dev)

**진입 조건**: 마이페이지 메인 화면에 있음. 다크모드를 한 번도 변경한 적이 없다면 값은 `시스템 기본값`이다.

**완료 조건**: 앱을 재실행해도 마지막으로 선택한 다크모드 값이 유지된다

### 유저 플로우 3 - 알림/위치 권한 켜기·끄기
사용자가 마이페이지에서 알림·위치 스위치를 켜 OS 권한을 요청한다. 스위치를 끄는 동작은 두 설정이 서로 다르다 — 알림은 OS 권한을 유지한 채 앱 자체 발송 설정만 끄고, 위치는 앱이 OS 권한 자체를 취소할 수 없어 OS 설정 화면으로 유도한다. 두 스위치 모두 화면에 들어올 때마다 각자의 실제 상태와 재동기화된다.

**Figma**: [마이페이지 메인 (알림 OFF)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151806&m=dev) · [마이페이지 메인 (알림 ON)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151589&m=dev) · [알림 권한 팝업](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151732&m=dev) · [위치 권한 팝업](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2792-151769&m=dev)

**진입 조건**: 마이페이지 메인 화면에 있음

1. `알림 설정` 스위치 클릭(OFF, 알림 권한 미결정) → OS 알림 권한 팝업이 표출된다
2. [허용] 선택 → OS 알림 권한이 허용되고, 앱 자체 알림 발송 설정도 함께 ON으로 저장되어 스위치가 ON으로 전환된다
3. ON 상태의 `알림 설정` 스위치를 다시 클릭 → OS 알림 권한은 그대로 유지한 채 앱 자체 알림 발송 설정만 OFF로 저장되어 스위치가 OFF로 전환된다(푸시 발송만 중단, OS 권한 자체는 회수하지 않음)
4. `위치 설정` 스위치 클릭(OFF, 위치 권한 미결정) → OS 위치 권한 팝업이 표출된다
5. [허용] 선택 → 위치 설정 스위치가 ON으로 전환된다
6. ON 상태의 `위치 설정` 스위치를 다시 클릭 → 앱은 이미 부여된 OS 권한을 스스로 취소할 수 없으므로, 확인 다이얼로그로 안내한 뒤 OS 앱 설정 화면으로 이동시킨다
7. 마이페이지에 다시 진입하거나 복귀 → 알림 스위치는 (OS 권한 허용 여부 AND 앱 자체 발송 설정)을, 위치 스위치는 실제 OS 권한 상태를 각각 재조회해 동기화한다. 사용자가 OS 설정에서 알림 권한 자체를 직접 거부한 경우에도 재진입 시 스위치가 OFF로 반영된다

**완료 조건**: 알림 스위치는 (OS 권한 허용 여부 AND 앱 자체 발송 설정)을, 위치 스위치는 항상 실제 OS 권한 상태를 정확히 반영한다

**테스트 시나리오**

| ID | 시나리오 | Given | When | Then | 관련 FR |
|---|---|---|---|---|---|
| TS-005 | 알림 권한 최초 요청 | 알림 권한이 아직 결정되지 않음 | `알림 설정` 스위치 클릭 | OS 알림 권한 팝업이 표출됨 | FR-007 |

| TS-012 | OS 설정에서 알림 권한 직접 거부 후 재동기화 | 알림 설정 스위치가 ON인 상태에서 사용자가 OS 시스템 설정에서 알림 권한을 직접 거부함 | 마이페이지 화면으로 복귀 | 스위치가 OFF로 갱신됨 | FR-009 |

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 마이페이지 메인 화면에 프로필 요약, 앱 설정(다크모드·알림 설정·위치 설정), 서비스 정보(약관 및 동의·앱 리뷰 남기기) 3개 섹션을 노출해야 한다. (근거: PRD [SCR-008], Figma 151806)
- **FR-002**: 시스템은 반드시 프로필 영역의 [연필] 아이콘 클릭 시 기존 닉네임·아바타 값이 채워진 프로필 설정 화면으로 이동시켜야 한다. (근거: PRD [SYS-011] Flow A, Figma 151449)
- **FR-003**: 시스템은 반드시 프로필 저장 완료 시 마이페이지 및 앱 전체의 프로필 표기에 변경 사항을 즉시 반영해야 한다. (근거: PRD [SYS-011] Flow C)
- **FR-004**: 시스템은 반드시 닉네임이 2자 미만이거나 아바타가 선택되지 않은 경우 저장을 비활성 상태로 유지해야 한다. (근거: PRD [SYS-011] Flow B)
- **FR-005**: 시스템은 반드시 `다크모드` 항목 클릭 시 라이트 / 다크 / 시스템 기본값 3개 옵션을 제시해야 하며, 사용자가 변경한 적이 없는 초기 상태의 값은 `시스템 기본값`이어야 한다. (근거: PRD [SCR-008] Flow B)
- **FR-006**: 시스템은 반드시 다크모드 옵션 선택 즉시 앱 전체 테마에 적용하고 값을 로컬에 저장해야 한다. (근거: PRD [SCR-008] Flow B)
- **FR-007**: 시스템은 반드시 `알림 설정` 스위치 클릭 시(권한 미결정 상태에 한해) OS 알림 권한 요청을 표출해야 한다. (근거: PRD [SCR-008] Flow C, Figma 151732)
- **FR-008**: 시스템은 반드시 `위치 설정` 스위치 클릭 시(권한 미결정 상태에 한해) OS 위치 권한 요청을 표출해야 한다. (근거: PRD [SCR-008] Flow D, Figma 151769)
- **FR-009**: 시스템은 반드시 스위치 표시 상태를 로컬 캐시가 아니라 마이페이지 진입·복귀 시점마다 재조회해 동기화해야 한다 — 알림 스위치는 (OS 알림 권한 허용 여부 AND 앱 자체 알림 발송 설정)을, 위치 스위치는 실제 OS 위치 권한 상태를 반영한다. 다른 화면이나 이전 세션, OS 시스템 설정에서 이미 결정된 상태도 동일하게 반영해야 한다. (근거: 이슈 #152 논의 — 권한이 다른 진입점에서 먼저 결정될 수 있음)
- **FR-010**: 시스템은 반드시 OS 수준에서 권한이 영구 거부되어 시스템 팝업이 재노출되지 않는 경우, 스위치 클릭(켜기 시도) 시 이동 사유를 설명하는 확인 다이얼로그를 먼저 보여준 뒤 OS 앱 설정 화면으로 이동시켜야 한다. (근거: PRD [SCR-008] Flow F, §5 TBD 질문 1 답변)
- **FR-011**: 시스템은 반드시 `약관 및 동의` 클릭 시 서비스 이용약관·개인정보 처리방침이 정리된 지정 노션 문서 링크(`https://app.notion.com/p/3bdbee7f599680028b69f036fd989613?source=copy_link`)를 웹 브라우저에서 열어야 한다. (근거: PRD [SCR-008] Flow E, §5 TBD 질문 3 답변)
- **FR-012**: 시스템은 반드시 `앱 리뷰 남기기` 클릭 시 Play Store의 앱 리뷰 페이지로 이동시켜야 하며, Play Store 앱이 설치되어 있지 않으면 웹 브라우저로 Play 스토어 웹페이지를 열어야 한다. (근거: PRD [SCR-008] Flow E, §5 TBD 질문 2 답변)
- **FR-013**: 시스템은 반드시 프로필 설정 화면의 [지우기] 클릭 시 닉네임 입력값과 아바타 선택을 함께 초기화해야 한다. (근거: PRD [SYS-011] Flow A)
- **FR-014**: 시스템은 반드시 ON 상태의 `알림 설정` 스위치를 다시 클릭하면 OS 알림 권한은 유지한 채 앱 자체 알림 발송 설정만 OFF로 저장하고 스위치를 OFF로 전환해야 한다. (근거: 이슈 #152 후속 논의 2026-08-16)
- **FR-015**: 시스템은 반드시 ON 상태의 `위치 설정` 스위치를 다시 클릭하면, 앱이 위치 권한을 직접 취소할 수 없음을 안내하는 확인 다이얼로그를 먼저 보여준 뒤 OS 앱 설정 화면으로 이동시켜야 한다. (근거: 이슈 #152 후속 논의 2026-08-16)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 다크모드 선택 UI는 Figma 시안의 iOS 네이티브 ActionSheet(시스템 기본값/꺼짐/켜짐/취소)를 그대로 이식하지 않고, Android 관용 컴포넌트(BottomSheet 등)로 표현한다. (근거: 사용자 지시 — 디자인의 iOS 편향 감안, Figma 151659)
- **UX-002**: 알림·위치 권한 요청은 Figma 시안의 iOS 시스템 다이얼로그 스타일이 아니라 Android 런타임 권한 요청 플로우(OS 표준 권한 다이얼로그)를 그대로 따른다 — 별도의 커스텀 사전 안내 팝업을 임의로 추가하지 않는다. (근거: 사용자 지시 — 디자인의 iOS 편향 감안, Figma 151732·151769)
- **UX-003**: 권한 팝업 응답을 기다리는 동안 스위치는 사용자의 실제 조작 이전에 미리 ON으로 바뀌지 않는다 — 권한이 확정된 뒤에만 상태를 반영한다(낙관적 업데이트 금지). (근거: PRD [SCR-008] Flow C·D)
- **UX-004**: 프로필 저장 실패 등으로 프로필 설정 화면에 남아있게 되어도 사용자가 입력한 닉네임·선택한 아바타는 유지한다. (근거: 일반 폼 입력 유지 관례)

### 2.3 주요 도메인 (Core Domain)

- **프로필 (Profile)**: 닉네임과 제공 아바타 1개로 구성되는 단일 공통 프로필. 앱 전체에서 하나만 존재하며 온보딩과 마이페이지가 같은 데이터를 공유한다.
- **앱 설정 (AppSettings)**: 다크모드 값(라이트/다크/시스템 기본값), 앱 자체 알림 발송 설정(로컬 저장), 위치 권한 허용 여부(OS 조회값)로 구성된다. 알림 스위치가 화면에 보여주는 최종 ON/OFF는 "OS 알림 권한 허용" AND "앱 자체 알림 발송 설정 ON"의 합성값이며, 위치 스위치는 OS 위치 권한 상태를 그대로 반영한다. 다크모드 값과 알림 발송 설정은 로컬 저장 대상이고, 알림 권한 허용 여부와 위치 권한 허용 여부는 OS가 단일 진실 공급원(source of truth)이다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 사용자가 마이페이지 진입 후 프로필 수정을 완료(연필 클릭 → 저장 → 반영 확인)하는 데 10초를 넘지 않는다.
- **SC-002**: 다크모드 옵션을 선택하면 1초 이내에 앱 전체 테마 전환이 완료된다.
- **SC-003**: 알림 스위치는 (OS 권한 허용 여부 AND 앱 자체 발송 설정), 위치 스위치는 실제 OS 권한 상태와 진입·복귀 시마다 재조회한 결과의 불일치가 0건이다.
- **SC-004**: 프로필을 처음 편집하는 사용자의 90%가 별도 안내 없이 아바타를 선택하고 저장을 완료한다.

### 3.2 비목표 항목 (Out of Scope)

- 온보딩([SCR-002]) 자체의 진입·완료 플로우는 이 스펙이 정의하지 않는다. 프로필 설정 화면 컴포넌트는 공유하되, 온보딩에서의 개인방 자동 생성 등 후속 분기는 온보딩 스펙이 정의한다.
- 바텀 네비게이션 셸([SYS-005], 이슈 #99)의 구현 자체는 이 스펙의 범위가 아니다. 이 스펙은 이미 존재하는 마이페이지 탭 진입 지점을 전제로 한다.
- 알림 탭([SCR-007])의 알림 종류·목록·읽음 처리는 이 스펙이 정의하지 않는다.
- 노션 문서에 담긴 약관·개인정보 처리방침의 실제 법률 문구 작성·검수는 이 스펙이 정의하지 않는다. 이 스펙은 그 문서로 연결하는 진입 동작만 정의한다.

## 4. 가정 (Assumptions)

- 사용자는 이미 온보딩을 통해 프로필(닉네임+아바타)을 생성한 상태에서 마이페이지에 진입한다.
- 다크모드 값은 디바이스 로컬에 유지되며, 재설치 전까지 별도 계정 동기화 없이 그대로 유지된다.
- 앱 리뷰 이동은 Play Store 스토어 페이지 이동으로 충분하며, 인앱 리뷰(In-App Review) API 적용 여부는 이 스펙에서 결정하지 않는다.
- 알림·위치 권한의 "영구 거부" 판정은 OS가 제공하는 권한 거부 이력 판정 표준 동작을 그대로 따른다.
- 노션 문서 링크는 별도 로그인 없이 열람 가능한 공개 링크 상태를 유지한다.
- OS 알림 권한이 어느 진입점에서든 최초로 허용되면, 앱 자체 알림 발송 설정의 기본값은 ON으로 저장된다.

- **Q**: 알림/위치 권한이 OS 수준에서 영구 거부된 상태에서 스위치를 클릭하면, 앱 설정 화면으로 이동하기 전에 별도 안내를 보여줄까요, 아니면 바로 이동시킬까요?

- **Q**: `약관 및 동의` 화면의 실제 문구·콘텐츠 소스(웹뷰 vs 네이티브 텍스트)는 무엇인가?
  → **A**: 콘텐츠 소스는 노션 문서(`https://app.notion.com/p/3bdbee7f599680028b69f036fd989613?source=copy_link`)이며, 클릭 시 웹 브라우저에서 이 링크를 연다. (2026-08-16 사용자 확정, PRD 3.1.0 Flow E 반영)
- **Q**: 이미 허용된(ON) 알림/위치 스위치를 다시 클릭해 끄려고 하면 어떻게 동작해야 하는가? — 기존 스펙(1.1.0)은 "켜기" 방향만 정의하고 있었다.
