# Quickstart: 마이페이지 & 환경설정

이 기능이 엔드투엔드로 동작함을 검증하는 실행 가이드. 계약·데이터 모델 세부는 복제하지 않고 링크한다 — [`data-model.md`](data-model.md), [`contracts/`](contracts/).

## 선행 조건

- `docs/specs/mypage-settings/spec.md` v2.0.0, `plan.md` v1.0.0 기준 구현이 완료돼 있다.
- 온보딩이 아직 없으므로(§3.2 비목표), 앱을 새로 설치한 기기에는 프로필이 없다. `ProfileRepository.saveProfile(...)`을 한 번 직접 호출하거나(디버그 진입점) 테스트용 초기 프로필을 DataStore에 미리 넣어 "프로필이 이미 생성된 사용자" 전제(spec §1 진입 조건)를 맞춘다.

## 빌드

```sh
./gradlew :app:assembleQaDebug
```

헌법 §품질 게이트의 최소선. CI가 없으므로 이 명령이 사람이 확인하는 유일한 자동 검증이다.

## 실행 시나리오 — spec 테스트 시나리오를 그대로 따라간다

에뮬레이터/실기기에 QA 빌드를 설치하고 마이페이지 탭으로 이동한다.

| 시나리오 | 조작 | 기대 결과 | spec ID |
|---|---|---|---|
| 최초 진입 | 마이페이지 탭 선택 | 프로필·앱 설정·서비스 정보 3섹션 노출 | TS-001 |
| 프로필 수정 | [연필] → 닉네임·아바타 변경 → [저장] | 마이페이지 복귀, 새 값 즉시 표시 | TS-002·TS-003 |
| 지우기 | 프로필 화면에서 [지우기] | 입력값 초기화, [저장] 비활성 | EC-006 |
| 다크모드 전환 | `다크모드` → "다크" 선택 | 화면 전체(마이페이지 밖 다른 탭 포함) 즉시 다크 테마로 전환 | TS-004, research.md D4 |
| 알림 최초 허용 | `알림 설정` 스위치 클릭 → 시스템 팝업에서 [허용] | 스위치 ON | TS-005 |
| 알림 발송만 끄기 | ON 상태에서 `알림 설정` 스위치 재클릭 | 스위치 OFF. **기기 설정 > 알림에서 이 앱의 권한은 여전히 허용 상태**인지 확인 | TS-011 |
| 위치 끄기 시도 | 위치 허용 상태에서 `위치 설정` 스위치 클릭 | 확인 다이얼로그 → OS 앱 설정 화면으로 이동 | EC-007 |
| 권한 영구 거부 | 알림 권한을 시스템 설정에서 "다시 묻지 않음"으로 거부한 뒤 스위치 클릭 | 확인 다이얼로그 → OS 앱 설정 화면으로 이동(시스템 팝업 아님) | EC-003 |
| 약관 열람 | `약관 및 동의` 클릭 | 웹 브라우저가 열리며 지정 노션 문서 표시 | TS-010 |
| 앱 리뷰 | `앱 리뷰 남기기` 클릭 | Play Store 앱 상세 페이지(미설치 시 웹 스토어 페이지) | TS-009, EC-004 |

## 회귀 확인 — 다크모드 전역 적용

`MinoAndroidAppTheme` 시그니처가 바뀌므로([`contracts/design-system-theme-override-contract.md`](contracts/design-system-theme-override-contract.md)), 마이페이지에서 테마를 바꾼 뒤 **홈 탭으로 이동해도 같은 테마가 유지되는지** 확인한다. 여기서 어긋나면 D4의 적용 지점(`MainActivity`)이 잘못 배선된 것이다.
