## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 공동방 정보 입력과 생성
사용자가 방 이름·방 설명·대표 색상을 입력해 새 공동방을 만든다. 방 이름 하나만 채우면 생성할 수 있고, 나머지 둘은 선택 입력이다.

**Figma**: [002-4-1 공동방 만들기 (빈 상태)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2331-62598&m=dev) · [002-4-1 공동방 만들기 (입력 상태)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2331-62200&m=dev)

**진입 조건**: 프로필 설정을 마친 사용자가 온보딩·홈 탭 방 변경 시트·방 리스트 탭 중 한 진입점에서 공동방 만들기를 호출해, 모든 입력이 비어 있는 생성 폼에 들어와 있다.

1. 사용자가 폼을 확인한다 → 시스템이 방 이름(필수)·방 설명(선택)·대표 색상(선택)을 표시하고, 하단 [방 생성하기]를 비활성 상태로 둔다
2. 사용자가 방 이름을 입력한다 → 시스템이 입력 글자 수를 `n/15`로 갱신하고, 이름이 유효해지는 순간 [방 생성하기]를 활성화한다
3. 사용자가 방 설명을 입력한다 → 시스템이 입력 글자 수를 `n/30`으로 갱신한다
4. 사용자가 색상 팔레트에서 색 하나를 누른다 → 시스템이 그 색만 선택 상태로 바꾸고 직전 선택을 해제한다
5. 사용자가 [방 생성하기]를 누른다 → 시스템이 버튼을 로딩 상태로 바꿔 중복 제출을 막고, 공동방을 생성한 뒤 요청자를 방장으로 지정한다

**완료 조건**: 입력한 이름·설명·대표 색상을 가진 공동방이 생성되어 사용자의 방 목록에 존재하고, 사용자가 그 방의 방장이다.

### 유저 플로우 2 - 생성 완료 후 진입점별 후속 이동
같은 생성 폼을 어디서 열었느냐에 따라 생성 직후 사용자가 도착하는 화면이 달라진다. 폼은 하나지만 도착지는 세 갈래다.

**Figma**: [002-4-1 방변경 시트 (홈 탭 진입점)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2331-59671&m=dev) · [002-5-1 메인_방 변경 시 툴팁](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2331-59744&m=dev) · [001-1 공동방 생성 유도 바텀시트 (방 리스트 진입점)](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2370-66503&m=dev)

**진입 조건**: 유저 플로우 1을 거쳐 공동방 생성이 성공했고, 폼을 연 진입점이 온보딩·홈 탭 방 변경 시트·방 리스트 탭 중 하나로 식별되어 있다.

1. 온보딩에서 폼을 열었던 사용자가 생성을 마친다 → 시스템이 온보딩의 친구 초대 스텝으로 이동시킨다
2. 홈 탭 방 변경 시트에서 폼을 열었던 사용자가 생성을 마친다 → 시스템이 홈 탭으로 돌아와 방금 만든 방의 카드 덱으로 전환하고, 그 방의 대표 색상·캐릭터로 뱃지와 툴팁을 갱신한다
3. 방 리스트 탭에서 폼을 열었던 사용자가 생성을 마친다 → 시스템이 방금 만든 방의 방 상세로 이동시킨다

**완료 조건**: 사용자가 진입점에 대응하는 후속 화면에 도착해 있고, 생성 폼이 뒤로 가기 대상으로 남아 있지 않다.

### 유저 플로우 3 - 공동방 편집 (방장 전용)
방장이 이미 만든 공동방의 이름·설명·대표 색상을 고친다. 생성과 같은 폼을 쓰되 기존 값이 채워진 상태로 열리고, 하단 버튼만 [방 편집 완료]로 바뀐다.

**Figma**: [004-5-2 (방장) 공동방 편집](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2407-60755&m=dev) · [004-5-3 (방장) 공동방 편집 중](https://www.figma.com/design/5P3HE7q8MGc6yAr4rTOSZn/MU_%EB%94%94%EC%9E%90%EC%9D%B8?node-id=2407-109186&m=dev)

**진입 조건**: 방장인 사용자가 자기 공동방의 방 상세에서 더보기 메뉴를 열어 [편집]을 선택했다.

1. 사용자가 [편집]을 선택한다 → 시스템이 생성과 동일한 폼을 열고 현재 방 이름·방 설명·대표 색상을 채워 넣은 뒤, 하단 버튼을 [방 편집 완료]로 표시한다
2. 사용자가 값을 고친다 → 시스템이 유저 플로우 1과 동일한 글자 수 상한·허용 문자·색상 단일 선택 규칙을 적용한다
3. 사용자가 [방 편집 완료]를 누른다 → 시스템이 변경된 값을 반영하고 방 상세로 되돌아가 완료 스낵바를 표시한다
4. 방의 대표 색상이 바뀌었다면 → 시스템이 그 방의 마커·뱃지·툴팁 색상을 바뀐 색으로 갱신한다

**완료 조건**: 방 상세에 편집한 값이 반영되어 있고, 같은 방을 보고 있는 다른 멤버에게도 같은 값이 적용된다.

| EC-013 | 개인방(`내 장소`)에서 편집을 시도한다 | [TBD: 개인방 편집 허용 여부 미지정 — 검토 보류 상태다. §5 참조 - 편집 메뉴 자체를 노출하지 않음 / 이름·색상만 편집 허용 / 공동방과 동일하게 허용] | FR-010 |

## 2. 요구사항 (Requirements) *(필수)*
### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 공동방 생성 폼에 방 이름(필수)·방 설명(선택)·대표 색상(선택) 세 항목만을 제공하고, 방 이름 항목에 필수 표시를 함께 노출한다. (근거: PRD [SYS-001] Flow A "필수 항목은 방 이름 하나다" / Figma `002-4-1 공동방 만들기` 2331:62598)
- **FR-002**: 시스템은 반드시 방 이름을 공백 포함 1자 이상 15자 이하로 제한하고, 한글·영문·숫자·공백만 허용하며, 15자를 넘는 입력은 받지 않는다. (근거: Figma 헬퍼 문구 `한글·영문·숫자만 입력 가능해요. (공백 포함 15자 이내)` / PRD [SYS-001] Flow A "상한을 넘는 입력은 받지 않는다")
- **FR-003**: 시스템은 반드시 방 설명을 30자 이하로 제한하고, 30자를 넘는 입력은 받지 않는다. (근거: Figma `002-4-1 공동방 만들기` 카운터 `0/30` / PRD [SYS-001] Flow A)
- **FR-004**: 시스템은 반드시 방 이름과 방 설명 각각에 `현재 글자 수/상한` 형식의 카운터를 입력과 동시에 갱신해 표시한다. (근거: Figma `002-4-1 공동방 만들기` 2331:62200 카운터 `2/15`·`0/30`)
- **FR-005**: 시스템은 반드시 대표 색상을 red·red orange·orange·lime·green·cyan·violet·pink·blue·brown·light blue·purple 12종 팔레트로 제공하고, 그중 최대 하나만 선택된 상태를 유지한다. 폼은 아무 색도 선택되지 않은 상태로 열리며, 선택 없이 생성·편집을 마치면 12종에 포함되지 않는 회색이 대표 색상이 된다. (근거: PRD 도메인 용어 "지정된 12종 팔레트 중 1개를 선택한다 … 고르지 않으면 기본값인 회색이 적용된다" / Figma 색상 인스턴스 2331:62617~62630)
- **FR-006**: 시스템은 반드시 방 이름이 FR-002를 만족할 때만 하단 CTA를 활성화하고, 그 외에는 비활성 상태로 둔다. (근거: Figma 빈 상태 2331:62598 비활성 CTA · 입력 상태 2331:62200 활성 CTA / PRD [SYS-001] Flow A)
- **FR-007**: 시스템은 반드시 허용하지 않는 문자가 방 이름에 입력되면 해당 입력 필드에 오류 상태를 표시하고 CTA를 비활성으로 유지한다. (근거: PRD [SYS-001] Flow B "해당 입력 필드에 오류 상태 표시 ➔ CTA 비활성 유지")
- **FR-008**: 시스템은 반드시 [방 생성하기] 실행 시 입력값으로 공동방을 생성하고 요청한 사용자를 그 방의 방장으로 지정한다. (근거: PRD 도메인 용어 "방장: 방을 최초로 생성했거나 방장 권한을 위임받은 사용자")
- **FR-009**: 시스템은 반드시 생성 완료 후 폼을 연 진입점에 따라 이동 대상을 나눈다 — 온보딩은 친구 초대 스텝, 홈 탭 방 변경 시트는 홈 탭의 새 방 카드 덱, 방 리스트 탭은 새 방의 방 상세. (근거: PRD [SYS-001] Flow C)
- **FR-010**: 시스템은 반드시 공동방 편집 진입을 그 방의 방장에게만 허용하고, 방장이 아닌 멤버에게는 편집 진입점을 노출하지 않는다. (근거: PRD 도메인 용어 "방장: 방의 전체 설정을 변경할 수 있는 권한" / PRD [SYS-001] Flow D "방 편집 (방장 전용)")
- **FR-011**: 시스템은 반드시 편집 진입 시 생성과 동일한 폼에 현재 방 이름·방 설명·대표 색상을 채워 넣고 하단 CTA 문구를 [방 편집 완료]로 표시하며, FR-002~FR-007의 입력 규칙을 그대로 적용한다. (근거: PRD [SYS-001] Flow D "Flow A와 동일한 폼에 기존 값이 채워진 상태로 진입" / Figma `004-5-2 (방장) 공동방 편집` 2407:60755)
- **FR-012**: 시스템은 반드시 편집 완료 시 변경된 값을 그 방에 반영하고 방 상세로 되돌아가 완료 스낵바를 표시하며, 대표 색상이 바뀐 경우 그 방의 마커·뱃지·툴팁 색상을 함께 갱신한다. (근거: PRD [SYS-001] Flow D / PRD 핵심 원칙 "방마다 다른 얼굴")
- **FR-013**: 시스템은 반드시 생성·편집 폼에서 뒤로 가기로 이탈하면 입력값을 반영하지 않고 진입 이전 화면으로 되돌린다. (근거: Figma 상단 네비게이션 뒤로 가기 2331:62633)
- **FR-014**: 시스템은 반드시 생성·편집 요청이 실패하면 사용자가 이해할 수 있는 오류를 안내하고, 폼과 입력값을 그대로 유지한 채 재시도할 수 있게 한다. (근거: PRD [SYS-001] Flow B / 프로젝트 에러 처리 규약)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: CTA를 누른 뒤 결과가 확정되기 전까지 CTA를 로딩 상태로 바꾸고 추가 입력을 받지 않아, 한 번의 생성 시도로 만들어지는 공동방이 정확히 1개가 되게 한다. (근거: PRD [SYS-001] Flow C / FR-008)
- **UX-002**: 입력 오류는 화면 상단 배너나 별도 팝업이 아니라 오류가 발생한 입력 필드에 붙여 표시하고, 오류가 해소되면 즉시 사라진다. (근거: PRD [SYS-001] Flow B "해당 입력 필드에 오류 상태 표시")
- **UX-003**: 생성·편집 요청이 실패해도 사용자가 입력한 방 이름·방 설명·대표 색상 선택은 지우지 않는다. (근거: FR-014)
- **UX-004**: 방 이름과 방 설명의 글자 수 카운터는 사용자가 글자를 입력·삭제할 때마다 갱신되어, 상한까지 남은 글자 수를 별도 조작 없이 확인할 수 있다. (근거: Figma 카운터 `2/15` 2331:62200 / FR-004)
- **UX-005**: 폼 상단의 방 미리보기 카드는 방 이름·방 설명·대표 색상 세 값을 모두 실시간으로 반영해, 사용자가 생성 버튼을 누르기 전에 만들어질 방의 모습을 확인할 수 있게 한다. 아직 입력되지 않은 값 자리에는 각 입력 필드와 같은 안내 문구를 둔다. (근거: PRD 핵심 원칙 "방마다 다른 얼굴" / Figma 미리보기 카드 2331:62203)
- **UX-006**: 색상 팔레트는 12종을 한 화면에서 스크롤 없이 훑을 수 있게 배치하고, 아무 색도 고르지 않은 상태와 특정 색을 고른 상태를 구분되는 선택 표식으로 나타낸다. (근거: Figma 색상 팔레트 3행 4열 배치 2331:62616~62630 / FR-005)

### 2.3 주요 도메인 (Core Domain)

- **공동방 (Group Room)**: 장소를 함께 모으는 공간. 방 이름(필수, 15자 이하), 방 설명(선택, 30자 이하), 대표 색상(12종 중 1개), 방장, 멤버 목록, 저장된 장소 목록을 가진다. 개인방과 달리 멤버 초대와 방 나가기가 가능하다.
- **대표 색상 (Room Color)**: 공동방을 시각적으로 식별하는 값. 12종 팔레트 중 하나이며, 그 방에 속한 장소의 지도 마커·뱃지·툴팁 색상의 기준이 된다.
- **방장 (Room Owner)**: 공동방을 만들었거나 권한을 위임받은 멤버. 방 이름·설명·대표 색상을 바꿀 수 있는 유일한 역할이다.

## 3. 범위 (Scope) *(필수)*
### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 사용자가 생성 폼 진입부터 공동방 생성 완료까지 30초 이내에 마칠 수 있다. 필수 입력이 방 이름 하나이므로 최소 조작은 이름 입력 1회와 CTA 탭 1회다.
- **SC-002**: 사용자의 90%가 방 이름 입력 오류로 되돌아오는 일 없이 첫 시도에 공동방 생성을 완료한다.
- **SC-003**: CTA를 누른 뒤 3초 이내에 성공 이동 또는 오류 안내 중 하나의 결과 피드백이 사용자에게 도달한다.
- **SC-004**: 생성 직후 도착한 화면에서 사용자가 방금 만든 방이 선택되어 있음을 방 이름을 읽지 않고 대표 색상·캐릭터만으로 식별할 수 있다.
- **SC-005**: 편집 완료 후 방 상세와 지도 마커에 변경된 방 이름·대표 색상이 3초 이내에 반영된다.
- **SC-006**: 공동방 생성 관련 문의 중 "생성 버튼이 눌리지 않는다" 유형이 전체 문의의 5% 이하로 유지된다 — 비활성 사유가 방 이름 미입력임을 화면에서 알 수 있어야 달성된다.

### 3.2 비목표 항목 (Out of Scope)

- 공동방 생성 유도(생성 유도 바텀시트·Ghost Card·홈 탭 빈 상태 CTA)는 PRD [SYS-009]를 다루는 별도 스펙이 정의한다. 이 문서는 유도 화면이 호출한 뒤의 생성 폼부터만 정의한다.
- 초대 링크 생성·공유와 초대 수신은 PRD [SYS-006]·[SYS-010]을 다루는 스펙이 정의한다. 생성 후 온보딩의 친구 초대 스텝으로 이동한다는 사실만 여기서 정의하고, 그 스텝의 동작은 정의하지 않는다.
- 방 나가기와 방장 권한 위임은 PRD [SYS-007]을 다루는 스펙이 정의한다.
- 개인방(`내 장소`)의 자동 생성 시점과 방 목록 고정 규칙은 프로필 설정 스펙이 정의한다.
- 공동방 삭제와 멤버 강제 퇴장은 이 문서가 정의하지 않는다.
- 방 상세 화면의 구성·더보기 메뉴 전체 항목은 PRD [SCR-005]를 다루는 스펙이 정의한다. 이 문서는 그중 [편집] 항목의 노출 조건과 진입 후 동작만 정의한다.
- 지도 마커의 색상 판별 규칙(중복 저장 장소 처리 등)은 PRD [SYS-004]를 다루는 스펙이 정의한다. 이 문서는 대표 색상 변경이 마커에 반영된다는 사실까지만 정의한다.
- 12종 팔레트 각 색의 실제 색상값과 디자인 토큰 정의는 디자인 시스템이 소유한다.
- 방 이름·설명에 대한 금칙어·신고 정책은 이 문서가 정의하지 않는다.

## 4. 가정 (Assumptions)

- 생성 폼에 들어오는 사용자는 이미 프로필 설정을 마쳐 디바이스 세션과 개인방을 가지고 있다. 프로필이 없는 사용자가 이 폼에 도달하는 경로는 없다고 본다.
- 방 이름의 최소 길이는 디자인에 명시되어 있지 않아 1자로 둔다. 공백만으로 이루어진 이름은 유효하지 않은 것으로 본다(EC-001).
- 방 이름 앞뒤 공백은 저장 시 제거한다(EC-002). 디자인의 헬퍼 문구가 공백을 허용 문자로 언급하므로 이름 가운데의 공백은 그대로 둔다.
- 방 설명의 허용 문자는 별도로 제한하지 않는다. 디자인이 허용 문자 안내를 방 이름 아래에만 두고 있어 그 제한이 이름 전용이라고 본다.
- 방 설명에 최소 길이 제약은 없다. 선택 입력이므로 빈 값이 정상 상태다.
- 색상 팔레트는 스크롤 없이 12종 전체가 한 화면에 들어간다. 디자인이 3행 4열로 모두 노출하고 있다.
- 편집으로 대표 색상을 바꾸면 그 방에 이미 저장된 장소의 마커에도 소급 적용된다. 색상이 방에 귀속된 값이고 장소별로 따로 지정되지 않기 때문이다.
- 생성·편집은 네트워크 연결을 전제로 한다. 오프라인 상태에서 만들어 두고 나중에 반영하는 동작은 없다고 본다.
- 생성·편집 실패 시 사용자에게 보이는 문구는 프로젝트의 도메인 예외 처리 규약이 결정한다. 이 문서는 오류가 안내된다는 사실과 입력값이 유지된다는 조건만 정한다.
- 한 사용자가 만들 수 있는 공동방 개수에 상한은 없다. PRD와 디자인 어디에도 상한이 언급되어 있지 않다.
- 방 상세 더보기 메뉴의 [편집] 노출 여부만으로 권한을 가르며, 방장이 아닌 멤버가 편집 화면에 도달할 경로는 없다고 본다.
- 편집 화면의 상단 타이틀은 디자인에 `공동방 만들기`로 그려져 있으나, 편집 맥락에 맞는 문구를 쓰는 것으로 본다. 디자인이 생성 폼을 복제하면서 타이틀을 갱신하지 않은 것으로 판단했다.
- 색상 팔레트의 미선택 상태는 디자인에 없다. 생성·편집 프레임 네 개(2331:62598·2331:62200·2407:60755·2407:109186)가 모두 팔레트 첫 색에 선택 표식이 붙은 상태로 그려져 있으나, FR-005는 PRD의 회색 기본값 규칙을 따르므로 미선택 상태 표현이 디자인에 추가로 필요하다.
- 미리보기 카드가 입력값을 반영하는 상태 역시 디자인에 없다. 생성·편집 프레임 여섯 개가 모두 기본 상태(`Room Thumbnail_Empty`)로만 그려져 있어, UX-005를 만족하려면 값이 채워진 카드 표현이 디자인에 추가로 필요하다.
- 회색 대표 색상을 가진 방의 마커·뱃지·툴팁 표현은 디자인 시스템이 12종 팔레트와 동일한 방식으로 제공한다고 본다.

### 확정된 항목

- **Q**: 폼 상단 미리보기 카드가 입력값을 어디까지 반영하는가? 디자인의 생성·편집 프레임 여섯 개가 모두 기본 상태(`Room Thumbnail_Empty`)로만 그려져 있어 판단 근거가 없다.
  → **A**: 방 이름·방 설명·대표 색상을 모두 실시간 반영한다. (UX-005에 반영)

- **Q**: 대표 색상을 고르지 않았을 때의 기본값은 무엇인가? PRD는 "고르지 않으면 기본값인 회색"이라 적었으나, 디자인 네 프레임 모두 팔레트 첫 색이 선택 표식을 단 상태로 그려져 있어 어긋난다.
  → **A**: PRD를 따라 회색을 기본값으로 한다. 폼은 아무 색도 선택되지 않은 상태로 열리며, 팔레트에 미선택 상태 표현이 새로 필요하다. (FR-005·UX-006·EC-003에 반영)

- **Q**: 같은 이름의 공동방을 또 만드는 것을 허용하는가? PRD·디자인 모두 방 이름 중복을 다루지 않는다.
  → **A**: 중복을 허용한다. 방은 이름이 아니라 대표 색상·캐릭터로 구분한다. (EC-004에 반영)

### 검토가 필요한 항목

- **Q**: 개인방(`내 장소`)도 편집할 수 있는가? PRD는 개인방에 대해 삭제·나가기 금지와 초대 불가만 명시하고 편집은 언급하지 않는다. 허용 여부에 따라 FR-010의 적용 대상과 방 상세 더보기 메뉴의 구성이 달라진다. (EC-013)
