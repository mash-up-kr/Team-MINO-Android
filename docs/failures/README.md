# Failure Records (실패 기록)

머지된 이후 잘못된 결정·구현으로 판명되어 되돌리거나 다시 고친 사례를 기록하는 문서 모음이다. [ADR](../adr/README.md)이 "왜 이렇게 하기로 했는지"를 남긴다면, 실패 기록은 "왜 그 결정이 틀렸는지, 무엇으로 대체했는지"를 남긴다. 목적은 같은 실패를 반복하며 재조사·재논의에 대화 토큰을 다시 쓰는 것을 막는 것이다.

## 언제 실패 기록을 쓰는가

- 머지된 코드가 이후(대개 다른 세션에서) 잘못된 설계·구현으로 판명되어 되돌리거나 크게 고친 경우
- 기존 [ADR](../adr/README.md)의 결정이 실무에서 틀렸다고 판명된 경우 — 해당 ADR의 상태를 `Deprecated` 또는 `Superseded by NNNN`으로 함께 갱신한다
- 시도했지만 채택하지 않기로 한 접근 (같은 시도를 다시 반복하지 않기 위해)

사소한 오타·단순 버그 수정처럼 "왜 틀렸는지"를 남길 필요가 없는 것은 기록하지 않는다.

## 작성 규칙

- 파일명: `NNN-kebab-제목.md` (3자리 일련번호, 예: `001-celery.md`)
- 번호는 **한 번 부여하면 재사용하지 않는다**
- 필수 항목: **상태 · 발생일자 · 작성자 · 관련 ADR/커밋 · 무엇을 시도했는가 · 무엇이 잘못됐는가 · 어떻게 발견했는가 · 무엇으로 대체했는가**
- **작성자**는 [ADR](../adr/README.md)과 동일하게, 문서를 쓴 사람이 아니라 **이 기록이 누구의 작업과 관련되면 좋을지**를 남기는 필드다
- 언어는 한국어
- 작성 후 아래 인덱스에 줄을 추가한다

## 상태 값

| 상태 | 의미 |
|---|---|
| `Open` | 원인은 기록됐지만 재발 방지책이 아직 정리되지 않음 |
| `Resolved` | 대체 방법까지 적용되어 마무리됨 |

## 문서 템플릿

내용은 채우지 않은 뼈대만 남긴다. 실제 작성 시 아래 헤더·순서를 그대로 따르되, 서술 내용은 매 사례마다 다르므로 예시 문장은 넣지 않는다.

```markdown
# NNN. {제목}

- **상태**: Open | Resolved
- **발생일자**: YYYY-MM-DD
- **작성자**:
- **관련 ADR**: (있으면 ADR 링크, 없으면 "없음 — 문서화되지 않은 결정")
- **관련 커밋/PR**:

## 무엇을 시도했는가

## 무엇이 잘못됐는가

## 어떻게 발견했는가

## 무엇으로 대체했는가
```
