## 개선된 것

- **wall clock 238.8 → 78.2분.** 정체는 병렬도가 아니라 **없어진 일**이다. 두 항목이 전부다.
  - **사용자 대기 129분 → 0분.** `AskUserQuestion` 호출이 0회다. 착수 게이트 `1-c` 프로브가 대조 대상 27노드 중 막힌 1개(`2242-51229` 방 썸네일 컴포넌트셋)를 배정 전에 찾아냈고, 리드가 묻기 전에 데스크톱 MCP·`download_assets` 대체 경로를 확인해 뚫었다. 다만 Round 1의 더 큰 차단(칩 컴포넌트셋, 82분)은 위 조건대로 스펙 정정으로 이미 사라져 있었다.
  - **총 작업량 204.5 → 137.9분(-33%).** 브리프의 부재 결론 분리 규칙이 걸렸다. Round 1에서 47분 대기와 세 번째 배정을 만든 "그 파일을 다시 열지 마라" 인계가 재현되지 않았다.
- **리드 출력 638.6k → 358.8k.** 개선 전(390k)보다도 아래다. 사용자에게 보인 텍스트 30,310자 → **9,556자**(114블록, 블록당 84자), 브리프 182,468자/40건 → **103,285자/34건**(건당 3,037자). 결정 5의 출력 계약과 결정 1의 배정 수가 서로 반대로 당기던 구조에서, 계약 쪽이 이겼다.
- **진행 로그 `note` 29줄 → 0줄.** 경과 시간 기준(배정 후 10분간 `done`·`blocked` 없음)으로 바꾼 트리거가 한 번도 안 걸렸다 — 이번 실행에 10분 넘게 무음인 에이전트가 없었다는 뜻이다. 총 63줄은 `작업당 done 1줄` + `배정당 start 1줄`의 구조적 바닥에 해당하고, Round 1이 재산정한 비율 목표를 충족한다.
- **`constitution-auditor`의 Phase 배리어 오탐이 사라졌다.** `tasks-template.md` 수정이 효과를 냈다 — 이번 `tasks.md`에는 폐기된 배리어 문구가 없고, 감사관이 지적한 6건(major 3 · minor 3)은 전부 실제 위반이다.

## 정체된 것

- **병렬도가 1.96에서 두 번 연속 멈췄다.** 동시 실행 분포도 Round 1과 거의 겹친다(가동 구간 기준 — 1명 37.0% · 2명 38.0% · 3명 18.9% · 4명 4.4% · **5명 1.7%**). 상한 5는 이번에도 안 걸렸다. [Round 1의 진단](2026-08-16-implement-round1.md#개선이-필요한-것)("실제 한계는 규칙이 아니라 `tasks.md`의 의존성 그래프")이 두 번째 표본으로 확인됐다. **규칙을 더 푸는 것으로는 안 오른다.**
- **최대 단일 에이전트를 정하는 것은 여전히 Figma다.** 최장 5개 중 4개가 Figma 중심이고, **Figma를 만지는 에이전트가 전체 에이전트 시간의 74%**(101.9 / 137.9분)를 차지한다. 1위는 `design-auditor`(13.4분·120턴·피크 141k), 구현자 최장은 `design-system-builder`(11.4분·82턴·피크 151k)로 둘 다 배정 작업 수 상한(3개)에 걸리지 않았다. 결정 1로는 8분에 닿지 않는다는 것이 두 번 나왔고, 남은 레버는 결정 3(값 시트)뿐이다.
- **피크 컨텍스트 210.4k·크로스 중복 83회는 미적용 축이라 판정 대상이 아니다.** 다만 방향은 Round 1과 같다 — 고유 노드 58개 중 **48개(83%)를 두 명 이상이 각자 조회**했다. 조회 총량은 280 → 219회로 줄었지만 중복 구조는 그대로다.

## 품질

속도가 검수를 깎아서 나온 것인지 확인하는 축이다. **깎이지 않았다.**

- `design-auditor` 지적 **12건 + 미검증 1건**(Round 1 12건). Phase 2 검수에서 `T005`·`T008` 10건, 최종 전수 대조에서 값 불일치 1건(칩 그림자 blur)·구조 불일치 1건·마커 경계 1건.
- 전수 대조는 저장소의 그림자 변환 계수(Figma radius × 0.433)를 역산해 코드의 계수(0.577)가 **Figma 원값도 저장소 변환값도 아닌 제3의 값**임을 잡아냈다. 구현자 누구도 발견하지 못한 종류다.
- 게이트 재작업은 디자인 10.6분 · 규범 2.8분 · 품질 0분이다. 품질 게이트의 `fail`은 `:core:analytics`의 **기존** lint 위반이라 범위 가드상 고치지 않고 보고에 남겼다.
- 미완 2건: `T043`(라이트·다크 프리뷰 — 세션에 렌더 수단이 없어 바인딩 추적으로 대체, 시각 축 미검증) · `T044`(위 lint 실패).

## 재발한 것

- **`T005`·`T008`(상단 내비게이션)에서 Round 1과 같은 유형의 지적 10건이 다시 나왔다** — 주석에 노드 ID 기재, 주석에 Figma 값 복사([`figma-design-fidelity.md`](../conventions/figma-design-fidelity.md) §2·§5 위반). 배정 축소·검수 파이프라이닝으로 잡히지 않고, **값 시트로도 잡히지 않는다**(값이 아니라 주석 규약 문제다). 같은 전문가가 같은 파일에서 두 번 같은 실수를 했다는 것은 규칙이 전문가 정의에 닿지 않고 있다는 뜻이다.
- 리드가 `T014`를 테스트만 보고 마킹했다가 ktlint 위반이 드러나 되돌린 일이 있었다(재작업 0.9분). 게이트 지적이 아니라 리드의 확인 누락이다.
