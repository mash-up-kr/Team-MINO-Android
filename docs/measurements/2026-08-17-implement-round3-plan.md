### 1. 검수 위치 — 깊이는 그대로, 자리만 옮긴다

`design-auditor`는 7건 40.1분이고 그중 **31.1분이 사슬 위**에 있다. Phase 종료와 완료 시점에 붙어 있어 뒤에 아무것도 못 온다.

- **컴포넌트가 완성되는 즉시 검수를 붙인다.** 검수자는 코드를 고치지 않으므로 다음 작업과 겹쳐 돈다
- 종단에는 **통합 대조 하나**만 남긴다
- **노드 그룹별로 병렬로 띄운다** — 최장 인스턴스 13.4분/120턴이 5분대로 내려간다
- **깊이(§4 전수 대조)와 독립 재조회는 건드리지 않는다.** 속도는 검수를 깎아서가 아니라 위치를 바꿔서 얻는다

### 2. 같은 파일 = 한 배정

`RoomFormScreen.kt`가 `T024 → T032 → T034 → T037` 네 번 쓰였다. 파일 8개가 작업 22개로 나뉘어 **링크 14개**가 사슬에 얹혔다.

**지금 이걸 상한이 막고 있다.** `SKILL.md` §5의 *"한 전문가에게 한 번에 배정하는 작업은 최대 3개"* 에 걸려 4개짜리 파일을 한 번에 못 준다.

상한의 목적은 컨텍스트 억제인데, **같은 파일 4개 작업은 컨텍스트를 4배로 만들지 않는다** — 한 번 읽고 네 요구를 반영하는 쪽이 네 번 읽는 것보다 가볍다. 그래서 기준을 **파일 수**로 바꾼다.

`tasks.md`는 손대지 않는다. 스토리별 분해를 유지한 채 **배정 단위에서만** 병합하므로 스토리 독립 검증을 잃지 않는다.

### 3. 값 시트 1단계 — 도구는 남기되 **사용을 계측 가능하게** 만든다

우선순위 3위다(1·2가 두 배 크다). ADR이 정한 2단계(*"시트가 부실한 채로 도구부터 뺏으면 구현자가 값을 추측하게 되고, 이건 품질이 조용히 무너지는 경로다"*)를 지킨다. 다만 **"시트만 만들고 도구는 유지"로 끝내면 구현자가 시트를 안 읽고 원본을 다시 판다** — 크로스 중복이 그대로 남고, 무엇보다 **1단계의 목적인 "시트 품질 확인"을 측정할 수단이 없어진다.**

1단계 설계는 이렇게 한다.

- `context-analyst`가 착수 시점에 값 시트를 만든다(추출 인스턴스 3~5개 병렬)
- 구현자 브리프에: **값은 시트를 먼저 읽는다. 시트에 없거나 어긋나면 원본을 조회해도 되지만, 그때는 조회한 노드와 사유를 보고에 적는다**
- 도구는 **회수하지 않는다** — 안전망이자, 시트의 구멍을 드러내는 장치다
- **구현자가 원본을 다시 판 횟수와 그 사유 목록이 곧 시트 품질 점수다.** 0에 가까우면 2단계(도구 회수)로 가고, 사유가 쌓이면 시트 산출 규칙을 먼저 고친다

### 4~6. 나머지

- **웨이브 선계획**: 링크당 인계 0.9분 × 10링크. 의존성이 풀리는 시점을 미리 계산해 두면 0.2~0.3분으로 준다
- **내부 중복 금지**: 219콜 중 **60회(27%)** 가 같은 에이전트의 같은 노드 재조회다. **ADR §원인 3이 "34회뿐"이라며 기각한 처방인데, 구성비가 뒤집혀 지금은 최대 항목이다.** 에이전트 경계를 넘지 않으므로 브리프 한 줄로 풀린다
- **게이트 로그**: 피크 208k의 정체는 Gradle 출력이다. Figma와 무관한 별개 축이다

### 원인 3(같은 노드를 여러 에이전트가 각자 다시 판다)은 어디까지 덮이나

ADR §원인 3이 지목한 중복은 Round 2에서 세 갈래로 갈리고, **구성비가 ADR 작성 시점과 뒤집혔다.**

| 갈래 | Round 2 | 처방 | 남는가 |
|---|---|---|---|
| 한 에이전트 안에서 재조회 | **60회 (27%)** | 조치 5 (브리프 한 줄) | 0을 목표 |
| 구현자 ↔ 구현자 | 13회 | 조치 3 (시트 우선 읽기) | 0을 목표 |
| 검수자 관여 | 30회 | **없음 — 의도적으로 유지** | 그대로 |

검수자 몫을 남기는 것은 [2026-08-09 ADR](../adr/2026-08-09-implement-agent-orchestration.md)의 *"검증 주체와 구현 주체가 같으면 자기 산출물을 통과시킨다"* 와 `design-auditor.md`의 *"구현자가 낸 대조 보고를 판정 근거로 삼지 않는다"* 를 지키기 위해서다. **그래서 "크로스 중복 0회"는 도달 불가능하고, 지표를 갈라야 한다**(§지표 재산정).

## 결정 3·4에 대한 판단

**결정 3(값 시트) — 적용한다. 단 2단계로, 우선순위 3위로.**

근거는 구현자가 적재하는 Figma 1,028KB(전체 tool_result의 53.4%)와, 최대 단일 에이전트의 병목이 두 라운드 다 배정 크기가 아니라 Figma였다는 것이다. 다만 기대 이득은 **피크 컨텍스트(구현자)와 최대 단일 에이전트 두 축으로 좁혀** 평가한다 — 재작업 감소는 값 시트 없이 이미 달성됐다.

**결정 4(검수 시점) — 방향을 뒤집어야 한다.**

ADR의 결정 4는 *"검수 시점은 Phase 종료를 유지하되 크리티컬 패스에서 빼낸다"* 인데, **두 라운드 다 빼내지 못했다**(사슬의 47.6%). 계측이 가리키는 처방은 시점 유지가 아니라 **컴포넌트 단위로 앞당기는 것**이고, 그건 ADR §고려한 대안이 기각한 안이다.

기각 근거는 *"검수 인스턴스가 컴포넌트 수만큼 늘어 Figma 호출과 토큰이 되레 증가한다"* 였는데, 계측은 검수자 시간이 **호출량이 아니라 턴 수**에 걸려 있다고 말한다(최장 13.4분·120턴·80KB). 값 시트가 들어오면 한계비용은 더 떨어진다. **기각 전제가 반증됐다.**

→ **이 반전은 ADR 개정 사안이다.** [`adr-format.md`](../../.claude/skills/adr-writer/adr-format.md)가 *"결정이 뒤집히면 새 ADR을 쓰고 기존은 상태만 `Superseded by`로 바꾼다"* 고 정하므로, **Round 3 결과로 이 처방이 실제로 먹는지 확인한 뒤** 새 ADR로 확정한다. 이번 라운드에서는 `SKILL.md`에만 적용해 검증한다.

## 적용 순서

파일이 아니라 **위험도와 판정 가능성**으로 묶는다.

### 왜 여섯 개를 한 라운드에 묶는가

레버를 하나씩 나눠 재면 라운드가 여섯 번(각 ~78분)이다. 그럴 필요가 없다 — **레버마다 전용 관측축이 있어 한 라운드 안에서 개별 판정이 된다.**

| 레버 | 그 레버만 보는 축 |
|---|---|
| 검수 위치 | 사슬 안 `design-auditor` 시간 (Round 2: 31.1분) |
| 파일 단위 배정 | 배정당 파일 수 · 파일별 배정 횟수 (Round 2: 파일 8 ↔ 작업 22) |
| 값 시트 | 구현자 Figma 적재 바이트 (1,028KB) · 시트 품질 |
| 웨이브 선계획 | 리드 인계 공백 (9.6분) |
| 내부 중복 금지 | 에이전트 내부 Figma 중복 (60회) |
| 게이트 로그 | 게이트 피크 컨텍스트 (208k) |

**교란되는 것은 wall clock 하나뿐이고**, 그건 애초에 합산 지표다. 개별 기여도가 필요해지면 그때 축별 실측으로 역산한다.

### 0단계 — 지표와 기록을 먼저 맞춘다 (실행 전 필수)

- **ADR 목표 4개 재산정**(§지표 재산정). 이걸 안 하면 Round 3도 "미적용/미달"만 찍는다
- **ADR §검증에 한 줄**: *결정 4의 시점 규정("Phase 종료 유지")은 Round 3에서 반전을 검증 중이며, 그동안 `SKILL.md`가 의도적으로 앞서 간다.* **이 줄이 없으면 `constitution-auditor`가 SKILL↔ADR 불일치를 매번 지적하고 리드가 매번 기각해야 한다** — Round 2에서 `tasks-template` 배리어로 겪은 것과 같은 오탐이다
- 계측 축 정의는 §Round 3에서 새로 잴 것에 이미 고정돼 있다

### 1단계 — 위험 0, 되돌리기 쉬움 (`SKILL.md` §5)

조치 **2**(배정 상한을 파일 기준으로) · **4**(웨이브 선계획) · **5**(내부 중복 금지).

규칙 문구만 바꾸고 에이전트 계약을 건드리지 않는다. 셋 다 전용 축이 있어 효과가 바로 보인다.

### 2단계 — 게이트 컨텍스트 (`quality-gate-runner`)

조치 **6**. 피크 208k는 Figma와 무관한 별개 축이라 다른 것과 섞이지 않는다.

### 3단계 — 위험 있는 둘, 각각 트립와이어를 달고

| 조치 | 트립와이어 — 이게 나오면 되돌린다 |
|---|---|
| **1. 검수 위치 이동** | `design-auditor` **지적 건수가 Round 2(12건 + 미검증 1) 아래로 떨어지면** 검수가 헐거워진 것이다. 속도만 좋아지고 지적이 줄면 실패로 본다 |
| **3. 값 시트 1단계** | 구현자가 시트를 두고 **원본을 다시 판 횟수와 사유**. 사유가 쌓이면 2단계(도구 회수)로 가지 않고 시트 산출 규칙을 먼저 고친다 |

조치 3은 **두 파일에 걸친다** — `context-analyst`(시트 산출)와 `SKILL.md` 브리프 계약(*시트 먼저 읽기, 원본 조회 시 보고*). 한 단계에서 함께 적용한다.

### 4단계 — 실행 전 정합성 점검 (몇 분이면 끝난다)

78분짜리 실행이 규칙 모순으로 헛돌지 않게 한다.

- `SKILL.md` 안에 서로 어긋나는 규정이 없는지(특히 배정 상한과 파일 병합, 검수 시점과 Phase 종료 서술)
- 브리프 계약의 *시트 먼저 읽기* 가 기존 *규약 본문을 옮겨 적지 않는다*(원칙 I)와 충돌하지 않는지
- 규약을 스킬이 다시 풀어쓴 곳이 없는지
- `tasks.md` 47개가 `[ ]`인지 · 저장소가 구현 이전 상태인지 · `:app:assembleQaDebug`가 서는지
