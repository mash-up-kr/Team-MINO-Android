# Measurement Records (계측 기록)

어떤 결정이 실제로 효과가 있었는지를 **숫자로 확인한 결과**를 남기는 문서 모음이다. [ADR](../adr/README.md)이 "왜 이렇게 하기로 했는지"와 "무엇을 목표로 했는지"를 남긴다면, 계측 기록은 "그래서 실제로 어떻게 됐는지"를 남긴다.

## 이 문서 모음의 성격

**규칙을 정의하지 않는다.** 여기 있는 문서는 특정 시점의 실행을 잰 결과이며, 다른 문서가 따라야 할 규범을 만들지 않는다. 그래서 [헌법](../constitution.md) 원칙 I이 규율하는 "규칙 문서"가 아니고, `../../CLAUDE.md`의 "상황 → 참조할 문서" 네비게이션 표에도 오르지 않는다. 도달 경로는 그 계측이 검증하는 **ADR의 §검증 절**이다.

**갱신하지 않는다.** 실측치는 잰 시점의 사실이므로 나중에 고치지 않는다. 판정이 뒤집히거나 목표 자체가 바뀌면 새 라운드를 재서 문서를 하나 더 만든다.

## 언제 계측 기록이 남는가

- ADR이 **목표 수치**를 명시하고 "다음 실행을 재서 검증한다"는 완료 조건을 건 경우
- 같은 대상을 반복해서 재며 라운드를 쌓아 가는 경우

## 작성 규칙

- 파일명은 `YYYY-MM-DD-<대상>-round<N>.md`(계측일 접두어)로 한다. 근거는 [ADR·실패 기록 파일명은 일련번호 대신 날짜 접두어를 쓴다](../adr/2026-07-27-record-filename-date-prefix.md)와 같다.
- 문서는 **대상·조건 → 실측 → 원인 → 후속 과제** 순으로 쓴다. 목표 수치와 그 산정 근거는 ADR이 소유하므로 여기서는 판정에 필요한 만큼만 인용하고 링크한다.
- **조건이 이전 라운드와 다르면 표보다 먼저 적는다.** 조건이 다른 두 숫자를 나란히 놓는 것이 이 문서가 만들 수 있는 가장 큰 오해다.

## `mino-implement` 라운드 계측 방법

아래 정의는 [mino-implement ADR](../adr/2026-08-16-implement-chunking-parallelism-figma-value-sheet.md)이 건 목표를 재는 라운드 전체에 공통으로 적용한다. 라운드끼리 비교하려면 정의가 같아야 한다.

| 항목 | 정의 |
|---|---|
| 자료 | 메인 세션 트랜스크립트 1건 + 서브에이전트 트랜스크립트 전건(`~/.claude/projects/<프로젝트>/<세션 ID>/subagents/*.jsonl`) |
| 계측 구간 | 실행 시작(`/mino-implement` 입력)부터 완료 보고까지. 실행이 끝난 뒤의 대화는 제외한다 |
| wall clock | 계측 구간의 첫 타임스탬프와 마지막 타임스탬프의 차 |
| 에이전트 실행 시간 | 한 서브에이전트의 첫 턴과 마지막 턴의 차. **실행 시간 합**은 그 총합이다 |
| 에이전트 가동 구간 | 최소 한 명이 돌고 있던 시간. wall clock에서 아무도 안 도는 구간(사용자 대기·리드 단독 작업)을 뺀 값이다 |
| **병렬도** | 에이전트 실행 시간 합 ÷ **에이전트 가동 구간** |
| 출력 토큰 | `usage.output_tokens` 합. 리드와 전문가를 나눠 센다. 사고·도구 호출 인자를 포함한다 |
| 피크 컨텍스트 | 한 턴의 `input + cache_read + cache_creation` 최댓값. 에이전트별로 구해 최댓값과 중앙값을 본다 |
| Figma 크로스 중복 | `(툴, 노드 ID)` 조합 기준 총 호출 − 고유 조합 − 한 에이전트 안에서의 중복. 노드 ID 표기(`-`/`:`)는 정규화한다 |
| 재작업 시간 | 게이트 지적을 받아 다시 띄운 에이전트의 실행 시간 합. 지적 주체(디자인·규범·품질)별로 나눈다 |
| 진행 로그 줄 수 | 전문가가 `PROGRESS_LOG`에 append 한 줄 수. 로그 파일은 실행 후 지워지므로 트랜스크립트의 `echo` 호출로 센다 |

병렬도를 **wall clock이 아니라 가동 구간**으로 나누는 이유는, 사용자 입력을 기다리느라 아무도 안 돌던 시간이 섞이면 "병렬로 얼마나 겹쳤나"가 아니라 "얼마나 기다렸나"를 재게 되기 때문이다. 두 축은 따로 본다.

## 라운드 실행 계획 문서

라운드를 재기 **전에** 무엇을 바꾸고 무엇을 잴지 정해 두는 문서가 앞설 수 있다. 파일명은 `YYYY-MM-DD-<대상>-round<N>-plan.md`로 한다.

- **계측 기록이 아니다.** 실측이 없으므로 위 "작성 규칙"의 대상·조건 → 실측 → 원인 → 후속 순서를 따르지 않는다.
- 그 라운드의 계측 기록이 나오면 **계획 문서를 대체한다.** 실행 결과가 계획과 갈린 지점은 계측 기록의 원인·후속 절이 소유한다.

## 종합 문서

라운드를 닫을 때 **세 라운드를 관통한 변화와 그 귀속**을 한 장으로 남긴다. 파일명은 `YYYY-MM-DD-<대상>-summary.md`로 한다.

- **라운드별 실측을 다시 계산하지 않는다.** 조건·원인·판정은 각 라운드 문서가 소유하고, 종합 문서는 인용하고 링크한다.
- 마지막 라운드의 §다음 Round 전에 할 일이 남긴 항목의 **처분**을 이 문서가 갖는다. 라운드가 끝난 뒤에는 그 항목들이 계측이 아니라 일반 작업이 되기 때문이다.
