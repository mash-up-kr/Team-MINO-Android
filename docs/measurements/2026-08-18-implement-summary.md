# `mino-implement` 계측 종합 — Round 1~3 (2026-08-16~18)

- **대상**: `group-room-form` 기능 구현을 같은 조건으로 세 번 재실행하며 잰 결과
- **검증한 결정**: [mino-implement는 배정을 잘게 쪼개 병렬로 돌리고, Figma 값은 착수 시점에 한 번만 추출해 공유한다](../adr/2026-08-16-implement-chunking-parallelism-figma-value-sheet.md) · [디자인 검수는 Phase 종료가 아니라 컴포넌트가 완성되는 즉시 붙인다](../adr/2026-08-18-design-audit-at-component-completion.md)
- **자료**: [Round 1](2026-08-16-implement-round1.md) · [Round 2](2026-08-17-implement-round2.md) · [Round 3](2026-08-18-implement-round3.md). 계측 방법은 [README §계측 방법](README.md#mino-implement-라운드-계측-방법)을 따른다
- **결론**: **Round 3에서 계측을 닫는다.** 여덟 목표 중 명목 달성은 2개지만, 실행 규칙이 겨냥한 여섯 축이 전부 개선됐고 **남은 미달의 원인이 실행 규칙 밖으로 나갔다.**

이 문서는 라운드별 실측을 다시 계산하지 않는다. 각 라운드의 조건·원인·판정은 위 세 문서가 소유하고, 여기서는 **세 라운드를 관통한 변화와 그 귀속**만 갖는다.

## 무엇이 개선됐고, 무엇이 그것을 만들었나

### 1. wall clock 136 → 76.2분 — 병렬화가 아니라 "없어진 일"과 "겹친 일"

세 라운드에서 wall clock을 실제로 움직인 것은 셋이며, **셋 다 서로 다른 라운드에서 나왔다.**

- **Round 1 → 2 (238.8 → 78.2분)**: 사용자 대기 129분이 0분이 됐고 에이전트 작업량 합이 204.5 → 137.9분으로 33% 줄었다. 착수 게이트 `1-c`(Figma 노드 개통 프로브. 이후 값 시트 추출 단계 `2-b`로 흡수됐다)와 **브리프의 사실/부재 분리** 규칙이 걸렸다 — Round 1에서 47분 대기와 세 번째 배정을 만든 "그 파일을 다시 열지 마라" 인계가 재현되지 않았다. 다만 Round 1의 더 큰 차단(82분)은 스펙 정정으로 이미 사라진 상태였으므로 전부를 규칙의 성과로 돌릴 수 없다([Round 2 §조건](2026-08-17-implement-round2.md#조건)).
- **Round 2 → 3 (78.2 → 76.2분)**: 겉으로는 2분이지만, 그 사이 **작업량이 31% 늘었다**(에이전트 시간 합 137.9 → 180.1분, 47/47 전건 완료). 이를 흡수한 것이 병렬도 1.96 → 2.64이고, 그 병렬도를 만든 것이 **검수 위치 이동**이다.
- **검수를 컴포넌트 완성 시점으로 옮긴 것이 단일 최대 레버였다.** 사슬 안 `design-auditor`가 31.1 → 12.9분(−18.2분). 두 라운드 동안 1.96에서 멈춰 "규칙으로는 안 오른다"고 진단했던 병렬도가 이때 움직였다 — **병렬도의 한계는 `tasks.md` 의존성 그래프만이 아니라 검수 배리어이기도 했다.** 이 반전은 원 ADR이 명시적으로 기각했던 안이며, 계측이 기각 근거를 뒤집어 [별도 ADR](../adr/2026-08-18-design-audit-at-component-completion.md)로 확정됐다.

### 2. 컨텍스트 — 원 ADR의 진단이 맞았고, 처방도 맞았다

원 ADR은 *"시간을 먹는 건 빌드가 아니라 컨텍스트다"* 라고 진단했다. 세 라운드가 이를 지지한다.

- **최대 단일 에이전트 20.1분/157턴 → 9.1분/37턴.** 시간보다 **턴이 4분의 1로 준 것**이 본질이다. 컨텍스트가 짧으면 턴당 재읽기가 줄고, 그것이 곧 시간이다.
- **컨텍스트 재읽기 117.9M → 82.5M.** 서브에이전트가 25 → 49건으로 두 배가 되고 작업량이 늘었는데도 총량이 30% 줄었다.
- **구현자 피크 210.4k → 141.7k**(중앙 79.8k)를 만든 것은 값 시트다. 구현자의 Figma 적재가 86콜/1,028KB → **34콜**로 떨어졌다.
- **`quality-gate-runner` 피크 208.2k → 35.4k**는 게이트 로그 절삭이 정확히 맞힌 축이다.

### 3. Figma 중복 — 값 시트가 겨냥한 축을 맞혔다

- **구현자↔구현자 중복 13 → 0회.** 값 시트가 없앨 수 있다고 예측한 딱 그 부분이 사라졌다.
- **에이전트 내부 중복 60회(27%) → 3회(1%).** 원 ADR이 §원인 3에서 *"34회뿐"* 이라며 프롬프트로는 안 풀린다고 기각했던 축인데, Round 2에서 최대 항목이 됐고 규칙 한 줄로 닫혔다. **기각이 틀렸다.**
- **검수자↔구현자 중복은 남아 있고, 남긴 것이다.** 검수자에게 시트를 주지 않는다는 규칙이 지켜져 검수자 조회가 전체의 60%(148콜)다. 이 중복이 품질의 마지막 방어선이다.

### 4. 품질은 깎이지 않았다

속도가 검수를 헐겁게 만든 것인지 보는 축이다. `design-auditor` 지적은 12건 → 12+1건 → **16건**(값 9 · 구조 7)으로 **늘었다.** 검수 인스턴스가 10건으로 쪼개졌는데도 4건이 `위반 없음`이고 나머지가 실제 지적을 냈다. 트립와이어(*"지적이 Round 2 아래로 떨어지면 되돌린다"*)는 걸리지 않았다.

## 라운드를 3에서 닫는 근거

- **실행 규칙이 겨냥한 축이 전부 움직였다.** 여섯 레버 중 넷(검수 위치 · 값 시트 · 내부 중복 금지 · 게이트 로그)이 자기 관측축에서 효과를 냈고, 하나(파일 단위 배정)는 적용됐으며, 하나(웨이브 선계획)는 역효과로 판정돼 규칙에 남지 않았다.
- **남은 병목이 이 ADR의 사정권 밖으로 나갔다.** Round 3에서 사슬의 75.7%가 구현자이고, 최장 에이전트 5개 중 3개는 Figma를 거의 만지지 않는다. 다음으로 줄일 것은 **구현자의 절대 속도**이며, 배정·병렬·데이터 흐름 규칙으로는 닿지 않는다.
- **wall clock이 목표에 1.9분까지 붙었다.** 남은 차이는 라운드 간 조건 편차(작업량·사용자 대기)와 같은 크기다. 한 라운드를 더 재도 규칙의 효과와 잡음을 가를 수 없다.
