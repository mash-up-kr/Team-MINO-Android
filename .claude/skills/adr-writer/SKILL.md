# adr-writer — 대화 중 자동 ADR 기록

이 Skill의 목적은 문서 자체가 아니라 **미래 세션의 토큰 절감**이다. 결정 당시의 맥락과 이유를 놓치지 않고 남겨서, 나중에 다른 세션(다른 사람 또는 다른 Claude 인스턴스)이 "왜 이렇게 했지?"를 처음부터 재조사·재논의하지 않게 한다.

## 입력 (트리거 조건 — 스킬 실행 시 판단 기준)

명시적 파라미터 없이, 대화 중 아래 중 하나가 **확정**되는 순간(제안·검토 단계가 아니라 결론이 난 시점) 자동으로 실행한다.

- 라이브러리·프레임워크 선택 또는 교체 (예: "Ktorfit 대신 Ktor 쓰자")
- 모듈 경계·레이어 구조에 영향을 주는 결정
- 되돌리기 어렵거나, 나중에 "왜 이렇게 했지?"라는 의문이 생길 만한 결정
- 의도적으로 **하지 않기로** 한 것 (예: 특정 우회책을 금지)

> 자명하거나 쉽게 되돌릴 수 있는 결정에는 트리거하지 않는다. 애매하면 남기는 쪽보다 사용자에게 "이거 ADR로 남길까요?" 한 줄로 먼저 확인한다.

## 작업 순서

1. **`docs/adr/README.md`를 먼저 Read**해 최신 작성 규칙·상태 값·번호 규칙을 확인한다. 이 Skill 안에서 규칙을 재정의하지 않는다.
2. 다음 번호를 정한다: `docs/adr/` 내 가장 큰 `NNNN`에 +1 (4자리, 0-padding).
3. 대화 맥락에서 아래를 추출한다.
   - **맥락**: 이 결정이 필요했던 배경, 제약 조건
   - **결정**: 무엇을 선택했는가
   - **결과**: 시스템에 미치는 영향, 후속 지침
   - **작성자**: `docs/adr/README.md`에 정의된 대로, 이 결정이 누구의 작업과 관련되면 좋을지 남긴다. 담당자가 특정되지 않으면 관련 이슈 번호·브랜치명으로 대체하고, 그마저 없으면 생략한다.
4. `docs/adr/README.md`의 Nygard 스타일 템플릿에 맞춰 `docs/adr/NNNN-kebab-제목.md`를 작성한다. 상태는 기본 `Accepted`(사용자가 확정한 결정이므로) — 아직 논의 중이면 `Proposed`.
5. `docs/adr/README.md` 인덱스 표에 새 줄을 추가한다.
6. 이 결정이 기존 ADR을 대체하는 것이라면, 기존 ADR의 상태를 `Superseded by NNNN`으로 갱신한다.

## 작성 규칙

- 결정의 "왜"가 대화에 없으면 추측해서 채우지 않는다. 사용자에게 한 번 확인한다.
- 이미 같은 주제의 `Accepted` ADR이 있는데 이번 결정이 그걸 뒤집는 것이라면, 이건 `adr-writer`가 아니라 [`failure-writer`](../failure-writer/SKILL.md)의 영역일 수 있다 — 이전 결정이 "틀렸던" 것인지 단순히 "갱신"되는 것인지 구분해 판단한다.
- 통제 어휘: 상태는 `docs/adr/README.md`에 정의된 값(`Proposed`/`Accepted`/`Superseded`/`Deprecated`)만 사용한다.

## 산출물 핸드오프

- 산출물: `docs/adr/NNNN-kebab-제목.md`(신규) + `docs/adr/README.md` 인덱스 갱신, 필요 시 대체된 기존 ADR 파일의 상태 갱신.
- 생성/수정한 파일을 사용자에게 요약해 알린다.
- **커밋은 이 Skill의 범위가 아니다** — `/done`에서 다른 변경사항과 함께 처리한다.
