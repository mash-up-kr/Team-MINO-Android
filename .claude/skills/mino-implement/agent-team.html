SDD Implement 단계 — 리드(메인 세션) + 전문가 서브에이전트 오케스트레이션

조율 계약

  • • 브리프에는 원문이 아니라 경로를 넣는다 (헌법 원칙 I)
  • • 보고는 작업 하나당 한 줄 — done · blocked · failed
  • • 세 번째 칸은 확인 근거. "구현했다"는 근거가 아니다
  • • 부분 완료는 done이 아니라 blocked

Phase별 배정

  • • 셋업 — build-setup-engineer 단독
  • • 기반 — test-engineer → core-layer-developer
  • • 스토리 — core ∥ ui ∥ design-system → navigation
  • • 다듬기 — 해당 모듈의 소유 전문가

진행 가시성

  • • 보고는 배정분을 다 끝내야 리드에 닿는다
  • • 그 사이는 로그 한 줄이 사용자 알림 하나
  • • 오래 걸리는 단계는 note 한 줄만
  • • 완료 후 Monitor 종료 · 로그 파일 정리

전문가 공통 금지

  • • tasks.md 수정 — [X] 마킹은 리드만
  • • git commit 실행
  • • 소유 범위 밖 파일 수정 (로그 append는 예외)
  • • 배정에 없는 개선 · 리팩터링
